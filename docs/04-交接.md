# 04 · 开发交接与启动入口

> 最后修改：2026-11-08 23:28（UTC+08:00）

本文帮助新接手者定位启动方式和代码；不重复维护协作规则、当前进度或检查等级。先读 [AGENTS](../AGENTS.md) 和 `pnpm agent:brief`，状态以 [STATUS](STATUS.md)为准。

## 1. 启动与环境

日常主目录、HTTP/HTTPS、Web/API 端口及排障统一见[本地开发环境与 5173](ops/本地开发环境与5173.md)。依赖以根 `package.json`、锁文件及包内配置为准；配置只从示例建立，不复制或输出真实密钥。开发库与测试库隔离。

纯文档任务不用启动应用、迁移数据库或重建前端。业务任务依照受影响路径验证，不重启其他任务的服务器。

## 2. 代码与规范

先看[技术方案](02-技术方案.md)理解数据流，再从 [apps](../apps/README.md)、[packages](../packages/README.md)、[prisma](../prisma/README.md)、[deploy](../deploy/README.md)逐层定位。每层 README 只列直属内容；行为权威从[任务索引](00-索引.md)查找。

交易冲突与离线、分析工作台配置、权限、导入和备份分别有专题契约，不从历史交接或代码文件名推导产品规则。

## 3. 完成一次修改

按[开发与验收规范](ops/开发与验收规范.md)选择检查；按[文档维护规范](ops/文档维护规范.md)更新受影响规则、目录入口与已有 PDF。用户可见改动维护当前系列技术日志和 STATUS，纯文档不升产品版本。现行系列入口由 [changelog/README](changelog/README.md)导航，旧系列不再追加新版本。

保留可恢复的本地 Git 记录；是否上传、部署或公开发布按 AGENTS 当次授权规则执行。本地与生产状态分开报告，历史记录中的“待真机确认”只表示当时状态。

## 4. 追溯与问题记录

- 具体未查明缺陷：[BUG 记录](BUG记录.md)。不因日期久远自动关闭。
- 经验与失败原因：[lessons](lessons.md)，按案例查询；通用硬规则只在 AGENTS 定义。
- 已有决定：[ADR](adr/README.md)和专题历史依据。
- 所有者对系统的理解：[学习记录](理解驱动开发-学习记录.md)，掌握状态只能由所有者确认。

## 5. 接手时应保留的工程成果与经验

| 已有基础 / 决定 | 接手时为什么需要知道 |
|---|---|
| S8 的离线本地账目与印记 store | 这是长期维护的完整离线读写成果，不是可丢弃的查询缓存。界面订阅模块级外部 store；曾发生持久化数据已到达而 iPad 界面未更新的问题，修复依赖让读写与订阅观察同一事实。定位从[离线目录](../apps/web/src/lib/offline/README.md)进入，不能因历史资料较旧而重新做一套并行缓存。 |
| 冲突判定的字段语义 | base、wanted、服务器当前值及历史值分别有含义；显示名、版本号、时间先后不能代替冲突契约。曾出现界面候选与判定读取不同来源的故障，数据到 UI 必须沿同一链路；现行算法从[冲突规格](specs/product/S8-冲突-设计决定.md)读取。 |
| 跨时区与整数金额 | ISO 字符串外观顺序不能代替瞬间比较；金额不能统一按两位小数或浮点求和。早期已为此修过真实缺陷，具体金额/日期契约见[技术方案 §2](02-技术方案.md#2-数据流与一致性)。 |
| 真实构建与运行证据 | 曾出现类型检查/测试通过但应用无法启动，以及编辑看似成功却没有实际接线。检查要覆盖最终构建及用户实际路径；修复反复失败时用开发规范的 Diagnostic Mode 收集证据。 |

这些是已经形成的能力和决定的来由；操作规则由 AGENTS 和专题规范维护，完整案例仍见 lessons。所有者反馈的是实际使用结果，不能用“代码看起来应该正常”否定其观察，也不能把日志里的成功直接当成用户目的已达成。
