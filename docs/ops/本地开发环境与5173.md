# 本地开发环境与 5173

> 最后核对: `local/current-1.17.8 @ 7d5b873` / 2026-10-28（修复日常启动：HTTP 入口、脚本不再秒关窗口、端口冲突显式报错；新增 LAN HTTPS 可选脚本）。性质：开发环境操作说明；版本、迁移与生产记录统一见 [STATUS](../STATUS.md)。

## 1. 唯一日常开发基线

| 项 | 值 |
|---|---|
| 工作区 | `C:\Users\<本机用户>\Desktop\工作\记账程序\记账程序v1`（主工作区） |
| 分支 | `local/current-<版本>`（当前见 [STATUS](../STATUS.md)「分支 / 远程」） |
| 本地版本 | 见 [STATUS](../STATUS.md)「本地开发版本」；页面 `/update` 与 `/api/v1/health` 必须一致 |
| Web 入口 | **<http://localhost:5173>**（`start-dev-lan.cmd` 启动；HTTP） |
| API | `http://127.0.0.1:3000` |
| 数据库 | 本机 `ledger_dev`（`DATABASE_URL` 写在主工作区 `.env`） |

**日常开发默认在主工作区进行。** 只有所有者明确要求独立 worktree，或任务确实需要隔离（例如多 Agent 并行、危险迁移验证）时才另建；临时 worktree 完成后必须把成果合回主工作区，并同步启动入口，不能让某个临时 worktree 的端口或分支长期冒充日常入口（规则见 [本地开发工作区与主目录更新规范](../specs/features/本地开发工作区与主目录更新规范-20261028.md)）。

## 2. 启动方式（双击即可）

| 脚本 | 用途 | 地址 |
|---|---|---|
| **`start-dev-lan.cmd`** | **日常入口**（本机 + 同 Wi-Fi 手机，HTTP） | <http://localhost:5173> |
| `start-dev.cmd` | 只在本机用（Vite 只绑 `127.0.0.1`） | <http://localhost:5173> |
| `start-dev-lan-https.cmd` | 仅手机录音/离线等安全上下文测试（HTTPS） | <https://localhost:5173>、`https://<LAN-IP>:5173` |

共同行为：

- 端口固定 Web `5173`、API `3000`；**5173 始终 strict**，被占用时明确报错，不会偷偷换到 5174。
- 启动后等 `/api/v1/health` 返回 `ok` 才自动打开浏览器，不靠固定睡眠时间猜。
- 命令窗口**不会在出错时消失**：服务退出后显示退出码并 `pause`。
- 重复双击不会启动第二个服务：检测到 5173 已监听时，只打印正在运行的版本并打开浏览器，窗口保持打开。

停止：在该窗口按 `Ctrl+C`，或直接关闭窗口。**不要**用任务管理器杀不确定归属的 Node 进程。

## 3. 为什么默认 HTTP，什么时候用 HTTPS

- 日常在 `localhost` 上，浏览器把 `localhost` 当作安全上下文，录音、离线、`crypto.randomUUID` 都可用，**不需要 HTTPS**。
- 只有从**手机**用局域网 IP 访问时，安全上下文 API 才要求 HTTPS；这时才运行 `start-dev-lan-https.cmd`。
- 默认入口只认 **HTTP** 一个地址。此前 `start-dev-lan.cmd` 在「服务已在运行」分支硬编码打开 `https://localhost:5173`，而当时占用 5173 的是 HTTP 服务，于是出现 `ERR_SSL_PROTOCOL_ERROR`；HTTP/HTTPS 混用还容易让浏览器记住错误协议或证书警告，故彻底拆开。

## 4. 常见问题

**A. 双击脚本后窗口消失 / 页面打不开**

1. 不要反复双击。看脚本最后打印的退出码与错误信息（现在窗口会保留）。
2. 检查端口归属：`netstat -ano | findstr :5173` 与 `netstat -ano | findstr :3000`。
3. 若 5173 已被占用：脚本会打印当前运行版本。**版本不是最新时，先关掉旧的服务器窗口**（不是杀未知进程），再运行脚本。
4. 只有 3000 被占用：通常是旧 API 残留，脚本会警告；先关闭旧窗口。

**B. 浏览器报 `ERR_SSL_PROTOCOL_ERROR`**

说明浏览器访问了 `https://localhost:5173`，但该端口是 HTTP 服务。改用 <http://localhost:5173>；如确实需要 HTTPS，先关闭 HTTP 服务，再运行 `start-dev-lan-https.cmd`。

**C. 页面版本与 `packages/shared/src/version.ts` 不一致**

先确认 5173 是哪个进程（`netstat -ano`），关闭旧服务器，再启动；浏览器强制刷新一次。开发服务器长期运行也可能返回旧模块，重启即可。

**D. `pnpm.cmd dev` 直接运行？**

可以，但不会自动处理端口冲突提示与浏览器打开。日常请用脚本，避免版本/端口混淆。

## 5. 本地环境隔离

- 主工作区使用自己的 `.env`；`.env`、证书（`apps/web/.certs/`）、构建产物与验收凭据均不入库。
- 本地登录测试账号仅用于开发/验收，不要把凭据写入文档或提交。
- 生产环境与真实用户数据不得由本地开发服务器访问或修改。

## 6. 其他 worktree 的定位

- 其他 `记账程序v1-*` worktree 是历史快照、隔离开发或验收现场，**不是日常入口**。
- 临时隔离开发完成后：按[更新规范](../specs/features/本地开发工作区与主目录更新规范-20261028.md)保护未提交内容 → 合回主工作区 → 同步 `start-dev-lan.cmd` 指向最新可验收版本。
- 不要 `git clean`、不要整目录覆盖；其他 Agent 的服务器端口（如 5176）不要停。

## 7. 维护

- 启动方式、端口或地址变化时，必须同时更新本文件、[AGENTS.md](../../AGENTS.md) 与相关脚本；地址是对所有者的承诺。
- 每次主目录归位后，按[更新规范](../specs/features/本地开发工作区与主目录更新规范-20261028.md) §6 记录。
