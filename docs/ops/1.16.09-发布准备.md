## 3. 发布步骤

沿用 [1.16.08 正式发布记录](../archive/releases/S16-1.16.08-主题与外观-发布记录-20261024.md) §3–§5 的服务器流程；本次多出 3 个迁移，必须按「先备份 → 再迁移 → 再切应用」执行。

1. **冻结候选**：确认候选提交为 `a1a2a91` + 本轮物料提交；`packages/shared/src/version.ts` 已为 `1.16.09`，无需修改；确认工作区没有未纳入范围的未提交业务改动（当前仓库仍有其他工作区/同事的改动，需先确认归属）。
2. **备份与恢复演练**：发布前对生产数据库做新备份，并做一次恢复演练（1.16.08 为 45 表演练）；建立源码快照，记录归档 SHA-256 与备份文件大小。
3. **构建与传输镜像**：构建 `libevra-rc-api:1.16.09-20261025`、`libevra-rc-web:1.16.09-20261025`，传输后在服务器 `docker image inspect` 记录 digest；relay 继续使用 `libevra-rc-relay:1.14.19-20261019`，不重建。
4. **执行生产迁移 53–55**：在维护窗口先跑 migrate（`prisma migrate deploy`），确认生产迁移数 52 → 55。三个迁移只新增 `users.avatar_id`（带默认值 `flower`）并扩充 CHECK 允许值，先迁移再切应用；迁移前必须已有可用备份。
5. **切换应用**：使用 `docker-compose.prod.yml` + `deploy/docker-compose.release-1.16.09.yml`（+ relay 独立 compose）；只重建 migrate / api / web，`db` 与 `critical-relay` 不重启。
6. **生产复验**：`/api/v1/health`（或公网 `/health`）返回 `version=1.16.09`、`database=up`；检查容器启动时间、资源、游客页脚版本；再用浏览器验证登录、语言切换、个人资料、头像、记账与账本关键路径。
7. **真机 / Safari 冒烟**：iPhone Safari 真机检查安全区、软键盘、手势与中英切换；未通过则按第 5 节回滚应用。
8. **发布收尾**：在服务器写部署标记（`.last-deployed`、`.deployed-commit`）；更新公告为已发布并同步英文映射与测试；更新 [版本记录（1.16）](../changelog/1.16.md)、[状态](../STATUS.md)、`docs/00-索引.md`；另写正式发布记录归档到 `docs/archive/releases/`；是否 push GitHub 由所有者决定。

## 4. 风险与未验收

- **真机 / Safari**：iPhone Safari 安全区、软键盘、手势未验收；1.16.08 也仍未做真机复验。
- **英文文案**：待母语审校；品牌标语、默认账本名英文、语音仅普通话说明等仍待所有者决定。
- **法律文本**：正文目前仍以中文版本为准，英文译本审核中。
- **包体积**：主包 gzip 增加约 123KB（离线优先，双语资源全部打进主包）。
- **既有待确认表述**：账单导入「全部本机处理」与实际上传服务器的说明不一致（见国际化验收 §9），发布前需确认是否一并修正。
- **并行改动**：仓库当前存在其他工作区/同事的未提交改动，发布前必须确认范围，避免把未验证改动带上生产。

## 5. 回滚与迁移兼容性

**应用回滚（推荐且最快）**：保留 1.16.08 的覆盖配置 `deploy/docker-compose.release-1.16.08.yml` 与旧镜像 `libevra-rc-api:1.16.08-20261024`、`libevra-rc-web:1.16.08-20261024`；切回旧 overlay + 旧镜像即可，`db` 和 `critical-relay` 不动。

**schema 说明**：应用的版本回滚**不会**自动回滚数据库迁移 53–55。这三个迁移均为向后兼容的增量变更——只新增带默认值的 `users.avatar_id` 列、扩充 CHECK 允许值，旧版 1.16.08 应用不读取该列也不会写入非法值，因此**旧镜像可以直接运行在 55 个迁移的库上**，无需恢复数据库。

**恢复到旧 schema**：只有确认必须回退数据库结构时，才停止写入、恢复发布前备份（会丢失备份时间点之后的写入，需所有者确认），再切回旧镜像。

**回滚触发条件**：`/health` 不健康、迁移失败、登录/记账/账本/资料等关键路径不可用、真机冒烟严重问题；应用回滚由发布执行人按本准备稿执行，数据恢复由所有者确认。
