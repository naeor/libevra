# 子 Agent 分派与额度控制

> 最后修改：2026-11-14 02:14（UTC+08:00）

本文给分派子 Agent 的 Agent（Claude、Codex、DeepSeek 等）使用：怎样在**不降低质量**的前提下控制模型额度。授权边界仍以 [AGENTS](../../AGENTS.md) 为准，检查等级以[开发与验收规范](开发与验收规范.md)为准。所有者 2026-11-14 提出：额度消耗过快，分派时避免重复计算，不重要的任务用较简单的模型，但质量优先。

## 1. 原则

1. **质量优先**：省额度不能成为降低检查等级、跳过高风险专项或省掉必要复核的理由。
2. **额度按任务重要性分配**：高风险、设计判断多的任务用最强模型；盘点、统计、登记类任务用中档或轻量模型。
3. **不重复劳动**：同一份材料只读一次、同一个结论只得出一次，后续步骤直接复用。

## 2. 选模型

| 任务类型 | 例子 | 建议模型档位 |
|---|---|---|
| 高风险实现 | 切换账本、权限、数据迁移、同步与冲突、导入导出、金额 | 最强（Claude 用 Opus） |
| 设计判断多的实现 | 新的模板体系、跨多个组件的交互改造 | 最强 |
| 高风险结论的复核 | 审查中会改变规则或涉及数据安全的结论 | 最强 |
| 只读盘点与统计 | 列清单、数文件、找出所有某类写法、空间盘点 | 中档（Sonnet） |
| 文档登记与整理 | 把已定决定写进文档、更新索引 | 中档，或主 Agent 自己做 |
| 开发用样板与演示页 | Component Gallery、lab 页面 | 中档 |
| 有守卫测试兜底的机械式改动 | 批量替换选择器、改名，且有测试能拦住遗漏 | 中档 |
| 简单查找、计数 | 某个函数在哪、某类文件有几个 | 轻量（Haiku），或主 Agent 直接用搜索工具 |

拿不准时按更高一档选；涉及 AGENTS §5 列出的数据、权限、金额、迁移、同步范围，一律按高风险处理。

## 3. 写任务说明（brief）

- **直接给位置**：写明要读、要改的文件路径与行号，以及权威规格的章节；不要让子 Agent 从头探索整个仓库。
- **结论用文件传递**：前一步的产出（例如系统地图、待复核清单）写进会话临时目录的文件，后续子 Agent 读文件；不要在多个任务说明里重复粘贴大段内容。
- **写清边界**：只读还是可改；哪些文件不能碰（尤其是并行的其他子 Agent 正在改的文件）；不启动或停止服务；不 push。
- **不重跑已通过的检查**：写明哪些检查已经通过，只在相关改动后重跑失败或受影响的那一项。
- **限制回复长度**：要求只回结论、表格与必要的文件行号，不贴原始命令输出和大段代码。子 Agent 的回复会进入主 Agent 的上下文，越长越贵。

## 4. 分派方式

- **几次工具调用能完成的事，主 Agent 自己做**，不为它开子 Agent。
- **只并行互不依赖的任务**；同一批文件同一时间只能有一个写入者。会改同一文件的任务按顺序排队。
- **复核只做一轮，并且只针对高、中风险结论**；低风险、可逆的事项不安排二次复核。
- **能续用就续用**：要给正在运行或刚完成的子 Agent 追加要求时，向它发消息继续，不另起一个从头读材料的新子 Agent。
- **验证从简**：外观核对优先用页面实际生效的样式和代码证据；只有需要所有者判断观感时才截图，截图用缩小比例。

## 5. 主会话自身

- 长会话每一轮都会带上前面的全部内容，越往后越贵。一个大阶段结束后，建议开新会话，交接靠仓库里的现行文档与待办文档，而不是聊天记录。
- 同一会话内换做无关的事情时，可由所有者使用 `/compact`（压缩历史，可附上要保留的要点）或 `/clear`。
- **不为省额度压缩给所有者的回复**：所有者希望回复详细、把道理讲清楚（2026-11-14 明确说明），会话太长时由所有者自行压缩。省额度的重点放在子 Agent 的选模型、任务说明和避免重复计算上，不放在主 Agent 对所有者的解释上；文档与报告文件的写法也照常，不为省额度删减。

## 6. 案例：2026-11-13～14 S19 审查与实施

这一轮先后派出约十个子 Agent，全部使用最强模型，每个消耗约 25–50 万 token。回看：系统地图、三路审查、复核和高风险实现用最强模型是合理的；清理空间盘点、弹出面板盘点、开发用样板页、有守卫兜底的作用域选择器替换，用中档模型即可达到同样质量。有效的做法：系统地图写成文件供三路审查共用；复核清单先合并去重再交给复核者。
