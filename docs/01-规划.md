## S19 之后的交互体验优化规划（待办草案）

**规划中，暂不实施。** 所有者于 2026-11-07 提出。关注交互连续性、视觉细节、桌面效率与整体使用体验，不属于当前 S19 视觉转场的交付范围；当前转场与材质开发继续由现有 Agent 负责。以下 P1–P7 是待办分类，不代表已完成现状审查，也不直接分配新的阶段编号；具体顺序与归属待功能审查后，按用户影响、实现成本与风险确定。

### P1 — 编辑草稿保留与恢复

目标：用户不应因暂时离开编辑页面而丢失输入。优先覆盖新增 / 编辑账目、账本信息、分类、标签、账户资料、多步骤设置及配置表单，以及输入较多的普通编辑页面。

- 开始编辑后自动保留未提交草稿；离开后回到同一编辑入口可恢复，刷新或意外关闭后尽可能恢复本地草稿。
- 草稿不等于正式保存，不自动写入业务数据；成功保存后清除对应草稿，明确放弃修改时允许删除草稿。
- 有历史草稿时提供合理的“继续编辑”“重新开始”操作。
- 按账户、账本、账目及编辑任务严格隔离；密码、安全验证等敏感表单不默认保存草稿。
- 原始数据已改变时，不得静默以旧草稿覆盖新数据；实施前明确冲突与恢复边界。
- 第一阶段只考虑本设备保存，不立即开发跨设备同步。

实施前审查现有表单状态、卸载和恢复机制，复用已有能力，不为每个页面各建一套草稿系统。已实现部分经代码核对后排除，不能将本清单直接认定为全部缺失。

### P2 — 全局按钮点击反馈与微交互

目标：让用户明确感受到按钮被按下、操作已接收，以及操作是否完成。

- **Press**：手指或鼠标按下时立即反馈，可轻缩至约 0.96–0.98 倍，背景快速过渡到较深的中间色、选中色或对应材质的按压状态；具体方式适配各视觉风格。
- **Release**：恢复正常尺寸，可轻微超过原尺寸再柔和回弹；幅度克制，高频小按钮更短、更轻，不将所有按钮做成橡胶跳动。
- **状态确认**：区分 Hover、Pressed、Processing、Success / Selected、Error / Disabled；按压动画不代表业务成功。例如“关注”先反馈按压，只有操作真正成功才显示“已关注”。此例说明状态语义，不新增关注功能。
- **桌面 Hover**：移入时适度改变颜色、表面亮度、阴影或边缘，移出自然恢复；与 Pressed 明确区分，不比实际选中状态突出，同时保留清晰的 Focus Visible。
- **统一参数**：复用微交互参数，普通按钮、图标按钮、Tab、开关、危险操作按钮允许不同强度，避免每个按钮独立制作弹性。
- 尊重减少动态效果设置；不为全站按钮引入昂贵模糊、滤镜或布局动画，反馈不得破坏业务操作与可访问性。

### P3 — 曲率连续圆角与同心圆角

目标：改善圆角轮廓及嵌套容器的几何协调性，不机械统一数值。

**曲率连续圆角**：研究 Continuous Curvature / Squircle 等形状，在适当组件上探索比传统圆弧与直线相接更连续的曲率变化。优先考虑主内容卡片、弹窗 / Bottom Sheet、大型按钮、悬浮面板和底部导航容器。不要求全部使用同一种 Squircle；按组件大小选择曲率，实施前检查 Safari / Chrome 支持及必要降级方案。

**同心圆角（Concentric Corners）**：检查均匀间距的嵌套容器，使内外曲率中心尽量协调。圆弧式圆角可参考“外层半径 ≈ 内层半径 + 间距”；连续曲率形状须按实际轮廓调整，不能机械套用。重点检查卡片内卡片、弹窗内容区、底栏选中背景、按钮容器及带边框组件，使视觉层次自然、边距均衡。

### P4 — 桌面端快捷键系统

目标：减少高频记账与管理任务中的鼠标操作。研究快速搜索、新增账目、保存编辑、关闭弹窗 / 退出当前局部操作、常用工作区切换及快捷键说明。

| 候选 | 用途 |
|---|---|
| `Ctrl/Cmd + K` | 搜索 |
| `Ctrl/Cmd + Enter` | 保存当前编辑 |
| `Esc` | 关闭当前弹窗或退出局部操作 |

以上仅为候选，其他按实际页面决定。兼容 Windows / macOS，避免覆盖浏览器常用快捷键；输入框内不得意外触发全局操作，重要操作不得因误触直接提交。界面应可查看快捷键说明，不影响移动端与 iPad 现有交互。实施前核对已有快捷键和焦点规则。

### P5 — 页面状态与操作连续性

检查返回时的滚动位置、筛选 / 排序 / 月份与日期范围 / 账本选择的保留、被中断的多步骤操作、主 Tab 各自浏览状态、异步操作完成后的自动跳转，以及导航 / 刷新 / 重新登录后的恢复边界。

与 P1 区分：P1 管未提交输入，P5 管浏览与操作上下文。共用必要的状态管理能力，复用现有导航和工作区状态，不让多个恢复器相互覆盖；现有返回保底和已验收恢复行为不能因规划被当作未实现而重做。

### P6 — 操作撤销与反馈

研究删除后的撤销入口、部分编辑操作撤销、保存成功 / 失败反馈、错误提示与输入定位、网络异常后的操作恢复。撤销必须结合真实数据操作和权限系统，不只是视觉上恢复按钮状态。

继续通过实际使用收集高频功能步骤、桌面键鼠协作、空状态等小型体验问题，不预设大规模开发。

### P7 — 现有玻璃材质的后续精修

沿用 B2 半透明材质、背景模糊、渐变和边缘高光的组合，以及 Hybrid Snapshot + Ambient 转场方向；当前开发进展仍由现有 Agent 维护，不在此重复记录。

后续研究玻璃边缘的光照变化、不同背景颜色下的透光效果、选中 / 按下 / 悬停时的材质变化、局部折射或光学形变的实际价值，以及大面积透明材质的性能和文字可读性。

优先基于现有 CSS 与浏览器合成方案精修，不要求立即实现完整物理光学折射或自研玻璃渲染引擎；既有自研算法继续保留在 Lab，不因本待办接入正式产品。
