## 5. 维护规则

1. **覆盖，不追加**：每行只写当前值；只保留一行「最后核对」。旧值不搬到别处——changelog 与 git 已有。
2. **何时改**：版本号变化（本地或生产）、迁移数变化、阶段状态变化、阻断问题新增或解除、下一步变化。其它情况不改本文件。
3. **不写**：计划细节（→ [01-规划](01-规划.md)）、过程与证据（→ changelog / archive）、长段落。表格单元格一两句话。
4. 发现与 `git log -1` / `version.ts` 不一致 → 先修本文件，再继续任务。`pnpm check:status` 会拒绝版本 / 迁移不一致、堆叠的「最后核对」与明显超长的 STATUS。
