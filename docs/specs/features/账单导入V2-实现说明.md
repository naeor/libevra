## 1. 一句话结论

`/import` 从“只接受 Libevra UTF-8 CSV、直接写入”升级为
**选择文件 → 服务端按内容识别来源并解析 → 统一概览核对（可改字段、可重新判重）→ 一次确认批量入账**；
支持微信 XLSX、支付宝 CSV、BOA PDF 和 Libevra CSV，重复导入由来源身份去重与统一内容判重两层保护。

## 2. 链路与接口

| 层 | 位置 | 职责 |
|---|---|---|
| 共享契约 | `packages/shared/src/billImport.ts` | `BillImportPreview` / `billImportCandidateSchema` / `billImportCommitRowSchema` / 限制常量；服务端与前端共用同一 schema |
| 路由 | `apps/api/src/routes/billImport.ts` | `POST /api/v1/import/preview`、`/recheck`、`/commit`；鉴权、账本头 `x-libellum-book`、multipart、错误码翻译 |
| 服务 | `apps/api/src/import/service.ts` | 预览缓存、格式识别、适配器调用、写入事务、`ImportLog` 幂等、提交前复核 |
| 解析器 | `apps/api/src/import/{wechat,alipay,boa,libevra}.ts` | 四个来源各自的表头/分区/合计/日期/金额规则 |
| 文档抽取 | `apps/api/src/import/extractor.ts` + `extract_document.py` | 本机内存解析 XLSX/PDF；**只用 Python 标准库**，不落盘、不联网 |
| 前端 | `apps/web/src/pages/ImportPage.tsx` + `components/import/BillImportViews.tsx` + `lib/billImportUi.ts` | 上传卡片、顶部汇总、状态筛选、逐笔卡片、详情编辑、疑似重复分组、底部统一确认 |
| 判重 | `packages/shared/src/duplicateDetection.ts` | 与手动/语音/OCR/账本导入同一核心、同一设置；文件内与历史两层 |

旧 `POST /api/v1/import`（Libevra CSV 直写）保留，供升级前客户端使用；新前端走 preview/recheck/commit。
**本轮无数据库迁移**。

## 3. 按内容识别（不看扩展名）

- 微信 XLSX：ZIP 结构 + workbook + 表头关键词；支持 Excel serial 日期、共享字符串、28–39 位长单号保真。
- 支付宝 CSV：UTF-8/GB18030 自动解码 + 支付宝表头；交易单号尾部制表符会 `trim`；识别“不计收支/交易关闭”并默认不勾选。
- BOA PDF：`%PDF-` + `Account summary`/`Deposits` 等文本层特征；按 `Date Description Amount` 表头识别交易页，按分区与合计行对账。
- Libevra CSV：自有表头；保留旧入口兼容。
- 未识别来源一律返回明确错误，**不按文件名猜**。

## 4. 真实样本核对结果（本机实测）

| 样本 | 读到 | 默认选中/提交 | 结果 |
|---|---|---|---|
| 微信 XLSX | 12 笔（支出 8 / 收入 4） | 12 笔 | 日期 2026-09-22 … 2026-10-16；二次上传 12 笔全部 `identityDuplicate`，新增 0 |
| 支付宝 CSV | 48 笔 | 46 笔 | 46 支出 + 1 “不计收支” + 1 “交易关闭”；后两类 `unknown`、默认不选，符合“关闭不能一律当支出” |
| BOA PDF | 108 笔（存入 14 / ATM 借记 83 / 其他 11） | 108 笔 | 8 页；三段合计与期初+存入−支出=期末一致，`reconciliation.ok=true`；全部 `timePrecision=day` |

说明：方案文档早期快速统计曾写“支付宝 47 支出 + 1 不计收支”，实现按逐行状态识别后为
**46 支出 + 1 不计收支 + 1 交易关闭**；以本实现说明为准。

## 5. 核对与提交语义

- 顶部汇总：读到 / 选中 / 可导入 / 待核对 / 疑似重复 / 已排除；逐笔卡片显示来源、行号/页码、日期精度、警告。
- 字段可改：金额、日期、时间、收支方向、分类、支付方式、备注、标签；改后 `POST /import/recheck` 重新计算警告与重复，**不把旧结论写回**。
- 2026-10-22 复核修复：币种、时区也可修正；服务端校验日期、金额精度、正金额、合法时区与真实时刻，拒绝夏令时缺失或歧义时刻。
  更改记录或勾选范围后，确认按钮暂时禁用，重核成功后才允许提交；新的提醒需要重新确认。
- 2026-10-22 P2 修复（1.15.03）：preview 响应带 `revision`（初始 1，每次 recheck 成功 +1）；commit 必须传同一个 `previewRevision`，并逐行匹配最后一次候选快照（金额/币种/方向/日期/时间/时区/分类/支付方式/备注/标签/勾选）。revision 不一致返回 409 `preview_revision_mismatch`，内容不一致返回 409 `preview_stale`；不会用绕过前端 recheck 的旧检测结果入账。recheck/commit 在单进程内串行化。
- 当前入口与指定账本入口均显式绑定目标账本；V2 三接口在鉴权后拒绝缺少明确账本编号的请求。
  Libevra 来源流水编号只用来回查身份，新候选使用独立 UUID，允许同一份导出分别导入不同账本。
- 重核从原始文件提醒重新派生，清除旧配对、字段错误与重复数量摘要；关闭业务检测仍保留来源身份保护。
  服务端粗筛仅应用已开启的规则，备注、商户和本账本标签参与统一核心；不比较历史记录彼此，超出资源预算明确提示覆盖范围。
- `identityDuplicate` 是“来源身份已存在”的唯一真相：勾选框禁用且不选中；`duplicateIds` 只是“疑似重复，待判断”。
- 身份去重（`sourceRef` + `ImportLog` 文件指纹）会阻止重复写入；内容判重只提示，不自动取消勾选、不自动删除。
- 用户已确认“不是同一笔”的关系（E3）由服务端按对抑制，不把已关闭的配对重新弹出来。
- `reconciliation.ok === null` 不阻断；只有 `false` 要求用户确认后才允许提交。
- 提交一次事务批量写入，沿用现有 `ImportLog`、来源单号、软删除/撤销/权限；失败保留预览可重试。
- 结果页给出来源文件、读到/导入/跳过数量与原因；错误定位到文件行或 PDF 页码。

## 6. 限制与已知边界（不得当成已完成）

1. **扫描版 PDF 不支持**：只支持带文本层的 PDF；抽不出文本时明确报“扫描件不支持”，不做 OCR 猜测。
2. **BOA 只有过账日期**：候选按 `day` 精度、不补 12:00；描述里若出现第二个 `MM/DD`，只加“可能是消费日期、与过账日期不同，请核对”的警告，
   **不编造消费日期，也没有把消费日/入账日作为两个字段落库**；要彻底解决需扩交易模型（新迁移，另行批准）。
3. **预览缓存 30 分钟**：服务端内存 Map，重启/过期后失效；前端没有 `GET preview`，刷新核对页会回到选文件态。
4. **CSV 内容判重发生在写入后**：旧 CSV 直写链路拿不到逐行数据，只能按 `importRef` 在写入后检查；新 preview 链路在提交前检查。
5. **大文件边界**：10 MB、20,000 行、PDF 30 页；超出明确拒绝。
6. **设置只在本设备**：沿用 E2 的 localStorage，按用户隔离、版本化，**不跨设备同步**（本轮明确不做）。
7. **部署验证**：该功能已随 `1.15.03` 发布生产；`apps/ocr/.venv` 是本机开发虚拟环境（不入库、不部署），生产 sidecar 的 Python 可用性与性能/内存按发布期记录验证（见 [1.15 changelog](../../changelog/1.15.md)）；
   本轮没有新增第三方 Python 依赖，PDF 解析用标准库。
