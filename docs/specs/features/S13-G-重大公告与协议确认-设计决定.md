# S13-G 重大公告与协议确认 · 设计决定与实现记录

> 2026-10-18。**本地开发版本 `1.13.11`（含统一弹窗布局优化），未 push、未部署。**
> 这是 L3 功能：涉及账号、服务端访问限制、数据库证据和数据处置边界。

## 1. 边界与三类内容

保留 S13-F 已有的普通版本公告，不把普通 UI 更新变成弹窗：

| 类型 | 展示 | 自动弹窗 | 需要确认 |
|---|---|---|---|
| 普通版本公告（1.13.07/1.13.08/1.13.09） | 软件更新首页、历史、详情 | 否 | 否 |
| 重大更新公告 | 满足条件时每个账号一次弹窗；历史仍可查 | 是，仅明确标记的重大公告 | 知情确认，不是协议同意 |
| 协议/条款文件 | 公开完整文件 + 确认摘要 | 必须处理时优先于重大公告 | 主动勾选同意，服务端记录证据 |

**没有生产法律文本。** 当前唯一协议是明确标记为本地测试的 `local-test-terms`；生产策略为空，因此不会在生产强制用户接受未审阅条款。

## 2. 数据模型（新增迁移）

迁移：`prisma/migrations/20261018142000_consent_system/migration.sql`（纯加法、无既有数据修改）。

### `agreement_acceptances`

- `id`、`user_id`、`document_id`、`document_version`、`content_hash`、`action`、`accepted_at`；
- 唯一键 `(user_id, document_id, document_version)`，同一版本重复确认幂等；
- 文件正文变化必须换版本/哈希，旧同意行不会被覆盖；
- 证据由服务端生成，客户端不能补造。

### `major_announcement_acknowledgements`

- `user_id`、`announcement_id`、`announcement_version`、`action`、`acknowledged_at`；
- 唯一键 `(user_id, announcement_id)`，同一账号同一公告只提醒一次；
- 与普通通知的 `read_at` 分离，避免把"看到了通知"当成"已确认重大更新"。

## 3. 服务端

### 访问限制

- 新增 `createRequireConsent`：业务路由先验证会话，再验证当前所有必须协议均已接受；
- **业务路由统一使用带协议检查的守卫**（books / ledger / transactions / stats / classification / OCR / voice / export / import / share / admin 等）；
- `/auth/*`、`/account/consent`、协议接受、重大公告确认、账号数据导出、登出等使用**原始会话守卫**，让受限账号仍能处理自己的状态；
- 缺协议时返回 `403 agreement_required`，普通业务 API 和深链刷新不能绕过。

### 新增 API

| 方法/路径 | 用途 |
|---|---|
| `GET /api/v1/legal/documents` | 未登录可读的当前必需协议元数据与内容哈希 |
| `GET /api/v1/legal/documents/:id` | 未登录可读的完整文件 |
| `GET /api/v1/account/consent` | 当前账号的必需协议、缺失项、待确认重大公告 |
| `POST /api/v1/account/agreements/accept` | 主动同意并写入证据（校验版本 + 哈希，幂等） |
| `POST /api/v1/account/major-announcements/:id/ack` | 记录 `acknowledged/opened_details/dismissed`（幂等） |
| `GET /api/v1/account/export` | 受限状态下可用的账号级 JSON 导出 |

注册接口增加可选 `agreements` 数组；服务端校验当前必需文件并**在创建账号的同一事务内写入接受记录**，缺失则拒绝注册。

### 新用户和历史重大公告

`GET /account/consent` 只返回 `publishedAt` 晚于账号创建时间的重大公告；新注册用户不需要补看历史重大公告。

## 4. 前端

- 新增全局 `ConsentGate`：先处理必需协议，再处理重大公告；普通公告不弹窗；
- 协议弹窗：摘要、完整公开文件链接、**未预选复选框**、「同意并继续」、「暂不同意」；
- 重大公告：标题/摘要/要点、「知道了」、右上角关闭、「查看详情」；三种动作都记录已确认；
- 输入页（`/add`、`/record`、`/scan`、`/voice/review`、`/transactions/:id`）不弹重大公告，避免打断；
- 协议门禁不依赖客户端：API 本身已阻断；前端只是展示和导航；
- 状态请求失败时**离线放行**，不清本地数据；服务端仍是写请求最终判据；
- 新增公开路由 `/legal/:documentId`，测试文件无需登录即可完整查看；生产构建不提供测试文件。

### 暂不同意后的「账户与数据处理」

- 不立即退出登录、不直接关闭弹窗；
- 可导出账号数据：账号资料 + 当前可访问账本的全部账目（包含共享数据与软删除条目），文件内明确标注范围，不冒充"完整个人数据"；
- 提供删除服务器数据、注销账号的入口和说明，但**本轮不执行不可逆删除/注销**：现状调查显示 `books.created_by`、`transactions.user_id` 等 CASCADE 会在共享账本中破坏其他成员的数据，且没有所有权转让接口；按任务要求优先保留数据安全；
- 可退出登录，保留本机 IndexedDB、历史账目和未同步记录；
- 可返回协议确认重新查看并同意。

## 5. 离线与例外

- 协议状态请求失败时 fail-open，避免离线启动被门禁废掉；
- 离线写入队列遇到 `agreement_required` **不再标为永久失败**，接受协议后仍可重试；
- 不因为门禁清除或迁移离线数据；
- 普通公告、1.13.07/1.13.08 不会被标为重大更新。

## 7. 明确未做 / 待所有者决定

1. **正式服务条款和隐私政策**：必须由所有者审阅后加入共享策略；本轮不写正式法律文本。
2. **物理删除服务器数据和永久注销账号**：现有共享账本所有权与 CASCADE 风险未解决，未实现危险的一键删除；界面明确说明未执行。
3. **重大公告发布后台**：本轮仍使用静态、代码内公告；没有公告 CMS 或管理员发布功能。
4. **生产策略**：生产当前没有必需协议、没有测试重大公告；需要所有者确认后再启用正式文件。
5. 是否将 viewer 导出放宽、是否转让账本所有权、物理删除范围，都需要单独决定。
