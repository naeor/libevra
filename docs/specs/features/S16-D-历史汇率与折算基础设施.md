## 1. 原有数据流审查

| 核查项 | 实际代码与结论 |
|---|---|
| 金额 | `prisma/schema.prisma` 的 `Transaction.amountCents` 是 PostgreSQL bigint；共享 DTO 使用安全整数 number，创建/编辑限制 0–10¹²。`money.ts` 已有币种精度和整数格式工具 |
| 币种 | 每笔 `currency`；`ledger.ts` 限定 CNY/USD/EUR/JPY/HKD/GBP；JPY 0 位，其余 2 位 |
| 日期 | `occurredAt` 是交易瞬间，`occurredLocalDate` 是交易当地日历日期；`createdAt`/`updatedAt` 是录入/编辑时间。折算仅用当地交易日期，不能根据服务器时区重算 |
| 默认币种 | `User.defaultCurrency`、`shared/auth.ts` 的用户返回结构；个人偏好，不属于 Book。调用者从当前用户取得目标币种，不从共享账本取得 |
| 月汇总 | 账目路由按币种分组；`routes/stats.ts` 先按当前账本、软删除、日期、单币种筛选，再汇总 |
| 分析 | 在线调用 stats API；离线 `offline/localStats.ts` 用已下载的原始流水计算；两条旧路径均不接入本轮模块 |
| 权限 | `ledger/access.ts` 的现有成员关系/角色检查、请求账本上下文；新模块不更改这些判断，也不接受原始财务查询 |
| 离线 | IndexedDB `libellum/kv`；`storage.ts`、`scope.ts`、按账号账本区分的月份副本/印记队列、TanStack 查询缓存；共享账本沿用离线只读策略 |
| 导入导出 | `shared/export.ts` 有独立金额/币种/交易日期列；导入工具按币种解析最小单位，保留原币。文件协议和导入写入路径不改 |
| 复用情况 | 基线没有汇率服务/表/计算实验代码；复用六币种定义、`decimalsFor`、kv 和既有作用域。不使用 `decimalsFor` 对未知币种的默认两位兜底 |

## 2. 财务合同

- 原始金额、币种、交易日期、编号和账本身份永不被折算覆盖；本模块没有流水写入接口。
- 折算是当前用户的显示/统计视图。模式关闭走既有路径，模式开启由未来调用者传当前用户的默认币种。改变目标币种只改变派生结果。
- 日历日期严格往返验证；当日没有参考数据时最多回退 7 个日历日，保留 `requestedDate` 与 `rateDate`。禁止未来汇率、混接不同日期币种、无来源 1:1。
- 主币单位交叉汇率为 `targetPerEUR / sourcePerEUR`；折算最小单位还乘 `10^targetDecimals / 10^sourceDecimals`。
- 汇率十进制字符串最多 12 位小数；服务端用 Node 22+ JSON source reviver 保留上游数字原文，再用 BigInt 精确有理数计算，只在每笔目标最小单位上四舍五入。金额非负，半单位向上；既有退款使用收入/支出语义，不引入负流水。
- 汇总严格累加逐笔舍入结果。例：两笔 0.01 EUR，EUR→USD=0.5，各显示 0.01 USD，合计 0.02 USD。规则版本 `minor-half-away-v1`，可解释与重算。
- 结果金额与汇总使用十进制整数字符串，可超过 number 安全范围；UI 应使用 BigInt 格式化，不得直接 `Number()` 丢精度。原件仍沿用既有 number DTO。
- 缺失/失败返回 `unavailable`、原因及 `convertedMinor=null`。汇总保留成功小计、原币总额、月份/分类桶，返回 `complete=false`、缺项数量与 ID/账本/日期/币种/原因。`shareDenominatorMinor=null`，不能展示完整占比。空样本为完整零笔。
- 历史参考值的有效性不等于缓存新鲜度。`FxLookup.review` / `FxResult.review` 单独返回核对时间、下次建议时间与 `needsReview`；汇总提供 `reviewNeededCount` / `reviewDates`。待复核可以与 `complete=true` 同时成立，不得被画成缺失或假定最新。

## 3. 数据来源与使用条件

采用可替换 `FxProvider`；首个适配器固定 Frankfurter v2 的 ECB provider 路径，以 EUR 为基准，仅请求六币种和需要日期的七日窗口。不会发送金额、账本或账号。不得自动改用 blended 或不同来源补齐缺币种。适配器显式调用才联网，不注册定时抓取或启动任务。

真实区间接口可能携带起点前的锚点：例如 `from=2024-05-12&to=2024-05-19` 返回 `2024-05-10`。解析器跳过窗口外的旧锚点，仍严格拒绝未来日期，最终仅从窗口内选最近实际发布日。ECB 提供方总体起点不能代替币种对覆盖；实测 1999-01-04 缺 CNY，CNY/EUR 覆盖查询返回边界 2000-01-13，但边界不保证中间每日有值。

[Frankfurter 官方文档](https://frankfurter.dev/)说明历史 REST 查询、无需 key、每日更新，公开实例无日/月配额但有防滥用限流，鼓励本地缓存；单一提供方数据仍适用该提供方条款。没有服务可用性承诺，不能把免费等同无限速率。其软件开源许可不能替代数据许可。

[ECB 参考汇率说明](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html)列有六币种，通常在工作日约中欧时间 16:00 发布，TARGET 休市日除外，用作参考而非实际兑换价格。[ECB 使用条款](https://www.ecb.europa.eu/services/using-our-site/disclaimer/html/index.en.html)允许依条件使用：准确再现并注明 ECB，说明交叉计算属于派生；付费文档还需告知原始信息免费可得。历史存储保留来源和日期；正式 UI/导出接入需展示 ECB 来源及派生口径，不使用央行标志暗示背书。

[ECB 修订框架](https://www.ecb.europa.eu/stats/pdf/exchange/Frameworkfortheeuroforeignexchangereferencerates.ga.pdf)说明可能更正已发布数据。因此不能把抓取到的历史数据当成永不修订。适配器用规范化内容 SHA-256 作为本地修订标识，**不是提供方签名或真实性证明**。直接 ECB 数据适配器可作为后续替换，不同时建设两套后台服务。

## 4. 存储、异常与修订

`fx_snapshots(provider, rate_date, revision)` 保存 EUR 参考集合、十进制字符串 rates JSONB、抓取时间；同一日期每币种一项，不保存所有币种对。修订保留旧内容。`fx_resolutions(provider, requested_date)` 保存实际参考日和核对时间；查询按参考日取得最近抓取版本，周末映射也自动获得修订。JSONB 不承担金额运算，写入前做正数、币种、精度与日期验证。

`PgFxRepository` 事务写入，按来源 advisory lock 串行；拒绝同版本不同内容、同时间不同版本和旧抓取覆盖新抓取。SQL 参数化，不读取财务表。迁移为纯新增表和索引；Prisma 模型片段与 SQL 放 `prisma/pending/s16-d/`，集成时重排迁移时间戳并保留 SQL CHECK。旧客户端不读取新表，无回填、无财务 schema 变更。

工程建议默认：交易日期在最近七天内，每 24 小时重新核对；更早历史日期每 30 天建议核对。分别配置 `recheckMs` 与 `historicalRecheckMs`。**30 天是复核周期，不是汇率有效期**；有效历史观察离线继续可用，逾期只标 `needsReview`。不存在按下载年龄作废的默认策略。`maxFallbackDays` 可在 0–7 天内收紧，七天仍是 SQL/计算层硬上限；扩大上限需跨层评审。最终体验策略在 D4 验收时由所有者确认。按需查询合并同进程同日期并发；恢复网络时按实际需要日期串行去重补齐，不扩大账本预下载范围。

错误区分 timeout/network/api_error/unsupported_currency/missing_rate/invalid_rate/conflict/anomaly/storage_error。超时覆盖响应体读取；服务失败返回不可用，不自动使用未经核对的新数据。新值和已知上次/前一日参考值超过默认 2 倍时隔离，本阈值是可配置防线，不能判断所有市场异常；没有历史基线时无法识别比例跳变。异常不覆盖已保存版本，刷新调用返回失败；旧已验证版本仍保留，其来源与抓取时间可审计。人工复核/异常告警与跨进程抓取请求合并属于后续运维工作。

## 5. 缓存与离线隔离

单笔结果只在内存，默认最多 5,000 项 LRU，不持久化用户财务派生数据。键覆盖账号、账本、流水 ID/版本/金额/币种/日期/类型、目标币种、实际汇率集合/版本/时间及规则版本；返回对象独立，调用者不能污染缓存。超容量批量汇总直接计算，避免全表扫描导致淘汰风暴。没有月份/分类物化表。

`OfflineFxRepository` 复用 `kv`，公共键 `fx-public-rates-v1` 默认最多 512 个实际请求日期解析；保存白名单汇率字段，不允许夹带账号或交易额。容量按使用顺序淘汰，不限制历史年份，清理仅影响可再获取的公共缓存。同一页面跨实例串行写，支持 Web Locks 的环境增加同名跨标签写锁；不支持时退回进程内队列，跨标签仍可能丢失公共缓存项。读写/等待均使用既有有界超时，迟到的写仍占有队列直到真正结束，避免旧写越过新写；损坏条目可在重新获取时清除，不能让它阻止全部补齐。真实浏览器的锁、配额与暂停恢复需 D4 专项验收。

`OfflineFxCalculator` 每次使用既有 `offlineScope()`，账号/账本变化清空内存，账本不匹配或未登录拒绝计算。D4 的会话生命周期还应在 logout/unmount 显式 `clear()`，避免实例继续驻留。服务器端纯函数的 account/book 参数只用于隔离，**不能代替成员鉴权**；未来财务查询必须先经过既有账本权限与软删除过滤，再调用计算器。

大批量视图使用 `aggregateFxAsync` / `OfflineFxCalculator.aggregateAsync`，默认每 200 笔通过 MessageChannel 让出宏任务；不支持时用定时器。可传 AbortSignal 取消。客户端每批检查作用域与请求代次；切换账号/账本、后续目标币种请求或 clear 都不能让旧计算回填新视图。全部计算结束才返回最终统计，取消不返回伪完整小计。同步接口保留给小样本/服务端/CLI；D4 不得把数万笔同步扫描直接放入交互主线程。

## 6. 后续 UI 的调用顺序

1. 沿用原有登录与账本访问检查；关闭模式直接沿用旧页面数据流。
2. 从当前用户取得 `defaultCurrency`；从授权、未删除的流水中取得 `occurredLocalDate`，按日期去重取得公共 `FxLookup`。
3. 在线通过已鉴权的公共汇率路由取得数据；路由插件需显式注册，并接入现有限流。客户端 provider 应请求自身 API，不能把第三方适配器直接放浏览器。
4. 保存所需公共汇率；离线 `lookup(date,{offline:true})`。单笔调用 `convertFx`，较大视图调用 `OfflineFxCalculator.aggregateAsync`，需要服务端统计时调用 `aggregateFx`。切换筛选/目标币种时废弃旧请求。
5. 展示原币、折算值、实际参考日、来源、待复核与不完整状态；金额字符串按目标精度格式化。不得自行把失败项补零或计算完整百分比。
6. 网络恢复调用 `refillFxDates`；历史修订产生新版本并自然使结果键失效。变更默认币种只重算实际访问的组合。

本轮不定义实际兑换、银行结算、投资汇兑损益，不改变导出协议，不新建用户开关字段或正式 UI。规则中的回退上限、近期/历史复核周期、异常阈值和缓存容量均为工程建议配置，正式启用前由所有者验收。
