## 1. 结论摘要

- **正式交付指标 83 项**：A 26 + B 24 + C 33。W6 保留 81 项口径；W7 增加真实分类模型后正式开放 P05/P07，P21 仍因独立维度编辑需求延期，不以 84/84 为退出条件。最后核对补充: `1e517449` 基线 / 2026-10-29；约束与语义见[W7 实现说明](S17-W7-多层级分类-实现说明.md)。
- **图表家族 31 个**：A/B 原有 15 个 + C 专用 16 个（明细表、增减条、瀑布、帕累托、直方、箱线、热力矩阵、堆叠柱、矩形树图、名次变化、散点、气泡、透视表、小多图、全年日历、斜率）。每项指标只列语义上成立的形式（`CardType.families`）。**1.17.12 起另有 7 种「读法」**（展示形式共 38 个，见 §9）：它们归到已有的正式图形编号，不是新的图表家族。
- **组合卡片（1.17.10）**：一张工作台卡片里可放 1–8 个内容槽位（数字 ≤ 6、图表 ≤ 4），按卡片内容模板 T1–T8 排布；组合卡片在工作台里仍是**一张**卡片（一个 objectId、一个几何对象），统一拖动、缩放、撤销与保存。
- **新的创建 / 编辑流程**：一个编辑面板内完成「选指标（分类浏览 + 搜索 + 名称与简短说明）→ 每项选展示形式 → 自动推荐模板（可手动换）→ 按真实格子像素实时预览与尺寸检查 → 名称与时间 → 确认才加入」。不再使用原生超长下拉框。

## 3. 用户可见的指标目录

`apps/web/src/statsWorkbench/metricCatalog.ts`：五个分类（数字指标 / 趋势与时间 / 构成与排行 / 分布与关系 / 其他专业分析——1.17.12 起由「高级与综合」改名），各有小组（合计、净额、笔数与频次、平均与中位、极值、比率与增长、周期趋势、平滑、周期规律、分类随时间、构成、排行、支付方式、集中度、变化归因、金额分布、关系、矩阵、离群、透视、两期比较、多币种与汇率…）。

- **呈现（1.17.12 精简）**：目录默认是紧凑列表——图标、名称、添加，必要时一句短说明（搜索结果的所属分类、需综合折算）；指标定义与可用展示方式在每项的「说明」按钮里按需展开，分类定义在分类标签旁的说明按钮里；分类标签横向滑动、按项吸附、两侧淡出提示。页面不显示指标总数与技术上限（数量接近或达到上限时才提示）。

- 同一指标可出现在多个分类（如分类集中度在「比率」与「集中度」），引用同一个定义（同一 `analysisId`），主分类唯一。
- 搜索匹配名称、简短说明、分类名与编号（不区分大小写、忽略空格）。
- `directoryProblems()` 自检：可选指标全部在目录、无重复无效项（`metricCatalog.test.ts` 守护）。

## 4. 组合卡片：保存形状、模板与排布

**保存**：组合配置写在 `card.chart.options.composition = { v: 1, template, slots: [{ id, analysisId, family }] }`。D 的 `chart.options` 本就是自由对象，**不改 D schema、不需要数据库迁移**；`analysis` / `chart.chartFamily` 镜像第一个槽位，旧版本（≤ 1.17.9）读到时按第一个槽位的单指标卡片显示（安全降级）。没有 `composition` 的旧卡片读成单槽位，无需迁移脚本；`v` 更高的卡片只读显示、编辑器拒绝改写；结构损坏退回主槽位显示。槽位只存「分析引用 + 展示形式」，不存金额、汇率或账本身份；账本、时间（`rangePolicy` / `pinnedRange`）、币种与综合折算、分类 / 支付方式 / 标签筛选由整张卡片共享。

**模板**（`composition.ts` 的 `CARD_TEMPLATES`，宽 × 高，单位为工作台格子）：

| 模板 | 内容 | 允许尺寸 |
|---|---|---|
| T1 双数字 | 2 数字 | 1×1、2×1、1×2、2×2 |
| T2 四数字 | 4 数字 | 2×1、1×2、2×2 |
| T3 图表 + 双数字 | 1 图表 + 2 数字 | 1×2、2×2、2×3 |
| T4 图表 + 多数字 | 1 图表 + 3–6 数字 | 2×2、2×3、2×4 |
| T5 双图表 | 2 图表 | 2×2、2×3、2×4 |
| T6 数字 + 图表并列 | 1 数字 + 1 图表 | 2×1、2×2、1×2、2×3 |
| T7 密集数字 | 3–6 数字 | 2×1、1×2、2×2、2×3 |
| T8 多图表综合 | 0–6 数字 + 2–4 图表 | 2×2、2×3、2×4 |

推荐规则：1 项 → 单项；只有数字 2 → T1、4 → T2、其余 → T7；1 图表：1 数字 → T6、2 数字 → T3、更多 → T4；2 图表无数字 → T5；其余 → T8。手动选择的模板在内容仍兼容时保留，不兼容时自动换成推荐模板并提示。

**排布**（`layoutComposition`）：按卡片正文的真实像素计算每个槽位的位置与展示密度（数字单行 / 两行，图表正常 / 迷你趋势）。有最小可读尺寸（数字单行宽 120、高 24；图表 140 × 96；迷你趋势 110 × 58，只对线 / 面积 / 柱）；需要更高绘图区的图形另有下限（日历热力 236、上期比较 196、小多图 150，均含名称一行），**不无限缩小字号**；放不下的项写「另有 N 项 · 点开查看」，详情页逐项完整显示。编辑器用同一函数检查每个尺寸「放得下 / 放不下 N 项」，预览用真实卡片组件按设备上的格子像素渲染（预览与工作台同一组件、同一像素，结果一致）。小格里的「数据不完整 / 缺汇率」说明收成右上角「!」标记（完整文字在悬停提示、读屏文字与详情页），不占图表高度。

**放得下的自动核对**：1.17.10 用真实浏览器把 81 项指标的每一种展示形式逐一放进组合卡片小格与单项卡片（窄屏 320 宽、手机 390 宽的推荐尺寸与最小尺寸、桌面 1280 宽），测量内容是否超出、金额是否被截断；首轮组合小格 42 处、单项卡片 37 处超出（固定高度的旧折线组件、说明行占高、环形图图例过长、日历热力 / 上期比较 / 小多图需要更高的格子、表格被当作迷你趋势等），修复后均为 0。

**金额只缩字号、不截断**：大号金额（`FitAmount`）放不下时逐级缩小字号（2xl → xl → lg → base → sm，严格按像素判断，多出 1px 也继续缩）；数字列在 320 / 390 宽各数字模板与尺寸下最窄约 90px，可完整显示到 ¥123,456.78；百万级金额只在最窄的数字列里才会省略（完整值在悬停提示、读屏文字与详情页）。行内形态（名称 · 数值同一行）数值按自身宽度完整显示，名称截断。

**单项卡片在矮尺寸下**（`singlePresentation`，与编辑器尺寸检查同一判断）：时间趋势（线 / 面积 / 柱）改画迷你趋势；S17-A 的构成 / 排行 / 列表按行数适配，2×1 也完整显示；其它图形写「空间不足，点开查看」并在编辑器里标为放不下。默认尺寸下没有卡片落到「空间不足」。

**数据读取**：同一张组合卡片里，共享时间、近 12 个月窗口、全年窗口三组槽位各只读取 / 折算一次（`useCardScope`），槽位只做轻量计算；单个槽位出错只影响这一格。

## 5. 编辑与工作台兼容

- 新建：工作台「编辑 → 我的自定义 → 新建自定义卡片」；编辑：卡片菜单「配置」或我的自定义列表。确认前不写工作台。
- 保存走 Agent D 命令：新卡 `insert-card`（重排避让）；改内容 `update-card`；改尺寸先尝试 `resize`，冲突时在原位置删除后重新插入并重排；变宽后从原列放不下（例如右列的 1×1 变成 2×1）就放到**同一行的行首**、同行邻居顺延到它后面，仍放不下才交给 D 找最早的空位；整次修改合并为**一个撤销步骤**（`session.ts` 的 `reconfigureCard`）。改布局不会清空内容，改内容不会丢位置（仍在原来那一行）。保存失败时编辑器说明「工作台里放不下这个尺寸，没有保存」，编辑内容保留，不静默关闭。
- 同一指标可在一张卡里放多次，用不同展示形式。上限：8 项、数字 6、图表 4。
- 只选一个指标时与旧流程一样快：默认展示 + 单项模板 + 推荐尺寸，一键添加。

## 6. S17-C 的口径要点

- **不画 0、不冒充完整**：没有数据、样本不足、两期不可比、上期没有支出、缺汇率、本机覆盖未确认都写明原因。
- 两期分析（A06 / A07 / A17 / P22 / P24）读上一可比期自己的账目（原币：`comparisonRead`；综合折算：上一期自己的折算），上一期未完整读取或两期任一缺汇率时不比较。
- 缺汇率（`fxPolicy.ts` 新增 `subset` 类）：分位、集中度、归因、份额「无法确定」；直方 / 散点只画已折算账目并写明另有 N 笔；构成类给小计不给占比，矩形树图与气泡图退化为小计排行，大额明细排行不给占比；小多图在含缺汇率账目的月份断线、不给分类合计；全年日历的合计写明「已知部分」；P17–P20 汇率诊断只在综合折算下显示。
- 两期分析在综合折算下同样要求本期与上期账目覆盖完整（与 A01 一致）。
- A15 连续无支出天数与「无支出的天数」同一口径（只看当前币种；本机覆盖未确认的日子是「未知」，不算无支出）。
- P06 矩形树图按单层分类显示，并在详情页说明分类目前只有一层。

## 9. 1.17.12：新增读法与卡片相对时间窗口

为布局预设（[S17 工作台布局预设](S17-工作台布局预设-20261028.md)）补的 7 种读法，全部复用已有计算，只是换一种呈现；手算测试在 `cCards.test.tsx`「1.17.12 新增读法」「A01 两种新读法」：

| 指标 | 读法（`ChartFamily`） | 正式图形 | 口径 |
|---|---|---|---|
| A01 上期收支比较 | `number`「较上期变化」 | CF-A01 | 本期支出相对上一可比期的增减率；上期不完整或没有支出时不给比率 |
| A01 | `cumulative-compare`「累计支出对比」 | CF-B11 | 本期与上一可比期逐日累计支出两条线（按第 N 天对齐） |
| A17 分类变化排行 | `top-rise` / `top-fall`「增加 / 减少最多的分类」 | CF-A02 | 与上期相比金额增减最多的一个分类 + 增幅 |
| A10 单笔支出箱线图 | `p90`「单笔支出 P90」 | CF-A01 | Type 7 分位（shared `quantileOfSorted`），样本少于 10 笔时写明 |
| A06 变化归因 | `insights`「本期要点」 | CF-A10 | 两条文字观察：总支出变化 + 贡献最大的分类 |
| P06 分类矩形树图 | `sankey`「支出流向」 | CF-C12 | **只画「支出总额 → 各分类」一层**（shared `buildHierarchy` + `buildHierarchySankey`，守恒校验）；不是 P07 分类层级桑基，也不拼接「收入 → 支付方式 → 分类」（所有者规格 §23） |
| P16 币种笔数 / P19 汇率覆盖 | `status`「数据完整性」「汇率覆盖」 | CF-A11 | 一个值 + 带状态色点的结论：本机读取是否完整、缺汇率笔数 / 外币已折算比例 |

**相对时间窗口**：卡片可以用「最近 7 天 / 本月至今 / 上个月 / 最近 4 周 / 最近 6 个月 / 最近 12 个月」（`timeWindows.ts`），存为 `chart.options.window`，按打开当天解析，副标题写明窗口与实际日期；组合卡片的窗口由全部槽位共享。优先级：分析自带窗口（近 12 个月 / 全年）> 相对窗口 > 固定区间 > 顶部筛选时间。编辑器「时间」多了「最近一段」一项（选窗口，下方预览实际日期）。旧卡片没有这个键，行为不变；旧版本读到它会忽略、改按顶部筛选（安全降级）。
