# 本地开发工作区与主目录更新规范（2026-10-28）

> 最后核对: `local/current-1.17.8 @ 7d5b873` / 2026-10-28（主目录归位流程建立并完成首次归位；同日补充「日常开发默认主工作区 + 启动入口」规则）。性质：开发流程规范；当前状态只写 [STATUS](../../STATUS.md)。

## 1. 目的与定位

- **`记账程序v1`（主工作区）**：所有者日常标准开发目录与 `localhost` 入口。它必须一直看到「已验收的最新候选」，而不是某个历史版本。
- **`git worktree`（隔离工作区）**：仅在所有者明确要求或确实需要隔离时使用；不能在两个工作区检出同一分支。
- **独立 clone / 历史副本**：先保护独有提交、源码、配置和恢复资料，不整包覆盖主目录。只有获得当次清理授权、核验保留副本并确认无人使用后，才清理已确认冗余的内容；不 gc。
- **归位 ≠ 删除其他工作区，也 ≠ 机械合并所有分支**。归位的目标只有一个：主目录的代码、版本与 `localhost` 显示，与已验收的集成候选一致，且旧现场可恢复。

## 2. 分支与 worktree 规则

1. 分支实际检出位置以 `git worktree list` 为准；历史集成分支不要求永久占用一个工作区。
2. 主目录使用本地主开发分支，具体名称见 STATUS；名称中的旧版本不表示当前代码版本，也不要求随每个补丁改名。未经批准不上推、不 force。
3. 日常在主目录开发和提交；只有确实使用隔离工作区时，才执行评审后的集成同步（见 §5）。
4. 禁止：`git push`（未经当次批准）、`git gc` / `git prune`、`git stash drop/clear`、`git checkout --force`、`git reset --hard` 到未备份状态。
5. **日常开发默认在主工作区进行。** 除非所有者当次明确要求独立 worktree，或任务必须隔离（多 Agent 并行改同一仓库、危险迁移演练等），否则不要为了「干净」另建 worktree。
6. 临时 worktree 不是日常入口。任务完成后必须：保护未提交内容 → 把成果合回主工作区（或经集成分支 ff 归位）→ **同步日常启动入口**（`start-dev-lan.cmd` 打开的 `http://localhost:5173` 必须指向最新可验收版本）。
7. 日常入口固定 **HTTP <http://localhost:5173>**；HTTPS 只用于手机录音/离线测试（`start-dev-lan-https.cmd`）。严禁让不同端口、不同分支、旧进程同时冒充「当前版本」；启动脚本在端口被占用时必须显式报错并说明正在运行的版本。

## 3. 主目录更新步骤（每次集成后）

1. 集成分支：完成验收、本地提交、`check:docs` / `check:status` 通过。
2. 主目录：先查 `git status --porcelain=v1 -uall`。**有未提交内容 → 先按 §4 保护，不允许直接切换。**
3. 关系判定：用 `git merge-base --is-ancestor HEAD <已评审集成分支>` 检查；为真才 `git merge --ff-only <已评审集成分支>`。双方都有提交时逐项评审并合并，禁止硬覆盖、机械合并所有旧分支或把未验收实验当正式功能。操作前另建本地快照 tag/branch。
4. 依赖：`pnpm-lock.yaml` 无变化则不需要 `pnpm install`；有变化才 `pnpm install --frozen-lockfile`。
5. 迁移：只有集成涉及迁移时才查 `prisma migrate status`；有 pending 时按数据库规范完成备份与恢复验证，再 `pnpm db:deploy`；**绝不 `db:reset`**。纯文档与工作区维护不触发迁移。
6. 启动主目录日常预览并验证：版本显示、`/api/v1/health` 版本与数据库状态、核心页面可用。

## 4. WIP 保护（强制门禁）

任何清理、切换、覆盖之前：

1. 快照：`status --porcelain=v1 -uall`、`rev-parse HEAD`、`stash list`、`rev-parse stash@{0}`。
2. 备份（放 `_backups/`，已被 `.gitignore` 忽略）：
   - `git diff --binary HEAD` 的 tracked patch；
   - 未跟踪文件逐文件复制 + SHA-256 manifest；
   - 用临时索引（`GIT_INDEX_FILE` 指向临时文件，不碰真实 index）建立 WIP 快照提交，挂到 `refs/wip/main-wip-<日期>`；
   - 既有 stash 追加 `refs/wip/r4-index-stash` 之类的稳定引用 + patch 双保险，**不 pop / 不 drop**；
   - `git bundle create … --all` 并 `bundle verify`。
3. 验证矩阵全部通过才允许清理：WIP 引用是 commit、diff 与工作区一致、未跟踪 manifest 逐个 hash 一致、bundle verify 通过、stash SHA 未变、`_backups` 不被 status 追踪、patch 可 `apply --check`。
4. 恢复方式：优先在新的隔离目录按保存的 HEAD/稳定引用恢复，再 `git apply --check` 并应用 patch，按 manifest 还原未跟踪副本。原 index 与 staged patch 用于区分暂存和未暂存状态。不要把恢复命令直接覆盖到已有 WIP 的主目录。
5. 任何一步无法可靠备份/恢复 → **停止归位并报告阻塞**，不得强行继续。

## 5. 后续同步策略

- **默认 ff-only**：主分支是已评审集成分支祖先时，使用 `git merge --ff-only <集成分支>`。
- 需要 cherry-pick 时只搬单个已评审提交；不要用 cherry-pick 搬整套 S17（用 ff/merge）。
- 日常开发默认在主目录；独立实验可以保留在明确标识的目录或分支，不自动注册业务入口，不将工程验证写成所有者验收。

## 6. 恢复记录与安全退出

- 当前工作区和恢复入口只写 STATUS；逐项路径、HEAD、分支、哈希、清理结果保存在本机 `_backups/`，不在本规范滚动堆叠。首次归位证据仍见[原验收记录](../../archive/releases/主工作区归位与S17-1.17.6-本地验收-20261028.md)。
- 获得当次清理授权后，逐个检查进程/Agent、tracked、untracked、ignored、独有提交与链接目标；`git status` 干净不代表没有资料。`.env`、数据库备份、私人资料只放本机恢复包，不进入 Git 对象或公开文档。
- 未集成或用途不明的成果保留工作区；仅缺少合并关系的历史提交也必须保留分支及已验证 bundle，不以清理工作区为由删引用。可再生成依赖与缓存单独核验；Junction 只处理链接自身，绝不递归进入目标，pnpm 硬链接不能按逻辑大小宣称释放量。
- 确认无人使用且独有文件已保存并验证后，使用标准 `git worktree remove <绝对路径>`。命令拒绝时先查原因，不加 `--force`，不用 `reset --hard` 或 `git clean -fdx` 绕过保护。

## 7. 验证清单（切换后）

| 项 | 检查 | 期望 |
|---|---|---|
| 版本 | `packages/shared/src/version.ts` | 与 STATUS「本地开发版本」一致 |
| git | `status` / `stash list` / `branch -vv` | 干净；stash 仍是原 SHA；无 upstream |
| 类型/测试 | `pnpm typecheck`、按需 `pnpm -r test` | 通过 |
| 文档 | `pnpm check:docs`、`pnpm check:status` | 通过 |
| 迁移 | `prisma migrate status` | 与仓库迁移数一致或已安全 deploy |
| 预览 | 浏览器 + `/api/v1/health` | 页面版本与 API 版本一致、`database=up` |

## 8. 维护

- 归位或清理后更新 STATUS 的当前工作区与恢复入口，版本变更写 changelog；本规范只维护长期操作规则。
- 本规范与 AGENTS.md §4.1「本地默认同步」配套：本地同步 = 更新主目录与 localhost；远端仍须当次批准。
