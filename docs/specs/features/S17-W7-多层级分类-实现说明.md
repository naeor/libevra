# S17-W7 多层级分类实现说明

> 最后核对: `1e517449` 基线 / 2026-10-29。执行状态与部署只见 [STATUS](../../STATUS.md)。

## 关系与兼容

分类使用稳定 ID、可空 `parentId`、既有排序及可选图标 / 颜色。旧分类成为根节点，ID、名称和交易引用不变，不从名称中的斜杠猜关系。父子必须同账本、同收支类型；系统分类不能成为父子节点；禁止缺失父节点、自指、循环。共享校验和数据库触发器统一限制 **64 层**（含根）。同类型同父节点名称唯一，不同分支允许同名。旧 PATCH 省略父字段时保留关系。

结构写入事务先锁账本行，等待后重新读树、验证并核对成员写权限；DB 另有 FK、同级唯一索引与触发器，避免并发互移成环。分类仍使用现有认证和账本权限，个人工作台与账本分类作用域分开。

## 低干扰交互与删除

单层分类选择保留原界面。有子分类时，名称直接选择，箭头进入下一层，提供返回和路径搜索；父分类仍能直接记账。明细列表只显示具体名称，交易详情显示最新完整路径。分类管理保留新建根分类入口，更多菜单提供编辑、添加子分类、归档和删除；所属分类、排序、外观放在编辑面板中，移动父节点时后代仍按 ID 跟随。

永久删除有子分类的节点必须明确确认 `childrenPolicy: "promote"`，对子分类提升一级，后代保留；交易沿用原替换流程，无选择时转系统分类。提升导致同级重名则整笔事务拒绝，用户先移动 / 改名，不自动删账或改名。归档保持关系与历史记录。

游客结构操作校验后保存在本机。正式账号结构操作沿用在线规则，离线立即报错，不假装完成，也不另造队列；离线交易继续引用分类 ID，重放时走现有分类和权限校验。

## 统计、筛选与追溯

原分析 `category`、明细 `categoryId` 继续精确匹配。新分析分支用可重复 `categoryBranch`，明细用 `categoryScope=branch`。按当前账本关系展开后去重，再进入同一过滤和 FX 流程；父子同时选择不重复计算，不限与空集仍有区别。展开 ID 仅运行时使用，不污染配置及按月份共享的离线覆盖回执。

现有 81 项平面指标仍按直接分类 ID 分组。P05/P07 复用 shared `buildHierarchy` / `buildHierarchySankey`：每笔只归一个直接节点，分支合计等于直接金额加后代金额；有子节点又有直接交易的父分类增加直接金额终端，守恒检查不得省略。原币先限单币种，综合统计复用逐笔历史 FX；缺汇率或覆盖不完整时显示已知部分，隐藏比例和面积 / 桑基表达。历史比较采用当前分类树，不提供结构时间旅行。

P05/P07 正式登记后为 **83 项**，P06 保持单层含义，P21 延期。卡片只显示根分支摘要，详情可收展、看直接 / 分支金额和笔数、追溯来源；下钻保留卡片实际日期。桑基区域内部横向滚动，图形最多显示 5 层 / 100 节点，完整树仍可展开与下钻。共享分析原有 2,000 节点 / 4,000 连线成本上限保留，超限明确不可用，不崩溃。

## 导入导出与同步

账本导入来源 / 目标快照、指纹、映射保留关系，按拓扑顺序先父后子创建，失败事务回滚；不同路径同名不合并，复用目标节点须符合父级映射。增量指纹包含祖先路径，根分类保持旧指纹兼容。CSV/XLSX 末尾追加 `分类路径JSON` 名称数组，原分类名列不变；旧文件继续读取，有歧义不猜 ID。CSV 仅匹配已有目标路径，缺失时提示先建立分类；跨账本建树通过原账本导入流程完成。

账号导出包含完整分类森林，数据库备份 / 恢复保留父子关系。文字、语音、OCR 推荐不随机选择同名节点。W6 仍同步工作台文档及必要筛选，不复制分类数据、不重写同步机制。

## 迁移与恢复

生产部署须另外批准、重新备份及恢复核对，按顺序应用 W6 `20261029040000_workbench_configuration`（第 62 个），再应用 W7 `20261029050000_category_hierarchy`（第 63 个）。W7 增加 `parent_id` / `color`、FK、同级唯一索引和触发器，不改变历史交易引用。

**不能通过删除父字段或拍平分类来声称安全回滚。** 未写入层级数据时可回旧应用并保留字段；已有同名分支后旧客户端会退化为平面视图，优先修复前进。若必须恢复迁移前 DB，需所有者确认，先保留迁移后完整备份并安排新增交易及层级数据恢复，不能静默丢弃。备份恢复物料在 Git 忽略的 `_backups/w7/`，含迁移前 dump 与精确行数恢复证明；不得上传。
