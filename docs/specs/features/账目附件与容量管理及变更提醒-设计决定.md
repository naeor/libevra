# 账目附件、容量管理与变更提醒 · 设计决定

> 依据：所有者 2026-11-01 的连续设计确认。本文定义产品约束，不表示对应代码已经实现；实现状态只见 [STATUS](../../STATUS.md)。本轮讨论不授权源码上传、部署或生产数据操作。
> 账本退出、归档、永久删除、墓碑与备份以 [S13-H 生命周期规格](S13-H-账号注销与账本生命周期-设计决定.md) 为唯一规则来源，本功能不得改变这些机制。

## 1. 用途与数据归属

- 附件用于保存账目的凭据与回忆线索，支持一笔或同一本账内多笔账目关联同一附件。支持 JPEG、PNG、GIF、WebP、HEIC 图片，PDF，WAV、OGG、FLAC、MP3、M4A 音频及 TXT / CSV；服务器验证文件签名，不能内嵌预览的格式提供下载。
- 附件属于账本内容，查看与下载受现有账本访问权限约束，不公开给账本外用户。
- 上传者退出后附件继续保留。普通删除账目时，相关附件随关联进入可恢复状态；恢复账目时恢复关联。文件仍被其他有效账目引用时，不影响那些账目的使用。
- 同一附件对象关联多笔账目，账本只保存并计算一份文件；不同账本不默认共享附件对象。
- 应用管理员可调整额度，但管理员身份不自动获得读取其他账本、附件或财务历史的权限，沿用 [管理员与账本权限边界](../product/管理员与权限边界-设计决定.md#6--管理员不等于能看别人的账本)。

## 2. 容量口径与默认限制

| 范围 | 默认上限 |
|---|---:|
| 每个账户 | 1 GB |
| 每个账本 | 500 MB |
| 单个附件 | 100 MB |
| 每笔账目的附件数量 | 10 个 |
| 每笔账目总占用 | 200 MB |

- 限额用于控制资源使用，不与付费升级绑定。统一使用十进制：1 MB = 1,000,000 字节，1 GB = 1,000,000,000 字节。
- 统计全部可归属的用户业务数据：附件原文件、长期保存的预览文件、账目、备注、分类、标签、留言、编辑历史，以及服务器保存的账户资料与个人配置。
- 文件按实际保存字节统计；结构化数据按统一且可复算的编码口径统计。数据库索引、物理页空闲、系统运行日志、备份等系统成本不分摊到用户额度，另做服务器容量管理。
- 账本占用包含仍可恢复及归档保留的数据。账户占用为账户自身数据加其仍拥有或参与的各账本占用，每本共享账本向每位成员完整计入，不均分，不叠加成员额度。
- 单笔总占用包括该账目数据、编辑历史、关联附件及仍可恢复的附件。同一个附件完整计入每笔关联账目的上限，但不能把这些单笔关联大小相加当成账本的物理文件占用。
- 10 个附件的名额包含仍可恢复的附件，永久清理才释放相应名额；可恢复附件继续占用空间，恢复不重复计算文件。
- 管理员可动态调整上述限制，账户总额和账本总额支持分别调整。配置由服务端持久保存并统一校验，不能只改管理者设备上的本地偏好。调低限制不自动删除旧数据或旧附件。

## 3. 额度只限制操作者本人和目标账本

上传前检查操作者的账户额度、目标账本额度、单文件限制以及各目标账目的数量 / 总占用限制；不检查其他成员的剩余额度。

例如 A 已达到个人额度，但 B 和共享账本仍有空间，B 可以继续上传。增加的账本占用仍计入 A，A 的实际占用允许超过个人上限，界面必须显示真实数值。只有目标账本达到上限时，才阻止任何人在该账本新增上传。

- 达到相关额度后，可以继续查看、下载、导出，以及执行自己有权限的删除和清理。
- 允许更正已有账目的金额、日期、分类、备注等非文件数据并同步服务器；更正与新增历史使用有限维护预留，不能借编辑旧账继续上传附件。
- 新增云端内容、附件上传及批量导入仍受额度约束。额度不足不能丢弃本机未同步数据；个人账本继续支持本地记账。
- 删除进入可恢复状态不释放实际保留内容的额度。清理权限与容量权限独立，满额不能赋予删除别人附件的权限。
- 维护预留用尽后仍允许旧账的非附件更正同步，只提示超额，不中断更正。正常字段长度与请求频率限制仍有效；不能借更正上传附件，不得静默删除历史。
- 本功能不改变既有共享账本离线只读范围，参见 [共享离线范围](../product/S13-E-新页面点击树.md#4-权限与状态矩阵受影响部分)。

## 4. 差值统计与上传一致性

- 每次操作计算受影响内容的字节差值，并计入新增历史等关联内容，不在每次请求中扫描全部账目。
- 保存账本容量汇总，账户据所属账本汇总计算；定期或发现异常时完整校准。计量规则必须能从原始业务数据重新计算。
- 上传前预留容量，完成后按实际大小结算，失败 / 取消 / 过期任务释放预留。并发请求不能重复使用同一份剩余额度，重试不能重复计数。
- 字节数与类型由服务器验证，不能信任客户端申报。临时文件和失败上传需要独立、有界的清理机制。
- 账目保存与文件传输分别呈现状态：账目保存后附件可继续上传或重试；明确显示「待上传 / 上传中 / 失败」，不把账目保存成功当成附件上传成功。
- 100 MB 文件按流传输，原件与较大预览按需读取，不要求把全部附件装入浏览器或服务器内存。

## 5. 附件编辑与删除权限

- 添加附件沿用账本编辑权限，与添加备注、标签同属账目编辑操作。
- 上传者仍在账本时，只有同时具备账本编辑权限的上传者可以删除其附件。
- 上传者退出后，当前具有账本编辑权限的成员可以删除其附件。
- 上传者重新加入后恢复上传者专属删除权，仍须具备编辑权限；不撤销其退出期间其他成员已经完成的删除。
- 替换文件或解除附件关联不得绕过删除权限；不得无痕覆盖原附件。操作写入账目历史。
- 多笔关联时必须说明影响范围，不能因删除其中一笔就删除其他账目仍引用的文件。
- 整本账本的退出、归档、永久删除严格调用 S13-H 的既有生命周期；不得新增「创建者可单方删除多人账本」的例外，不修改墓碑机制。

## 6. 完整账目历史

- 每次有效保存保留操作者、账目与版本、服务器接收时间、变更字段及修改前后值、服务器取得的本次来源 IP、操作标识。历史以追加方式保存，普通编辑不能覆盖或删除先前记录。
- 当前值可以作为列表和统计的快速读取数据，当前值更新与历史写入必须在同一事务中成功或失败。无实际变化的保存不制造假变更，幂等重试不重复写入。
- 保留初始内容以及各次有效变化，历史中的分类、标签等含义不能因其名称后来修改而漂移。批量变更可以摘要显示，但需保留可追溯的逐笔实际影响。
- 离线有效保存的中间修改不能被最终值静默替代；设备报告时间与服务器接收时间区分。来源 IP 表示同步请求来源，不能声称知道离线编辑发生时的 IP。
- IP 为受限审计信息，不默认出现在其他成员收到的变更提醒正文中；获取链路必须验证可信代理，不能相信任意客户端填写的地址。
- 同步冲突判断所用的有限最近值记录不能替代长期编辑历史。维护预留不足不能通过清空历史解决。
- 正常删除保留可恢复数据和删除事实；明确永久清理时，对应业务正文及历史按 S13-H 清理。既有备份不受业务操作回写，墓碑仍按既有规则保留。

## 7. 创建者变更提醒

### 7.1 触发与消息内容

- 创建账目的用户是该账目的创建者；其他人修改账目不会改变创建者。复用现有服务器账目创建身份，不从最后编辑者推断，也不接受客户端任意指定收件人。
- 其他用户实际修改金额、分类等账目数据成功后，服务器向创建者生成一条站内提醒，总结谁、何时、修改了哪笔账目、哪些值从什么变成什么。
- 自己修改自己的账目不提醒自己；失败、回滚、无变化保存和同一次请求重试不产生额外提醒。一次有效修改的多个字段合为一条消息。
- 提醒依据服务器确认的编辑历史生成，不能根据客户端尚未生效的意图生成。历史保存与提醒生成采用可靠的事务提交 / 待发送机制，不能出现账目已修改但提醒被无声丢弃。
- 创建者已退出或不再有账本访问权限时，不继续发送或显示该账本的内容摘要；读取旧通知和跳转详情时也重新检查访问权限。
- 提醒是告知，不提供邀请的「同意 / 拒绝」按钮。可进入对应账目及相关修改记录；IP 不出现在普通提醒中。
- 示例：`张三于 11 月 1 日 14:32 修改了你创建的「午餐 #000123」：金额 ¥10.00 → ¥20.00。` 时间和金额按用户语言与显示规则呈现。

### 7.2 账户与账本两个范围

| 入口 | 提醒范围 |
|---|---|
| Dashboard 页头右上角铃铛 | 当前账户的邀请等账户级提醒 |
| Dashboard 每张账本卡片右上角铃铛 | 发给当前用户、属于这本账的变更提醒 |
| 协作 / 账本页现有铃铛 | 对应账本范围的提醒，与卡片入口使用同一份已读状态 |

- 账本邀请虽然关联一本账，仍属于账户级提醒；不能只根据是否有 `bookId` 判断消息范围。
- 新的未读消息在所属铃铛显示红点。账户级与各账本独立统计，打开一本账的提醒不能顺带清空账户或其他账本的未读。
- 已读状态按收件人保存，在多个入口与设备保持一致；标记已读不等于接受邀请或删除消息。标记请求范围要固定，不能把打开面板后刚到的新消息一并清掉。
- 卡片铃铛点击只打开通知，不触发整张卡片跳转、切换当前记账账本或拖动卡片。通知内容不受 Dashboard 当前月份筛选限制。
- 账户入口也必须在手机、平板和没有共享账本时可达，不能因账本铃铛分区而失去接收邀请的入口；手机和平板在「我的」及个人资料页提供账户铃铛。
- 新变更提醒不能直接套用邀请的有效期、接受 / 拒绝状态、发件人撤回和人工发送配额。通知随账本保留，每次保存合并该笔的字段变化，一页 100 条；各入口每 30 秒读取未读，不改变完整历史保留要求。
- 通知正文中的财务信息随可永久删除的账本一起清理，不保留为墓碑内容。仍沿用原备份独立保留边界。

## 8. 附件与空间的界面

| 位置 | 行为 |
|---|---|
| 新建 / 编辑账目 | 可折叠附件区，多文件选择、预览、大小、额度及上传状态；成功后也可补充 |
| 批量记账 | 明确选择附件关联的账目，显示关联笔数，同一本账内共享文件对象 |
| 明细列表 | 附件图标与数量，按空间排序时显示占用；不默认展开大图 |
| 单笔详情 | 图片预览、PDF 阅读、音频播放；桌面用辅助栏或展开预览，移动端进入预览视图 |
| 账本详情 | 附件数量、已用 / 限额、少量最近预览、「全部附件」入口；单列可恢复占用 |
| 全部附件 | 账本范围内搜索、筛选、排序；文件信息与关联账目；电脑列表 / 网格配右侧预览 |
| 账户空间 | 总占用 / 限额及按账本的完整计额，说明共享计额与超额原因 |
| 下载与离线 | 云端占用与本机占用分开，原件按需下载；清除本机副本不删除云端或释放云端额度 |
| 管理界面 | 限额调整、实际用量和调整记录；不因此开放账本内容访问 |

未上传成功的原件不能作为普通缓存静默清除。与既有备份、导出和永久清理的接线须覆盖附件内容及关联信息，不能只包含数据库中的文件名。

### 8.1 记账过程中的附件（所有者 2026-11-01 指定布局）

- 电脑端手动表单按主字段与支付方式 / 备注 / 标签分列，后者常显；手动、文本、语音、照片识别、账单导入及核对页右侧统一放附件，支持图片、PDF 和录音预览。窄窗口回到单列，手机 / 平板保留原表单结构。
- 添加附件使用明确按钮，也支持拖入侧栏。先保存原件到本机，账目成功保存后再上传；识别原图和账单来源文件不会自动作为附件上传。
- 每份附件可关联本次全部或指定账目，沿用服务端单份最多关联 100 笔的上限。单笔默认关联当前账目，多笔需明确选择；未关联原件留在本机。逐笔校验数量与总大小，不把多笔独立附件合并成一笔额度。
- 部分保存失败时，已成功账目的 ID 与未完成关联一起暂存；所选账目全部保存后才上传同一份原件。用户可去掉不再需要的目标，仅关联已保存账目。导入中被跳过或未保存的项目不获得附件。
- 文本识别核对一笔后返回仍保留其余候选；按账户、账本与工作区隔离，仅保存在当前页面会话内存。刷新后附件原件仍可在“下载与离线”取回，不把原件当缓存清除。

## 9. 筛选与排序

- 默认按时间从新到旧；提供时间、金额及占用空间的升 / 降序。排序作用于筛选后的全部结果，包含完整分页范围，不能只排序当前加载的一页。
- 支持有无附件、类型与空间范围筛选；与既有收支、日期、分类等筛选共同生效。
- 时间排序可保留日期分组；金额 / 空间排序用连续列表，每行仍显示日期，避免分组破坏全局顺序。
- 总占用和附件大小在界面中明确区分，同一附件多笔关联的计额遵循 §2。
- 开启跨币种折算模式后，按当前用户默认币种的逐笔折算金额排序；复用 [S16-D](S16-D-历史汇率与折算基础设施.md) 的交易日期、汇率、币种精度及逐笔舍入结果，不另建计算口径。
- 缺汇率项单独列于末尾并说明，不能按零金额处理；模式关闭时不混排不同币种的原始数字。金额大小按绝对值，收入 / 支出通过筛选控制。
- 离线仅对实际可用数据排序，明确范围不完整，不伪称已覆盖整本账。

## 10. 实现与验收边界

- 原件以 1 MiB 分块保存于 PostgreSQL，上传预留 1 小时，未完成任务每分钟限量清理；完成时校验总字节数、签名和 SHA-256。下载支持 Range；导出流式 TAR 包含原件、原名、哈希与关联账目。已生成的备份不回写。
- PDF 使用随应用分发的 PDF.js 按页绘制，字体与解码资源均从本站按需读取；提供翻页、缩放和原件下载。不开启 PDF 脚本、XFA 或 WebAssembly，不放宽既有站点 CSP；加密或无法解析的文件显示下载入口。
- 结构化内容按 PostgreSQL JSONB 文本的 UTF-8 字节计量，排除派生容量字段；原件只计算一份实际文件字节，不重复累计分块封装。数据库触发器维护差值，每 24 小时重新核算。导入业务锁期间差值存独立汇总，解锁后原子合并；读取额度包含待合并值，不修改既有导入锁。
- 旧账非附件更正不因维护预留耗尽而停止同步，历史增长纳入实际占用。新内容提交后在同一事务复核额度，失败整笔回滚；本机待同步数据不删除。
- 管理员调低数量 / 大小限制后，不自动删除已有附件，不阻止恢复已计额的附件；新增附件按调整后的限制校验。
- 新消息与账目历史同事务持久保存，再更新红点；只对展示过的明确通知 ID 标记已读。非文件更正完整留痕从本功能启用后生效，不能还原旧版本没有记录的历史。
- IP 默认读取连接地址；仅显式配置 `AUDIT_TRUSTED_PROXY_IPS` 且请求来自该可信代理时读取转发地址。配置前可能记录反向代理地址，不能伪称真实客户端 IP；本轮不修改生产代理或环境变量。
- 涉及数据库、权限、历史、离线和金额排序，按 AGENTS 的 L3 / 交付检查及对应专项执行；迁移前备份与恢复验证不省略。
- 至少覆盖：多人并发上传、被动超额、维护预留、失败重试、可恢复计额、多笔关联、退出及最后成员删除、历史完整性、创建者提醒去重、通知范围与越权、未读隔离、折算排序、备份与墓碑回归。
