## 1. 概念模型：五件不同的事

所有者要求区分“分析指标、分组方式、比较方式、图表类型、具体卡片实例”（总需求规格 §5）。**把同一组数据画成三种图表，不叫三种财务分析**；同一指标换一个维度才是另一种分析。

| 概念 | 回答的问题 | 例子 | 所属层 |
|---|---|---|---|
| **指标 Metric**（M-xx） | 算什么数 | 支出合计、收支差额、笔数、日均支出 | A 计算引擎 |
| **维度 Dimension**（D-xx） | 按什么切分 | 日 / 月 / 星期 / 分类 / 币种 / 支付方式 | A |
| **比较 Comparison**（C-xx） | 和什么比 | 上一可比期、去年同期 | A |
| **分析 Analysis**（AN-xx） | 指标 × 维度 × 比较 的一个**有数学意义的组合** | “分类变化贡献排行” | A（定义）+ B/C（展示） |
| **图表家族 Chart family**（CF-xx） | 用什么形状表达结果 | 环形、柱状、折线、数值卡 | B 图表层 |
| **卡片实例 Card instance** | 用户工作台里放的**一张具体卡片** | “本月餐饮占比”环形卡，1 个实例 id | C 卡片层 |

关系：一个**分析**可以有多种**图表家族**表达（受[兼容性规则](../design/S17-图表与卡片规格.md)约束）；一个**图表家族**可以承载多种**分析**；用户的工作台里放的是**卡片实例**，同一分析可出现多个实例（不同筛选或不同图表家族），每个实例有自己的 `instanceId`、配置与详情页。

### 2.1 今天仓库里确实有的数据【已核对源码】

| 来源 | 内容 | 出处 |

| 原币统计 API | `totals{expenseMinor, incomeMinor, netMinor, count, largestExpenseMinor}`、`series[{bucket, expenseMinor, incomeMinor}]`（日 / 月桶）、`byCategory[{categoryId, name, kind, minor, share}]`、`comparison{range, totals}` | `packages/shared/src/stats.ts`；审查报告 §5 |
| 本地离线统计 | `computeStats` 与服务端共用日期补桶规则 | 审查报告 §5 |
| 综合（折算）路径 | 授权交易按月分页 → 逐笔查公共汇率 → `aggregateFxAsync` 逐笔舍入后汇总；输出整数字符串；三种独立状态 `complete / sourceComplete / needsReview` | S16-D §2、§5、§7；审查报告 §5 |

### 2.2 今天**没有**的数据（不得假装有）

| 缺失项 | 后果 |
|---|---|
| 来源交易 ID（统计 API 不返回） | 任何“点数值看来源”要靠**同一筛选条件**重新查询，不能靠 API 带 ID；“最大单笔”现在只有金额 |
| 最大**收入**单笔、分类笔数、分类前期值、周桶 | 见下表对应项，归为“需扩展查询” |
| 转账（transfer）数据合同、资金账户、账户余额、净资产 | **不可分析**。支付方式 ≠ 资金账户；不得自动识别并排除“疑似转账”（审查 §5.2） |
| 预算 / 目标 | 02-技术方案 §1.2 把“预算与超支提醒”列为 v1 明确不做，§5.4 列为 v2 及以后的预留扩展，**无数据模型**；预算对比为“需新数据模型” |
| 二级分类 | 分类只有一级；“分类层级下钻”需新数据模型 |
| 交易作者字段 | `Transaction` DTO 无记账人字段；“按成员分析”需先确认历史 / 审计记录能否提供，【待研究】 |
| 商户字段 | DTO 无独立商户字段（商户只在文本识别中出现，落库后进入 `note` 或分类）；**不以备注文本做分析维度**（隐私与准确性） |
| 综合模式的时间桶 / 分类占比 | 当前综合模式只有三项摘要、月份条形、分类金额列表，**不显示占比**；日 / 周趋势与占比需 shared 纯函数增量（审查 §10） |

### 2.3 四档可行性（每项分析必须标一档）

| 档 | 名称 | 判据 |
|---|---|---|
| **T1** | 现有数据可准确计算 | 直接用现有 API / 纯函数，或对**已返回的精确序列**做纯函数派生（求和、排序、百分位），不新增查询、不改 schema |
| **T2** | 需扩展查询接口 | 只读扩展：新增分组 / 过滤参数、返回来源 ID、前期分类值、或在 shared 逐笔遍历中增加投影；**无 schema 变更、无迁移**；须追加越权验证，且不改动既有敏感判断 |
| **T3** | 需新增业务数据模型 | 需要新字段 / 新表 / 迁移 / 新的产品语义（转账、预算、二级分类、账户）；**独立立项**，不在 S17 内偷做 |
| **T4** | 暂不推荐 | 缺乏数据合同，或误导 / 隐私 / 维护成本高于价值 |

**原币与综合分别标档**：同一分析在“原币路径”和“综合路径”下的数据基础不同（2.2 末行）。表中“原币 / 综合”两列即为此；综合路径下凡需要时间桶或分类分组的，普遍是“T2：shared 纯函数增量”，仍无 schema 变更。

### 2.4 每项分析的共同底线（引用，不重述）

- 金额只在同币种内相加；综合必须走 S16-D 逐笔折算（ACC-03/04/05）；
- 数据不完整时不显示完整占比，状态四分（ACC-06/07）；
- 可点击数值带来源筛选（ACC-08/09）；
- 新增公式要在本目录登记，并给出整数 / 有理数实现说明（ACC-15）。**浮点标准差等无法精确表达的统计量不上架**（见 AN-P03 的替代）。

## 9. 新增一项分析的登记清单（给后续开发者）

每新增或修改一项分析，在本目录登记并满足：

1. **定义**：ID、名称、回答的问题、指标 × 维度 × 比较、可展示的图表家族；
2. **公式**：写明分子 / 分母 / 舍入（引用 `minor-half-away-v1`）/ 零分母处理 / 负数处理；浮点不能精确表示的统计量不登记；
3. **档位**：原币与综合分别标 T1–T4；T2 要写清新增的查询参数与越权验证；
4. **完整性**：缺汇率、缺原件、无交易、加载失败的展示；
5. **来源追溯**：每个可点击数值的来源筛选（from / to / 分类 / 币种…），并给出“来源合计 = 图表数值”的断言；
6. **验收样本**：至少包含空账本、单笔、跨月、跨年、闰月、跨午夜、大金额（> 2^53）、缺汇率、共享账本只读成员；
7. **不做的事**：明确列出该分析刻意不回答的问题（例如不判断“浪费”）。

## 10. 分析定义草案（【待研究】，仅表达意图，不是接口承诺）

```text
AnalysisDefinition (草案，S17-W2 冻结前可变)
  analysisId      稳定字符串，如 "AN-B05"（目录登记的 ID）
  metric          M-xx
  dimension       D-xx | null
  comparison      C-xx | null
  filters         { currencyMode: "original" | "converted", currency?, categoryIds?, tags?, kind? }
  range           { kind: "inherit" | "preset" | "custom", ... }   // inherit = 跟随工作台的时间筛选
```

分析定义**不含金额、不含账本 ID**：账本由运行时的工作台作用域注入（详见[配置与分享方案](../product/S17-工作台个人配置与布局分享-方案草案.md)）。这样同一分析定义才能被导出、分享而不泄露账务数据。
