# S18 · 分析工作台响应式布局引擎（1.18.01）

> 最后核对: 本机未提交改动 / 2026-10-30（1.18.01 本地实现，未部署）
> 性质：**现行权威规格**。依据所有者 2026-10-30「分析工作台响应式布局引擎重构」要求与当次确认（列数滑条只在编辑器里；列数偏好主 / 辅工作区各记一份、只在本机；版本 1.18.01）。
> 取代：[S17 布局规格](../design/S17-工作台布局与格式模板规格.md) §5.1 的列数选择、§5.3 的行高、§14 的**跨列数**投影（同列数下的显示与损坏修复仍按 §14）、§18 的统一 / 独立档案语义。
> 实现：`packages/shared/src/analysis/layout/responsive.ts`（纯函数）；Web 接线在 `apps/web/src/statsWorkbench/Grid.tsx`、`columns.ts`、`editOrigins.ts`、`pages/StatsPage.tsx`。

## 1. 三个概念

| 概念 | 存在哪里 | 谁写 | 说明 |
|---|---|---|---|
| **基础权威布局** | 布局文档 `main`（`baseCols` + 每个对象的行优先 `anchor`、`colSpan × rowSpan`） | 在基础列数下保存排列；或新增 / 删除卡片后保存 | 只存逻辑格，不存像素 |
| **列数专属布局** | 布局文档 `profiles`，键 `cols-<N>`，同时 `mode = "independent"` | 在非基础列数下**只调整排列**并保存 | 只覆盖该列数的几何；不同专属布局互不推导 |
| **临时显示布局** | 不存储 | 由下面 §2 每次重算 | 永不写回 |

- 沿用 S17 已有的 `profiles` / `mode` 字段，**没有数据库或配置 schema 变化**；服务器、同步、导入导出、分享与预设的既有校验原样适用。
- 有专属布局 ⇔ `mode = "independent"`；去掉最后一份时回到 `unified` 并删除 `profiles` 字段。
- 卡片内容（内容文档）与位置（布局文档）分离；内容修改在所有列数下都生效。

## 2. 解析顺序（`resolveDisplayLayout`）

给定目标列数 T：

1. **A**：T 有**有效**的专属布局 → 用它（同列数原样显示）；
2. **B**：T 等于基础列数 → 基础布局原样（包括用户留的空位，不重排）；
3. **C**：其它 → `reflowLayout(基础布局, T)`。

- **永远从基础布局推导**：不从屏幕上一次的结果、也不从别的列数的专属布局再推，所以 3 → 6 → 4 → 8 → 3 没有累计失真。
- 专属布局**有效**的条件：列数与键一致、几何合法、对象集合（不计 Spacer）等于基础布局里实际显示的根对象。旧版本客户端在别处新增 / 删除卡片后，旧专属布局不再适用，按 B / C 显示，下一次保存时清理。
- `unified` 模式下即使带着档案也不当作专属布局（S17 的档案从未启用过）；写入新专属布局时这些旧档案不带过来。

## 3. 响应式投影（`reflowLayout`）

1. 按基础布局的**阅读顺序**（行、列、ID）依次处理；Spacer 不参与（留白只对它所在的列数有意义）。
2. **尺寸**：原尺寸放得下且不小于卡片最小尺寸就保持格数不变（自动列数让每格宽度相近，卡片实际大小因此接近）；放不下时取尺寸档里面积最接近的，再不行用 1×1 入口；容器列数不足时收起为入口，用户主动收起的保持收起。
3. **位置**：从「最近放下的两张卡片里最靠上的那一行」起找最早的空位——保持先后，又能让后面的小卡片补进前一两张卡片旁边的空缺。实测名次偏移不超过 2。
4. **填空洞**：卡片右侧是被包围的空洞（下方还有内容）时，在它自己的尺寸档里横向加宽补上；只横向，数字卡片不会变成无意义的高卡片；页尾留白不补。
5. 确定性：同一输入同一输出；不改输入。

S17 的 `projectLayout` 保留行优先**编号**跨列（三列第 7 格到五列成了第 2 行第 2 列），这是 1.17 宽屏错位与大片空白的根因；现在它只用于同一列数下的原样显示与损坏修复。

## 4. 自动列数与网格尺寸

**宽度**取网格容器的实际 CSS 宽度（ResizeObserver），两个工作区各算各的，不看窗口宽度或机型。

| 常量 | 值 | 作用 |
|---|---|---|
| 每格最窄 | 104 px | 手动列数上限 `floor((W + 12) / 116)`，最多 8，至少 1 |
| 自动目标格宽 | 172 px | 手机两列约 160、iPad 横屏 170–190 |
| 舒适上限 | 280 px | 基础 / 专属布局在 [104, 280] 内优先被自动模式采用 |
| 间距 | 12 px | |
| 行高 | `116 + 0.35 × (格宽 − 190)`，夹在 116–168 | 手机与 iPad 六列不变；格子越宽行越高但平缓 |

**评分**（越低越好）：`|ln(格宽 / 172)|`；对自动排出的布局再加 `3 ×（被包围空洞 + 列底空白）/ 面积 + 0.5 × 最后一行空格 / 面积 + 0.6 × 被迫缩小的卡片比例`；基础 / 专属布局（用户亲手排的）不计空白，格宽舒适时减 0.5。上一次的选择在分数差 ≤ 0.08 内保持（防抖）。首帧未测出宽度时沿用基础列数（最多 2）。所以「能放 8 列」不等于选 8 列；两格宽模块为主的预设会避开空出整列的奇数列数。

## 5. 列数偏好与编辑器

- **显示偏好，不是布局数据**：「自动」或某个手动列数，存在本机 `libevra.stats-columns:v1:<primary|secondary>`（主 / 辅工作区各一份，不同步）。手动值超过当前宽度上限时按上限显示，偏好不变。
- 只在编辑器「调整行列」里调：「自动调整列数」开关 + 1…上限的整数滑条 + 当前列数；取代 S17 的 2 / 3 列按钮。
- **编辑会话固定列数**：进入编辑时编辑的是当前看到的那一份（专属 / 基础 / 自动排列），不会跳回基础列数；进入编辑不写任何东西。编辑中拖分界线、旋转只改格子像素，不改编辑列数。有未保存修改时滑条禁用并说明——保存目标永远是正在看的列数。
- 「调整行列」显示当前排列来源；有专属布局时提供「恢复此列数的自动排列」（一步撤销，点「完成」后删除这一列数的专属布局）。
- **较宽松提示**（非阻断）：每格宽于 300 px、有卡片宽高比超过 4、或空洞与列底空白合计 ≥ 20% 时显示「当前布局较宽松，部分卡片可能显得空旷。」

### 5.1 编辑辅助工具面板（1.18.01 发布前精修）

- 进入编辑默认收起为 54px 胶囊：添加卡片 / 容器 / 预设；44px 点击区、上下各 4px 内边距与 1px 边框形成同心半圆端。添加入口使用实心胶囊强调色；低于 360px 时图标优先，保留无障碍名称。
- 复用 `usePaneSize` 的所属工作区宽高，绝不按整屏给双区定位。展开宽度为 `min(440, 工作区宽 − 24)`；常规高度约 56%、上限 448px，矮区至少给顶栏留 80px，内容内部滚动。上下分区的上区不重复计入底部安全区。
- 宽 / 中 / 窄初值为 700 / 420px，跨档有 16px 迟滞；窄档单列，其余双列。标题与分类不随内容纵滚；标签过长局部横滚，卡片名称允许换行。
- 按钮、Escape、同工作区外部点击或标题下拉收起；只改变面板呈现，不取消编辑。分类、搜索保留，按分类记住列表滚动位置；工作区换位 / 缩放不重新挂载卡片库。
- 卡片拖动开始时不自动收起，不改变来源 DOM 或滚动区域属性；沿用 `dnd.ts` 的 Safari 长按策略。收起内容 `inert`，浮层宿主透传空白处点击，不增加全屏遮罩。
- 本节只定义工具面板呈现，不参与基础布局、专属布局、列数偏好和保存规则。

## 6. 保存：按编辑行为决定写到哪里（`commitLayoutEdit`）

起点（`origin`）是编辑开始时的已保存文档，或会话里套用的模板 / 恢复的默认；它**随编辑历史登记**（`EditOrigins`：布局文档对象 → 起点，撤销 / 重做恢复同一个对象），不按卡片集合猜——系统默认的卡片 ID 固定。

| 编辑结果（与起点比） | 写入 |
|---|---|
| 卡片集合变了（新增 / 删除 / 复制 / 移入移出容器） | 编辑结果成为**新的基础布局**，`baseCols` = 编辑列数；全部专属布局清除 |
| 卡片集合相同，排列没变（可能只改了卡片内容） | 布局取起点原样（起点是模板时就是模板自己的基础与专属布局） |
| 在基础列数下调整排列 | 更新基础布局；其它列数的专属布局保留；同列数的专属布局（只可能来自导入）一并删除 |
| 在其它列数下调整排列 | 写入这一列数的专属布局；基础布局不变 |
| 调整后正好等于自动排列 | 删除这一列数的专属布局 |

- 「新增后又撤销」按最终结果判断。取消编辑什么都不写。
- 同时清理已与卡片集合不符的旧专属布局；看不懂的其它档案原样保留。
- 结果与系统默认完全相同时仍按 1.17.23 规则「跟随系统默认」。

## 7. 旧数据与兼容

- 已有布局就是基础布局（原 `baseCols`、原坐标），专属布局为空；第一次升级、第一次进入 iPad 都**不写**任何东西；没有破坏性迁移。
- 生产 1.17.15 客户端读到带专属布局的配置：schema 允许，只显示基础布局；它保存时保留 `profiles`（`withMain` 只换 `main`），新增卡片使专属布局失效，由新版本识别并清理。

## 8. 一致性

基础布局与专属布局在**同一份**工作台配置里，由既有的本机保存 + CAS 同步整份写入（`version` 递增、旧版本被拒绝、冲突走既有选择流程），不存在「基础写成功、专属清理失败」的中间状态。

## 10. 未决与需要真机

- 浮动工具栏桌面浏览器实测未完成（控制工具初始化失败、无头进程被执行策略拦截）；需验收单区、左右 55:45 / 70:30 / 30:70、上下矮区、连续调节 / 收起恢复 / 身份换位；实际按钮命中、焦点恢复、内外滚动、快捷添加、鼠标拖动均待实测。真实 iPad Safari 另验长按拖拽与普通滚动区分、安全区、软键盘及旋转；不能将其它版本已验收的拖动直接视为本轮通过。

- 自动列数的常量（172 / 280 / 评分权重）按浏览器与系统预设调出，需 iPad / 手机真机确认观感。
- 编辑中把工作区缩到很窄时，固定的编辑列数可能让格子窄于 104 px（只影响编辑态的结构形态显示）。
- 基础布局里的空位一律视为用户有意留的（自动模式不因此避开该列数）；若所有者认为旧版删卡留下的空洞应区别对待，再议。
