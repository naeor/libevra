## 3. 新 S17：模块化财务分析工作台（七阶段；2026-10-29 新增 W7）

### 3.0 通用约束

- **每个阶段结束都应是可独立验收、可独立发布的**（发布仍须所有者逐次授权，AGENTS §4）；不要把六个阶段攒到最后一起发。这里的“发布”指现有邀请制环境的**版本发布**（`1.16.xx` 补丁线与后续版本）；**S21（原 S19）是对外“正式公开发布”的准备与关口，排在 S17、S18、S19、S20 之后**，两者不是一回事；
- **模块接口与跨设备架构提前设计**：W1–W2 就冻结 A–F 层的接口草案、结果协议（RS-xx）、配置 schema 的 v1 骨架与“卡片与几何解耦”的数据结构，即使布局编辑器要到 W5 才开发（总需求规格 §11）；
- 每个阶段都有**安全 / 隐私关口**（§6.3）：新查询追加越权测试、新数据进入数据处理清单；
- 各阶段文档的“退出标准”是**必要条件**，不是估时；本文不给日历承诺，只给相对规模（S/M/L，【推荐】）；
- 数据库迁移：**W1–W5 预期无迁移**（扩展查询为只读、配置先落本地）；**W6 已确认采用本地优先 + 服务端同步（Q-03）和（若做）分享，将需要迁移**，必须另行评审、备份、回滚演练并经所有者批准（路线图 §7 的既有规则）；**W7（多层级分类）已确认需要分类父子结构迁移**，同样必须单独评审、备份、回滚演练并经所有者批准，且不得破坏现有账本与单层分类；
- **布局迁移契约提前**：行优先编号、`宽×高`、锚点 + `baseCols`、稳定对象 ID、Spacer、容器 `1×1` 形态、展示意图字段、档案键，在 W2 的 schema v1 中**一次留位**（[布局规格 §12–§18](../design/S17-工作台布局与格式模板规格.md)），否则 W5/W6 会被迫迁移配置格式；
- **动画与视觉细化的归属【已确认 2026-10-27】**：S17 只提供**必要的交互反馈**（例如布局移动后的即时状态、保存提示、合法 / 非法位置预览），**不建立全应用统一的高级动画体系**；统一动画、转场与页面级 UI 细化归 **S19**（全站 UI 与交互优化，承接原 S18-A 规划，§4.2 保留原 S18-A 范围作为 S19 的来源）。S17 的实现必须为呈现层留出可替换空间：**动画只能呈现 S17 布局引擎已经确定的结果，不能决定卡片位置**。

### 4.2 原 S18-A 范围（2026-10-29 起归入 S19）：统一动画、转场与 UI 细化

目标不是无差别增加动画，而是形成一套**简洁、自然、克制、具有 Libevra 品牌辨识度**的动态交互规范。尽量使用共享设计 token 与可复用组件，**不为每个页面单独发明不一致的动画参数**；所有动效必须兼容现有七套主题与浅色 / 深色模式。

#### 4.2.1 全局动态设计原则【范围已确认；具体参数待研究】

| 项 | 要求 | 状态 |
|---|---|---|
| 时长与节奏分级 | 短反馈 / 常规过渡 / 大范围转场分层；同一类动作使用同一档位，不按页面各写一套 | 【待研究】毫秒值须原型与真机验证（§4.6） |
| 过渡规则 | 进入、退出、展开、收起、位移、缩放各自的起止状态与信息连续性 | 【待研究】 |
| Easing / spring 选用 | 按动作语义（反馈 / 空间移动 / 弹性提示）选用，不同语义不混用同一曲线 | 【待研究】 |

#### 4.2.2 绿色顶部的统一滚动收缩（S18-A 重点）【范围已确认；参数待研究】

现状：账本、分析等页面顶部的绿色区域会随内容滚动直接离开屏幕。所有者希望：

- **向上滚动时，完整的绿色顶部逐渐收缩为一条较矮的绿色顶栏；收缩后始终紧贴屏幕最上方**；
- 紧凑顶栏保留：**当前页面标题** + **当前页面最重要的操作按钮**（通常为右侧两个按钮）；副标题、辅助说明等可以随收缩自然淡出；
- **向下滚动返回页面顶部时恢复完整展开**；原则上仅在接近原始顶部时恢复完全展开，不需要用户每次轻微反向滚动就频繁展开 / 收缩；
- 收缩过程**连续、平滑**：不出现内容突跳、顶栏遮挡内容、滚动位置错乱或按钮暂时无法点击；
- 顶栏高度、收缩距离与时长：【待研究】在实现与真机测试中确定，**规划阶段不冻结像素值**（§4.6）。
- 页面范围：账本、分析等使用绿色顶部的页面；各页面是否需要差异（例如是否常驻操作按钮）由 S18-A 的页面接入清单与视觉验收确定；「我的」页面的特殊处理见 §4.2.3。

#### 4.2.3 「我的」页面特殊处理【范围已确认；最终排布待真机视觉验收】

「我的」页面采用相关设计语言，但**不要求机械复制分析页的实现**：

- 展开状态保留现有个人资料头部与用户头像；
- 收缩状态：绿色顶部变为紧凑顶栏；用户头像缩小并自然移动到左上角；根据实际视觉效果保留「我的」、用户名或必要的操作按钮；**不挤压其他按钮，也不让头像在页面切换时闪烁**；
- 「我的」页面内容较少、有时不足以产生正常滚动，因此需要研究两种实现条件：
  1. **内容足够长时**：随真实滚动触发收缩；
  2. **内容不足时**：保持展开，或设计明确的头部折叠交互（不得为了触发动画而强行添加大量无意义空白）；
- 头像与标题的最终排布【待研究】保留为 S18-A 的真机视觉验收项（§4.6）。

#### 4.2.4 分析工作台卡片动画【范围已确认；技术路线待评估】

S17 建立正确的布局操作与预览语义（布局引擎负责结果）；S18-A 在此基础上补充完整动画：

- 卡片拖起与放下、被拖动卡片的轻微悬浮反馈、目标区域高亮；
- 其他卡片顺延、交换、重排时的平滑位移；
- 不同尺寸卡片的合法位置预览；
- 删除卡片后的自然补位；
- 取消操作后的恢复；撤销 / 重做的状态过渡；
- 容器展开、折叠与内部切换。

可以评估 FLIP 或其他适合的布局过渡技术，但**不预先绑定某一种动画框架**；**动画只能呈现布局引擎已经确定的结果，不能自己决定卡片位置**（§4.1）。

#### 4.2.5 全应用其他关键动画【范围已确认；按优先级分批】

逐步统一：筛选区域展开与收起；底部卡片抽屉升起 / 下滑 / 收起；卡片菜单、弹出层、日期选择器；页面导航与详情页进入 / 返回；模态窗口打开与关闭；Tab 状态与必要的交互反馈；数值、图表在数据切换时的合理过渡；必要的加载、空状态与保存反馈。

需要把动效分成**高优先级交互反馈**与**低优先级装饰效果**：优先保证清晰、稳定、低性能开销；**不要为了视觉效果增加不必要的等待时间**。

#### 4.2.6 S18-A 验收目标【已确认】

至少包括：

#### 4.3.2 布局与自适应规则【方向已确认；具体断点与阈值待研究】

**设备覆盖范围**（至少规划，且不以设备型号为分支依据）：小屏手机（320 CSS px 起）、常规尺寸手机、大屏手机；平板竖屏与横屏（含分屏与可调整大小的窗口）；常规笔记本、大尺寸桌面浏览器；浏览器窗口任意调整尺寸的情况；缩放与辅助（浏览器缩放、系统字体放大、高 DPI 屏）；输入方式（触摸、鼠标、触控板、键盘）。

**布局适配检查面**（全应用，不只分析页）：顶栏与底部导航；不同宽度下的文字、按钮与图标；卡片网格的列数与尺寸；分析工作台的容器与嵌套卡片；日期与币种选择栏；弹窗、抽屉及操作菜单；表格、复杂图表与数据密集型卡片；长文本、英文及其他语言下的布局；横屏与竖屏变化；安全区域与刘海 / 圆角屏幕；移动端虚拟键盘出现后的可视区域变化。避免出现裁切、重叠、不可点击、横向意外溢出和文字过度缩小；**组件不应依赖某个固定像素尺寸才能正常工作**。

**权威布局与漂移规则【已确认】**：

- 继续沿用现有 S17 / D 的布局系统：不同屏幕宽度可以有**派生布局**，但必须遵守既有的权威布局、迁移规则和**不累计漂移**原则（[布局规格 §13–§19](../design/S17-工作台布局与格式模板规格.md)）；
- **不能因为用户切换屏幕宽度，就静默破坏保存的卡片配置和原始布局**；派生结果不得写回权威布局（除非用户显式保存）；
- 如果未来允许用户保存特定宽度的独立布局档案，必须明确权威关系与同步策略（与 Q-08、OQ-LM-07 / OQ-LM-08 联动）；在此之前，跨宽度只做确定性派生。

**显示与交互差异**：触屏、鼠标、触控板与键盘操作；系统字体缩放与浏览器缩放；高 DPI 屏幕；安全区域与刘海 / 圆角；虚拟键盘；长文本与多语言；设备性能差异；横向滑动 / 纵向滚动 / 拖放手势冲突——上述均作为 S18-B 的验收覆盖项，具体做法【待研究】。

## 6. 安全、隐私、数据丢失与法律事项不得机械后移

## 9. 主要风险与缓解

| 风险 | 缓解 |
|---|---|
| 范围膨胀（分析种类、卡片家族、模板无限增加） | 批次制；每批先验收；“待研究”不排期；能力目录登记制 |
| 编辑器吃掉计算正确性的投入 | 严格阶段顺序：W1 / W2 先于 W5；W5 不得改动 A 层 |
| 性能（多卡片 × 大账本） | W2 建基线；去重与按需挂载；预算冻结后再做 W5 |
| 手势冲突（滚动 / 图表 / 抽屉 / 拖动）在 Safari 才暴露 | W5 前做 spike 与真机；方案 Q-13 |
| 个人布局与共享账本语义混淆 | 术语与测试（A 与 B 互不影响）；D-05 帮助文案 |
| 分享引入新的服务端用户生成数据与合规义务 | 关口 §6.3；先做本地导出 / 导入可降低风险 |
| 配置格式频繁变更导致迁移债 | schema v1 在 W2 冻结骨架；迁移链永久夹具 |
| 正式公开发布被推到 S18 / S19 / S20 之后（S21），法律 / 备案等外部依赖闲置，或邀请制环境长期承担新风险 | P / K 类并行不停（§5.4）；补丁线不受阶段阻塞；S17-W6 的分享部分受隐私 / 法律关口约束；S21 不设强制发布日期 |
| 单人维护与并发 worktree 的合并冲突 | 文档修改分小块、独立 hunk；交接摘要记录冲突点 |
| S19 动效与布局语义耦合，动画“自己决定位置” | 动画只呈现 S17 布局引擎结果；布局权威数据与动画层分离；S19 验收必须回归“动画不改变节点位置 / 布局数据”（§4.1、§4.2.6） |
| 动画性能与低端设备差异，或忽略减少动态偏好 | 动效 token 内置性能预算；提供降级策略；`prefers-reduced-motion` 作为硬性验收；真机记录（§4.2.1、§4.6） |
| 绿色顶栏收缩与安全区 / 刘海 / 滚动容器冲突 | 顶栏高度、收缩距离与恢复条件真机后定；不冻结像素值；滚动位置与按钮可点击性回归（§4.2.2） |
