## 3. 新 S17：模块化财务分析工作台（六阶段）

### 3.0 通用约束

- **每个阶段结束都应是可独立验收、可独立发布的**（发布仍须所有者逐次授权，AGENTS §4）；不要把六个阶段攒到最后一起发。这里的“发布”指现有邀请制环境的**版本发布**（`1.16.xx` 补丁线与后续版本）；**S19 是对外“正式公开发布”的准备与关口，排在 S17、S18 之后**，两者不是一回事；
- **模块接口与跨设备架构提前设计**：W1–W2 就冻结 A–F 层的接口草案、结果协议（RS-xx）、配置 schema 的 v1 骨架与“卡片与几何解耦”的数据结构，即使布局编辑器要到 W5 才开发（总需求规格 §11）；
- 每个阶段都有**安全 / 隐私关口**（§6.3）：新查询追加越权测试、新数据进入数据处理清单；
- 各阶段文档的“退出标准”是**必要条件**，不是估时；本文不给日历承诺，只给相对规模（S/M/L，【推荐】）；
- 数据库迁移：**W1–W5 预期无迁移**（扩展查询为只读、配置先落本地或复用现有存储）；W6 若采用服务端配置同步或布局分享，将需要迁移，**必须另行评审、备份、回滚演练并经所有者批准**（路线图 §7 的既有规则）。

## 9. 主要风险与缓解

| 风险 | 缓解 |
|---|---|
| 范围膨胀（分析种类、卡片家族、模板无限增加） | 批次制；每批先验收；“待研究”不排期；能力目录登记制 |
| 编辑器吃掉计算正确性的投入 | 严格阶段顺序：W1 / W2 先于 W5；W5 不得改动 A 层 |
| 性能（多卡片 × 大账本） | W2 建基线；去重与按需挂载；预算冻结后再做 W5 |
| 手势冲突（滚动 / 图表 / 抽屉 / 拖动）在 Safari 才暴露 | W5 前做 spike 与真机；方案 Q-13 |
| 个人布局与共享账本语义混淆 | 术语与测试（A 与 B 互不影响）；D-05 帮助文案 |
| 分享引入新的服务端用户生成数据与合规义务 | 关口 §6.3；先做本地导出 / 导入可降低风险 |
| 配置格式频繁变更导致迁移债 | schema v1 在 W2 冻结骨架；迁移链永久夹具 |
| 正式公开发布被推到 S18 之后（S19），法律 / 备案等外部依赖闲置，或邀请制环境长期承担新风险 | P / K 类并行不停（§5.4）；补丁线不受阶段阻塞；S17-W6 的分享部分受隐私 / 法律关口约束 |
| 单人维护与并发 worktree 的合并冲突 | 文档修改分小块、独立 hunk；交接摘要记录冲突点 |
| 本地候选 `1.16.23`（P0）长期未合并导致 W1 基线不清 | Q-06 优先答复 |
