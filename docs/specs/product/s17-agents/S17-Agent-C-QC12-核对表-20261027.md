## 2. 核对方法

1. **独立 SQL 导出**（`psql`，全部 `SELECT`）：
   - 总量：支出/收入/笔数/最大单笔（全量与 CNY 两组）；
   - 记录级支出金额列表（仅金额、kind、业务日、匿名分类键/支付方式键）；
   - 分类×月、分类合计、日合计、月合计、币种构成、并列最大单笔；
   - 矩阵/数据库层：分类×月填充组合数、多维填充组合数、成员列表、隔离账本总量。
2. **独立期望值计算**：分位/方差依赖 PostgreSQL 的 `percentile_cont`（= Type 7 线性插值）与 `var_pop`/`stddev_pop`（总体口径）；两期贡献、排名迁移、矩阵合计由独立枚举脚本计算，不复用 C 的实现。
3. **C 侧实现**：直接调用 `@libellum/shared` 的 `advanced/*` 纯函数（分位、分布、直方图、围栏、排行、Pareto、贡献、矩阵、透视、迁移、散点、气泡、箱线、小多图、日历、多维交叉、币种构成），不经过图表/适配层。
4. **比对**：金额整数精确相等；有理数（分位/方差/份额）按精确分子分母比较；仅在「日序列计数一致性」等结构性检查上用整数；失败信息只记「不一致」不放原始行。
5. **临时核对脚本**：`packages/shared/src/analysis/advanced/__qc12.fixture.test.ts`（临时，跑后删除）；期望值 JSON 在系统临时目录 `%TEMP%\qc12\`；命令 `QC12_EXPECTED=... pnpm --filter @libellum/shared test src/analysis/advanced/__qc12.fixture.test.ts` → **23 项测试全过**。

## 4. 差异与缺陷记录

- **实现侧差异：0 项**（金额/分位/分布/归因/矩阵/排名/箱线/日历/多维/币种构成全部一致）。
- 核对脚本早期出现的差异均为**核对侧错误**，已修正并登记（不涉及 C 实现）：
  1. 混币：初版把「全币种支出」与「单币种记录」对比（M-14/M-16）——违反「不同原币不得直接相加」，改为单原币口径。
  2. 类型：`number` 与 `bigint` 严格不等（日历记录数），改为显式 `Number()` 转换。
  3. SQL 期望值：箱线导出使用 `having count(*) >= 5`（只导可靠组），实现保留全部组并标 `reliable=false`——两者语义一致，核对时按此对齐。
  4. 维度语义：交叉表 `metric="amount"` 的 `metricValue` 与 `metric="share"` 不同，份额核对改用 share 口径。
- 以上 4 条已作为「核对方法学」记录，避免后续 Agent 重复踩坑。
