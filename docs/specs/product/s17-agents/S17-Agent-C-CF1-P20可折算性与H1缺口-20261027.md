### 2.2 字段与语义

| 字段/常量 | 定义 | 位置 |
|---|---|---|
| `DraftFxFallbackResult.available` | `needsConversionCount > 0`（存在需要折算的记录）→ `true`；否则 `false`（本分析不适用，不得显示「0 次回退」结论） | `draftTypes.ts`（P20 结果形状） |
| `DraftFxFallbackResult.unavailableReason` | `available === true` → `null`；否则为原因码 | 同上 |
| `FX_DRAFT_FALLBACK_UNAVAILABLE_NO_TRANSACTIONS` | `"no-transactions"`：所选范围内没有任何交易（`records.length === 0`） | `fxDiagnostics.ts` 常量区 |
| `FX_DRAFT_FALLBACK_UNAVAILABLE_NO_CONVERSION_NEEDED` | `"no-conversion-needed"`：有记录但全部已是目标币种，无折算需求 | 同上 |

原因码选择说明：冻结件只要求「可选 `unavailableReason`」，未冻结具体字符串；本批用两个机器可读短码区分「无交易」与「无折算需求」，并与既有 `completeness` 语义对齐（空输入同时为 `no-transactions`）。若 S-01 v2 后续冻结具体文案，C 按冻结值改常量值即可（不改变语义）。

### 3.2 需要冻结方给出的问题（建议至少回答 1–9）

1. **归属**：`dominantBins` 挂在 `distribution` 结果上，还是 `histogram` 子结构上，还是单列一个 `histogram-bins` 形状？
2. **语义**：`dominant` 的判定（按 count 最高的桶？按金额占比最高的桶？还是「占样本 ≥ N%」的全部桶）？
3. **数量与上限**：最多返回几个桶；超出时是截断（带 omitted 计数）还是拒绝？
4. **排序与并列**：按什么排序；并列时次级键是什么（桶下标升序？）。
5. **零值/空值**：`zeroCount` 是否参与 dominant 判定；空结果（`no-transactions`）时字段为 `[]` 还是不可用。
6. **与分箱算法关系**：分箱算法仍待 G-24（Sturges vs C 的 `histogram-nice-bin-width`）——`dominantBins` 是否随算法变化而重算；是否必须同时冻结算法（如联动 G-24）。
7. **口径字段**：是否携带 `method`/`binWidthMinor`/样本量等最小上下文，还是由 `distribution` 自动继承。
8. **序列化形态**：`{ index, lowerMinor, upperMinor, count }` 数组？还是只给 `index[]`（由 histogram 索引）？
9. **一致性约束**：不同尺寸/详情页是否必须同值（ACC-02）；是否允许适配层按尺寸折叠（若允许，折叠规则也需冻结）。
