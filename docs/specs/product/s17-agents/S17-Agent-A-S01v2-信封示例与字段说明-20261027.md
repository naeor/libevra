## 1. 三个真实形状的 envelope 示例

### 1.1 complete — B01 总支出（scalar，原币 CNY）

场景：工作台期间 2026-10-01…2026-10-27（27 天），筛选支出、原币 CNY，查询数据完整（无缺失汇率、无离线缺口）。

## 2. 信封逐字段语义

| 字段 | 类型/取值 | 语义 | 适配层（可改/不可改） |
|---|---|---|---|
| `version` | 固定 `"s01-v2"` | 协议版本串（唯一正式值）。`s01-draft`/`s01-v2-draft` 仅历史（旧数据按 §16.5 兼容读取） | **不可改**；可只读校验，非 `s01-v2` 时按兼容读取规则只读展示 |
| `analysisId` | `"AN-B01"`…`"AN-I17"` / B、C 编号 | 稳定分析标识；用于目录、来源、缓存键 | **不可改**；不得用卡片标题替代 |
| `analysisType` | 字符串（A：`scalar`/`ranked-groups`/`composition`/`record-extreme`；B/C 有各自域） | 结果类型域，用于分派渲染 | **不可改**；适配层按 `shape`/`analysisType` 分派 |
| `metric` | 字符串（如 `expense-total`） | 指标语义与聚合口径 | **不可改**；不得改写成别的指标名 |
| `resolvedFilters` | `{kind, categoryIds, paymentMethodIds, tagIds, currency}` | 计算**实际生效**的筛选。`null`＝该维度不限；`[]`＝限制为空集（结果无匹配，语义与 `null` 不同） | 可显示筛选 chips；**不得**把 `[]`/`null` 混同、不得按 UI 状态改写 |
| `resolvedPeriod` | `{from, to, dayCount}` | 计算**实际生效**的闭区间业务日期（`occurredLocalDate` 语义；DB 查询为 `[from, to+1)` 半开）。`dayCount` 两端都算 | 用于日期显示与来源跳转；**不得**改区间/重算 |
| `resolvedCurrency` | `{mode:"original", currency}` 或 `{mode:"aggregate", targetCurrency}` | 原币模式=不跨币种相加；aggregate=逐笔经既有 FX 引擎折算后求和 | 只读展示口径；**不得**自行换算/二次折算 |
| `completeness` | 9 态（见 §3） | 数据完整性/可用性状态，是**唯一**权威判断字段 | 决定展示态；**不得**布尔化、不得合并状态、不得用其他字段推断替代 |
| `unavailableReason?` | 字符串（如 `no_matching_transactions`/`fx_incomplete`/`request_failed`/`no_permission`/`currency_mismatch`/`no_matching_transactions`） | 不可用/不完全的**原因补充码**（开放字符串，非封闭枚举）；不替代 `completeness` | 可映射提示文案/诊断信息；**不得**当固定枚举硬编码，遇到未知值原样展示 |
| `dataVersion` | `string \| null` | 数据版本令牌；`null`=客户端本地/非权威。用于缓存键与一致性判断（分析结果缓存键） | 只透传；不参与财务计算、不得当权威账本版本 |
| `computation` | 对象（见 §2.1） | 计算口径元信息，解释派生值如何得出 | 只读展示解释；**不得**用它重算权威值 |
| `source` | `SourceDescriptor`（见 §2.2） | 「如何重新取到来源记录」的**地址**，不是权限凭证 | 用于查看来源/下钻；每次下钻由查询层重查权限，**不得**扩大可见范围 |
| `shape` | `scalar`/`ranked-groups`/`composition`/`record-extreme` | 结果负载种类 | 渲染分派依据 |

### 2.1 `computation`（计算口径元信息）

- 必填 `rounding`：恒为 `"minor-half-away-v1"`（逐笔/展示统一舍入政策）。
- A 侧实现当前定义（`ComputationMetadata`）：可选 `numeratorMinor?`（精确分子，最小单位字符串）、`denominator?`（笔数/样本分母）、`denominatorDays?`（B06 自然日分母）、`sampleCount?`、`tieCount?`、`convertedWithFx?`、`fxPolicy?`、`notes?`（人类可读解释，如 `incomeMinor=…`）。
- 协议 v2 §2 另登记的可选项 `method?`（算法名，见 v2.0.1 取值裁定）、`sampling?`（仅视觉层采样标注）、`coverageEnd?`（离线覆盖终点）、`analysisLimit?`（限额可追溯）属于 **B/C 形状扩展位**；A 26 项当前不产出。适配层应**容忍其存在并原样透传**，不得因未知可选字段丢弃整个 `computation`。
- **不可改**：`rounding`/分子/分母/样本数等数值与政策；显示层只能用它们解释，不得重算。

### 2.2 `source`（来源地址）

```
source = {
  analysisId, period, filters, groupBy,
  query: { kind: "stats" | "transactions", from, to, currency,
           categoryId?, paymentMethodId? },
  transactionIds?: string[],   // 分析返回单条记录时（如极值/交易明细类）
  dataVersion: string | null
}
```

- `query.kind` 标明实际读路径（`stats`/`transactions`）；`from`/`to` 为闭区间业务日期。
- 可按此条件重新查询来源记录，但**权限由查询层重查**（只读成员不会因此扩大权限）；不得把 `source` 当权限令牌或导出入口。

## 3. `completeness` 9 态语义（整结果层）

| 状态 | 含义 | 值可用性 | 建议展示 |
|---|---|---|---|
| `complete` | 数据完整：查询完整、无缺失汇率（aggregate 全可折算）、无离线缺口 | 可用 | 正常渲染 |
| `no-transactions` | 区间内无匹配交易（真实空/零） | 总额类可显示**真实零**；平均/中位数/极值等呈 `null`（不可计算） | 空态提示；不是错误 |
| `partial` | 部分数据缺失（非汇率根因，如部分记录未加载/仅部分可用） | 谨慎：不得宣称完整；缺失范围以 `null`/提示表达 | 部分结果提示 |
| `fx-incomplete` | **仅因汇率缺失/折算失败**导致不完整（aggregate 模式） | `total`/`share` 不得当 100% 基准；金额可为部分覆盖 | 「部分覆盖」提示；不画完整构成 |
| `offline-incomplete` | 离线数据覆盖不足（缺失≠0） | 谨慎：不得把缺数据当零 | 覆盖不足提示 |
| `loading` | 计算/加载中 | 不可用（`value: null`） | 加载骨架 |
| `request-failed` | 请求失败 | 不可用 | 错误态 + 重试 |
| `no-permission` | 无权限（未登录/成员失效/只读限制等） | 不可用 | 无权限态，不展示数字 |
| `not-applicable` | 该分析对此数据不适用（如未来日期、类型不支持） | 不可用 | 不适用说明 |

注意：这 9 态是**整结果/信封层**；B/C 时间序列的**桶级**另有五态 `state`（同一状态词汇但不同层，见 v2 §2/§4.10），不得混用。`partial` 与 `fx-incomplete` 的判别：**只有明确汇率缺失/折算失败根因**才映射 `fx-incomplete`；其他缺失原因按自身状态（`partial`/`request-failed`/`unknown` 等）表达，不得一律标成 FX 问题；混合原因优先级按 v2 §5.1-3。

## 4. 适配层可改 vs 不可改

### 4.1 不可改（协议 / 权威值）

- 信封字段与其值（`version`/`analysisId`/`analysisType`/`metric`/`resolvedFilters`/`resolvedPeriod`/`resolvedCurrency`/`completeness`/`unavailableReason`/`dataVersion`/`computation`/`source`/`shape`）；
- 金额类 `MoneyValue.amountMinor`（整数最小单位十进制字符串）、`exact-money` 的 `numeratorMinor`/`denominator`、比例 `Ratio`（JSON 为 `{"numerator":"…","denominator":"…"}` 十进制字符串）；
- 权威值默认**不得**由适配层重算：不得重新求和 groups/parts、不得重算 share/百分比、不得把 `null` 当作 0、不得把 `no-transactions` 当错误或反过来、不得把 `fx-incomplete` 归一化为 100%；
- `source` 条件不得被 UI 改写后声称等同来源；`dataVersion` 不得改写；未知可选字段不得丢弃（保留透传）。

### 4.2 可改（UI 投影 / 展示层）

- 数字格式化：按币种 `decimals` 格式化 `MoneyValue`；`exact-money` 展示时**一次**舍入（half-away）；`Ratio` 显示按 `scale`（`percent-100` 1 位小数/`fraction`）格式化，**只在显示层舍入**；
- 图表类型/密度/尺寸切换（Compact/Medium/Expanded）、布局（由 D 布局引擎驱动，不自建）；
- 颜色/主题/i18n/文案/图标/提示；图例与排行的**视觉顺序**（不改变数值语义与 stable color 规则）；
- 「其他」分组展示：按 `isFolded`/`foldedGroupIds` 折叠展示；折叠金额仍是权威合计，不得重算；
- 空态/部分覆盖/无权限/错误/加载的展示形态；tooltip、复制、键盘与无障碍语义；
- 由展示派生且**明确标注为派生**的展示值（不得覆盖或替代权威字段）。

## 5. 兼容与常见陷阱

1. **旧数据**：`version` 为 `s01-draft`/`s01-v2-draft` 的数据按 v2 §16.5 兼容读取（必填字段校验通过即接受、不重算）；适配层只读展示、不迁移、不回写。
2. **未知分析**：未知 `analysisId`/`analysisType`（含 B/C 形状）→ 只读占位，不推断、不隐藏。
3. **大小写/空值语义**：`categoryIds: []`≠`null`；`share: null` 表示基准不可用（不是 0%）；`extreme: null` 可能因该分析极值非金额（B20 用 `extremeValue`）。
4. **大整数**：金额一律字符串；前端不得 `Number()` 后参与财务累加（超出 `Number.MAX_SAFE_INTEGER` 会失真）。
5. **`Ratio` 序列化**：跨 JSON 用十进制字符串 `{numerator, denominator}`；不要依赖 float。
6. **桶级 vs 整结果**：时间序列桶级 `state` 五态与信封 `completeness` 9 态是两层，不要互相赋值。
7. **示例仅演示**：本文数值为合成数据，不是真实账本，也不构成对具体分析的验收数据。
