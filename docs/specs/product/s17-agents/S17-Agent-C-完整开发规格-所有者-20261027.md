# 0. 任务总目标

Agent C 负责构建 Libevra 的深入分析与专业分析能力。

相比 Agent A 负责的基础统计，以及 Agent B 负责的时间趋势，Agent C 需要解决更复杂的问题：

- 用户的消费主要集中在哪里？
- 哪些分类造成了支出的增加或减少？
- 交易金额具有怎样的分布？
- 哪些分类的单笔支出通常更高？
- 分类的金额、频率和占比有什么关系？
- 不同月份、星期和支付方式之间存在怎样的差异？
- 分类排名随时间如何变化？
- 历史多币种账目究竟由哪些原始币种构成？
- 汇率折算结果有多少数据能够可靠覆盖？
- 用户如何通过自定义维度组合分析自己的账目？

本模块需要同时开发：

**A. 计算函数：** 从真实、经过授权的数据及已有权威统计结果中，计算分布、分位数、变化归因、矩阵、层级结构、排名变化及多币种分析等结果。

**B. 绘图函数：** 将标准化分析结果呈现为直方图、箱线图、散点图、气泡图、瀑布图、矩阵热力图、Treemap、旭日图、桑基图、排名变化图等。

两者必须严格分离：

```text
授权后的真实账目
       │
       ▼
权威金额及汇率计算
       │
       ▼
基础聚合 / 时间分析
       │
       ▼
Agent C 专业统计计算
       │
       ▼
标准化专业分析结果
       │
       ▼
图表兼容性检查
       │
       ▼
图表组件 / 数据表
       │
       ▼
工作台卡片及分析详情页
```

禁止从 SVG 尺寸、柱形高度、扇区角度或动画数值反向推导财务结果。

**最终交付的 34 项分析，必须是有真实统计意义的产品功能，而不只是 34 个看起来不同的图表。**

# 4. 全部专业统计的通用财务合同

## 4.1 原始数据只读

所有专业分析只能读取授权数据。

不能：

- 更改交易金额。
- 修改交易日期。
- 自动重分类交易。
- 更改用户财务记录。
- 修改汇率来源。
- 绕过账本权限。

## 4.2 精确金额

使用项目既有的 BigInt、精确十进制或等效权威金额体系。

金额的：

- 求和。
- 比较。
- 排序。
- 差额。
- 分位数。
- 分类归因。

必须保证精度。

绘图阶段可以将已计算金额映射到浮点坐标，但绘图值不能反向成为财务结果。

## 4.3 跨币种规则

原币模式只对当前指定币种执行金额计算。

综合模式复用历史逐笔汇率折算和舍入规则。

严禁：

`100 USD + 100 CNY = 200`

也严禁使用当前汇率重新计算历史交易，除非用户明确使用另一个有正式定义的模拟分析模式。

## 4.4 统计完整性

每项分析必须保留：

- 数据范围。
- 实际有效记录数。
- 无记录状态。
- 部分数据状态。
- 不可计算状态。
- 汇率覆盖状态。
- 来源描述。

对于占比、增长率、分布、浓度及归因分析，完整性尤其重要。

一个完整性不足的结果不能因为图表漂亮，就被视为可靠结论。

## 4.5 可比性

凡是比较两个周期、两种分类或两个数据集合，必须确认：

- 账本范围一致。
- 权限一致。
- 币种口径一致。
- 指标定义一致。
- 数据完整性适合比较。
- 日期和统计范围明确。
- 分类归属规则一致。

比较结果需要返回实际比较区间与可比性状态。

# 5. 专业计算的共同数学规则

## 5.1 分位数

本模块包含：

- 中位数。
- 四分位数。
- 任意分位数。
- 跨分类分位数比较。
- 箱线图。

建议采用一种明确、可测试的分位数定义，并全项目统一。

可考虑线性插值型样本分位数，例如常见的 Type 7 方法：

对已排序数据 `x[1] … x[n]`，令：

`h = 1 + (n - 1) × p`

再在相邻次序统计量之间插值。

但这是**推荐的技术口径**，并非所有者已确认的最终数学约定。

正式落地前，应与 Agent A 的中位数计算保持一致。

不能出现：

- Agent A 的 Q2 是 25。
- Agent C 的 Q2 却采用另一种定义得到 20。

分位数插值可能得到高于货币最小单位精度的结果。

内部必须保留足够精度，显示时再统一舍入。

## 5.2 方差和标准差

交易金额波动应明确是：

- 所选全部交易的描述性总体标准差。
- 或从抽样中推断总体的样本标准差。

默认建议选用**描述性总体标准差**。

计算：

`Mean = Σxi / n`

`Variance = Σ(xi - Mean)² / n`

`StdDev = sqrt(Variance)`

需要：

- 明确样本数。
- 处理 n = 0。
- 处理全部金额相同。
- 避免大整数转浮点造成精度灾难。
- 避免平方和导致普通整数溢出。

如果采用数值稳定算法，也要保证最终统计合同和精度可解释。

## 5.3 变异系数

`CV = StdDev / Mean`

当均值为零或缺乏意义时不可计算。

不能将 CV 直接作为绝对的财务健康评分。

## 5.4 百分比与排名

百分比必须基于相同统计口径的完整分母。

排名要使用精确金额或整数笔数。

同值排名必须有确定性处理。

建议区分：

- 展示顺序。
- 统计名次。

同值时的名次是否并列，应在统一排行合同中明确，不能由图表随意决定。

## 5.5 统计分布

直方图分箱时必须明确：

- 箱边界。
- 左右端点是否包含。
- 箱宽。
- 各箱数量。
- 最大值归属。
- 零金额归属。
- 极端离群值。
- 所有交易是否恰好进入一个箱。

需要满足：

**各有效箱频数合计 = 原始有效交易笔数。**

不能因为区间边界错误丢失交易或重复计数。

## 5.6 变化归因

设两期分类金额：

`Previous(c)` 与 `Current(c)`。

各分类变化：

`Delta(c) = Current(c) - Previous(c)`

总体变化必须满足：

`Σ Delta(c) = CurrentTotal - PreviousTotal`

当分类体系可能变化时，需要先使用明确的分类身份和映射策略。

不能按显示名称简单匹配类别。

## 5.7 未分类与历史分类

任何分类汇总都应考虑：

- 未分类账目。
- 已删除分类。
- 历史分类引用。
- 同名不同 ID 分类。
- 分类重命名。
- 可用分类层级。

不得因为某个分类不存在于当前分类列表就丢掉交易金额。

# 7. I18 · 大额交易排行

## 分析目标

让用户查看某个时间范围内金额最高的交易。

默认以支出交易为对象。

可以支持收入/支出参数切换，但必须标明当前比较范围。

## 计算

对符合条件的交易按**精确金额降序**排序。

返回 Top N。

建议支持：

- Top 3。
- Top 5。
- Top 10。
- 自定义 N（受性能与安全上限约束）。

## 输出

- 金额。
- 交易业务日期。
- 分类。
- 安全的交易摘要。
- 原始币种。
- 当前显示币种。
- 排序名次。
- 来源 ID 或安全来源描述。
- 统计完整性。

## 重要规则

- 不能根据格式化后的金额字符串排序。
- 综合模式必须按权威逐笔折算金额比较。
- 原币模式不能混合不同币种排序。
- 同金额排序需确定。
- 缺汇率记录不能被悄悄忽略并宣称完整排行。
- 无记录时显示空态。

## 图表

- 大额交易排行表。
- 横向金额条。
- Top N 交易卡片。
- 简化金额榜单。

图表点击后进入具体交易或经过授权的来源详情。

# 8. A06 · 支出变化贡献

## 分析目标

解释两期支出总额的变化由哪些分类贡献。

## 计算

对当前期与比较期分别进行分类汇总。

`Delta(c) = CurrentExpense(c) - PreviousExpense(c)`

例如：

| 分类 | 上期 | 本期 | 变化 |
|---|---:|---:|---:|
| 餐饮 | 500 | 800 | +300 |
| 交通 | 400 | 250 | -150 |
| 娱乐 | 200 | 350 | +150 |

总变化：

`+300 -150 +150 = +300`

当前总支出比上期增加 300。

以上数值仅为示例。

## 输出

- 两个完整区间。
- 各分类两期金额。
- 各分类差额。
- 正负贡献。
- 总变化。
- 来源筛选。
- 可比性信息。

## 图表

- 正负发散条形图。
- 分类贡献排行。
- 瀑布图。
- 变化摘要表。

## 重要要求

不能只显示增加的分类而忽略减少的分类，否则贡献总和可能无法解释总体变化。

必须验证：

`分类变化净合计 = 总支出变化`

若存在未知分类或汇率缺失，不允许伪装成完全解释了总变化。

# 9. A07 · 分类份额变化

## 定义

比较两期各分类在总支出中所占比例的变化。

前期：

`SharePrevious(c) = PreviousExpense(c) / PreviousTotal`

本期：

`ShareCurrent(c) = CurrentExpense(c) / CurrentTotal`

差异：

`ShareDelta(c) = ShareCurrent(c) - SharePrevious(c)`

单位应是**百分点**。

## 示例

餐饮占比：

前期 20%，本期 35%。

结果：

**增加 15 个百分点**。

不是“增加 15%”。

如果需要相对增长率，则属于另一个明确的指标。

## 图表

- 发散百分点条。
- 双期斜率图。
- 分类份额变化表。
- 双环图。

## 边界

如果某一期总支出为零，分类占比不可计算。

数据不完整时不能假装占比准确。

分类新增与消失需明确表示为相应期金额为零，而不是删除该分类。

# 12. A10 · 支出四分位数

## 定义

计算单笔支出金额分布的：

- 最小值。
- Q1。
- Q2（中位数）。
- Q3。
- 最大值。
- IQR = Q3 - Q1。

可选提供更详细分位数。

## 图表

- 箱线图。
- 分位数指标卡。
- 五数概括表。

## 异常值

经典 Tukey 箱线图可使用：

`LowerFence = Q1 - 1.5 × IQR`

`UpperFence = Q3 + 1.5 × IQR`

但箱线图须区分：

- 真正数据最小值与最大值。
- 箱线图须端点。
- 离群点。
- 统计分位值。

不能把理论围栏直接标成真实最小交易金额。

## 特殊数据

- 无记录。
- 一笔记录。
- 所有交易相同。
- 少量记录。
- 极大金额。
- 非整数中位数。

必须与 Agent A 的 B08 中位数保持一致。

计算复用 Agent B 的分类时间序列。

# 32. P16 · 币种交易构成

## 定义

- 交易数量。
- 收入笔数。
- 支出笔数。
- 各币种交易笔数占比。

## 图表

- 币种笔数柱状图。
- 构成环图。
- 币种排行表。

USD 多少、CNY 多少、EUR 多少。

# 33. P17 · 综合金额币种贡献

## 定义

在综合折算模式下，按照交易原始币种分组，统计各币种对已折算总收入或总支出的贡献。

例如：

原始 USD 交易折算后贡献多少目标币种金额。

原始 CNY 交易折算后贡献多少。

## 计算

逐笔复用已有权威 FX 结果。

`ConvertedContribution(currency) = Σ ConvertedAmountOfTransactionsOriginallyInCurrency`

## 图表

- 环图。
- 堆叠柱。
- 币种贡献排行。
- 金额构成表。

## 正确性

各币种已折算金额合计必须与同口径综合总额一致。

缺汇率交易必须明确标记。

不能为了使已知部分构成 100%，就隐藏缺失数据。

# 35. P19 · 汇率完整性分析

## 定义

帮助用户了解在所选时间范围内，哪些交易能够准确按照系统汇率合同进行综合折算。

## 核心指标

- 需要折算的交易笔数。
- 成功折算笔数。
- 未成功折算笔数。
- 完整性比例。
- 缺失的日期与币种组合。
- 原始币种分布。
- 可能的回退使用情况。

## 图表

- 币种 × 日期状态矩阵。
- 统计摘要。
- 问题记录表。
- 完整性比例条。

## 重要说明

可用记录占比不等于金额覆盖比例。

如果某笔缺汇率交易原始金额为 100 USD，就不能在不知道正确目标币种折算结果的情况下推断其目标币种金额。

可以报告：

“已成功折算 95/100 笔。”

但不能因此声称：

“已覆盖总金额的 95%。”

除非另有数学上成立且清楚标注口径的金额覆盖定义。

- 回退来源。

- 状态统计表。

## 数据限制

该情况下应先实现接口与测试设计，并明确真实数据依赖。

# 37. P21 · 自定义多维分析

这是专业分析库中自由度最高的能力之一。

## 目标

允许用户在受控范围内选择：

- 分析指标。
- 时间范围。
- 分组维度。
- 筛选条件。
- 排序。
- 图表类型。

例如：

**支出金额 × 分类 × 月份**

或者：

**交易数量 × 支付方式 × 自然周**

## 实现原则

不是开放任意代码执行。

不是让用户直接输入 SQL。

应使用明确的声明式 AnalysisDefinition 与允许列表。

## 能力检查

系统必须判断：

- 指标和维度是否兼容。
- 当前数据模型是否支持。
- 当前账户是否有查询权限。
- 是否跨币种。
- 是否需要汇率折算。
- 计算成本是否合理。
- 结果规模是否超限。
- 当前结果适合哪些图表。

## 输出

标准化的：

- Scalar。
- RankedGroups。
- TimeSeries。
- Matrix。
- Distribution。
- 其他正式支持的结果形状。

然后由图表兼容性规则确定可以使用哪些图表。

## 重要限制

不允许用户通过自定义条件调用任意数据库表。

不得让用户通过构造配置绕过只读限制或读取其他账本。

自定义分析保存时，保存的是分析定义，不是秘密财务数据快照。

# 38. P22 · 同期变化瀑布分析

## 定义

将两个可比时期的总支出变化按照分类贡献展示成瀑布图。

底层应直接复用 A06 的变化归因计算。

## 图表结构

1. 起始：前期总支出。
2. 中间：各分类的正负变化。
3. 结束：当前期总支出。

必须满足：

`起始金额 + Σ 分类变化 = 结束金额`

## 交互

每个中间变化条可查看：

- 分类。
- 前期金额。
- 本期金额。
- 增加或减少金额。
- 来源交易。

## 要求

不能为了图表排列方便，改变分类变化的数值或正负号。

如果总差额无法完整解释，不能画出一张貌似完全守恒的瀑布图。

- 完整性。

## 图表

# 42. 图表的数学与几何正确性

## 42.1 精确值与绘图值分离

所有结果保留精确金额、精确比较关系和实际统计单位。

仅图形坐标使用安全映射后的展示数值。

对于极大金额，应采用避免直接将 BigInt 粗暴转为不安全 Number 的归一化策略。

## 42.2 面积和长度的含义

Treemap：

矩形面积代表数值比例。

气泡图：

必须明确气泡面积还是半径对应指标。

柱状图：

柱长必须遵守数值尺度。

瀑布图：

正负变化与累计高度必须守恒。

桑基图：

连线宽度必须代表真实可加的数值关系。

## 42.3 不能为了美观改变数据含义

禁止：

- 为了让极小分类可见而任意扩大其占比。
- 将负变化画成正变化。
- 将缺失数据绘制成零。
- 将不具备可比性的分组共用一个误导性比例尺。
- 将不存在的层级连接画成真实关系。
- 把历史汇率样本补成虚假的完整行情。

## 42.4 无障碍

高级图表必须有可读的文本或表格替代形式。

尤其是：

- 桑基图。
- 箱线图。
- Bump Chart。
- Treemap。
- 旭日图。
- 大型矩阵。

不能仅靠颜色和鼠标悬停才能理解分析。

- 完整显示方式。
- 详情页展示要求。

但不能改变分析实际值。

## 43.2 Medium

显示主要图表、关键标签及少量图例。

## 43.3 Expanded

显示：

- 完整图表。
- 多维图例。
- 详细数值。
- 来源。
- 统计说明。
- 数据完整性。
- 必要的操作。

无论图表被放到：

- 普通卡片。
- 田字格容器。
- 滑动抽屉。
- 自定义布局。
- 跨设备自动转换的网格。

分析计算都应相同。

当外层布局容器自动收缩到 1×1 时，Agent C 不需要强行把大型专业图表塞进去。

容器负责提供入口，完整图表在容器详情或分析详情中展示。

# 46. 测试矩阵

Agent C 属于严格财务与专业统计模块，需要系统性测试。

但审核应集中在高风险计算和接口部分，不对每个简单视觉微调重复全项目审查。

## 46.1 金额与精度

测试：

- 非常大金额。
- 非常小金额。
- 相同金额。
- 非整数平均值。
- 精确分位数。
- 百分比舍入。
- 负变化。
- 缺失汇率。

## 46.2 分布统计

测试：

- 空数据。
- 一笔交易。
- 两笔交易。
- 奇数/偶数样本。
- 所有交易金额相同。
- 高度偏态数据。
- 大量零值。
- 极端离群值。
- 直方图区间边界。
- 箱线图围栏。

## 46.3 周期归因

测试：

- 全部分类增长。
- 全部分类下降。
- 有增有减。
- 总变化为零。
- 分类新增。
- 分类消失。
- 同名不同分类。
- 历史分类删除。
- 汇率不完整。

必须保证分类变化净额与整体差额一致。

## 46.4 多维矩阵

测试：

- 行列合计。
- 空行。
- 空列。
- 零值。
- 缺失值。
- 多分类。
- 跨年月份。
- 支付方式缺失。
- 无权限数据。
- 不同币种。

## 46.5 层级结构

测试：

- 无分类层级。
- 单层分类。
- 多层分类。
- 节点只有直接交易。
- 节点既有直接交易又有子分类。
- 分类循环异常。
- 历史孤立节点。
- 真实金额守恒。

## 46.6 汇率诊断

测试：

- 全部成功折算。
- 部分缺失。
- 全部缺失。
- 多原币。
- 直接命中。
- 回退使用。
- 回退来源缺失。
- 不同目标币种。
- FX 结果变更。
- 离线状态。
- 历史记录与当前统计一致性。

## 46.7 来源一致性

所有可下钻的金额和分组，必须能够通过来源条件重新得到同一权威统计结果。

特别测试：

- 瀑布图分类贡献。
- 矩阵单元格。
- 排名图。
- 箱线图的样本集合。
- 桑基图的层级金额。
- 汇率异常日期。

## 46.8 统计性质测试

至少建立以下关键性质：

**分布守恒：**

`Σ HistogramBinCount = EligibleTransactionCount`

**分类归因守恒：**

`Σ CategoryDelta = CurrentTotal - PreviousTotal`

**矩阵守恒：**

完整互斥矩阵的行合计、列合计、总合计一致。

**累计集中度：**

在非负分类金额、分母有效的条件下，帕累托累计比例不下降，最终达到完整总体的 100%。

**层级守恒：**

真实父子分类汇总不能重复计数交易。

**汇率贡献守恒：**

各原始币种已折算金额汇总与权威综合统计一致。

**配置无副作用：**

图表切换和布局尺寸变化不会修改财务结果。

## 最终目标
