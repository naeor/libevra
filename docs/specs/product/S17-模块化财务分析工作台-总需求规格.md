## 3. 数据原则（最高优先级）

### 3.1 财务数据严格单向流动【已确认】（所有者指令 §3）

```text
原始账本数据  →  分析计算结果  →  图表展示
 （权威来源）     （只读派生）      （只读呈现）
                                       ▲
                      布局 / 配置 ─────┘  只“组织”图表，不回流
```

绝不允许反向的数据修改：

- 原始账目是财务数据的权威来源；
- 分析模块只负责**读取并计算**；
- 图表模块只负责**展示**计算结果；
- 工作台布局只负责**组织图表**；
- 用户修改卡片、图表、网格或模板，**不得**修改原始交易；
- 切换原币 / 综合模式**不得**修改原始金额、币种、日期或账本；
- 调整布局**不得**生成、修改、删除任何交易记录；
- 更换卡片尺寸**不得**影响计算结果。

### 3.2 允许与禁止的写入【已确认】

禁止的不是“整个分析系统一切数据库写入”，而是**对原始账务数据产生副作用**。

| 类别 | 是否允许 | 说明 |
|---|---|---|
| 用户个人分析配置、卡片实例、布局、模板、偏好 | ✅ 允许写入**个人设置存储** | 作用域为用户本人，见 §3.3；存储位置待决策（本地 / 服务端 / 混合） |
| 交易、账本、分类、支付方式、标签、成员、汇率公共缓存的**业务内容** | ❌ 分析 / 图表 / 布局代码路径不得写入 | 汇率公共缓存由既有 S16-D 机制维护，与工作台无关 |
| 分享模板（服务端副本） | ✅ 仅在用户主动分享时写入，且**不含账务数据** | 见[配置与分享方案](S17-工作台个人配置与布局分享-方案草案.md) |

【推荐】落实方式：工作台模块不引入任何交易写 API 的调用；增加一条静态守卫测试（思路同 `scopedStorage.test.ts`：扫描工作台目录对交易 / 账本写接口的引用，出现即失败）。该测试属于 S17-W2 交付物，**本轮不编写**。

### 3.3 工作台是用户个人显示设置【已确认】（所有者指令 §4）

分析工作台与主题色、头像、个人汇率显示偏好同属“某个用户自己的配置”。共享账本的数据属于账本本身，工作台配置属于用户自己：

- A 和 B 使用同一本共享账本；A 选三列网格，B 选两列；
- A 使用大量专业图表，B 只保留三个基本卡片；
- A 修改分析图表类型不影响 B；A 导入别人的模板也不影响其他人。

所有设置**按用户身份隔离**。必须研究账号切换、退出、注销、缓存清理、删除账号以及多端同步时的配置作用域（所有者指令 §4）——研究结果与方案草案见[配置与分享方案 §3](S17-工作台个人配置与布局分享-方案草案.md)，**不得因共用账本而共享个人布局**。

### 3.4 分析准确性的验收判据【已确认】（所有者指令 §5）

任何新的图表、卡片或模板都必须遵守下表。每条给出一个可验证的判据 ID，供后续测试与验收引用。

| ID | 要求（所有者指令 §5） | 验收判据（示例，具体用例在各阶段设计） |
|---|---|---|
| ACC-01 | 用户选择的账本、日期、币种和分类正确生效 | 同一筛选条件下，摘要 / 趋势 / 分类 / 来源列表的逐笔合计一致 |
| ACC-02 | 相同条件下，不同卡片计算结果一致 | 同一 `AnalysisDefinition` 在 N 张卡片中产生同一结果（金额文本、完整性标识逐字节相同） |
| ACC-03 | 原币金额不得跨币种直接相加 | 原币结果只按币种分面；任何跨币种合计必须经 S16-D 折算并标注目标币种 |
| ACC-04 | 汇率综合使用现有历史汇率及逐笔精确舍入合同 | 只调用既有 `convertFx` / `aggregateFxAsync` 路径；规则版本 `minor-half-away-v1` |
| ACC-05 | 大整数金额不得为了绘图直接损失财务精度 | 金额以整数最小单位字符串传递；仅 0–10000 的比例可转 `number` 绘图；见 S16-D §2 |
| ACC-06 | 缺汇率、缺原始账目、无交易、加载失败必须区别处理 | 四种状态各有独立的结果状态码与文案；见[图表与卡片规格 §4.3](../design/S17-图表与卡片规格.md) |
| ACC-07 | 不完整数据不能伪装成准确的总额或占比 | `complete=false` 时不渲染占比，只给小计与缺项入口（沿用 S16-D `shareDenominatorMinor=null`） |
| ACC-08 | 分析结果能够追溯到对应交易 | 每个可点击数值携带“来源筛选”，由来源列表复现同一合计 |
| ACC-09 | 统计时间范围与来源账目一致 | 下钻不得再出现“90 天统计落入结束月份”（审查 F01）；来源列表与图表使用同一 `from/to` |
| ACC-10 | 收入、支出、收支差额明确区分 | 差额始终标注“收支差额”，不称余额 / 资产 / 储蓄；负数用零基线表达 |
| ACC-11 | 负数、零分母、短月份、跨年、跨午夜等边界处理正确 | 边界样本集（前期为零、闰月、31→28 天、跨午夜不刷新页面）全部有断言 |
| ACC-12 | 共享账本权限不得被图表或详情页绕过 | 所有读取走既有账本 read guard；详情页不自行过滤出“看似有权限”的副本 |
| ACC-13 | 离线时必须尊重真实的数据覆盖范围 | 本机未覆盖的时段显示“本机时段不完整”，不显示“全年总额” |
| ACC-14 | 切换账户或账本后，旧异步请求不能污染新视图 | 每个异步边界核对 scope + 请求代次（沿用 S16-D §5、§7 的做法） |
| ACC-15 | 保留 FX 与统计引擎的既有正确性规则，不另写互相矛盾的计算方法 | 新分析只组合既有纯函数；任何新公式（如波动率）要在能力目录登记并给出整数 / 有理数实现说明 |

### 3.5 复用而非重写的既有合同

- 汇率与折算：S16-D §2（财务合同）、§5（缓存与离线隔离）、§7（D4/D5 显示与交互）。UI 约束不新建规则，只引用。
- 比较期：`packages/shared/src/stats.ts` 的 `comparisonRangeFor`（完整月对完整月、本月至今对上月同日、滚动窗口对等长前一窗口）。审查 F02 指出 90 天说明文案与真实比较区间不符——这是**文案 / 模型统一**问题，在 S17-W1 处理，不得借机改变既有计算定义而不记录。
- 分类占比 `share` 为服务端 0–1；综合模式缺项时 `shareDenominatorMinor=null`。

## 4. 架构：六层模块划分【已确认】（所有者指令 §6）

避免“一个巨大组件同时承担财务计算、绘图、布局、交互和持久化”。下表是**职责边界**；具体包 / 目录划分属【待研究】，在 S17-W2 冻结。

| 层 | 名称 | 输入 | 输出 / 职责 | 明确不做 |
|---|---|---|---|---|
| **A** | 分析计算引擎 | 授权范围内账目；账号与账本；时间范围；指标（收入 / 支出 / 差额…）；分类等过滤；分组方式；比较期；原币或综合规则 | **精确分析结果**；统计序列 / 分组结果；数据完整性；统计时间与币种说明；来源追溯所需筛选；错误或不可用状态 | 不绘图、不知道卡片尺寸、不读布局 |
| **B** | 图表适配与渲染 | 分析结果（先过兼容性检查） | 展示为数值卡、环形图、柱状图、折线图、面积图、趋势图、分类排行、日历热力图、分布图、对比图等 | **不重新计算权威财务金额**；不编造不符合数学 / 财务意义的输入 |
| **C** | 卡片系统 | 一种分析与展示配置 | 按卡片**实际宽高**选择显示密度；处理图表布局、标题、单位、说明、交互；提供不同尺寸版本；完整性 / 空态 / 错误 / 加载状态；打开该分析实例的详情页 | 不修改分析定义的语义 |
| **D** | 分析详情页 | 被点击卡片的分析实例配置 | 完整分析内容、更精细图表、历史时期比较、文字说明、进入来源账目与单笔交易、汇率与完整性依据；返回并恢复工作台状态 | 不重新定义筛选语义 |
| **E** | 布局与容器系统 | 卡片实例、容器定义 | 放置卡片、基础网格、位置与尺寸、自由分割布局、滑动抽屉布局、保存与恢复布局 | 不做任何财务计算、不改时间筛选、不混合币种 |
| **F** | 个人配置及布局分享 | 用户工作台设置 | 配置持久化、跨设备适配、预设模板、导出 / 分享 / 导入、配置版本兼容 | 不携带任何账务数据 |

### 4.1 选择分析什么 → 怎么展示 → 展示在哪里【已确认】

用户的操作顺序是 **分析什么 → 怎么展示 → 展示在哪里**，对应 A → B / C → E。**分析结果与图表类型并非任意组合**（所有者指令 §7）：

- 一个单独金额适合数字卡；
- 多个非负分类且分母可靠完整时适合环形图；
- 时间序列适合趋势图；
- 净收支正负值适合带零基线的柱状图；
- 不完整数据可能不适合完整占比图。

不能因为用户选择了某个图表，就编造不符合数学或财务意义的输入。【推荐】为分析结果与图表**分别定义能力声明（capabilities）与兼容性规则**，由 B 层在渲染前检查；规则草案见[图表与卡片规格 §3](../design/S17-图表与卡片规格.md)。

### 4.2 层间约束

1. 依赖方向单向：F → E → C/D → B → A；上层可以引用下层的**类型与结果**，下层不得引用上层。
2. A 层输出对 B / C 层是**不可变值**；任何展示层要做的派生（排序、折叠“其它”、取整到像素）必须声明为“展示派生”，且不得改变其金额文本。
3. 同一次渲染中不同卡片对同一 `AnalysisDefinition` 的结果必须共享计算（查询去重 / 结果复用），并携带**同一数据版本戳**，避免“同一屏两张卡片金额不同”（遗漏发现 G-08，见[问题清单](S17-待所有者确认的问题.md)）。
4. 敏感权限判断（`ledger/access.ts` 等）按 AGENTS §6：**只许新增，不许改动既有判断**；新查询需追加越权验证，不移动或抽取既有 guard。

## 5. 分析功能库【已确认】需求；清单【推荐】

所有者希望未来拥有十几种乃至几十种分析，包含普通、进阶和专业类型（所有者指令 §8）。要点：

- 区分**分析指标、分组方式、比较方式、图表类型、具体卡片实例**——不能把同一组数据画成三种图表就称为三种财务分析；
- 每项分析按数据可行性分四档：**现有数据可准确计算 / 需扩展查询接口 / 需新增业务数据模型 / 暂不推荐**；
- **不要把所有候选都标为第一批必须开发**；
- 不能把支付方式当资金账户；不能在没有转账模型时自动扣除“转账”或编造账户余额。

完整目录、编号（`AN-xxx`）、可行性分级与批次建议见[S17 分析能力目录](../features/S17-分析能力目录.md)。

## 6. 图表卡片、尺寸与详情【已确认】需求

核心约束（细节见[图表与卡片规格](../design/S17-图表与卡片规格.md)）：

- **图表家族 × 分析结果 × 卡片尺寸 / 形态**，而不是为每种组合复制一套绘图代码。用户举的“环形图 1×1 / 1×2 / 2×2、柱状图 1×1 / 1×2 / 2×2”**只是设计方向示例，不是最终尺寸清单**（所有者指令 §9）；
- 卡片根据**父容器提供的实际可用宽度与高度**决定内容与布局，**不能只根据手机型号、屏幕宽度、网格列数或固定 1×1 / 2×2**——因为自由分割布局会创造不规则可用空间（所有者指令 §10）；
- 不同尺寸必须保证**同一分析结果一致**；不能整体缩放 SVG 与文字，不能截断重要金额制造“适配”；不是所有图表都必须支持每一种尺寸；
- 每张卡片点击进入对应**分析实例**的详情页，详情页继承被点击卡片的配置，而不是只按图表类型打开通用结果（所有者指令 §11–§13）。

## 7. 默认工作台与预设模板【已确认】需求

普通用户**无需先配置**：第一次进入分析页即可直接看到设计完善的默认工作台，不应被要求先配置算法、网格或卡片（所有者指令 §14）。【推荐】考虑的模板：日常总览、消费习惯、收支研究、多币种观察、空白自定义。模板可包含具体分析定义、图表类型、卡片实例、卡片尺寸、顺序、布局容器、默认筛选继承规则；用户可继续修改，支持恢复默认并避免误覆盖已有个人配置。结构与草案见[布局规格 §9](../design/S17-工作台布局与格式模板规格.md)。

## 8. 编辑模式与布局【已确认】需求

- 普通模式与编辑模式**严格分离**：日常分析页不轻易触发拖动、缩放和编辑；必须有明确入口（例如“自定义布局 / 编辑工作台”）和清楚的退出方式（所有者指令 §15）；
- 编辑模式视觉：低对比度棋盘格或网格线、可辨认列数、卡片边界、可放置新卡片的空白区、拖动时合法位置预览、与品牌一致的克制绿色高亮；正常模式隐藏辅助格线；风格参考简洁自然的 Apple 风格，而非复杂的网页编辑器（所有者指令 §16）；
- 网格列数由真实可用空间决定（两列、三列、其他技术可行列数），**使用 CSS 视口 / 容器实际可用尺寸并扣除页边距、卡片间距、安全区**，不使用物理像素；不能假设所有手机都能显示三列（所有者指令 §17）；
- 占格记法、基础行高 / 列宽、最小 / 最大尺寸、间距、重排算法均**待定**（所有者指令 §18）；纵向不设固定行数上限，但需按需渲染与性能控制；
- 拖动与吸附、布局容器（自由分割、滑动抽屉）、容器约束与嵌套限制（所有者指令 §19–§24）。

全部细节见[布局规格](../design/S17-工作台布局与格式模板规格.md)。

## 9. 跨设备、配置与分享【已确认】需求；方案【待决策】

- 跨设备：用户自定义的卡片、容器、分割比例不得因设备变化而丢失。**跨设备保持一致，主要是保持相同卡片、分析参数、模板意图及用户配置，不等于在不同宽高比的屏幕上保证每一像素位置完全相同**（所有者指令 §25）。已比较三种方案（A 单一布局自动响应 / B 多种设备尺寸分别保存 / C 共同分析配置 + 设备布局映射），**本轮不最终决定**。
- 分享：布局保存在服务器，识别码只是唯一引用；**布局分享不等于分享账务数据**，是强制安全边界；导入后所有分析都绑定接收用户自己有权访问的账本数据并重新计算（所有者指令 §26–§28）。**本轮只规划，不实现公开分享 API，也不建立分享数据库。**
- 配置持久化：分析定义、卡片实例、图表展示配置、尺寸与位置、容器树、设备尺寸布局映射、用户预设模板、分享模板副本在概念上分离保存；需有版本号与迁移规则，旧配置 / 缺失模块 / 损坏配置**安全降级而不是白屏**（所有者指令 §29）。

## 10. UI 风格与质量标准【已确认】（所有者指令 §33–§34）

保持 Libevra 设计语言：Apple 风格的简洁和克制、品牌绿 `#55997a`、合理留白、清晰层次、柔和自然的动画、连续的形状与布局变化、避免过度装饰、七主题与深浅色兼容、中英文兼容。**模块化功能不应让正常分析页面充满编辑器控件**；正常页面应像成熟的财务产品，进入自定义模式后才显示棋盘格、拖动辅助线、边界和尺寸控制。

质量标准必须覆盖（不得认为“看起来正常”就等于数据正确或无障碍合格）：

| 类别 | 内容 | 细节出处 |
|---|---|---|
| 交互 | 点击和选择图表元素、分类高亮、数据点读数、时间段切换、图表下钻、来源追溯 | 图表与卡片规格 §7 |
| 状态 | 图表动画、加载状态、错误状态、无数据状态、缺数据状态 | 同上 §4.3 |
| 内容鲁棒 | 大金额与长英文、不同容器尺寸 | 同上 §5.5 |
| 可访问性 | 触摸区域、键盘操作、屏幕阅读器、减少动态效果 | 同上 §7.4–§7.6 |
| 性能 | 大量卡片、大量账目 | 同上 §9 |

## 11. 开发顺序原则【已确认】（所有者指令 §30）

**计算正确性优先；卡片和详情页先成熟；布局自定义后开发；全站桌面适配最后开发。模块化接口及跨设备架构必须提前设计，而不是等到拖动编辑器完成时再补救。** 子阶段划分与交付物见[新路线图 §3](S17-S18-新路线图.md)。

## 12. 非目标与暂不推荐

| 项 | 原因 |
|---|---|
| 自动识别转账并排除 / 账户余额 / 资产净值 | 项目现有流水只有 income / expense，支付方式不是资金账户；无 transfer 数据合同。需独立产品立项，可能涉及字段、API、迁移 |
| Sankey / 雷达 / 3D 饼图 / 词云 | 缺少对应数据模型或增加误导与维护成本（审查 §9） |
| 云 AI 点评、自动财务健康分、无依据预测结余 | 隐私与误导风险；01-规划明确“不引入第三方 AI API” |
| 更换图表库（Recharts / ECharts / Canvas） | 当前不需要；若 S17 后期需要多轴 / 大跨度 brush / 复杂分面，另做独立 spike（审查 §10） |
| 在 S18 重写财务计算系统 | S18 只处理跨屏适配，复用 S17 的分析与卡片系统（所有者指令 §31） |
| 本轮实现公开分享 API / 建分享数据库 / 写迁移 | 本轮只允许修改文档（所有者指令 §12、§40） |
