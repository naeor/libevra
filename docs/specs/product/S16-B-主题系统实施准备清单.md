## 2. 实施原则

1. **先语义，后颜色；先默认绿，后七色盘。** 不先做七套色值再补结构。
2. **两个独立维度**：`appearance = light | dark | system` 与 `palette = green | red | orange | yellow | cyan | blue | purple`；不要用 `theme = "dark-green"` 这类组合枚举。
3. **组件不写主题分支。** 组件只消费 token；`data-mode`/`data-palette` 只出现在 `<html>`；禁止每个页面写 `dark:`。
4. **默认零视觉变化。** 接入 token v2 后，默认浅色绿外观应与 1.16.03 一致；差异必须有所有者确认。
5. **状态色不跟品牌色旋转。** 成功/警告/错误/危险保持语义；品牌色只影响强调角色。
6. **用户数据不主题化。** 标签保留原色；二维码保留黑白；用户已保存的金额/币种永不被主题系统改写。
7. **深色不是反相。** 需要独立的对比度、表面层级、图表斜坡、阴影与海浪色阶。
8. **无障碍是 P0，不是收尾项。** 焦点环、输入框边界、主按钮前景、状态文字、热力前景、图表形状/直接标注必须在实现验收内。
9. **主题偏好先设备级。** 账号级同步需要 S16-E 与数据库/API 决策，不在 S16-B 默默引入。
10. **不改财务口径、不建迁移。** 主题系统不应触碰账目金额、币种、汇率和历史金额契约。

## 6. 推荐执行顺序

```
决定记录（P0-01）
  → token v2 骨架 + 守卫扩展（P0-02/03）
  → 前景/焦点/边框/状态色基线（P0-04）
  → 主题运行时 + prepaint + 持久化（P0-05）
  → 默认绿深色（P0-06）
  → 图表/海浪/标签/热力（P0-07/08/09）
  → 默认绿 P0 验收（P0-10）
  → 系统跟随/动画/PWA 主题色/第二色盘（P1）
  → 其余色盘与延期项（P2）
```

依赖关系：
- S16-B-P0-01 必须由所有者与 Codex 共同确认，DeepSeek 不替产品决定色盘/默认值。
- S16-B-P0-02 是 P0-04~09 的硬前置；不要在组件里先写 `dark:` 再倒推 token。
- S16-B-P0-07/08/09 可以并行于默认绿深色，但必须共用同一 token 约定。
- S16-E 的外观/语言设置实现应等 S16-B 的偏好模型确定；S16-E 不反向决定颜色值。
- S16-F 负责统一验收；S16-B 的 P0-10 是 S16-F 的前置证据，不是最终验收替代。

## 7. 需要先决定的问题

1. 默认外观：浅色 / 跟随系统。
2. 偏好归属：设备级 / 账号级；游客、登录、退出后的规则。
3. 首版提供几套色盘；`#55997a` 是否原值保留；品牌填充上白字还是深字。
4. 图表策略：A（固定可辨识分类色 + 主题 chrome）/ C（热力单指标）是否首版；是否随色盘轻微协调。
5. 标签：任意用户色 + 自动前景，还是统一浅底/描边/色点。
6. `focus-ring`、`line-strong` 是否按 WCAG 非文本 3:1 强制。
7. 深色是否首版必发；切换动画是否首版需要。
8. PWA `theme-color`/manifest 归 S16-B 还是 S17-E。

上述问题不决定，不应开始大面积写死颜色或组件 `dark:` 分支。

## 8. 明确不做

- 不在本轮或 S16-B 准备阶段改 UI 颜色、CSS token 值、组件布局、动画、图表业务逻辑。
- 不用七套色盘批量替换现有 19 token。
- 不在组件里写 `dark:` 分支或按 `theme` 分支。
- 不把用户标签、QR、用户数据主题化。
- 不修改数据库、历史金额、币种/汇率契约或生产环境。
- 不新增 `primary`/`secondary`/`accent` 等与 `brand`/`ink` 竞争的名字。
- 不把“有设置入口”当成“主题已实现”。
- 不把 S16-B 的 P0 验收写成“所有色盘完成”；默认绿可用才是 P0。
