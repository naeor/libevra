## 2. 个人配置的概念分层

所有者要求这些东西**概念上分开保存**，以便单独演进、迁移与分享（所有者指令 §29）：

| 层 | 内容 | 含账务数据？ | 可分享？ | 备注 |
|---|---|---|---|---|
| ① 分析定义 | 指标 / 维度 / 比较 / 过滤（能力目录 `AnalysisDefinition` 草案） | ❌ | ✔ | 过滤中的“分类 / 支付方式 / 标签”只存**引用**，见 §6.5 |
| ② 卡片实例 | `instanceId`、`analysisRef`、`chartFamily`、`rangePolicy`、`title` | ❌ | ✔（`instanceId` 导入时重生成；自定义 `title` 见 §6.2） | |
| ③ 图表展示配置 | 家族内的可选项（是否显示图例、颜色方案偏好等） | ❌ | ✔ | 不得包含任何计算结果 |
| ④ 尺寸与位置 | `colSpan`、`rowSpan`、锚点编号 + `baseCols`（[布局规格 §12](../design/S17-工作台布局与格式模板规格.md)）、所在容器 / 槽位、展示意图；**含 Spacer**（只存在于布局文档） | ❌ | ✔ | 属**布局文档**（§5.5） |
| ⑤ 容器树 | 容器类型、分割比例（整数）、抽屉页序 | ❌ | ✔ | 受节点数 / 深度上限约束（§7） |
| ⑥ 设备尺寸布局映射 | 统一模式的主布局；独立模式下按宽度分别保存的“布局档案”（profile） | ❌ | ✔ | 【已确认 Q-08】，见 §5.5 |
| ⑦ 用户预设模板（“我的方案”） | 一组 ①–⑥ 的命名集合 | ❌ | ✔ | 数量上限候选 10 |
| ⑧ 分享模板副本 | 服务器上的不可变快照（见 §6.3） | ❌ | — | 属于分享功能的数据，不属于用户个人设置 |
| ⑨ 全局筛选与偏好 | 时间范围预设、默认列数、当前启用的方案 | ❌ | ✘（默认不随分享，导入时由用户选择是否采用） | 综合 / 原币开关属**设备级**（S16-E），不放这里 |

**存放什么、不存放什么**：配置只存**意图**与**结构**。任何计算结果（金额、占比、序列）、任何账本内容（交易、分类名、成员）都不存。这既是隐私边界，也避免了配置里出现与权威数据不一致的“缓存数字”。

## 3. 作用域与用户身份

### 3.1 个人隔离【已确认】

- A 与 B 共用同一本共享账本，各自的工作台互不影响；A 导入别人的模板不影响他人；
- 配置的键**必须包含用户身份**（`userId`），与主题 / 重复检测设置的隔离方式一致；
- 共享账本的数据属于账本；工作台属于用户，**不得因共用账本而共享个人布局**。

### 3.2 作用域粒度【已确认 2026-10-27：A，Q-02】

| 方案 | 含义 | 优点 | 缺点 |
|---|---|---|---|
| A 每用户一套【已选 2026-10-27】 | 所有账本共用一个工作台 | 最简单，学习成本低 | 卡片中涉及分类 / 标签 / 支付方式的过滤会在不同账本里失效；个人账本与家庭账本的分析诉求可能不同 |
| B 每用户每账本一套 | 每本账本有自己的工作台 | 与账本数据最贴合，无悬空引用 | 新账本需重新配置；跨账本不一致；配置数量随账本增长 |
| C 混合【推荐倾向】 | 布局方案（“我的方案”）是用户级的命名资产；“当前使用哪个方案”按 `(用户, 账本)` 记录，缺省回退用户默认方案；与账本绑定的引用（分类 / 支付方式 / 标签）放在 `(用户, 账本)` 的**绑定表**，失效时提示重选 | 兼顾复用与准确；导入分享布局时绑定表天然承接“重选” | 概念最多，需要清晰的 UI 与说明 |

**【已确认 2026-10-27，Q-02】选 A**：每个用户账号拥有**一套共同的分析工作台内容配置**。同一用户进入不同账本时，默认沿用相同的卡片、图表和工作台结构；切换账本只会让分析重新使用**当前授权账本**的数据计算，不会自动更换另一套个人工作台。这**不代表不同设备上的几何布局必须完全相同**——跨设备布局规则见 §5.5。现阶段不做“每用户每账本一套”，数据模型保留未来扩展空间。

后果与要求：

1. 带账本专属引用（分类 / 支付方式 / 标签）的过滤，在另一本账里可能找不到对应项：对应卡片显示“需要重新选择”（§4.3 引用失效），**不影响其余卡片**。因此账本专属引用从第一天起通过“引用槽”间接保存（按名称 / 键查找，不把真实 ID 内嵌在卡片里，图表与卡片规格 §4.1 已要求），为将来升级到 `(用户, 账本)` 绑定表留位置（OQ-CF-09）；
2. 账本切换时取消在途请求并清空卡片结果，先显示 `loading`，不得短暂显示上一账本的数字（ACC-14，图表与卡片规格 §4.5）；
3. 共享账本里 A、B 仍各自拥有自己的工作台（§3.1）。

> （以下为历史推荐，已被所有者的决定取代）
> 倾向 C 仅为【推荐】。若所有者希望首版从简，A 是安全的起点，**只要数据结构保留“绑定表”这一层的位置**（引用不内嵌在卡片里而是按名字查找），之后升级为 C 不需要改写已有配置。

下表规定每个事件下**个人工作台配置**应如何处理。涉及删除语义的行，实施前需所有者确认（S16-E 对同类问题的做法是“先列方案，由所有者决定”）。

| 事件 | 规则（【推荐】） | 备注 |
|---|---|---|
| 登录 | 读取该 `userId` 的配置；本地有未同步的离线编辑则按 §4.5 的规则合并 | |
| 切换账号 | 视图立即切到新账号的配置；**旧账号配置绝不渲染到新账号界面**；在途请求按 scope 丢弃（ACC-14） | |
| 退出登录（保留离线数据） | 本地配置缓存保留，仍按 `userId` 隔离 | 与离线账目一致 |
| 退出登录（不保留离线数据） | 清除本机该账号的工作台缓存与草稿 | 服务端配置不受影响 |
| 清除本机全部数据 | 工作台本地键纳入 `deviceStorageKeys` 的统一清理谓词 | 必须加测试，避免重蹈 `libevra.language` 遗漏（S16-E §2.1） |
| 注销账号 / 删除账号 | 服务端工作台配置与其创建的**分享项**一并删除；已被他人导入的副本保留（副本属于接收者）；本机缓存按账号清理 | 分享者注销后清理其分享项【已确认 2026-10-27，Q-14】 |
| 从共享账本被移除 / 账本被删 | 配置本身保留（它是用户的，Q-02 选 A：一账号一套）；引用该账本专属分类 / 标签 / 支付方式的槽位进入“需重新选择”；其余卡片照常用当前授权账本计算 | 不得因失去账本权限而保留任何缓存数字 |
| 角色降为只读 | 配置不变；写入口本来就不存在于工作台 | 分析读取仍走账本 read guard |
| 游客 | 仅本机；游客数据无服务端账号，布局只存本机，且按“游客”键隔离；转为正式账号时是否迁移配置【待决策 OQ-CF-04（原 G-01）】 | |
| 多端同步 | 见 §4.5 | |
| 清理缓存 / PWA 更新 | 配置不得只存在于可被清理的缓存（Cache Storage）；本地使用 localStorage / IndexedDB 视为**缓存**，权威副本在服务端（Q-03 已选 c，服务端部分属 W6；在此之前本地保存是唯一副本，需提示用户） | |

### 3.4 存储位置【已确认 2026-10-27：c 本地优先 + 服务端同步，Q-03】

| 方案 | 说明 | 满足需求 #13（跨设备） | 代价 |
|---|---|---|---|
| a 仅设备本地 | 与主题、语言一致（现状为设备级，S16-E D-15 尚未决定是否账号化） | ❌ | 零后端；换设备丢布局 |
| b 账号服务端 | 新增账号级配置存储（新表 + 迁移 + API），属 S17 后期 | ✔ | 需迁移与后端；离线需本地缓存与同步队列 |
| c 本地优先 + 服务端同步【已确认】 | 编辑落本地即时生效，联网后同步；服务端为权威 | ✔ | 最复杂；冲突规则见 §4.4 |

**注意**：布局分享本身必须有服务端存储（§6.3），因此 b / c 的服务端基础设施与分享可共用一套校验与限额代码；但“个人配置同步”与“公开分享”是两个不同的数据域（访问控制不同），**不得合并成同一张表的同一权限模型**。

**Q-03 选 c 的要求【已确认】**：

1. 登录后恢复账号级配置；
2. 本机缓存允许离线使用；离线修改先保存在本地，恢复联网后同步到服务端；
3. 同一账号在另一设备登录后能够恢复配置；
4. 同步**不得覆盖其他用户设置**：键包含 `userId`；与主题、语言、综合折算开关等设备级设置分开存放，互不影响；
5. 必须处理离线编辑、并发修改和版本冲突（§4.5）；
6. 本地清除、退出账号、账号注销时执行正确的数据清理（§3.3）；
7. 落地节奏：W5 本地保存，W6 增加账号级存储与迁移。2026-10-29 所有者授权本地开发与隔离验证；正式部署及生产迁移仍须另行批准，备份与恢复演练不能省略。

主题和语言是否进一步账号化（S16-E D-15）是**相关但独立**的产品事项，不阻塞本方案（§9）。

## 4. 版本、迁移与安全降级

### 4.1 版本字段

每份配置（与每份分享快照）带整数 `schemaVersion`。迁移是一串**纯函数** `vN → vN+1`，可单元测试；每次格式变更必须新增迁移与对应测试夹具（旧版本样例永久保留）。

### 4.2 读取规则

| 情形 | 行为 |
|---|---|
| 版本等于当前 | 校验（严格 schema）后使用 |
| 版本较旧 | 按链迁移；迁移失败的节点降级（见 4.3），其余节点继续 |
| **版本较新**（来自更新的客户端 / 其他设备） | 以只读方式尽力渲染已知部分，**不回写**、不删除未知字段；提示“请更新应用以编辑此布局”。PWA 缓存导致的版本偏差同理。**【已确认 2026-10-27，Q-20】**：尽力只读显示；无法识别的对象按 §4.3 安全降级；**不得由旧客户端直接覆盖新版配置**；提示更新；保留用户配置与恢复能力。是否需要强制客户端更新机制是单独的技术决策（OQ-CF-08） |
| 校验失败（缺字段、类型错、越界） | 回退到默认工作台，**保留原始损坏副本为“上一个布局”以便恢复**；绝不白屏 |
| 超限（节点数 / 体积 / 深度） | 视同损坏 |

### 4.3 节点级降级

- 未知分析 ID / 未上线批次的分析：显示占位卡片“此卡片需要更新版本 / 当前不可用”，**保留其位置与配置**，不静默删除；
- 家族与结果形状不兼容：降级到允许家族（图表与卡片规格 §3.2）；
- 引用失效（分类被删等）：显示“需要重新选择”的卡片状态，不影响其余卡片；
- 每张卡片独立错误边界：一张卡片渲染异常不得拖垮整个工作台。

### 4.4 多端并发（首版建议）

- 乐观并发：服务端保存 `version`（整数）；提交携带基版本，不一致则拒绝并返回最新版；
- 冲突处理、离线编辑与合并粒度：见 §4.5（Q-03 已确认本地优先 + 服务端同步后，离线编辑是常态，不再只做“整体替换”）。

### 4.5 同步、离线编辑与冲突【2026-10-29 所有者任务确认】

**保存单元**：继续保留内容文档与布局文档的分离形状，包括主布局、独立档案、容器和 Spacer。服务端把正式保存的文档对与个人预设集合放在一个账号级配置中，以**一个同步版本号**原子提交，避免分别接受内容与几何后出现悬空引用。设备主题、语言和未提交编辑草稿不在此单元内。

**本机与服务端**：服务端是权威副本，本机是缓存加**离线写入队列**。离线编辑先落本机并立即生效；联网后按“基版本”提交。键包含 `userId`，退出登录 / 清除本机数据 / 注销账号按 §3.3 清理。

**冲突检测**：提交携带服务端基版本；不同则返回 409 与最新版，不静默覆盖。首次本机与云端都存在不同配置时也进入冲突；本机空则下载，云端空则以有效本机配置建立首份副本。预设删除受同一 CAS 版本保护，旧列表不得自动复活已删除预设。

**解决规则**：用户可以选择采用云端或保留并提交本机；选择前可以导出本机工作台和预设。采用云端前保留本机原文恢复副本，提交本机前保留云端副本；服务端另留一个先前配置。解决前重新读取服务端版本，期间再变化则继续冲突，不强制覆盖。

本轮不实现 CRDT 或自动逐对象合并；旧“冲突服务器优先”的意向不再用于 W6。必须满足不丢对象 ID、容器结构和 Spacer，冲突可见、可恢复（布局规格 TC-19）。

**离线与失败**：正式保存先落本机，恢复联网、页面可见或手动重试时同步；仅正式保存和预设管理触发待同步，不逐次拖动上传。请求中的新本机修改保留到下一次提交，编辑草稿期间延后安装云端布局。损坏配置和较新 schema 不得上行覆盖云端。账号切换使旧异步响应失效。安装本机文档对时写恢复日志，异常或中断后回滚到原文，写备份失败就不替换。未点“完成”的草稿仍沿用既有编辑会话，不承诺进程被杀后恢复。

## 5. 跨设备适配

### 5.1 需求边界【已确认】

> 跨设备保持一致，主要是保持**相同卡片、分析参数、模板意图及用户配置**，不等于在不同宽高比的屏幕上保证每一像素位置完全相同。

### 5.2 三个方案比较（历史比较；2026-10-27 已选定“扩展 C”，见 §5.5）

| | A 单一布局，自动响应 | B 按设备尺寸分别保存 | C 共同分析配置 + 设备布局映射 |
|---|---|---|---|
| 做法 | 只保存一份“有序卡片列表 + 相对尺寸意图”，各设备按算法推导位置 | 为每个设备尺寸类（例如手机 / 平板 / 桌面，或按列数）各存一份完整布局 | 卡片集合与参数在用户级共享；几何按“布局档案”（以**列数**为键）保存；某档案不存在时由共享卡片集合**自动推导**，用户编辑后才生成该档案 |
| 跨设备一致性 | 卡片集合完全一致；位置由算法决定，可预测 | 各设备可以完全不同（新增卡片只出现在编辑时所在的尺寸类） | 卡片集合一致；位置在未定制的档案里由算法推导，在已定制的档案里按用户意图 |
| 用户控制力 | 低（位置受算法限制） | 高 | 高（按档案） |
| 实现复杂度 | 低 | 中（多份布局的存储与同步） | 高（共享集合 + 档案 + 推导 + 缺失档案的生成） |
| 同步 / 冲突 | 简单（单份） | 多份各自冲突；容易出现“手机上有、平板上没有” | 集合冲突与档案冲突分开，规则较多 |
| 与分享契合 | 好（单份即可） | 差（分享哪一份？） | 好（分享集合 + 可选带一个档案） |
| 与 S18-B 契合 | 一般（大屏需要更多自定义） | 好但维护重 | 好（新增档案即可） |
| 存储量 | 小 | 大 | 中 |

**历史倾向【推荐】**（已被 §5.5 的确认方案取代）：数据结构按 **C** 设计（卡片与几何**从第一天就解耦**，几何按列数键存放），首版只启用一个档案。2026-10-27 所有者确认的是**扩展后的 C**，见 §5.5。

### 5.3 档案的依据：真实可用宽度，而非设备名

档案依据实际可用宽度推出的列数（布局规格 §5.1），不是设备型号；同一台设备旋转或调整窗口会改变列数，直接对应不同档案。键的粒度（精确列数如 `cols-2`、`cols-3`，还是“窄 / 中 / 宽”宽度档）【待研究 OQ-LM-08】。

### 5.4 推导算法

算法由[布局规格 §13–§15](../design/S17-工作台布局与格式模板规格.md)**单一定义**（行优先编号、优先级、逐个放置、尺寸降级、无累计漂移），本文不重复。本文只保留对配置的要求：

- 纯函数：同输入同输出，不读视口高度、不读财务数据；
- 不丢卡片、不丢容器内部配置：放不下时降级到合法形态、容器 `1×1` 收缩、卡片兼容入口，而不是悄悄丢弃；
- 自动推导的结果不写回；只有用户在编辑模式明确保存，才更新对应的布局文档。

### 5.5 已确认方案：共同内容配置 + 自动布局迁移 + 可选独立布局档案【2026-10-27，Q-08】

- **共同内容**：卡片身份、分析定义、图表配置、容器树，账号共有（§2 的 ①②③⑤）；
- **默认：统一布局**：同一账号一份权威主布局（`baseCols` + 行优先锚点）；不同设备 / 窗口宽度用布局规格 §14 的统一迁移算法从主布局推导目标布局；**每次都从主布局重算，不覆盖主布局，不累计漂移**；
- **可选：独立布局**：设置里明确开关。开启后可为不同宽度档案分别保存位置、尺寸与排列；卡片身份与分析定义仍共用；新增 / 删除卡片同步到各档案（新卡片在尚无条目的布局里按“未定位”补位）；仅修改某个档案不得破坏其他档案；
- **内容与几何分离存放**（布局文档 vs 内容文档），同步各自进行（§4.5）；
- 仍待研究：档案粒度与列数开放门槛（OQ-LM-08）、统一模式下跨列数编辑保存后的主布局落点（OQ-LM-07）、容器分割比例是否按档案独立。

## 6. 导出、分享与导入

### 6.1 目标与形态

用户可以把自己的布局方案导出 / 分享给别人，别人导入后在**自己的数据**上得到一份类似的工作台。所有者采纳的形态：**布局保存在服务器，用户拿到一个识别码，识别码只是唯一引用**（不是把布局编码进字符串里）。本轮只规划。

典型流程（【推荐】）：

```text
作者：选择“我的方案” → 预览将要分享的内容（逐项可见）→ 确认 → 服务器保存不可变快照 → 得到识别码
接收者：输入识别码 → 看到预览（卡片类型与排布示意，用示例数据绘制，不含任何真实账务）
        → 映射需要绑定的引用（分类 / 支付方式等）→ 确认 → 保存为“我的方案”之一（不自动覆盖当前布局）
```

### 6.2 强制安全边界：白名单与黑名单

**布局分享 ≠ 账务数据分享。** 以下是强制规则：

| 允许进入分享快照（白名单） | 说明 |
|---|---|
| `schemaVersion` | |
| 分析引用：目录 ID + 参数（指标 / 维度 / 比较的枚举值，区间的**预设或相对写法**） | 例如“近 30 天”，不含绝对日期，除非是用户明确固定的区间且分享前确认 |
| 图表家族与展示选项 | |
| 容器树与几何（整数占格、整数千分比） | |
| 模板名称 / 描述 | 受内容审核与长度限制（§6.4） |
| 语言提示（可选） | |

| 永不进入分享快照（黑名单） | 原因 |
|---|---|
| 任何金额、占比、序列、汇总（含缓存的计算结果） | 财务数据 |
| 交易 ID、`seq`、备注 | 账务内容 |
| 账本 ID / 名称、成员 ID / 昵称 / 邮箱 | 身份与关系 |
| **自建**分类名、**自建**支付方式名、标签名 | 可能含私人信息（例如“给妈妈的钱”）；系统预置项只导出**预置键**（当前预置只有名称、没有独立键，见 §6.5 与 OQ-CF-05（原 G-19）），自建项导出为“待绑定占位” |
| 访问令牌、会话信息、设备标识 | 凭据 |
| 用户自定义卡片标题 | 自由文本可能含私人信息：**默认不导出**【已确认 2026-10-27，Q-14】；作者能否主动勾选导出另行研究（OQ-CF-06） |
| 缩略图 / 截图 | 若用真实数据渲染就泄露财务数据；预览图只能用合成示例数据生成 |
| 设备级偏好（综合 / 原币开关、主题、语言） | 属接收者自己的设置 |
| 作者身份 | **默认匿名**【已确认 2026-10-27，Q-14】；是否提供“作者可选展示”【待研究 OQ-CF-06】 |

**实现要求（必须）**：

1. 分享快照由**白名单序列化器构造**（只拷贝列出的字段），**禁止“复制整份配置再删字段”**；
2. 服务端对收到的快照用严格 schema 再校验一遍（`strict`，拒绝未知字段）；
3. 自动化“金丝雀测试”：构造一份所有可写文本字段都塞入唯一标记字符串的工作台，导出后断言标记字符串一个都不出现在快照中（除作者已勾选的字段）；
4. 导入侧同样严格校验（§7），不信任快照来自可信客户端。

### 6.3 服务端存储草图（仅规划，不实现）

```text
shared_layouts   （概念草图，非迁移）
  id              内部主键
  code            识别码（见 §6.4），唯一
  ownerUserId     创建者内部 ID（不对外返回）
  schemaVersion   整数
  payload         已校验的快照 JSON（受大小上限约束）
  createdAt
  revokedAt       撤销时间（可空）
  expiresAt       过期时间（可空）
  ——不可变：修改 = 创建新快照与新识别码
```

接口草图（不实现）：`POST` 创建、`GET by code` 读取（限速）、`DELETE` 撤销。**不可变快照**的理由：避免“作者事后改成恶意内容而已导入者未察觉”，也避免接收者看到的和作者分享时不同。

### 6.4 识别码与分享系统要考虑的事项

| 议题 | 考虑 | 倾向 / 状态 |
|---|---|---|
| 熵与可读性 | 易读短码（如 Crockford base32 去歧义字符，8–10 位）便于口头传递，但易被枚举；长随机令牌（≥128 bit）抗枚举但不便输入 | **【已确认 2026-10-27，Q-14】选短随机分享码**：易读的随机识别码，通过服务器查找对应的布局快照；码本身只是引用，**不包含布局数据，更不含任何财务信息**，也不含可推断作者或账本的内容。具体位数、字符集、校验位、限速阈值【待研究】 |
| 防枚举与唯一性 | 服务端限速（按用户 / IP）、统一的“未找到或已失效”响应、不暴露存在性差异；创建时检查唯一性（冲突重试） | **【已确认 2026-10-27，Q-14】** |
| 有效期与撤销 | 作者可随时撤销；撤销后已导入者的副本不受影响（副本属于接收者）；可选过期时间 | 撤销、以及“导入得到独立副本、此后修改不影响原作者”**【已确认 2026-10-27，Q-14】**；是否提供过期时间【待决策 OQ-CF-06】 |
| 作者匿名 | 默认匿名；展示作者需作者主动同意 | **【已确认 2026-10-27，Q-14】默认匿名** |
| 内容审核 | 模板名称 / 描述是用户生成文本：长度、字符集、违规词过滤、举报与下架流程 | 【待决策 OQ-CF-07（原 G-03）】 |
| 配额与滥用 | 每用户创建数量上限、速率限制、总大小上限 | 【推荐】 |
| 版本兼容 | 快照带 `schemaVersion`；较新快照在旧客户端提示更新 | 【推荐】 |
| 重复导入 / 统计 | 是否统计导入次数；统计即产生行为数据，需纳入隐私说明 | 【待决策 OQ-CF-06】默认不统计 |
| 离线 | 分享 / 导入需要联网；离线时入口置灰并说明 | 【推荐】（G-05） |
| 账号注销 | 删除其创建的分享项；已导入副本保留 | **【已确认 2026-10-27，Q-14】** 分享者注销账号后清理相关分享项 |
| 隐私政策与数据处理清单 | 分享项是**新的服务端用户生成数据**：必须补入 [S17-A-01 数据处理事实清单](S17-A-安全与隐私能力事实清单-20261025.md)、隐私政策、账号数据导出与删除流程 | 阻塞公开分享上线（见路线图 §5.4、§6） |
| 法律 | 用户生成内容、下架义务、与 S19（原 S17，正式公开发布准备）的合规项关系 | 与 S19-A / S19-B（历史写作 S17-A / S17-B）合并评估 |
| 缓存与分发 | 是否经 CDN；若是，撤销生效延迟 | 【待研究】 |

### 6.5 导入：校验、映射与重算

导入流程：**校验 → 解析引用 → 试运行（dry-run）→ 预览 → 用户确认 → 保存**。保存前不修改当前布局。

| 步骤 | 规则 |
|---|---|
| 校验 | §7 的全部限制；失败则整体拒绝并说明，不部分导入 |
| ID 映射 | 快照内的所有 `instanceId` / 容器 ID **导入时重新生成**，建立“旧 → 新”映射表仅用于重写快照内部引用；**快照中的 ID 不用于任何数据库查询** |
| 分析引用 | 对照接收者客户端的分析目录；未知（更高版本）的分析保留为占位卡片并提示 |
| 系统预置分类 | 按预置键映射到接收者账本中的同键分类。**事实核对**：`packages/shared/src/presets.ts` 的预置分类只有 `name`（中文）与 `description`，数据库只有 `isSystem` 布尔，**没有独立稳定键**，且显示名随语言翻译。因此需要先定义“预置键”（例如以预置原名为键，或新增 key 字段——后者属数据模型变更）；在此之前所有分类引用一律按“待绑定占位”处理【待决策 OQ-CF-05（原 G-19）】 |
| 账本 / 分类 / 支付方式 / 标签（引用缺失） | 导出时已是“待绑定占位”；导入时（或工作台切换账本后）显示“请为此卡片选择分类 / 支付方式 / 账本”，由用户**重新选择**；允许“按名称建议”但必须用户确认，**不按名称猜测并自动绑定**（避免绑错）。其余卡片不受影响。**【已确认 2026-10-27，Q-15】** |
| 范围 | 导入的卡片绑定到接收者**当前有权访问**的账本；无权访问的数据永远不会被读取 |
| 重算 | 导入的配置不含数据，所有卡片用接收者自己的数据重新计算（ACC-01…15 照常适用） |
| 与当前布局关系 | 作为新方案保存；套用时走“替换当前布局 + 保留上一个布局”（布局规格 §9.3） |

## 7. 导入校验与“渲染炸弹”防护

导入内容（及来自服务器的任何配置）视为**不可信输入**。下表限制均为**候选值**：首版容量先用候选值，随后按性能、安全与存储成本测试调整，**不得未经测试固化为永久规格**（Q-15，2026-10-27）：

| 限制 | 候选 | 说明 |
|---|---|---|
| 总字节数 | ≤ 64 KB（候选） | 超限直接拒绝 |
| 卡片总数 | ≤ 40 | 与布局规格 §8.4 一致 |
| 容器总数 / 深度 | ≤ 12 / 深度 ≤ 2 | 同上 |
| 字符串长度 | 标题 ≤ 40 字符、描述 ≤ 200 字符（候选） | |
| 数值范围 | `colSpan ≤ 当前最大列数`、`rowSpan ≤ 8`、比例为 0–1000 整数 | 越界拒绝，不夹紧后接受 |
| 枚举 | 分析 ID / 图表家族 / 容器类型 / 区间预设必须在已知集合 | 未知 → 占位或拒绝，按 §4.3 |
| 结构 | 必须是树，不允许环 / 重复 ID | |
| 危险键 | 拒绝 `__proto__`、`constructor`、`prototype` 等；使用无原型对象或 `Map` 解析 | 防原型污染 |
| 文本渲染 | 所有字符串仅作文本渲染；不解释为 HTML / Markdown / URL；配置里**不得含可点击链接或远程图片** | |
| 查询放大 | 导入方案同一时刻需要的**不同**分析查询数有上限（同分析去重后计）；超限时分批挂载 | 防“每张卡片一个不同大查询”拖垮服务器 |
| 校验耗时 | 设上限，超时视为失败 | |

不执行任何配置中的代码；配置只能选择“已有的分析 / 家族 / 容器”，不能定义新的计算。

## 9. 与现有设置体系的关系

- 现状（S16-E 矩阵）：账号级设置在服务端（默认币种、上次账本…），设备级设置在 `localStorage`（语言、主题、重复检测…）。工作台配置**既不是**其中任何一类的简单延伸：它是账号级需求（跨设备）但数据量与结构远大于已有账号设置；
- 综合折算开关 `libevra.fx-mode:<userId>` 是设备级，**不进入工作台配置、不随分享**；
- 本地缓存键必须登记到 `apps/web/src/lib/deviceStorageKeys.ts` 的统一谓词，并加清理测试；
- “语言 / 主题是否账号化”（S16-E D-15）是**相关但独立**的产品事项（2026-10-27，所有者），不阻塞工作台配置方案；若日后账号化，应与工作台配置共用同一账号级偏好存储，避免两套同步机制。

## 11. W6 实现、文件格式与发布边界（2026-10-29）

### 11.1 账号配置与数据流

- 表 `workbench_configurations`：`user_id` 主键 / 用户外键，`schema_version`、同步 `version`、`configuration` JSONB、`previous_configuration`（上一份）与 `updated_at`。工作台是账号级，切账本只重算；不复制官方系统预设，不存金额、结果、交易列表、登录凭据或账本成员权限。
- `GET /api/v1/workbench` 返回当前账号的记录或 `null`；`POST /api/v1/workbench` 接收 `baseVersion` 与 `configuration`，使用既有认证 / 协议门禁、账号锁及 CAS。前端附带期望账号作用域，账号切换后拒绝错配请求；不提供读取其他用户的参数。不复用或改写既有账本授权判断。
- 共享契约：[configuration.ts](../../../packages/shared/src/workbench/configuration.ts)；接口：[workbench.ts](../../../apps/api/src/routes/workbench.ts)；本地与同步：[sync.ts](../../../apps/web/src/statsWorkbench/sync.ts)。配置 schema 为 1，内部布局 schema 沿用 D 的 1。
- 本机原工作台 / 预设键保持不变；新增 `libevra.stats-workbench-sync:v1:user:<id>` 保存基版本与基配置，附属 `:journal` / `:recovery` / `:cloud-recovery` 用于安装回滚与冲突恢复。全部属于统一设备清理范围；账号清理按完整账号边界删除，不能误删相似 ID 或游客配置。普通登出沿用既有缓存策略，保留的内容仍按账号隔离。
- 登录、重新联网、重新可见、每分钟可见轮询与手动按钮触发读取；正式保存或预设操作防抖触发同步。断网不阻塞本地保存，异常只显示失败；不清空有效配置。服务端已接受但响应丢失时，下一次读取通过内容相等确认成功，不重复写入。
- 注销和“删除全部账号数据”清理服务端个人配置；硬删除用户时外键级联。账号数据导出包含配置与上一份，包含没有可访问账本的账号。配置接口不读取任何交易，来源账目仍走现有账本权限路径。

### 11.2 本地 JSON 文件交换

- 格式标识 `libevra-workspace`、`formatVersion: 1`、`createdAt`、`kind: workspace | preset | presets` 与 `entries`。每项是名称 / 说明、完整内容文档 / 布局文档、可选筛选参数。导出分别支持已正式保存工作台、单个个人预设、最多 10 项的个人预设集合；不导出未提交编辑草稿。
- 文件上限 2 MiB，预设沿用 10 项上限，单工作台沿用 D 的 40 对象与容器限制；递归深度、总节点数、原型键、未知字段、交叉引用、重复 ID、几何、参数白名单、组合槽位、模板与图表兼容均校验。布局旧版本复用既有迁移链；没有迁移路径、较新文件格式或较新配置只报告不兼容，不降级覆盖。
- 文件选择后逐项预览，有效项可独立添加或应用；一个普通损坏项不阻止其余有效项。恶意全局结构与过量输入整份拒绝。名称冲突追加编号，不覆盖同名预设。导入重新生成主布局、独立档案、上一个布局、容器与卡片引用涉及的对象 ID。
- 导出 / 导入不携带账号或账本身份；分类、支付方式、标签的内部引用移除并提示在目标账本重选，日期 / 币种 / 原币或综合模式语义保留。卡片相对窗口按语义保存，不固化为导出当天日期。
- “应用到当前工作台”先确认，再替换编辑会话，可撤销；仍需“完成”才正式保存与同步。个人预设新增立即本机保存并排队同步。文件只在浏览器本地读写，不上传原文件、不建立公开分享码、模板市场或用户间分享服务。

### 11.3 迁移与恢复
