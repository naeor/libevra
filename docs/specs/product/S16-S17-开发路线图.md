## 1. 文档定位与维护规则

### 1.1 三份文档的分工

| 文档 | 回答的问题 | 谁维护 | 更新时机 |
|---|---|---|---|
| [`STATUS.md`](../../STATUS.md) | **现在是什么状态**：版本、迁移、风险 | 发版/阶段推进的人 | 发版、阶段开工/完成、风险新增或解除 |
| [`01-规划.md`](../../01-规划.md) | 阶段目标、边界、历史迁移、验收原则 | 所有者 + 规划维护者 | 阶段目标或范围变化 |
| 本文件 | S16/S17 的完整任务、依赖、顺序、验收、待决策 | 规划维护者 + 各任务负责人 | 任务状态变化、决策落地、范围调整 |

**不允许**在本文件写“当前生产版本/当前阶段”，也不允许在 `STATUS.md` 写计划。发现三份文档互相矛盾时：先核对代码与 `STATUS.md`，再改本文件；涉及阶段范围的改动先请所有者确认。

### 1.2 任务编号规则

- 编号格式 `S16-X-NN` / `S17-X-NN`，**发布后不改编号**；新增任务追加编号，取消任务标记“不做/已并入”。
- 每个任务必须能落到一个可验证的交付物：代码、文档、测试、报告、截图或所有者确认记录。
- “已实现待验收”不等于“已上线”；“有 UI 入口”不等于“功能可用”。
- 只有真实运行记录（含环境、时间、输入、结果）才能作为验收证据；测试数量不能替代产品验收。

### 1.3 状态定义

| 状态 | 含义 |
|---|---|
| ✅ 已上线 | 已部署生产，且有发布记录与线上证据 |
| 🟢 已实现待验收 | 代码/文档完成，但未通过独立验收或未发布 |
| 🟡 进行中 | 已开始，有明确未完成项 |
| 🟠 待核实 | 代码可能存在基础，但未逐项确认，不得按“已完成”排期 |
| ⬜ 未开始 | 尚未开始 |
| ⛔ 阻塞 | 依赖所有者/法务/外部条件，当前不能推进 |
| ➖ 不做/延后 | 明确不进入当前阶段或移至 S18+ |

## 3. S16 总体目标与完成条件

### 3.1 目标

S16 结束时应形成统一的**产品体验与个性化底座**：

1. 页面、组件、文字、颜色、间距有稳定语义系统，结果可自动检查；
2. 用户可选择浅色/深色/跟随系统与预设强调色，刷新、重登不丢偏好（已随 1.16.08 交付；跨设备同步规则见 S16-E-02）；
3. 简体中文与 English 可切换，界面、错误、动态历史和金额格式完整；用户输入内容不被翻译；
4. 多币种统计口径明确、可审计，折算不修改用户原始金额；
5. 设置项有明确的账号级/设备级/账本级边界，跨设备行为可解释；
6. S16 的验收由真实浏览器/真机与产品所有者共同完成，不以单元测试数量代替。

### 3.2 S16 完成条件（全部满足才可标记 S16 完成）

- [ ] S16-A 遗留项有明确结论：S15-D 真机验收完成或所有者书面延后；历史金额、法律正文等风险不再被静默忽略。
- [ ] 默认绿色主题的完整深色模式通过对比度、色觉辨识、减少动画和真机验收（深色与七套主题已随 1.16.08 上线；**对比度债务与真机验收未完成**）。

## 5. S17 总体目标与公开发布边界

### 5.1 目标

S17 结束时，Libevra 应具备向公众开放所需的最低**安全、隐私、运营与产品完整度**，而不是“功能都做完了”。

### 5.2 公开发布必要条件（Blockers）

以下必须完成，不能以“可以发布后补”处理：

- [ ] 正式隐私政策/服务条款可访问，数据处理事实与实现一致，需专业法律审核的事项已标记并由所有者确认。
- [ ] 账号安全与权限基线通过：会话、越权、限流、上传/临时文件、日志敏感信息、依赖安全检查有证据。
- [ ] 备份/恢复演练、异地备份、生产监控/告警、部署回滚有记录；真实用户数据保护责任明确。
- [ ] 用户帮助/反馈渠道可用；严重问题有处理路径。
- [ ] 公开注册/邀请策略由所有者明确；公开演示账号（若提供）无真实数据且只读/重置。
- [ ] 核心路径在真实设备与主流浏览器通过；S15-D 已完成或被所有者明确接受为发布后风险。
- [ ] 生产发布授权、版本/公告/CHANGELOG/回滚材料齐全。
- [ ] 发布后观察机制（24h）与责任人明确。
