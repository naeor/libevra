# S17-A · 安全与隐私能力事实清单（2026-10-25）

> 用途：宣传片 / 对外文案的**事实底稿**。每条都必须是"已实现且验证过"的能力；标注 ✅（可讲）、🟡（可讲但需限定）、❌（现状不具备，不可讲）。
> 原则：**不做法律结论**（正式隐私政策/使用条款尚未提供，页面上明确写占位）。广告只能讲产品事实，不能讲"合规/审计/加密等级"。
> 证据以当前主工作区 `release/s16-1.16.05`（`1.16.13`）代码与 `deploy/` 脚本、`docs/03-运维手册.md`、`docs/ops/S13-I-*.md` 为准。

## 1. 结论先行

**可以自豪讲的三件事**
1. **账本数据在你自己的服务器上、由你自己的备份体系保护**：每日自动备份 → 隔离恢复验证 → AES-256 加密 → 上传异地对象存储（COS）→ 远端校验 → 失败邮件告警；另有外部心跳（死手开关）与月度异地演练。
2. **账号安全有实打实的实现**：密码用 Argon2id 哈希（只存哈希）、会话令牌只存 SHA-256、Cookie 为 HttpOnly/Secure/SameSite、写操作校验 Origin、登录失败限速、邀请码注册、管理员双表授权 + 与操作同事务的审计记录。
3. **无广告、无第三方统计、不把识别交给第三方 AI**：全站 CSP 只允许自有资源；OCR/语音模型跑在自己的服务器（同一容器），不是 OpenAI/Google 等外部 API。

**绝对不能讲的（现有技术不支持）**
- ❌ "端到端加密 / 只有你能解密"——服务端需要读取数据来同步与统计。
- ❌ "所有数据只留在你的设备上"——账本、图片、语音都会到 Libevra 自己的服务器。
- ❌ "加密存储 / 军事级加密"——应用层数据库**未**做字段加密（仅备份与关键状态登记簿加密）。
- ❌ "数据永不丢失 / 备份万无一失"——有三层备份与演练，但没有 SLA，也不是异地双活。
- ❌ "完全匿名 / 无法关联到人"——有账号、邀请码、会话与服务器 IP 日志（22 字节内），且可被运维接触。
- ❌ "符合 GDPR / 个人信息保护法 / 已备案 / 已通过安全审计"——正式法律文本、公安备案、第三方审计都还没做。

## 2. 能力清单（按领域）

### A. 传输、浏览器与攻击面（✅ 可讲）
| 能力 | 现状 | 证据 |
|---|---|---|
| 全站 HTTPS，证书自动续期 | ✅ | `deploy/Caddyfile`（Caddy + Let's Encrypt 自动签发/续期） |
| HSTS（1 天，当前未开 preload） | ✅ | 同上 `Strict-Transport-Security "max-age=86400"` |
| 严格 CSP：仅同源资源、禁内联脚本/eval、禁被其它站嵌入 | ✅ | 同上 `Content-Security-Policy`、`frame-ancestors 'none'`、`X-Frame-Options: DENY` |
| 关闭不用的浏览器能力（定位/摄像头/支付/USB） | ✅ | `Permissions-Policy "geolocation=(), camera=(), payment=(), usb=()"` |
| 无第三方 CDN/字体/脚本；单站同源、无 CORS | ✅ | CSP `default-src 'self'`；Caddyfile 注释明确"无 CORS 是设计" |
| 服务端不回显框架版本等指纹 | ✅ | `-Server` 头 |

**可讲**："全站加密传输；页面只加载我们自己的资源，别的网站无法把 Libevra 套进自己的页面里。"
**不可讲**："证书固定 / TLS 1.3 强制 / 防中间人绝对安全"。

| 写操作 Origin 校验（CSRF 纵深防御） | ✅ | `apps/api/src/app.ts:144-170` |
| 登录失败节流（按账号/IP 计数，返回重试秒数） | ✅ | `apps/api/src/auth/login-throttle.ts`、`routes/auth.ts:221-230` |

**不可讲**："零信任 / 硬件密钥 / 多因素登录"（目前没有 MFA/WebAuthn）。

### C. 数据访问控制（账本权限）与审计（✅ 可讲，🟡 细节需限定）
| 能力 | 现状 | 证据 |
|---|---|---|

**不可讲**："管理员绝对看不到任何数据"——运维（服务器/Docker/数据库）在物理上仍可接触数据；宣传应限定为"应用层管理员权限"。
