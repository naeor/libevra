## 1. 背景与命名冲突

分析工作台在 1.17.6 之前只有「时间 / 币种（原币或综合折算）/ 统计方式」三组筛选，**分类、支付方式、标签三个维度在协议层已定义、但端到端未接通**。2026-10-28 的 W5 任务要求补齐「完整筛选能力」。

项目内存在一处命名冲突，必须先说明：

- 路线图 §3.1 里的 **`S17-W5` 正式交付名是「模块化布局与格式模板」**（布局 / 容器 / 模板），不是筛选；
- 但 `docs/STATUS.md` 长期把「W5 全筛选」作为未完成项跟踪；
- 所有者本轮任务书把 **W5 定义为「完整筛选能力」**。

本文件按**所有者任务书的定义**交付「筛选语义清单」，不改变路线图里 W5 的布局交付名；布局规格仍以 [工作台布局与格式模板规格](../design/S17-工作台布局与格式模板规格.md) 为权威。两者是不同工作面，不应互相替代。

## 2. 权威来源与优先顺序

筛选语义不是本文件发明的，而是把既有权威定义汇总成一处，避免后续实现各写一套：

1. **冻结协议 S-01 v2**：`packages/shared/src/analysis/types.ts` 的 `ResolvedFilters`；`context.ts` 的 `resolveFilters` / `filterEntries`；G-12a 的 params 白名单约束。
2. **总需求规格 ACC-01**：用户选择的账本、日期、币种和分类必须正确生效；摘要 / 趋势 / 分类 / 来源列表逐笔合计一致。
3. **代码现状**：`apps/web/src/statsWorkbench/filters.ts` 是可执行契约（幂等、可序列化、纯函数），本文件与它不一致时以代码 + 测试为准并回改本文件。
4. 本文件只做「汇总 + 解释 + 缺口登记」，不新增冻结协议未定义的能力；需要新语义时先补协议再实现。

**权威顺序**：S-01 v2 / G-12a > 本文件 > 具体卡片实现。任何卡片实现都不能绕开 `ResolvedFilters` 自行发明语义。

## 3. 维度与作用域

### 3.1 五个筛选维度【已确认】

W7 补充（最后核对: `1e517449` 基线 / 2026-10-29）：旧分类条件继续精确匹配；分支条件使用独立 `categoryBranch` 参数，运行时按当前树展开、去重后进入既有过滤 / FX。不限与空集不变，不下推到月覆盖回执。明细另用 `categoryScope=branch`；完整定义见[W7 说明](../features/S17-W7-多层级分类-实现说明.md)。

| 维度 | 数据字段 | URL 参数 | 说明 |
| --- | --- | --- | --- |
| 时间 | `occurredLocalDate` 派生区间 | `range` / `month` / `from` + `to` | 沿用既有口径；自定义区间上限 400 天（`MAX_STATS_DAYS`），超限在应用前拒绝，不截断静默少算 |
| 币种 / 统计方式 | `currency` + `combined` | `currency` + `analysis` | 原币只统计单一币种；综合折算按逐笔历史汇率折算为默认目标币种 |
| 分类 | `categoryId` | `category`（可重复） | 多选，维度内 IN；分类必须属于当前账本 |
| 支付方式 | `paymentMethodId` | `payment`（可重复） | 多选，维度内 IN；支付方式可为空，**筛选时 null 支付方式不匹配任何选中项** |
| 标签 | `tags[].id` | `tag`（可重复） | 多选，账目带有任一选中标签即保留（任一命中，不是全部命中） |

**账本不是筛选维度**，是数据作用域：账本切换由 bookId 进入查询键与缓存键完成；筛选条件本身不携带账本，也不会跨账本复用结果。

### 3.2 生效上下文【已确认】

同一份筛选同时作用于以下上下文，缺一不可：

1. 工作台 `scope` 派生的账目集合（`WorkbenchScope.entries`）；
2. A 层分析结果（`agentAResult` / `fxAgentAResult` 的 `filters` 入参，对应协议定义字段）；
3. B / legacy 卡片的前置 `Transaction[]` 过滤（这类卡片没有 filters 形参）；
4. 固定窗口卡（pinned、近 12 个月等 `rangePolicy`）与上期比较卡（A01）的独立读取；
5. 综合折算的源账目集合（进入 `projectFx` 之前过滤），因此缺汇率影响范围随筛选变化；
6. 结果信封的 `resolvedFilters` 元数据（供详情、导出与后续追溯）；
7. URL 持久化与缓存键（筛选条件变化必须导致重算，不展示过期统计）。

**禁止下推**：筛选不进入 `analysisRange.ts` 的读取回执（`fx-month-coverage` 按 scope + month 共享）与离线 fill；把筛选混进回执会污染其他筛选组合的完整性判断。

## 4. 语义规则【已确认】

1. **`null` = 不限，`[]` = 空集**，两者不可互换。空集是合法状态：该维度下不显示任何账目，UI 必须明确提示而不是静默退回「全部」。
2. 维度之间是 **AND**；维度内部是 **IN（OR）**。
3. 多值上限 50、去重、trim、单个 id 最长 64；未知 id 不会命中任何账目，但保留在条件中（刷新后仍可见，由 UI 显示为缺失项）。
4. 标签是 **任一命中**（`entry.tags` 与选中集合有交集）；多标签账目只计一次，不因标签数量重复计算笔数 / 金额。
5. 分类和支付方式按 id 精确匹配；归档分类/支付方式在当前账本仍可被历史账目命中，是否在筛选栏展示由 UI 决定（见 §8）。
6. **本版只做一级分类**，不含子分类展开；子分类/层级是后续决策，不在本轮擅自实现。
7. 权限只来自账本成员关系；筛选不得绕过权限，也不得读取无权账本。
8. 转账等特殊类型仍按 `kind` 语义处理：分类筛选不会把「转账」等系统分类与普通支出混为一谈；`kind` 由卡片定义自身决定，不因筛选改变。

## 5. URL 契约【已确认】

- ~~生效条件唯一权威是 URL~~（1.19.53 起由 §13 取代：筛选保存在本机、默认与明细共用；地址栏里的旧参数读入后移除。统计方式与币种 `currency` / `analysis` 仍在地址栏）。
- 多值参数用重复键表达：`?category=a&category=b&payment=c&tag=d`。
- **空集**写成单个空值参数：`?category=`（读回 `[]`）；**不限**则是不出现该键（读回 `null`）。
- 旧参数（`range` / `month` / `currency` / `analysis`）保持兼容；未知参数原样保留。
- 写回时按稳定顺序输出（时间 → 币种 → 分类 → 支付方式 → 标签），便于比较与分享。

## 9. 已知缺口与开放决策

1. **排除条件**（「不含分类 X」）：S-01 v2 未定义，不得自行实现。
2. **标签「全部命中」**：当前只有任一命中；如需改语义必须先改协议。
3. **子分类 / 层级分类**：首版不做；分类模型若引入层级，需要重新定义筛选语义。
4. **筛选指纹**：缓存键目前用序列化条件（`filterKey`），未定义跨版本稳定指纹。
5. **持久化 / 跨设备同步**：属 W6，不在本轮实现；当前 URL 分享即复制筛选条件。
6. **归档分类可见性**：历史账目可能仍引用归档分类；当前候选列表来自 `useLedger()`，归档项如何处理由 UI 决策。
7. **账本维度**：目前是数据作用域；若所有者希望出现「跨账本汇总」，属于新需求，需先定义权限与折算口径。
8. **真实大数据量性能**：本轮筛选在客户端内存中执行；离线读取单月上限约 50,000 笔，真实 50,000+ 端到端仍未实测（与 1.17.6 的边界相同）。

## 12. 明细统一筛选（所有者 2026-11-01 确认）

- 明细入口合并时间、分类、标签、支付方式、币种、附件六组条件。组内 OR、组间 AND，标签命中任一个即可；空选择表示不限。此处不改变分析工作台空数组表示空集的协议。
- 时间支持按月、全部时间、起止日期（含两端，按账目本地日期）。「月份」区域内直接选择某月或全部时间，日期范围另设入口；选择全部时间时不再保留具体月份。新增其它条件默认保留当前月份。明确为空的月份禁用，未知月份不当作空月份。
- 分类默认精确匹配，可显式勾选含子分类；兼容旧 categoryId / categoryScope=branch 链接。附件数量状态、文件类型、空间范围合计一个筛选维度。
- 同一维度多值 OR。只有一个有效维度时显示其具体值；该维度多值显示“支付方式 · 2”等。多个有效维度显示“筛选 · N”。月份也计为维度，全部时间不计；收支方向、搜索与排序不计。各端均通过面板切月，不提供页头前后翻月箭头；入口使用统一的折线下拉箭头，展开时朝上。
- 手机采用底部面板，左侧条件目录、右侧选项、顶部已选条件和底部重置 / 查看结果。Pad 弹窗及遮罩只覆盖明细所在工作区，宽工作区居中、窄工作区底部；电脑锚定入口。取消丢弃草稿，查看结果统一应用；重置恢复当月并清除其它条件，保留排序及收支方向。
- ~~条件以明细 URL 的 f.* 多值参数承载~~（1.19.53 起见 §13：保存在本机，`f.*` / `month` 只作为打开时带来的条件读入）；不加入分析配置同步协议。筛选后再排序，金额摘要只统计命中的账目并分别保留币种；月内综合折算复用既有逐笔历史汇率，不扩大既有跨月折算上限。
- 组合筛选读取当前账本的完整查询分页，未完成或出错不把部分结果标为完整；离线只在本机可读范围内筛选并提示。超大历史账本分页性能及真机软键盘仍需专项验收。

## 13. 明细与分析共用筛选、筛选保留（所有者 2026-11-09 决定，1.19.53）

- **保留**：筛选（月份 / 全部时间 / 日期范围与分类、标签、支付方式、币种、附件）保存在本机，按账号（或游客身份）与账本分开（`lib/ledgerFilter.ts`，键 `libevra.ledger-filter:<页>:<账号>:<账本>`）。刷新、切 Tab、记一笔回来、从账目返回都不再回到当月；没有保存过时默认当月。随账号清理时一起清除。收支方向、搜索与排序不在其中，仍按原来的会话规则。
- **默认共用**：开关“明细与分析使用同一筛选”默认打开（本机偏好 `libevra.filter-sync`），记账偏好与两页的筛选面板里是同一个开关。打开时分析读写的就是明细这一份，分析统计的就是明细筛选出的账目；关闭时分析从当时那份复制一份自己的，之后两页各自独立；重新打开回到共用。
- **同一个面板**：分析页的筛选入口改为与明细相同的面板（手机底部半屏、宽屏弹出框），原工作台内联筛选面板（草稿 / 撤销 / “有未应用的修改”）不再用于分析页。统计方式与币种仍在统计控制条与“统计设置”里，写在地址栏。
- **换算到分析**：某月 → 那个月（当月 → “本月”，到今天为止）；日期范围 → 同一区间；“全部时间”与超过 400 天的范围按截至今天（或截至结束日）的最近 400 天计算（`MAX_STATS_DAYS`），摘要写明“分析最多统计 400 天，按最近 400 天计算”。分类（含子分类）、支付方式（含“未指定”= 没有支付方式的账目）、标签（任一命中）、币种、附件条件逐项作用于分析的账目集合（`matchesWorkbenchFilters` 增加币种与附件；不选“未指定”时没有支付方式的账目照旧不保留）。工作台“空数组 = 空集”的协议不变，明细的空选择仍是不限。
- **地址栏**：旧链接与卡片详情“去明细看”带来的 `month` / `f.*` / `categoryId`（明细）或 `range` / `month` / `from` / `to` / `category` / `categoryBranch` / `payment` / `tag`（分析）在打开时读入当前使用的那一份并从地址栏移除，避免 Tab 记住的旧地址把别处改过的筛选覆盖回去。布局预设附带的筛选同样换算后写入；“近 N 天”变成具体起止日期。
- **明细收起态的入口**：明细收起到账目列表时，月份前出现与分析筛选相同的漏斗图标（16px，与右侧工具图标对齐），随收起后半程长出，A / B1 / B2 位于月份的玻璃底面内；有其它筛选条件时始终显示。
- 测试：`statsWorkbench/ledgerFilterBridge.test.ts`（换算、400 天、未指定支付方式、币种、附件、旧参数读入、规范化）。

## 14. 当前月份、筛选设置、多选月份与记录人（所有者 2026-11-10 决定，1.19.55）

- **当前月份始终可选**：月份格子里当前月份不再因为“这个月还没有账目”而变灰，切到别的月份后总能点回来；未来月份仍不可选。已选中的月份即使没有账目也能取消。
- **筛选设置**：“明细与分析使用同一筛选”从筛选面板正文移到页头的齿轮按钮里（小面板，点外面或 Esc 关闭，Esc 不关闭整个筛选面板）；记账偏好里的同一开关不变。
- **多选月份**：页头“多选”按钮（在齿轮左边）打开后，月份格子可以同时选中多个月份，再点一次取消；打开时带入当前选中的那个月，关闭时保留最后一个选中的月份；选择“全部时间”或日期范围会清除多选。保存为 `months`（升序），此时 `month` 为“全部”。明细只保留这些月份的账目，汇总卡片的图表覆盖第一个月月初到最后一个月月底、日均按所选月份的天数（当月算到今天）。分析的统计时间是第一个月月初到最后一个月月底（不超过今天），中间有没选的月份时再按月份去掉（只作用于首尾月份之间，上一期比较仍按等长的前一段），超过 400 天同样按最近 400 天计算；只选当月等于“本月”。标签：单月“2026年10月”，同一年“2026 年 10月、11月”，跨年“N 个月”。
- **记录人**：只在多人账本出现（账本成员数 > 1，或已设了记录人条件）。按每笔账最初是谁记的（`Transaction.recorderId` = 创建者账号，别人修改不变）筛选，按成员多选，上方“只看自己”一键只选自己；另有“已退出的成员”（记录人不在当前成员里）。服务器从 1.19.55 起随账目下发 `recorderId`；1.19.55 之前存在本机的副本没有它，按记录人筛选时不命中，自动下载会把这样的月份重新取一轮（每个“账号 : 账本”一次，`libevra.offline-recorder-refresh:<账号>:<账本>`）。分析逐项作用（`matchesWorkbenchFilters`），摘要写“记录人 · N”。
- 测试：`statsWorkbench/ledgerFilterBridge.test.ts`（多选月份的明细谓词、读入规范化、分析换算与空缺月份、记录人与“已退出的成员”、本机副本补取判断）。
