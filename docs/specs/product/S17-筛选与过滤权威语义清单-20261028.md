## 1. 背景与命名冲突

分析工作台在 1.17.6 之前只有「时间 / 币种（原币或综合折算）/ 统计方式」三组筛选，**分类、支付方式、标签三个维度在协议层已定义、但端到端未接通**。2026-10-28 的 W5 任务要求补齐「完整筛选能力」。

项目内存在一处命名冲突，必须先说明：

- 路线图 §3.1 里的 **`S17-W5` 正式交付名是「模块化布局与格式模板」**（布局 / 容器 / 模板），不是筛选；
- 但 `docs/STATUS.md` 长期把「W5 全筛选」作为未完成项跟踪；
- 所有者本轮任务书把 **W5 定义为「完整筛选能力」**。

本文件按**所有者任务书的定义**交付「筛选语义清单」，不改变路线图里 W5 的布局交付名；布局规格仍以 [工作台布局与格式模板规格](../design/S17-工作台布局与格式模板规格.md) 为权威。两者是不同工作面，不应互相替代。

## 2. 权威来源与优先顺序

筛选语义不是本文件发明的，而是把既有权威定义汇总成一处，避免后续实现各写一套：

1. **冻结协议 S-01 v2**：`packages/shared/src/analysis/types.ts` 的 `ResolvedFilters`；`context.ts` 的 `resolveFilters` / `filterEntries`；G-12a 的 params 白名单约束。
2. **总需求规格 ACC-01**：用户选择的账本、日期、币种和分类必须正确生效；摘要 / 趋势 / 分类 / 来源列表逐笔合计一致。
3. **代码现状**：`apps/web/src/statsWorkbench/filters.ts` 是可执行契约（幂等、可序列化、纯函数），本文件与它不一致时以代码 + 测试为准并回改本文件。
4. 本文件只做「汇总 + 解释 + 缺口登记」，不新增冻结协议未定义的能力；需要新语义时先补协议再实现。

**权威顺序**：S-01 v2 / G-12a > 本文件 > 具体卡片实现。任何卡片实现都不能绕开 `ResolvedFilters` 自行发明语义。

## 3. 维度与作用域

### 3.1 五个筛选维度【已确认】

W7 补充（最后核对: `1e517449` 基线 / 2026-10-29）：旧分类条件继续精确匹配；分支条件使用独立 `categoryBranch` 参数，运行时按当前树展开、去重后进入既有过滤 / FX。不限与空集不变，不下推到月覆盖回执。明细另用 `categoryScope=branch`；完整定义见[W7 说明](../features/S17-W7-多层级分类-实现说明.md)。

| 维度 | 数据字段 | URL 参数 | 说明 |
| --- | --- | --- | --- |
| 时间 | `occurredLocalDate` 派生区间 | `range` / `month` / `from` + `to` | 沿用既有口径；自定义区间上限 400 天（`MAX_STATS_DAYS`），超限在应用前拒绝，不截断静默少算 |
| 币种 / 统计方式 | `currency` + `combined` | `currency` + `analysis` | 原币只统计单一币种；综合折算按逐笔历史汇率折算为默认目标币种 |
| 分类 | `categoryId` | `category`（可重复） | 多选，维度内 IN；分类必须属于当前账本 |
| 支付方式 | `paymentMethodId` | `payment`（可重复） | 多选，维度内 IN；支付方式可为空，**筛选时 null 支付方式不匹配任何选中项** |
| 标签 | `tags[].id` | `tag`（可重复） | 多选，账目带有任一选中标签即保留（任一命中，不是全部命中） |

**账本不是筛选维度**，是数据作用域：账本切换由 bookId 进入查询键与缓存键完成；筛选条件本身不携带账本，也不会跨账本复用结果。

### 3.2 生效上下文【已确认】

同一份筛选同时作用于以下上下文，缺一不可：

1. 工作台 `scope` 派生的账目集合（`WorkbenchScope.entries`）；
2. A 层分析结果（`agentAResult` / `fxAgentAResult` 的 `filters` 入参，对应协议定义字段）；
3. B / legacy 卡片的前置 `Transaction[]` 过滤（这类卡片没有 filters 形参）；
4. 固定窗口卡（pinned、近 12 个月等 `rangePolicy`）与上期比较卡（A01）的独立读取；
5. 综合折算的源账目集合（进入 `projectFx` 之前过滤），因此缺汇率影响范围随筛选变化；
6. 结果信封的 `resolvedFilters` 元数据（供详情、导出与后续追溯）；
7. URL 持久化与缓存键（筛选条件变化必须导致重算，不展示过期统计）。

**禁止下推**：筛选不进入 `analysisRange.ts` 的读取回执（`fx-month-coverage` 按 scope + month 共享）与离线 fill；把筛选混进回执会污染其他筛选组合的完整性判断。

## 4. 语义规则【已确认】

1. **`null` = 不限，`[]` = 空集**，两者不可互换。空集是合法状态：该维度下不显示任何账目，UI 必须明确提示而不是静默退回「全部」。
2. 维度之间是 **AND**；维度内部是 **IN（OR）**。
3. 多值上限 50、去重、trim、单个 id 最长 64；未知 id 不会命中任何账目，但保留在条件中（刷新后仍可见，由 UI 显示为缺失项）。
4. 标签是 **任一命中**（`entry.tags` 与选中集合有交集）；多标签账目只计一次，不因标签数量重复计算笔数 / 金额。
5. 分类和支付方式按 id 精确匹配；归档分类/支付方式在当前账本仍可被历史账目命中，是否在筛选栏展示由 UI 决定（见 §8）。
6. **本版只做一级分类**，不含子分类展开；子分类/层级是后续决策，不在本轮擅自实现。
7. 权限只来自账本成员关系；筛选不得绕过权限，也不得读取无权账本。
8. 转账等特殊类型仍按 `kind` 语义处理：分类筛选不会把「转账」等系统分类与普通支出混为一谈；`kind` 由卡片定义自身决定，不因筛选改变。

## 5. URL 契约【已确认】

- 生效条件唯一权威是 URL；组件内草稿只存在于编辑过程，点击「应用」后写回 URL，点击「撤销修改」恢复生效条件，收起面板保留草稿并显示「有未应用的修改」。
- 多值参数用重复键表达：`?category=a&category=b&payment=c&tag=d`。
- **空集**写成单个空值参数：`?category=`（读回 `[]`）；**不限**则是不出现该键（读回 `null`）。
- 旧参数（`range` / `month` / `currency` / `analysis`）保持兼容；未知参数原样保留。
- 写回时按稳定顺序输出（时间 → 币种 → 分类 → 支付方式 → 标签），便于比较与分享。

## 9. 已知缺口与开放决策

1. **排除条件**（「不含分类 X」）：S-01 v2 未定义，不得自行实现。
2. **标签「全部命中」**：当前只有任一命中；如需改语义必须先改协议。
3. **子分类 / 层级分类**：首版不做；分类模型若引入层级，需要重新定义筛选语义。
4. **筛选指纹**：缓存键目前用序列化条件（`filterKey`），未定义跨版本稳定指纹。
5. **持久化 / 跨设备同步**：属 W6，不在本轮实现；当前 URL 分享即复制筛选条件。
6. **归档分类可见性**：历史账目可能仍引用归档分类；当前候选列表来自 `useLedger()`，归档项如何处理由 UI 决策。
7. **账本维度**：目前是数据作用域；若所有者希望出现「跨账本汇总」，属于新需求，需先定义权限与折算口径。
8. **真实大数据量性能**：本轮筛选在客户端内存中执行；离线读取单月上限约 50,000 笔，真实 50,000+ 端到端仍未实测（与 1.17.6 的边界相同）。
