## 1. 范围与原则

1. **普通模式与编辑模式严格分离**：日常看分析不触发拖动、缩放；
2. **布局只组织卡片，不触碰数据**：任何布局操作不得生成、修改、删除交易，不影响计算结果（总需求规格 §3.1）；
3. **列数由真实可用空间决定**，使用 CSS 像素的容器实际宽度，不是物理像素、不是机型名、不是视口；
4. **安全降级**：布局数据缺失 / 损坏 / 版本不符时回退到可用布局，绝不白屏；
5. **可访问**：所有只能靠拖动完成的操作必须有单指针 / 键盘替代（WCAG 2.2 拖动动作的 AA 要求）；
6. **性能**：纵向不设固定行数上限，但按需渲染（图表与卡片规格 §9）。

## 2. 对象模型（概念）

| 对象 | 说明 | 是否有财务语义 |
|---|---|---|
| **工作台 Workbench** | 一个用户一个作用域下的一套布局（作用域见配置与分享 §3） | 无 |
| **根网格 Root grid** | 工作台的第一层：N 列、行向下无限延伸，网格项按“占格”放置 | 无 |
| **网格项 Grid item** | 根网格里占据 `w 列 × h 行` 的单元，内容是**卡片**、**容器**或**空白占位（Spacer）**。位置用 §12 的行优先编号 | 无 |
| **卡片 Card instance** | 一个分析实例的展示（图表与卡片规格 §4） | **有**（但语义由分析定义决定，与布局无关） |
| **容器 Container** | 一种特殊网格项，内部有若干**槽位（slot）**，槽位里放卡片（或受限的子容器）。分两种：自由分割、滑动抽屉。**所有容器都有 `1×1` 保底收缩形态**（§17） | **无** |
| **空白占位 Spacer** | 用户有意保留的留白，属于布局系统，不是分析卡片（§16） | 无 |
| **权威布局 / 布局档案 / 投影** | 用户保存的几何（统一模式一份主布局，独立模式每档案一份）；投影是把它推导到目标列数的纯函数结果，不持久化（§14、§18） | 无 |

容器是“摆放卡片的几何结构”，**不是数据结构**：它没有指标、不聚合子卡片、不决定筛选。因此容器内的卡片仍然只遵守卡片自己的数据规则（总需求规格 §4.2、图表与卡片规格 §4.4）。

## 3. 普通模式与编辑模式

### 3.1 入口与出口

| 项 | 规则（【推荐】） |
|---|---|
| 入口 | 分析页明确的“自定义布局”入口（例如页头次要按钮或菜单项）；**不**通过长按卡片隐式进入 |
| 普通模式 | 卡片只响应查看与进入详情；无格线、无拖动手柄、无尺寸控制；页面外观像成熟的财务产品 |
| 编辑模式 | 进入后页头切换为“完成 / 取消”；显示棋盘格背景、卡片边界、手柄与尺寸控制；底部或侧栏出现“添加卡片 / 添加容器 / 套用模板” |
| 退出 | “完成”提交本次改动；“取消”放弃（有未保存改动时二次确认）；系统返回键等同于取消（有改动时确认） |
| 误触防护 | 编辑模式内的破坏性操作（删除卡片 / 容器）可撤销（§6.4）；不依赖确认弹窗 |
| 编辑中断 | 应用被杀、断网、账号被退出时：编辑中的草稿**不得**部分写入已提交布局；是否本地保留草稿【待研究】（见 §10） |

### 3.2 数据只读保证

编辑模式下，卡片仍显示真实分析结果（或占位骨架），但**任何点击不会进入详情页**（避免误入）、不会触发交易写入。静态守卫测试（总需求规格 §3.2）覆盖此条。

## 4. 编辑模式视觉（【推荐】）

参考 Apple 风格的简洁自然，而非复杂的网页编辑器（总需求规格 §8）：

- 棋盘格 / 网格线：**低对比度**，仅编辑模式显示，列数可辨认；浅色与深色主题各自有令牌；
- 卡片边界：细边框 + 轻微抬升；可选中卡片出现控制手柄；
- 空白可放置区：以虚线或浅色格标示；
- 拖动时：被拖卡片轻微放大 / 抬升；目标位置以**与品牌一致的克制绿色**（`#55997a` 的低饱和变体）高亮合法落点预览；非法位置不高亮；
- 动画：连续柔和；`prefers-reduced-motion` 下直接跳到终态；
- 七主题与深浅色均需验收；中英文标签长度差异不撑破控件。

## 5. 基础网格

### 5.1 列数

> **1.18.01**：列数的选择（自动评分 / 编辑器滑条 / 主辅工作区各自的显示偏好）与行高以 [S18 响应式布局引擎 §4–§5](../features/S18-分析工作台响应式布局引擎-20261030.md) 为准；下面的公式与表格是 S17 的推导过程。

所有者要求：用户可选两列、三列或其他技术可行的列数，**取决于真实 CSS 空间**，不假设所有手机都能三列（总需求规格 §8）。

```text
可用列数上限  maxCols = floor((W − 2·margin + gap) / (minCol + gap))
卡片列宽      colWidth = (W − 2·margin − (cols − 1)·gap) / cols
```

`W` 为工作台容器内容盒的 CSS 宽度（扣除安全区），`margin` 页边距，`gap` 卡片间距，`minCol` 最小列宽。**全部是候选值**，下表以 `margin=16, gap=12` 做算术示例：

| 容器宽 W | minCol=110 的 maxCols | minCol=130 的 maxCols | 说明 |
|---|---|---|---|
| 320 | 2（列宽约 138） | 2 | 小屏手机 |
| 375 | 2（约 165） | 2 | |
| 390 | 3（约 111） | 2（约 173） | 差异点：minCol 决定 390 宽的手机能否三列 |
| 430 | 3（约 125） | 2（约 193） | |
| 768 | 6 | 5 | 平板竖屏（S18-B 重点） |
| 1024 | 8 | 7 | |

- **用户选择**：列数选择器只列出 `2 … maxCols` 中**当前可用**的值；
- 窗口缩小导致用户已选列数不可用 → 自动降到当前 `maxCols` 显示，**不覆盖用户保存的偏好**，空间恢复后回到所选值；
- **默认列数【已确认 2026-10-27，Q-10】**：手机默认**两列**；三列及更多列可以提供，前提是实际可用宽度足以保证最小卡片可读。判断依据是 CSS 容器尺寸，不是物理像素；
- `minCol`、`margin`、`gap`、最小可读宽度与各宽度开放几列的门槛：【待研究】，由原型的可读性测试决定（OQ-LM-08）。

### 5.2 占格记法

**【已确认 2026-10-27，Q-09】采用方案 α `宽×高`**（`1×1` 一列宽一行高、`2×1` 两列宽一行高、`1×2` 一列宽两行高、`2×2` 两列宽两行高）。β 不采用，留档如下：

| 方案 | 写法 | 说明 |
|---|---|---|
| α【已确认】 | `宽×高`，单位为格，如 `2×1` = 2 列宽、1 行高 | 与屏幕直觉一致；文档中首次出现必须写“2 列 × 1 行”以免歧义 |
| β | `行×列` | 数学矩阵习惯，易与 α 混淆 |

持久化字段用显式命名（`colSpan`, `rowSpan`），不依赖记法顺序。格子编号与占格见 §12。

### 5.3 行高与尺寸

| 项 | 候选 | 说明 |
|---|---|---|
| 行高 | (a) 固定值（例如 72px）；(b) 等于列宽（方格） | (a) 内容高度可预期；(b) 卡片比例随列数变化，窄屏卡片更矮。**【待研究】** 原型对比（Q-09 确认记法与摆放策略，基础行高、格子最小 CSS 尺寸与对象尺寸约束仍须原型测试） |
| 最小占格 | 由卡片家族声明 `minSize`（图表与卡片规格 §5.3） | 缩放手柄不允许缩到小于 `minSize` |
| 最大占格 | `colSpan ≤ 当前列数`；`rowSpan` 候选 ≤ 8 | 防止单卡片占满大量空间 |
| 纵向 | 无固定上限 | 视口外卡片按需挂载 |

### 5.4 摆放与重排策略

| 方案 | 行为 | 优点 | 缺点 |
|---|---|---|---|
| A 垂直紧凑【已确认为默认，Q-09】 | 卡片自动上浮填补空洞；拖动时其余卡片被向下推 | 无重叠、无空洞、结果可预测；跨设备映射简单 | 用户无法靠“空着”来留白——由 **Spacer**（§16）解决 |
| B 允许空洞 | 卡片只能放在空闲格；不自动上浮 | 用户对布局有完全控制，可刻意留白 | 不同列数下同一布局可能出现大量空洞；跨设备更难 |
| C 推挤 + 空洞 | 拖到已占位置时推开相邻卡片 | 手感好 | 实现复杂；推挤结果有时出人意料 |

**【已确认 2026-10-27】默认采用确定性的垂直紧凑**，但保护用户有意创建的 Spacer、布局容器结构和明确保存的位置；与跨列数投影的组合方式见 §14.4（OQ-LM-03）。方案 B / C 不属于首版范围。采用成熟网格库还是自研，需 S17-W5 前做独立 spike（评估项：功能适配、移动端 Safari、拖动性能、包体、键盘与无障碍、许可证、维护成本），**只有明确发现自研或现有方案不足时才引入新依赖**（Q-19 已确认），不在本文冻结。

## 6. 拖动、吸附、缩放、撤销

### 6.1 拖动（触摸与指针）

- 触摸：在编辑模式下从卡片的**拖动手柄**拖动，或**长按**卡片（候选 ≈ 250ms）后拖动；页面其余区域仍可正常纵向滚动；
- 指针（鼠标 / 笔）：按住手柄或卡片标题栏拖动；
- 拖动中：显示合法落点的预览占位；接近视口边缘时自动滚动；
- 释放：吸附到最近的合法格；非法落点则卡片平滑回到原位；
- 吸附阈值、自动滚动速度、长按时长：【待研究】。

### 6.2 缩放

- 选中卡片出现**尺寸手柄**（角或边）；拖动时按整格吸附；
- 手柄命中区 ≥ 44×44 CSS px，视觉上可以更小；
- 缩小到低于卡片 `minSize` 被拒绝并给出轻提示；放大受列数与容器限制；
- 缩放时实时显示当前占格（如“2 列 × 2 行”）。

### 6.3 键盘与单指针替代（必须）

| 操作 | 键盘 | 触摸 / 点击替代 |
|---|---|---|
| 选中卡片 | Tab 聚焦，Enter / Space 选中 | 点击 |
| 移动 | 方向键移动 1 格，Esc 取消，Enter 确认 | 卡片菜单中的“上移 / 下移 / 左移 / 右移” |
| 缩放 | Shift + 方向键调整占格 | 卡片菜单中的“放大 / 缩小”或占格选择器 |
| 删除 | Delete | 卡片菜单“移除”（可撤销） |
| 反馈 | 实时区域播报“已移到第 2 列第 3 行 / 现为 2 列 × 2 行” | 同 |

### 6.4 撤销 / 重做

- 编辑会话内维护操作栈（候选上限 50 步）：移动、缩放、添加、删除、套用模板、容器分割比例变化；
- 撤销 / 重做按钮在编辑模式页头可见，键盘 `Ctrl/Cmd+Z`、`Shift+Ctrl/Cmd+Z`；
- “取消”整体放弃，等价于撤销全部；“完成”后栈清空；
- 套用模板属一步可撤销操作，且**自动保留上一个已提交布局为“上一个布局”**，防止误覆盖（§9.3）。

## 7. 自由排列

“自由排列”在首版即 §5.4 的方案 A（垂直紧凑下的自由顺序与尺寸），有意留白用 Spacer（§16）；方案 B / C 不在首版范围。下列不变量成立（投影层的不变量见 §14.6）：

1. 任何时刻网格项不重叠；
2. 每个网格项的占格不小于其内容的 `minSize`；
3. 布局序列化后再反序列化得到同一几何（确定性，便于测试）；
4. 列数变化时的重排是**纯函数**（相同输入相同输出），可在单元测试中穷举；算法与夹具见 §14、§19。

## 8. 布局容器（格式模板）

### 8.1 容器与卡片是不同对象

容器本身占据网格项（`colSpan × rowSpan`），内部再细分为槽位。容器**不能**包含财务逻辑：不改变子卡片的时间范围、币种或模式（总需求规格 §4.2、§3.1）。

### 8.2 自由分割容器（“田字格”）

所有者要求：左右分割、上下分割、田字格（可自由调整比例）、非对称布局。

**几何模型（【推荐】分两期）**

| 期 | 模型 | 说明 |
|---|---|---|
| 首期【已确认 2026-10-27，Q-12】 | **对齐式 `GridSplit`**：`cols` 个纵向分隔线 + `rows` 个横向分隔线形成共享分割，覆盖左右（2×1）、上下（1×2）、田字格（2×2），以及“1 大 + 2 小”（通过合并槽位）。田字格的十字中心手柄同时移动横纵两条分割线 | 比例参数少、手势直观、持久化小；适合手机 |
| 后期【待研究】 | **任意二叉分割树**：每个分割节点有自己的方向与比例，可嵌套出任意非对称结构 | 表达力强；编辑 UI、最小尺寸传播、跨设备映射都复杂得多 |

**比例**

- 持久化为整数（建议千分比 0–1000）而非浮点，避免精度漂移与序列化差异；
- 吸附点：1:1、1:2、2:1、1:3、3:1（候选）+ 键盘微调步长（候选 1% / Shift 5%）；
- 每个槽位的最小尺寸取自其卡片的 `minSize`（图表与卡片规格 §5.3）；分隔线只能拖到使所有槽位满足最小尺寸的范围内；
- 分隔手柄：视觉细线、命中区 ≥ 44 CSS px，仅在编辑模式出现；
- 宽高比：容器本身的最小 / 最大宽高比约束（例如不允许比 1:2 更细长）仅为**候选，不是最终值**，【待研究 OQ-LM-09】；Q-12 明确**不直接锁定 1:2**。

**槽位内容**：卡片；首期不允许槽位再放容器【已确认，Q-12】（见 §8.4）。**自由分割容器与滑动抽屉是首期必须实现的两种容器，且都必须支持 `1×1` 保底收缩（§17）。**

### 8.3 滑动抽屉容器

横向切换多张卡片的“抽屉 / 分页”式容器。

| 项 | 规则（【推荐】） |
|---|---|
| 内容 | 2–6 张卡片（上限候选）；每页一张卡片；首期不放子容器 |
| 切换 | 横向滑动；页码指示点 + 可选标题；同时提供“上一页 / 下一页”按钮或标签（非滑动替代） |
| 呈现 | 当前页完整显示；可露出邻页边缘暗示可滑动（候选） |
| 状态 | 当前页不跨会话持久化；从详情页返回时恢复（图表与卡片规格 §8.4） |
| 数据 | **只有当前页（及预取的相邻页）发起查询**；离屏页不挂载图表（性能） |
| 可访问性 | 容器 `role="region"` 且 `aria-roledescription="carousel"`；每页“第 N 张，共 M 张”；离屏页对读屏隐藏；不依赖滑动 |
| 减少动态 | 页间切换为即时或短淡入淡出 |
| 手势冲突 | 抽屉内含可横向拖动读数的图表时，读数需先长按激活，或将滑动限定在页边缘 / 指示条区域；方案取舍：【已确认原则，Q-13】普通模式与编辑模式分离；抽屉不得轻易抢占页面纵向滚动；图表交互不与抽屉滑动、卡片移动冲突；编辑模式的拖动不得误触详情页。具体交互（图表长按读数、抽屉从边缘识别滑动、编辑模式用明确手柄）为【推荐】，须真机验证后才定稿，Safari pointer capture 未验证 |

## 12. 格子编号与坐标【已确认 2026-10-27】

> §12–§20 记录所有者 2026-10-27 对跨设备布局迁移、空白占位与容器收缩的规则。**标注【已确认】的是规则本身；仍未定的参数与取舍集中登记在 §20（OQ-LM-xx），不要把它们当成已决定。** 本文的参考模型、示例与夹具（§14、§19）用一次性演算脚本核对过结果（脚本没有入库，也不是布局引擎实现）。W5 开发时以 §19 的夹具为验收起点。

### 12.1 行优先编号

目标网格有 `C` 列。格子用 `(r, c)` 表示第 r 行第 c 列，r、c 均从 **1** 开始。编号从 1 开始，从左到右递增，满一行再到下一行（Row-major）：

```text
编号   n = (r − 1) × C + c
行     r = ⌊(n − 1) / C⌋ + 1            （等价于 ⌈n / C⌉）
列     c = ((n − 1) mod C) + 1
```

| 3 列 | | | | 4 列 | | | |
|---|---|---|---|---|---|---|---|
| 1 | 2 | 3 | | 1 | 2 | 3 | 4 |
| 4 | 5 | 6 | | 5 | 6 | 7 | 8 |
| 7 | 8 | 9 | | 9 | 10 | 11 | 12 |
| 10 | 11 | 12 | | 13 | 14 | 15 | 16 |

**编号只在给定列数下有意义。** 同一个编号在不同列数下指向不同的行列：编号 5 在 3 列下是 `(2,2)`，在 4 列下是 `(2,1)`。因此任何持久化的位置编号都必须和它的列数 `baseCols` 一起保存；脱离列数的编号视为无效（§13.5）。

### 12.2 位置与尺寸是两个独立概念

- **位置编号** = 对象**左上角格子**的编号（锚点）；
- **尺寸** = 宽度跨度 × 高度跨度，写作 `宽×高`（单位：格）：`2×1` 是两列宽、一行高，`1×2` 是一列宽、两行高。持久化字段显式命名 `colSpan` / `rowSpan`，不依赖书写顺序；
- 位置不隐含尺寸，尺寸也不隐含位置。例如三列网格里的 `2×2` 对象 A：

```text
 A   A   ·
 A   A   ·
 ·   ·   ·
```

A 的位置编号是 1，占据格子 1、2、4、5。

### 12.3 占格集合与合法性

锚点 `(r, c)`、尺寸 `w×h` 的对象占据 `{(r+i, c+j) | 0 ≤ i < h, 0 ≤ j < w}`，对应编号 `n + i×C + j`。在 `C` 列网格里它**合法**，当且仅当：

```text
c + w − 1 ≤ C        （不越过行尾；行向下没有上限）
```

**占据的编号不是一段连续区间。** 常见错误如下：

| 想法 | 为什么错 |
|---|---|
| “`2×2` 起点 1 占 1、2、3、4” | 3 列下占 1、2、4、5；4 列下占 1、2、5、6。要用 `n + i×C + j` 计算 |
| “`2×1` 起点 3 占 3、4” | 在 3 列下 3 在行尾（`c = 3`），`3 + 2 − 1 = 4 > 3`，**非法**；编号 4 在下一行，不是它的右邻 |
| “编号相邻就是格子相邻” | 只有同一行内才成立；行尾与下一行行首的编号相邻，位置却不相邻 |

### 12.4 阅读顺序

同一列数下，按编号升序等价于按 `(行, 列)` 字典序，即“从左到右、从上到下”。**不同列数下的编号不能直接比较**；比较前先还原为 `(行, 列)`，或统一到同一个 `baseCols`。迁移优先级用的是**源布局**自己的阅读顺序（§13.3）。

## 13. 参与迁移的对象与优先级

### 13.1 对象清单【已确认】

外层根网格里的“网格项”都是迁移对象：

- 分析卡片；
- 自由分割容器、滑动抽屉容器、未来新增的其他布局容器；
- 用户主动创建的**空白占位对象**（Spacer，§16）。

容器**内部**的卡片不是外层迁移对象，随容器整体处理（§17.5）。

### 13.2 稳定唯一 ID【已确认】

每个对象有创建时生成、**永不复用、不随位置变化**的 `objectId`。迁移只依据 `objectId` 识别对象，不依据位置、标题或类型。分享导入时重新生成（配置与分享方案 §6.5）。

### 13.3 优先级【已确认】

```text
排序键 = (源行, 源列, objectId)      升序；objectId 按 Unicode 码点比较
```

即原布局左上角编号越小的对象优先级越高，也就是用户在原工作台里“从左到右、从上到下”的阅读顺序。`objectId` 只用于处理损坏配置里出现的同一锚点，保证顺序确定，**不是**业务优先级。

**优先级只来自布局规则。** 布局引擎不得读写交易，不得依据金额、分析结果、数据量或卡片内容改变对象顺序或位置（总需求规格 §3.1、§3.2；静态守卫测试，W2 交付）。

### 13.4 迁移的输入输出

| 输入 | 输出 |
|---|---|
| 对象列表：`objectId`、种类、锚点编号、`baseCols`、`colSpan`、`rowSpan`、用户意图的展示形态；类型约束（§15.1）；目标列数 `C` | 每个对象：`objectId`、锚点编号、`colSpan`、`rowSpan`、展示形态（`full` / `compact` / `collapsed` / `compat`，§15、§17）及降级原因 |

输入输出里**没有**视口高度，也没有任何财务数据。

### 13.5 损坏或不完整配置的确定性处理【推荐，细节 W2 冻结，OQ-LM-12】

规则的目标是：任何输入都得到合法布局，不丢对象，不随机。

| 情形 | 处理 |
|---|---|
| 同一锚点有多个对象 | 按排序键，先到者占位，后到者作为“位置冲突”走重定位（TC-06） |
| 锚点缺失、非整数、≤ 0，或缺 `baseCols` | 视为“未定位”：排在所有已定位对象之后，再按 `objectId`，走“最靠前的合法空位”（TC-09） |
| 尺寸缺失、非整数、< 1 | 取该类型默认尺寸（卡片取家族默认，Spacer 与容器取 1×1），打 `repaired` 诊断标记；标记不写回，直到用户保存 |
| 尺寸超过类型最大值 | 夹到最大值 |
| `objectId` 重复 | 保留首个；后者用派生 ID（如 `<id>~2`）保留内容，**不丢弃** |
| 布局条目引用的对象不存在（孤儿） | 忽略，不渲染；下次用户保存时清理 |
| 内容里有对象但布局里没有条目 | 视为“未定位”（新增卡片就是这样补位，§18.5） |
| 超出对象数量上限（§8.4 与配置与分享 §7） | 视同损坏配置，按配置与分享 §4.2 回退，保留原始副本 |

## 14. 投影：从权威布局推导目标列数

> **1.18.01**：本节的「先试原编号格」只在**同一列数**下使用（原样显示、损坏修复）。跨列数时编号会把卡片放到错误的行列（三列第 7 格到五列是第 2 行第 2 列），宽屏因此错位留白；跨列数显示改按阅读顺序重排，见 [S18 响应式布局引擎 §3](../features/S18-分析工作台响应式布局引擎-20261030.md)。

### 14.1 术语

| 术语 | 含义 | 是否持久化 |
|---|---|---|
| 权威布局 | 用户保存的几何：统一模式下是“主布局”，独立模式下是各“布局档案”（§18）。带 `baseCols` | 是 |
| 投影 | 把权威布局推导到目标列数 `C` 的结果。**纯函数**，相同输入相同输出 | 否（可缓存） |
| 展示形态 | 对象在投影里的呈现：`full`（完整）/ `compact`（容器的合法紧凑档）/ `collapsed`（容器 1×1 入口）/ `compat`（卡片兼容入口） | 用户意图可保存；**自动降级不保存**（§17.6） |
| 派生标记 | 投影附带的诊断信息：为什么降级、是否被夹宽（Spacer）、`repaired` | 否 |

### 14.2 总流程

```text
投影(权威布局, C, 约束, 策略):
 1 规范化      按 §13.5 修复输入，不丢对象
 2 排序        按 (源行, 源列, objectId) 升序               —— 优先级，§13.3
 3 逐个放置    对每个对象，在已放置对象留下的空间里：
     a. 形态序列   forms(对象, C)                            —— §15.3
     b. 试原锚点   用“同一个编号”在 C 列网格里的位置
                   第一形态合法（不越过行尾）且格子全空 → 放下，结束
     c. 被占用     从编号 1 起向后找“最靠前的合法空位”，同一形态放下   —— 纵向无限，必能找到
     d. 行尾放不下  按 OQ-LM-01 的策略处理（§15.5）
 4 紧凑（可选）  默认开启的垂直紧凑，见 §14.4、OQ-LM-03
 5 校验        §14.6 不变量；失败即实现缺陷，不得输出
```

要点：

1. **按编号保位**：原锚点用的是**同一个编号**，不是同一个行列。3 列里的 6（第 2 行第 3 列）到 4 列里是第 2 行第 2 列。这是所有者定的规则，效果是保持“阅读顺序里的序位”。
2. **被占用从不降级尺寸**：工作台纵向可无限延伸，被占用只意味着“往后找位置”（步骤 c）。
3. **只有宽度会触发降级**：`w > C`（步骤 a），或策略 P 下行尾放不下（步骤 d），或容器 / 卡片的内部最小可读区域不满足（§15.3、§17.3）。
4. **同一输入永远同一输出**：没有随机，没有对输入数组顺序的依赖（TC-21）。

### 14.3 “最靠前的合法空位”

```text
earliest(w, h):
  for n = 1, 2, 3, …:
      若 n 的列 c 满足 c + w − 1 ≤ C，且 n + i×C + j（0≤i<h, 0≤j<w）全部空闲 → 返回 n
```

必然终止：最后一个已占用行之后的所有格子都空，行首 `c = 1` 满足 `w ≤ C`（`w > C` 的对象已在步骤 a 降级或进入收缩 / 兼容形态）。扫描**从编号 1 开始**，所以被挤开的对象可能落到比原位更靠前的空位（TC-02 里 C 从 6 移到 4）。

### 14.4 垂直紧凑与投影的组合【规则的一半已确认，组合方式待决策 OQ-LM-03】

已确认（Q-09）：默认采用确定性的**垂直紧凑**排布，但保护用户有意创建的 Spacer、布局容器结构和明确保存的位置。

本节的推荐组合方式（夹具 §19 按此给出期望）：

- 步骤 4 的紧凑只做“**逐对象向上平移**”：按当前位置的阅读顺序处理，每个对象在**列不变**的前提下，只要上一行对应格子全空就上移一行，直到不能再上移；
- **Spacer 锚定**，不上浮，也不被当作普通空格消除；其他对象可以越过它旁边的空列上浮，但不会穿过它；
- 容器作为整体上浮，内部结构不变；
- 紧凑不改变宽度、高度和展示形态，也不改变列。

两点仍待所有者或原型决定：(a) 紧凑是否应用于**投影**（推荐：应用，否则列数骤减时会出现无意义的空行，TC-14 与 TC-20 都出现过）；(b) “明确保存的位置”指什么（例如用户在编辑模式钉住的对象）。Spacer 锚定的副作用也在 TC-20 里可见：它上方因收缩留下的空行不会被消除。

### 14.5 示例：三列迁到四列，四列迁到三列【已确认的规则，示例为所有者提供】

三列权威布局：A 为 `2×2` 起点 1（占 1、2、4、5），B 为 `1×1` 起点 3，C 为 `1×1` 起点 6。迁到四列：

1. A 优先级最高，原锚点 1 合法、空闲，占 `1、2、5、6`；
2. B 的原锚点 3 仍空闲，保留；
3. C 的原锚点 6 已被 A 占用，从编号 1 起找最靠前的合法空位——1、2、3 被占，**4 空闲**，C 落在 4。

```text
 A   A   B   C
 A   A   ·   ·
```

反向（四列→三列，对象配置同上，C 起点 4）：A 占 `1、2、4、5`；B 保留 3；C 的 4 与 A 冲突，最靠前的空位是 6：

```text
 A   A   B
 A   A   C
```

结论：算法不需要为“增加列数”和“减少列数”准备两套基本规则。减少列数会额外遇到“尺寸容纳不下”的问题，由 §15 处理。更多夹具见 §19。

### 14.6 不变量（INV）

每次投影的输出都必须满足；它们是 W5 单元测试与属性测试的基础（§19）：

| 编号 | 不变量 |
|---|---|
| INV-1 | 对象数量与 `objectId` 集合与输入完全相同，不丢、不增（修复产生的派生 ID 除外，且内容保留） |
| INV-2 | 任意两个对象的占格集合不相交 |
| INV-3 | 每个对象满足 `c + w − 1 ≤ C`，`w ≥ 1`，`h ≥ 1` |
| INV-4 | 每个对象的内部配置（卡片参数、容器树、分割比例、槽位内容）与输入逐字节相同 |
| INV-5 | 输出与输入数组顺序无关；多次执行结果相同 |
| INV-6 | 对已处于规范形态的权威布局，用其自身列数投影得到它自己（幂等） |
| INV-7 | 投影不写回权威布局，不改变任何持久化数据 |
| INV-8 | 任何对象都可访问：`full` / `compact` / `collapsed` / `compat` 四种形态都有可操作的入口 |

### 14.7 视口高度、布局空间与对象约束是三个概念

| 概念 | 含义 | 影响投影？ |
|---|---|---|
| 可视窗口高度 | 浏览器此刻可见的高度 | **不影响**。工作台可纵向滚动，不得因为屏幕不够高就折叠正常的 `2×2` 对象 |
| 工作台可用布局空间 | 宽度（决定列数 `C`，§5.1）；高度无上限 | 宽度决定 `C`；高度不限 |
| 对象尺寸约束 | 卡片 `minSize` / 降级档、容器的完整形态最小列数与比例、Spacer 范围 | **是**。只有它与 `C` 的关系会导致降级 |

投影函数的签名里**没有**高度参数（TC-25 断言这一点）。

### 14.8 无累计漂移【已确认】

**每一次**自动投影都从保存的权威布局重新计算，目标列数只是同一份配置的不同投影视图。

- 禁止链式推导（`3 → 4 → 2 → 3` 每步都以上一步的结果为基础）。TC-17 演示了链式推导会让对象位置漂移，而直接推导不会；
- 投影结果、自动收缩、夹宽、兼容入口等派生状态**不写回**；
- 只有用户明确进入编辑模式并“完成”，才允许更新权威布局，且更新规则见 OQ-LM-07；
- 实现提示：投影缓存键 = `(权威布局版本, C, 约束版本, 策略版本)`。

### 14.9 为什么是“单遍优先级贪心”

另一种想法是“两遍”：第一遍让所有原锚点合法的对象先保位，第二遍再重定位被挤开的对象。它让低优先级对象把高优先级对象推到更靠后的位置，违反“原锚点编号越小，迁移优先级越高”的已确认规则。TC-22 给出对照。所以投影采用按优先级逐个处理的**单遍**贪心；TC-06 展示它的一个副作用：被挤开的高优先级对象可能占掉后面对象的原位，这是预期行为。

## 15. 尺寸约束与降级

### 15.1 约束从哪里来

布局层不自己决定“多小还算可读”，它读取各对象类型**声明**的约束：

| 对象 | 声明的约束 | 定义在 |
|---|---|---|
| 卡片 | `minSize`、降级档 `sizeLadder`（按偏好顺序的若干 `宽×高`）、兼容入口行为 | [图表与卡片规格 §5.6](S17-图表与卡片规格.md) |
| 容器 | 完整形态最小列数 `minFullCols`、合法紧凑档、内部各槽位最小可读尺寸、比例范围 | 本文 §17、§8.2–§8.4 |
| Spacer | 最小 `1×1`，最大跨度候选 | 本文 §16 |

所有数值（`minSize`、各档宽高、`minFullCols`）都是【待研究】，由原型和真机冻结（OQ-LM-02、OQ-LM-09）。

### 15.2 什么时候才会降级

纵向可以无限延伸，因此：

| 触发 | 是否降级 | 处理 |
|---|---|---|
| 目标位置被更高优先级对象占用 | **否** | 往后找最靠前的合法空位（§14.3） |
| 视口高度不够 | **否** | 滚动（§14.7） |
| `w > C`（对象比整个网格还宽） | 是 | 沿降级档找宽度合适的形态；卡片无合适档则进入兼容入口；容器进入合法紧凑档，仍不行则收缩为 `1×1` |
| 原锚点在行尾，放不下原宽度（`c + w − 1 > C` 但 `w ≤ C`） | 取决于策略 | **OQ-LM-01** |
| 容器 / 卡片的内部最小可读区域在 `C` 列下不满足 | 是 | 同上：降级档 → 收缩 / 兼容 |

**不得**把对象缩小到无法理解或操作；`collapsed` 与 `compat` 是定义好的终点，不是继续往下缩。

### 15.3 形态序列 forms(对象, C)

| 对象 | 序列（按偏好从前到后；取第一个在 `C` 列下合法的） |
|---|---|
| 卡片 | 保存的尺寸（`w ≤ C` 且不小于 `minSize`）→ `sizeLadder` 中 `w ≤ C` 的各档 → `compat`（`1×1` 兼容入口，OQ-LM-11） |
| 容器 | 保存的完整尺寸（`w ≤ C` 且 `C ≥ minFullCols`）→ 合法紧凑档（OQ-LM-09）→ `collapsed`（`1×1`，§17） |
| Spacer | `min(w, C) × h`（夹宽，OQ-LM-04）；不会进入 `compat` 或 `collapsed`，更不会被删除 |

用户在权威布局里保存的尺寸始终是“完整尺寸”；降级形态只存在于投影里（§14.8）。

### 15.4 降级顺序【待研究 OQ-LM-02】

宽度不够时先改什么？候选：

| 候选 | 做法 | 适合 |
|---|---|---|
| ① 先减宽、保持高 | `3×1 → 2×1` | 数值卡、排行条等“横向展开”的内容 |
| ② 减宽并增高以保面积 | `3×1 → 2×2` | 日历热力等需要最小面积的图表 |
| ③ 由家族自己声明 | 每个家族的 `sizeLadder` 写明顺序 | **推荐起点**：布局层只执行，不替各家族决定 |

TC-04、TC-08a、TC-10 里用的降级档只是夹具设置，不是产品尺寸清单。

### 15.5 位置与尺寸的冲突：行尾放不下【待决策 OQ-LM-01】

场景：对象原锚点所在列太靠右，在目标列数下放不下它的**完整宽度**，但整个网格是放得下的（`w ≤ C`）。例如四列里的 `2×1` 起点 3（第 3–4 列）迁到三列：编号 3 在行尾，放不下。

| 策略 | 做法 | 保住 | 牺牲 |
|---|---|---|---|
| **S** 尺寸优先 | 保持尺寸，从编号 1 起找最靠前的合法空位 | 尺寸（可读性） | 位置编号，在阅读顺序里可能前移或后移 |
| **P** 位置优先 | 保持锚点编号，沿降级档缩小，直到放得下 | 位置编号 | 尺寸；没有合适降级档时仍要走 S |
| **L** 同行左移 | 保持所在行，把起点左移到恰好放得下的列；那里被占就走 S | 行 | 列、位置编号 |

示例（TC-07，四列→三列，B 为 `2×1` 起点 3，声明降级档 `1×1`）：S 得到 `A X · / B B ·`，P 得到 `A X B`。

这是一个**取舍**，不同类型的卡片未必适用同一结论（“缩小后图表还可读吗”因家族而异），因此**不做对所有卡片通用的最终决定**。夹具同时给出 S 与 P 的期望。原型暂以 S 运行只是为了让夹具可执行，不代表决定。需所有者在 W5 前选择：全局统一、按家族声明，或用户可配置。

### 15.6 卡片的兼容状态【待研究 OQ-LM-11】

卡片在任何降级档下都放不下（例如要求至少 4 列宽的卡片落在 3 列网格）时，进入“兼容 / 不可用状态”：以 `1×1` 的入口呈现，显示卡片名称与“在详情页中查看”，点击进入该卡片的详情页（详情页有整页空间，通常能完整显示）。它不删除卡片、不改配置，空间恢复后自动回到完整形态。具体样式见图表与卡片规格 §5.6。

## 16. 空白占位对象 Spacer【已确认 2026-10-27；参数待研究】

### 16.1 定位

Spacer 是**布局系统的对象，不是财务分析卡片**：没有分析引用、没有数据请求、没有状态机，只有位置与尺寸。它的用途是**用户有意保留的留白**：视觉分区、强调某张卡片、两组卡片之间的间隔、为未来的分析内容留位、个性化布局。

它与“普通空格”的区别：普通空格可以被自动补位消除；Spacer 是用户明确创建的对象，**自动补位不得把它当作普通空格消除**。

### 16.2 用户操作与存储【已确认】

| 操作 | 规则 |
|---|---|
| 添加 | 编辑模式的“添加”菜单里与“添加卡片 / 容器”并列 |
| 移动、调整尺寸 | 与其他网格项相同的拖动、手柄和键盘 / 菜单替代（§6.3）；尺寸以整格为单位，最小 `1×1` |
| 删除 | 编辑模式内，可撤销（§6.4）。删除是**用户操作**，同步时产生删除记录 |
| 保存 | 随个人布局保存；因为它是几何装饰，所以存放在**布局文档**里（统一模式在主布局，独立模式在对应档案），不进入内容文档（§18.2） |
| 跨设备 | 参与统一迁移流程，尽可能保留（§14、TC-11、TC-12） |

### 16.3 显示

- **普通模式**：真正的留白，没有边框、背景或文字；对读屏隐藏（`aria-hidden`）；
- **编辑模式**：虚线轮廓 + “空白”标签 + 手柄，可聚焦、可键盘操作；与分析卡片明显不同，也与“被自动收缩的容器”不同。

### 16.4 与自动紧凑的关系

Spacer 锚定：不上浮，也不被其他对象的上浮穿过（§14.4）。在垂直紧凑下，如果 Spacer 被拿掉，下面的对象会上浮填满；有 Spacer 时则保留这一块留白。

### 16.5 参与迁移

Spacer 按 §13.3 的排序键参与，原锚点编号、尺寸、优先级与其他对象相同（TC-11 保位，TC-12a 与高优先级对象冲突时改到最靠前的合法空位）。

### 16.6 极端窄屏：不能阻塞分析卡片【待研究 OQ-LM-04】

因为纵向可无限延伸，Spacer **不会**阻塞卡片的放置，它只会占用滚动距离。真正的问题是：一块 `3×2` 的留白在一列网格里仍有两行高，在手机上可能过大。候选：

| 候选 | 做法 | 备注 |
|---|---|---|
| a 夹宽（**当前夹具默认**） | 宽度夹到 `C`，高度不变（TC-12b） | 最简单；窄屏仍占原高度 |
| b 夹宽并限高 | 在窄网格里限制最大高度（候选值待测） | 避免大块留白吞掉屏幕 |
| c 临时折叠 | 在极窄网格里投影为 0 高 / 隐藏，宽度恢复后按权威尺寸回来 | 要把“不是用户删除”表达清楚 |
| d 不处理 | 原样 | 可能出现整屏空白 |

无论选哪个：

1. **所有者进一步确认前，不得自动删除用户的 Spacer。** 缩小、夹宽、临时折叠都只存在于投影中；
2. **区分“用户删除”与“系统临时降级”**：用户删除 = 权威布局里移除并产生同步删除记录；系统降级 = 只写入投影的派生标记（`shrunk` / `suppressed`），永远不写回，回到足够宽度时按权威尺寸自然恢复（每次都从权威布局重算，§14.8）；
3. Spacer 的最小尺寸、最大跨度（候选 `colSpan ≤ 当前列数`、`rowSpan ≤ 8`）、数量上限（候选：与卡片合计受 §8.4 对象总数约束，并另设 Spacer 数量上限）均待测。

## 17. 布局容器的 1×1 保底收缩形态【已确认 2026-10-27；UI 与参数待研究】

### 17.1 需求【已确认】

每一种布局容器——自由分割、滑动抽屉、未来新增的任何一种——都必须有一个保底的 `1×1` 展示形态。它的职责是让用户知道这里有一个容器，并给出进入完整内容的入口，**不要求**在这么小的空间里展示内部图表。

| 编号 | 要求 |
|---|---|
| C-1 | `1×1` 是容器的**安全降级形态**，所有容器类型必须支持 |
| C-2 | 不要求直接显示内部卡片的财务信息；入口上**不显示金额或图表** |
| C-3 | 不得删除、改写内部卡片，不得改变内部分析定义和计算结果 |
| C-4 | 必须能清楚识别这是一个容器（图标、简短名称），并有明确的打开入口 |
| C-5 | 点击后能访问容器内全部原有卡片，并能进入各卡片自己的详情页 |
| C-6 | 打开后有明确的返回路径 |
| C-7 | 返回后工作台的滚动位置、筛选与布局状态保留 |
| C-8 | 设备宽度恢复或切换到合适布局时，恢复完整形态 |
| C-9 | 编辑模式下明确显示“这是被收缩的容器”，而不是普通分析卡片 |
| C-10 | 收缩是显示状态，不是永久修改（§17.2） |

### 17.2 三样东西分开保存

| 内容 | 存在哪里 | 谁能改 |
|---|---|---|
| 用户原始配置：容器类型、槽位与卡片、分割比例（整数千分比）、完整尺寸 | 内容文档（容器树）与布局文档（完整尺寸），见 §18.2 | 用户（编辑模式保存） |
| 自动迁移后的目标布局：锚点、宽高 | **投影**，不持久化 | 算法（§14） |
| 当前展示形态：`full` / `compact` / `collapsed` | 投影的派生值；另有**用户意图**字段（§17.6） | 算法 / 用户 |

一个原本 `2×2` 的田字格在窄布局里临时显示为 `1×1`，回到合适宽度后**恢复原来的分割比例和内部卡片**，而不是把 `1×1` 当成新的永久尺寸（TC-16）。

### 17.3 什么时候才收缩

正常情况下优先保持完整容器。只有以下两种才收缩：

1. 完整尺寸的宽度超过目标列数，且没有合法的紧凑档；
2. 容器内部的**最小可读区域**在目标列数下不满足（例如田字格的每个槽位都需要一定宽度，所以需要至少 2 个网格列；一列网格里就只能收缩）。

**不因为以下原因收缩**：容器高度超过当前可见高度（工作台可纵向滚动，§14.7）；目标位置被占用（往后找位置即可）。

### 17.4 `1×1` 入口的内容【待研究 OQ-LM-05】

【推荐】图标（按容器类型区分）+ 简短名称（用户起的名称，没有则用默认名，如“田字格”）+ “N 张卡片” + 明确的“打开”入口；整块可点击，同时有可聚焦的按钮语义。不显示金额、占比、折线，因为在 `1×1` 里这些无法安全展示，也避免误读。编辑模式叠加“已收缩”徽标，并说明“在更宽的布局里显示完整内容”。

### 17.5 外层迁移只处理容器本身【已确认】

容器内部有四张卡片，外层网格也只看到**一个**布局对象：不会把内部卡片拆出来和其他工作台卡片重新混排。内部布局由容器自己的规则负责，可能的展示状态是：完整比例、合法紧凑、`1×1` 入口。原比例在目标尺寸下不再合法时，可以临时调整或降级，但**不得永久覆盖**原始比例配置。

### 17.6 自动收缩与用户主动收缩【待研究 OQ-LM-06】

用户可能在编辑模式里主动把容器收成 `1×1`（想让工作台更紧凑），这和“空间不足被自动收缩”必须区分。【推荐】的数据形状：

| 字段 | 位置 | 含义 |
|---|---|---|
| `presentation` = `full` \| `collapsed` | 权威布局条目 | **用户的意图**。`collapsed` 才表示用户主动收缩 |
| `expandedSpan`（`colSpan` × `rowSpan`） | 权威布局条目 | 用户主动收缩时仍保留的完整尺寸，便于还原；`presentation` 为 `full` 时它就是当前尺寸 |
| `derived.form` | 投影 | 自动降级的结果与原因，**永不写回** |

规则：用户保存编辑时，只写 `presentation`；一个因空间不足而被自动收缩的容器，保存时**不会**因此变成“用户主动收缩”。编辑模式需要区分显示“手动收缩”与“空间不足，已自动收缩”，并让后者能在够宽的布局里展开、编辑。如果用户在窄布局里想编辑这个被自动收缩的容器，需要提示“请在更宽的布局中编辑，或在独立布局档案中单独排列”（§18）。

### 17.7 完整查看方式【待研究 OQ-LM-05】

被收缩的容器点开后看什么？候选：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A 独立详情页 | 路由进入“容器详情页” | 深链、系统返回键自然、整页空间；移动端最易操作 | 页面切换；需要状态保留 |
| B 全屏覆盖面板 | 全屏 sheet / 模态 | 切换轻、返回像关闭 | 与系统返回键、深链配合差；可访问性（焦点陷阱）要小心 |
| C 自适应详情容器 | 窄屏用 A 或 B，宽屏用侧栏 / 嵌入面板 | 随空间变化 | 实现复杂；S18-B 才有大屏价值 |

共同要求：完整展示容器内的全部卡片，保留内部配置；能进入各卡片自己的分析详情页（图表与卡片规格 §8）；保留财务权限与数据口径（工作台全局筛选，被固定区间的卡片照常标明）；有返回路径，且返回后工作台滚动位置、筛选与布局状态不丢；移动端易于操作；**与分析卡片详情页不冲突**。

**两种详情页概念不同**：容器详情是“查看一组卡片”，路由与状态独立（例如 `…/workbench/container/:objectId`），没有“来源追溯”和“历史比较”；卡片详情是“深入研究某项分析”（图表与卡片规格 §8）。【推荐】窄屏起点用 A，空间允许时再考虑 C；最终取决于原型和真机。

### 17.8 容器详情里的数据规则

容器详情只是换一个地方显示同一批卡片：沿用工作台全局筛选或卡片自己的 `pinned` 区间，走同样的 read guard 和去重 / 过期结果丢弃（图表与卡片规格 §4.4、§4.5），不新增查询类型，不改变任何计算结果。

### 17.9 可访问性

入口是按钮，名称含容器名与“包含 N 张卡片”；打开 / 返回的焦点管理明确（返回后焦点回到入口）；方案 B 需要焦点陷阱与 Esc 关闭；减少动态偏好下无过渡动画。

## 18. 统一布局与设备独立布局档案

> **1.18.01 起本节只作历史参考**：现行模型是「基础权威布局 + 按列数（不是按设备或宽度档）的专属布局」，没有手动的统一 / 独立开关；只调整排列时保存为该列数的专属布局，增删卡片时成为新的基础布局。见 [S18 响应式布局引擎 §1、§6](../features/S18-分析工作台响应式布局引擎-20261030.md)。存储仍是本节的 `mode` / `profiles` 字段。

### 18.1 两种模式【已确认 2026-10-27】

| 模式 | 说明 |
|---|---|
| **统一布局（默认）** | 同一账号一套权威主布局。不同设备 / 窗口宽度下，系统用 §14 的统一迁移算法从主布局推导目标布局。用户不必分别维护手机、平板、桌面 |
| **独立布局（可选）** | 用户主动开启（设置里有明确开关）后，可以为不同宽度档案分别保存位置、尺寸与排列。分析卡片及其定义仍是账号共有内容，**只把几何分开保存** |

档案的判断依据是**真实可用宽度推出的列数**（§5.1），不是设备型号。例如平板分屏、桌面窄窗口会落到它们自己的档案。

### 18.2 内容与几何分离【已确认的原则，字段形状 W2 冻结】

| 层 | 内容 | 范围 |
|---|---|---|
| 内容文档 | 卡片身份与实例、分析定义、图表配置、容器树（槽位、卡片、分割比例） | **账号共有**，所有设备同一份 |
| 布局文档 | 主布局（`baseCols` + 各对象的锚点 / 宽高 / `presentation`）；独立模式下另有各档案；**Spacer 只存在于布局文档** | 统一模式一份；独立模式每个档案一份 |
| 派生（不持久化） | 投影、自动收缩、夹宽、兼容入口、`repaired` | 无 |

对象通过 `objectId` 把内容与布局关联起来。这样新增 / 删除卡片是对内容文档的修改；某设备单独调整几何，只改它自己的布局文档，**不必要地覆盖其他档案**（配置与分享方案 §5、§4.5）。

### 18.3 统一模式下的编辑【待决策 OQ-LM-07】

用户在一台 2 列的手机上编辑，而主布局是在 4 列平板上排的。编辑看到的是主布局的 2 列投影，“完成”后应当如何更新主布局？

| 方案 | 做法 | 风险 |
|---|---|---|
| M1【推荐起点】 | 以编辑后的排列作为新的主布局，`baseCols` 记为 2，并在保存前提示“这会成为所有设备的主布局；如果希望各设备分开排列，请开启独立布局” | 4 列的精细排列会因为在 2 列设备上的一次编辑而被改写 |
| M2 | 只把“相对改动”（顺序、尺寸）并回主布局，不重写 `baseCols` | 实现复杂；“相对改动”的定义不简单 |
| M3 | 统一模式只允许在“基准列数”的设备上编辑，其他设备只读 | 体验差 |

本规格只要求：编辑后的写回**只发生在用户明确保存时**；自动投影永远不写回（§14.8）。

### 18.4 独立模式下的档案【待研究 OQ-LM-08】

- **首次进入某档案**：没有保存过的档案以主布局的投影为初值显示；用户在该档案里第一次保存时，才把当时的排列物化为该档案（写时复制）；
- **档案之间互不覆盖**：编辑 A 档案不改 B 档案（TC-18）；
- **档案键的粒度**：精确列数（每个 `C` 一份，灵活但多）还是宽度档（如窄 / 中 / 宽三档，每档一个 `baseCols`）。所有者的例子是“手机 / 平板 / 桌面”三类，但实现不能只看设备型号。【推荐起点】宽度档，阈值待原型；
- **具体网格列数的开放门槛**（哪个宽度开放几列）待研究；
- 容器分割比例是否也按档案独立：当前按内容文档共用（保持“原始容器配置完整保留”），是否需要独立待研究；
- **切换模式**：统一 → 独立时各档案暂为空（投影显示）；独立 → 统一时保留各档案数据但不使用，并提供“以当前档案作为统一主布局”的选项。

### 18.5 新增、删除与同步

- 新增卡片：写入内容文档。各布局文档里还没有它的条目，投影按“未定位”规则（§13.5）把它放到末尾，用户在某个档案里挪动它并保存时才生成该档案的条目；
- 删除卡片：内容文档产生删除记录；各布局里的孤儿条目被忽略，下次保存时清理；
- 新增 / 删除 Spacer：只改所在布局文档；
- 同步粒度、冲突处理、离线编辑：配置与分享方案 §4.5（单一定义，本文不重复）。

- 说明：不做垂直紧凑时，A 的原锚点 3 在 1 列里是第 3 行，K 与 A 之间会多出一个空行；紧凑后消除（OQ-LM-03 (a)）。

**TC-16** 宽屏恢复完整形态（权威布局 2 列；先投到 1 列，再回到 2 列）
- 输入（2 列）：A@1(1×1)；B@2(1×1)；K@3(2×2)〔容器〕；C@7(1×1)
- 期望（1 列）：A@1(1×1)、B@2(1×1)、C@4(1×1)、K@3(1×1)〔收缩〕
  ```text
  A
  B
  K
  C
  ```
- 期望（2 列）：A@1(1×1)、B@2(1×1)、C@7(1×1)、K@3(2×2)
  ```text
  A B
  K K
  K K
  C ·
  ```
- 说明：两次投影都以同一份 2 列权威布局为输入；2 列结果与权威布局一致。

**TC-17** 无累计漂移（3→4→2→3 列）
- 输入（3 列权威布局）：A@1(2×1)；B@3(1×1)；C@4(2×1)
- 正确做法（每次都从权威布局投影）：3 列结果与权威布局相同：
  ```text
  A A B
  C C ·
  ```
- 错误做法·第 1 步（3→4，以 4 列结果为新基础）：
  ```text
  A A B ·
  C C · ·
  ```
- 错误做法·第 2 步（4→2）：
  ```text
  A A
  B ·
  C C
  ```
- 错误做法·第 3 步（2→3）：
  ```text
  A A B
  · C C
  ```
- 说明：链式推导后 C 从“第 2 行第 1–2 列”漂移到“第 2 行第 2–3 列”。这正是禁止链式迁移的原因。

**TC-20** 极端窄网格：所有类型对象在 1 列下仍可访问
- 输入（4 列）：K@1(2×2)〔容器〕；P@3(2×1)〔空白〕；W@9(4×1)；Z@13(1×1)
- 期望（1 列）：K@1(1×1)〔收缩〕、P@3(1×1)〔夹宽〕、W@4(1×1)〔兼容〕、Z@5(1×1)
  ```text
  K
  ·
  P
  W
  Z
  ```
- 期望（3 列）：K@1(2×2)、P@7(2×1)、W@3(1×1)〔兼容〕、Z@10(1×1)
  ```text
  K K W
  K K ·
  P P ·
  Z · ·
  ```
- 说明：1 列时 P（Spacer）锚定在第 3 行，它上方因 K 收缩留下的空行不会被消除；这是“Spacer 锚定”的副作用（OQ-LM-03）。W 无合适降级档，进入兼容入口，仍可访问。

**TC-22** 对照：两遍“先保位、后重定位”的做法（被拒绝）
- 输入（3 列）：A@1(1×1)；B@2(2×2)；C@4(1×2)
- 单遍优先级贪心（本规格采用）→ 2 列：
  ```text
  A ·
  B B
  B B
  C ·
  C ·
  ```
- 两遍法（低优先级的 C 先保住原位，B 被挤到后面）→ 2 列：
  ```text
  A ·
  · C
  · C
  B B
  B B
  ```
- 说明：两遍法让 C 排到 B 之前，违反“原锚点编号越小优先级越高”。
