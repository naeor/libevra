# S17 · 工作台布局与格式模板规格

> 最后核对: `486c603` / 2026-10-26
> 性质：**设计与技术规格（规划文档）**。所有交互、尺寸、算法都是【推荐】或【待研究】，**没有任何一项被所有者批准为视觉定稿**；网格单位、行高、列数、容器比例等一律为候选，须原型与真机后冻结。【未开发】。
> 上位：[S17 总需求规格](../product/S17-模块化财务分析工作台-总需求规格.md)。卡片内部见[图表与卡片规格](S17-图表与卡片规格.md)；布局的保存、跨设备、分享见[配置与分享方案](../product/S17-工作台个人配置与布局分享-方案草案.md)。
> **E 层（布局与容器）不做任何财务计算、不改时间筛选、不混合币种**（总需求规格 §4）。

## 1. 范围与原则

1. **普通模式与编辑模式严格分离**：日常看分析不触发拖动、缩放；
2. **布局只组织卡片，不触碰数据**：任何布局操作不得生成、修改、删除交易，不影响计算结果（总需求规格 §3.1）；
3. **列数由真实可用空间决定**，使用 CSS 像素的容器实际宽度，不是物理像素、不是机型名、不是视口；
4. **安全降级**：布局数据缺失 / 损坏 / 版本不符时回退到可用布局，绝不白屏；
5. **可访问**：所有只能靠拖动完成的操作必须有单指针 / 键盘替代（WCAG 2.2 拖动动作的 AA 要求）；
6. **性能**：纵向不设固定行数上限，但按需渲染（图表与卡片规格 §9）。

## 2. 对象模型（概念）

| 对象 | 说明 | 是否有财务语义 |
|---|---|---|
| **工作台 Workbench** | 一个用户一个作用域下的一套布局（作用域见配置与分享 §3） | 无 |
| **根网格 Root grid** | 工作台的第一层：N 列、行向下无限延伸，网格项按“占格”放置 | 无 |
| **网格项 Grid item** | 根网格里占据 `w 列 × h 行` 的单元，内容是**卡片**或**容器** | 无 |
| **卡片 Card instance** | 一个分析实例的展示（图表与卡片规格 §4） | **有**（但语义由分析定义决定，与布局无关） |
| **容器 Container** | 一种特殊网格项，内部有若干**槽位（slot）**，槽位里放卡片（或受限的子容器）。分两种：自由分割、滑动抽屉 | **无** |

容器是“摆放卡片的几何结构”，**不是数据结构**：它没有指标、不聚合子卡片、不决定筛选。因此容器内的卡片仍然只遵守卡片自己的数据规则（总需求规格 §4.2、图表与卡片规格 §4.4）。

## 3. 普通模式与编辑模式

### 3.1 入口与出口

| 项 | 规则（【推荐】） |
|---|---|
| 入口 | 分析页明确的“自定义布局”入口（例如页头次要按钮或菜单项）；**不**通过长按卡片隐式进入 |
| 普通模式 | 卡片只响应查看与进入详情；无格线、无拖动手柄、无尺寸控制；页面外观像成熟的财务产品 |
| 编辑模式 | 进入后页头切换为“完成 / 取消”；显示棋盘格背景、卡片边界、手柄与尺寸控制；底部或侧栏出现“添加卡片 / 添加容器 / 套用模板” |
| 退出 | “完成”提交本次改动；“取消”放弃（有未保存改动时二次确认）；系统返回键等同于取消（有改动时确认） |
| 误触防护 | 编辑模式内的破坏性操作（删除卡片 / 容器）可撤销（§6.4）；不依赖确认弹窗 |
| 编辑中断 | 应用被杀、断网、账号被退出时：编辑中的草稿**不得**部分写入已提交布局；是否本地保留草稿【待研究】（见 §10） |

### 3.2 数据只读保证

编辑模式下，卡片仍显示真实分析结果（或占位骨架），但**任何点击不会进入详情页**（避免误入）、不会触发交易写入。静态守卫测试（总需求规格 §3.2）覆盖此条。

## 4. 编辑模式视觉（【推荐】）

参考 Apple 风格的简洁自然，而非复杂的网页编辑器（总需求规格 §8）：

- 棋盘格 / 网格线：**低对比度**，仅编辑模式显示，列数可辨认；浅色与深色主题各自有令牌；
- 卡片边界：细边框 + 轻微抬升；可选中卡片出现控制手柄；
- 空白可放置区：以虚线或浅色格标示；
- 拖动时：被拖卡片轻微放大 / 抬升；目标位置以**与品牌一致的克制绿色**（`#55997a` 的低饱和变体）高亮合法落点预览；非法位置不高亮；
- 动画：连续柔和；`prefers-reduced-motion` 下直接跳到终态；
- 七主题与深浅色均需验收；中英文标签长度差异不撑破控件。

## 5. 基础网格

### 5.1 列数

所有者要求：用户可选两列、三列或其他技术可行的列数，**取决于真实 CSS 空间**，不假设所有手机都能三列（总需求规格 §8）。

```text
可用列数上限  maxCols = floor((W − 2·margin + gap) / (minCol + gap))
卡片列宽      colWidth = (W − 2·margin − (cols − 1)·gap) / cols
```

`W` 为工作台容器内容盒的 CSS 宽度（扣除安全区），`margin` 页边距，`gap` 卡片间距，`minCol` 最小列宽。**全部是候选值**，下表以 `margin=16, gap=12` 做算术示例：

| 容器宽 W | minCol=110 的 maxCols | minCol=130 的 maxCols | 说明 |
|---|---|---|---|
| 320 | 2（列宽约 138） | 2 | 小屏手机 |
| 375 | 2（约 165） | 2 | |
| 390 | 3（约 111） | 2（约 173） | 差异点：minCol 决定 390 宽的手机能否三列 |
| 430 | 3（约 125） | 2（约 193） | |
| 768 | 6 | 5 | 平板竖屏（S18 重点） |
| 1024 | 8 | 7 | |

- **用户选择**：列数选择器只列出 `2 … maxCols` 中**当前可用**的值；
- 窗口缩小导致用户已选列数不可用 → 自动降到当前 `maxCols` 显示，**不覆盖用户保存的偏好**，空间恢复后回到所选值；
- `minCol`、`margin`、`gap`、默认列数：【待研究】，由原型的可读性测试决定；默认列数策略见 Q-10。

### 5.2 占格记法

所有者尚未确定记法（总需求规格 §8）。候选：

| 方案 | 写法 | 说明 |
|---|---|---|
| α【推荐】 | `宽×高`，单位为格，如 `2×1` = 2 列宽、1 行高 | 与屏幕直觉一致；文档中首次出现必须写“2 列 × 1 行”以免歧义 |
| β | `行×列` | 数学矩阵习惯，易与 α 混淆 |

【待决策 Q-09】。无论选哪个，持久化字段用显式命名（`colSpan`, `rowSpan`），不依赖记法顺序。

### 5.3 行高与尺寸

| 项 | 候选 | 说明 |
|---|---|---|
| 行高 | (a) 固定值（例如 72px）；(b) 等于列宽（方格） | (a) 内容高度可预期；(b) 卡片比例随列数变化，窄屏卡片更矮。**【待研究】** 原型对比 |
| 最小占格 | 由卡片家族声明 `minSize`（图表与卡片规格 §5.3） | 缩放手柄不允许缩到小于 `minSize` |
| 最大占格 | `colSpan ≤ 当前列数`；`rowSpan` 候选 ≤ 8 | 防止单卡片占满大量空间 |
| 纵向 | 无固定上限 | 视口外卡片按需挂载 |

### 5.4 摆放与重排策略

| 方案 | 行为 | 优点 | 缺点 |
|---|---|---|---|
| A 垂直紧凑【推荐首版】 | 卡片自动上浮填补空洞；拖动时其余卡片被向下推 | 无重叠、无空洞、结果可预测；跨设备映射简单 | 用户无法刻意留白 |
| B 允许空洞 | 卡片只能放在空闲格；不自动上浮 | 用户对布局有完全控制，可刻意留白 | 不同列数下同一布局可能出现大量空洞；跨设备更难 |
| C 推挤 + 空洞 | 拖到已占位置时推开相邻卡片 | 手感好 | 实现复杂；推挤结果有时出人意料 |

**空洞与紧凑的取舍属【待决策 Q-09】**（与跨设备方案 Q-08 相关）。采用成熟网格库还是自研，需 S17 阶段 5 前做独立 spike（评估项：包体、触摸 / Safari 行为、可访问性、许可证、与自适应卡片的配合），不在本文冻结。

## 6. 拖动、吸附、缩放、撤销

### 6.1 拖动（触摸与指针）

- 触摸：在编辑模式下从卡片的**拖动手柄**拖动，或**长按**卡片（候选 ≈ 250ms）后拖动；页面其余区域仍可正常纵向滚动；
- 指针（鼠标 / 笔）：按住手柄或卡片标题栏拖动；
- 拖动中：显示合法落点的预览占位；接近视口边缘时自动滚动；
- 释放：吸附到最近的合法格；非法落点则卡片平滑回到原位；
- 吸附阈值、自动滚动速度、长按时长：【待研究】。

### 6.2 缩放

- 选中卡片出现**尺寸手柄**（角或边）；拖动时按整格吸附；
- 手柄命中区 ≥ 44×44 CSS px，视觉上可以更小；
- 缩小到低于卡片 `minSize` 被拒绝并给出轻提示；放大受列数与容器限制；
- 缩放时实时显示当前占格（如“2 列 × 2 行”）。

### 6.3 键盘与单指针替代（必须）

| 操作 | 键盘 | 触摸 / 点击替代 |
|---|---|---|
| 选中卡片 | Tab 聚焦，Enter / Space 选中 | 点击 |
| 移动 | 方向键移动 1 格，Esc 取消，Enter 确认 | 卡片菜单中的“上移 / 下移 / 左移 / 右移” |
| 缩放 | Shift + 方向键调整占格 | 卡片菜单中的“放大 / 缩小”或占格选择器 |
| 删除 | Delete | 卡片菜单“移除”（可撤销） |
| 反馈 | 实时区域播报“已移到第 2 列第 3 行 / 现为 2 列 × 2 行” | 同 |

### 6.4 撤销 / 重做

- 编辑会话内维护操作栈（候选上限 50 步）：移动、缩放、添加、删除、套用模板、容器分割比例变化；
- 撤销 / 重做按钮在编辑模式页头可见，键盘 `Ctrl/Cmd+Z`、`Shift+Ctrl/Cmd+Z`；
- “取消”整体放弃，等价于撤销全部；“完成”后栈清空；
- 套用模板属一步可撤销操作，且**自动保留上一个已提交布局为“上一个布局”**，防止误覆盖（§9.3）。

## 7. 自由排列

“自由排列”在首版即 §5.4 的方案 A（垂直紧凑下的自由顺序与尺寸）；方案 B / C 是否提供【待决策 Q-09】。无论哪种，下列不变量成立：

1. 任何时刻网格项不重叠；
2. 每个网格项的占格不小于其内容的 `minSize`；
3. 布局序列化后再反序列化得到同一几何（确定性，便于测试）；
4. 列数变化时的重排是**纯函数**（相同输入相同输出），可在单元测试中穷举。

## 8. 布局容器（格式模板）

### 8.1 容器与卡片是不同对象

容器本身占据网格项（`colSpan × rowSpan`），内部再细分为槽位。容器**不能**包含财务逻辑：不改变子卡片的时间范围、币种或模式（总需求规格 §4.2、§3.1）。

### 8.2 自由分割容器（“田字格”）

所有者要求：左右分割、上下分割、田字格（可自由调整比例）、非对称布局。

**几何模型（【推荐】分两期）**

| 期 | 模型 | 说明 |
|---|---|---|
| 首期【推荐】 | **对齐式 `GridSplit`**：`cols` 个纵向分隔线 + `rows` 个横向分隔线形成共享分割，覆盖左右（2×1）、上下（1×2）、田字格（2×2），以及“1 大 + 2 小”（通过合并槽位）。田字格的十字中心手柄同时移动横纵两条分割线 | 比例参数少、手势直观、持久化小；适合手机 |
| 后期【待研究】 | **任意二叉分割树**：每个分割节点有自己的方向与比例，可嵌套出任意非对称结构 | 表达力强；编辑 UI、最小尺寸传播、跨设备映射都复杂得多 |

**比例**

- 持久化为整数（建议千分比 0–1000）而非浮点，避免精度漂移与序列化差异；
- 吸附点：1:1、1:2、2:1、1:3、3:1（候选）+ 键盘微调步长（候选 1% / Shift 5%）；
- 每个槽位的最小尺寸取自其卡片的 `minSize`（图表与卡片规格 §5.3）；分隔线只能拖到使所有槽位满足最小尺寸的范围内；
- 分隔手柄：视觉细线、命中区 ≥ 44 CSS px，仅在编辑模式出现；
- 宽高比：容器本身的最小 / 最大宽高比约束（例如不允许比 1:2 更细长）仅为**候选，不是最终值**，【待研究 Q-12】。

**槽位内容**：卡片；首期不允许槽位再放容器（见 §8.4）。

### 8.3 滑动抽屉容器

横向切换多张卡片的“抽屉 / 分页”式容器。

| 项 | 规则（【推荐】） |
|---|---|
| 内容 | 2–6 张卡片（上限候选）；每页一张卡片；首期不放子容器 |
| 切换 | 横向滑动；页码指示点 + 可选标题；同时提供“上一页 / 下一页”按钮或标签（非滑动替代） |
| 呈现 | 当前页完整显示；可露出邻页边缘暗示可滑动（候选） |
| 状态 | 当前页不跨会话持久化；从详情页返回时恢复（图表与卡片规格 §8.4） |
| 数据 | **只有当前页（及预取的相邻页）发起查询**；离屏页不挂载图表（性能） |
| 可访问性 | 容器 `role="region"` 且 `aria-roledescription="carousel"`；每页“第 N 张，共 M 张”；离屏页对读屏隐藏；不依赖滑动 |
| 减少动态 | 页间切换为即时或短淡入淡出 |
| 手势冲突 | 抽屉内含可横向拖动读数的图表时，读数需先长按激活，或将滑动限定在页边缘 / 指示条区域；方案取舍【待决策 Q-13】，Safari pointer capture 未验证 |

### 8.4 容器约束与嵌套限制

下列均为候选，用于防止“无限嵌套”“极端比例”“渲染炸弹”，**数值待原型与性能基准**：

| 约束 | 候选 |
|---|---|
| 嵌套深度 | 首期：容器内**不放容器**（深度 1）；后期最多 2 层 |
| 容器最小占格 | 由槽位 `minSize` 之和与间距推出；不满足时禁止创建 / 缩小 |
| 每个容器的槽位数 | 自由分割 ≤ 4（首期）；抽屉 ≤ 6 |
| 每个工作台的卡片总数 | 候选 ≤ 40；容器总数候选 ≤ 12；超过时禁止添加并提示（同时是导入校验的上限，配置与分享 §7） |
| 容器间互拖 | 允许把卡片拖入 / 拖出容器；拖入时校验最小尺寸，不满足则拒绝 |
| 容器删除 | 删除容器会询问“同时移除其中的卡片”或“把卡片移出到网格”，可撤销 |
| 抽屉与自由分割互嵌 | 首期不允许 |

### 8.5 容器内部仍遵守数据规则

容器内的卡片：沿用工作台全局筛选或自己的 `pinned` 区间（图表与卡片规格 §4.4）；仍走同一分析去重与过期结果丢弃；容器不会让两个槽位对“同一时间范围”出现不一致，除非其中卡片被固定且标明区间。

## 9. 默认工作台与预设模板

### 9.1 原则

普通用户**无需配置**：首次进入分析页直接看到设计完善的默认工作台，不被要求先选算法、网格或卡片（总需求规格 §7）。

模板不是“多一个页面”，而是**一棵可序列化的布局树 + 每张卡片的分析参考 + 筛选继承规则**。模板数据**不含任何账务数据**（配置与分享 §6.2）。

### 9.2 候选模板

| 模板 | 目的 | 卡片内容（用能力目录 ID，**以已上线批次为限**） |
|---|---|---|
| **日常总览**（默认，【推荐】） | 一眼看清近期收支 | AN-B01 概览（2×1）；AN-B03 比较（2×1）；AN-B04 趋势（2×2）；AN-B05 分类占比（2×2）；AN-B08 热力（2×2）；AN-B02 日均与笔数（1×1）；AN-B09 最大单笔（1×1）；AN-B11 依据（2×1） |
| **消费习惯** | 看自己怎么花钱 | AN-B05、AN-B06、AN-A04 周内分布、AN-A05 月内分布、AN-B08、AN-A12 平均每笔与频次（抽屉容器可收纳周内 / 月内分布） |
| **收支研究** | 深入看变化与结构 | AN-B04、AN-A06 周趋势、AN-A01 变化贡献、AN-A02 分类环比、AN-P01 移动平均、AN-P02 去年同期（含田字格示例） |
| **多币种观察** | 有外币账目的用户 | AN-B10 原币构成、AN-P05 币种敞口、AN-B01（综合）、AN-B04（综合）、AN-B11 依据 |
| **空白自定义** | 从零开始 | 空网格 + “添加卡片”引导 |

表中尺寸是**示意**，在 2 列手机网格上的占格；它们不是已确认设计。

**模板按批次分期上线**：一个模板只能包含当时已上线的分析；批 1 首发只提供“日常总览”和“空白自定义”，其余随批 2 / 批 3 上线（能力目录 §8）。

**“多币种观察”与设备级设置**：综合折算的开关是设备本地偏好（`libevra.fx-mode:<userId>`，S16-E 矩阵）。模板**不得静默改变**该开关；套用该模板时若尚未开启综合模式，提示“此模板的部分卡片需要开启综合折算”，由用户决定。

### 9.3 套用与恢复

| 操作 | 行为 |
|---|---|
| 套用模板 | 预览 → 选择“替换当前布局”或“另存为新方案”；替换时自动保留上一个已提交布局为“上一个布局”，可一键还原（候选保留最近 1–3 个） |
| 保留个人配置 | 套用模板**不**覆盖用户的全局筛选与列数偏好，除非用户在预览中勾选 |
| 恢复默认 | 重置为“日常总览”的当前发布版本；有确认与可撤销 |
| 默认版本演进 | 用户**从未编辑过**布局时，随应用版本获得改良后的默认；已编辑过的用户保持自己的布局，并可选择“查看新默认”【推荐】 |
| 用户模板 | 用户可把当前布局保存为“我的方案”（数量上限候选 10），可重命名、删除；分享见配置与分享 §6 |

## 10. 保存、恢复与草稿

- 编辑会话是**内存里的草稿**；“完成”时一次性提交（原子写入个人设置存储）；
- 提交成功前不覆盖已提交布局；提交失败（离线、被退出）保留草稿并提示重试【推荐】；
- 草稿是否落本地以抵御应用被杀：【待研究】——收益是不丢编辑，风险是增加“按用户隔离的本地数据”清理面（须纳入 S16-E 的 `deviceStorageKeys` 清理）；
- 并发：同一用户在两台设备同时编辑，以“版本号 + 整体替换并保留对方为‘上一个布局’”处理，不做逐卡片合并（首版），见配置与分享 §4。

## 11. 性能与测试要点

- 拖动 / 缩放期间只更新几何，不触发数据重算；
- 视口外卡片与抽屉离屏页不挂载图表；
- 重排算法为纯函数，单元测试穷举：不同列数、不同占格、`minSize` 冲突、删除后紧凑；
- 序列化往返测试；损坏数据（缺字段、越界占格、环形引用、超限节点数）逐项降级测试；
- 真机：iOS Safari / PWA 拖动与滚动冲突（尚未验证）；小屏 320 宽与大字号；
- 可访问性：全键盘完成“添加 → 移动 → 缩放 → 删除 → 撤销 → 完成”。
