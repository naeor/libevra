本规范负责「控件用途 → 风格表现」。颜色、字号、布局仍遵循同目录原有规范；不替代业务权限、导航协调器或特殊动画。

### 动效语义与实验依赖

页面导航由 `workspace/paneHistory.ts` 与 `PaneRouter.tsx` 管理，S19 呈现层只消费已接受的 push/pop；`pilot.tsx` 是唯一协调器，按账本空间海浪 → switchTab → objectExpand → 记账工作区 → 默认次级导航的顺序判定，五类语义各用一个呈现器，不因材质相同而叠加另一套导航或入场动画。账目容器 Object Expand 的正式接入与独立演示边界见 §6；正式实现复用原型几何，演示数据不进入业务。

**常驻底栏随层级退出 / 升回**（1.19.75，审查 T1）：底栏在哪些层级显示只由 `s19/motion/navigation.ts` 的 `navVisibleAt(level, workspaceChrome)` 决定——主 Tab 显示、次级页面隐藏、记账工作区在 S19 浅色手机端隐藏（1.19.78，`workspaceChrome` 来自 `useS19Light()`）、Original 与深色仍显示。前后两页结果不同时，底栏在 S19 浅色手机外壳里向下退出（走完才 `hidden`）或先显示再从屏幕下方升回，复用底栏让位的 `NAV_YIELD`（退出 180ms、升回 220ms，升回不过冲），压在页面转场之上（A / B1 / C 转场期间 z 81、B2 单独成组 `lv-persistent-nav`），中途反向从当前位置折返；对象展开不再放底栏副本。实现 `s19/motion/navMotion.ts`、`components/Layouts.tsx` 的 `PaneShell`。

**返回关系与换风格**（1.19.75，审查 T2–T5）：协调器给每一页记着“从哪一页进来”（`s19/motion/relations.ts`），只跟账号、账本、工作区挂钩，与外观无关——改风格 / 明暗 / 配色只收束正在播放的转场，返回关系保留；replace 出来的记录接过原记录的来源；从次级页 push / replace 去主 Tab 按返回方向播放（刚打开就被重定向的不播）；返回语义的出口用 `useReturnTo` / `useReturnToPath`（上一条正是目标时 `-1`）。账本空间的成员 / 分享走默认次级导航；在开着的弹层里导航先收起再走（`closeThen`）。

**滚动位置与面板状态**（1.19.82）：返回（POP）到一条记录时恢复离开时的滚动位置，从别处回到主 Tab 接上该 Tab 上次的位置，打开新页面从页面自己的初始位置开始。S19 手机由协调器记（`relations.ts`），Original、电脑与 Pad 由工作区路由记（`workspace/scrollMemory.ts`），规则相同。从弹出面板里打开别的页面时，面板状态（通知的滚动位置、附件预览看的是哪一个）记在面板所在的历史记录上，返回到这条记录时等页面转场结束再重新打开面板（`lib/panelMemory.ts`）。应用离开屏幕超过 30 分钟算“不连续使用”，回来时两类记忆都重新开始，返回关系不动（`lib/continuity.ts`）；重新载入、换账号本来就从头开始。

`s19/motion/abcPresentation.ts` 和 `aTabs.ts` 仍直接引用 `experiments/abc-motion/controller.js` 与 `tab-glide.js`，由开发风格入口注册；`abcBridge.ts` 还依赖对应类型声明。该目录不能按“历史实验”删除。1.19.57 起控制器不再自己监听视口与舞台尺寸（原来任何尺寸变化都自行取消，iOS 工具栏伸缩会让 A / B1 / C 的转场闪到终点），视口变化由 `pilot.tsx` 按 Motion Token 的转场打断规则统一收束，被动画节点的内容尺寸变化也只按调用方传入的同一规则判断。后续建议在独立任务中把被产品消费的控制器及类型迁入共享呈现层，保留实验页作为调用方，并回归快速反向、返回、滚动恢复与减少动态效果；本轮维护不搬动实现。

### 四风格的深色背景与材质

同一张静态中性灰光场供 A、B1、B2 使用。各风格调整光场的取景和可见度，壁纸设置仍沿用既有选择。C 采用经典灰底。深色工具、选中、反馈、弹层和转场由同一套正式主题令牌驱动。

| 风格 | 背景定稿 | 内容与操作 |
|---|---|---|
| A 柔和空间 | 最轻处理，均匀的灰度环境 | 五档浮空继续承担视觉层级，顶区与卡片以阴影和表面明度区分。 |
| B1 深色瓷片 | 轻档，宽而柔的漫反射 | 内容瓷片不透明。Satin 用宽柔反射，Glazed 用较集中的灰白反射。 |
| B2 层叠玻璃 | 稍明显档，保留大尺度灰阶起伏 | 均衡档内容填充约 86%，操作面约 92%。玻璃边缘和透出的背景共同区分层次。减少透明度或不支持模糊时使用实底。 |
| C 经典精修 | 接近纯灰 | 黑灰顶区、实体卡片与分隔线保持经典结构，转场沿用 C 的节奏。 |

固定背景与随页面移动的内容分开绘制。换肤继续使用用户选择的手动或系统模式。屏幕尺寸变化沿用 Pad 规则，工作区的动画范围、跟随与返回历史各自独立。各小版本记录中“仅浅色”等表述描述当时的接入范围。

### 作用域标记（总闸）

S19 材质与转场只认外壳元素上的作用域标记 `data-s19-scope`（`apps/web/src/s19/scope.ts`）。2026-11-14 的内部整理（审查 H7）用它替换了原来复制进 247 条 CSS 选择器、5 处脚本判断和 4 个转场舞台的 `.lv-shell[data-shell="contents"]`，外观没有变化。`data-shell` 只管外壳布局（手机 `contents`、Pad `wide`、电脑版 `html[data-shell="desktop"]`），不再作为材质条件。

| 外壳 | `data-shell` | `data-s19-scope` | 生效层 |
|---|---|---|---|
| 手机外壳（含今天落到手机外壳的 iPad 尺寸登录前页面与 `/join/*`、`/legal/:id` 等独立路径，见审查 H10） | `contents` | `phone` | 通用层 + 手机专属层 |
| Pad 宽屏 | `wide` | `pad` | 通用材质 + 工作区局部呈现 |
| 电脑版 | 不渲染 `.lv-shell` | 不设 | 原组件外观 |
| 四个呈现器挂在 body 上的转场舞台；Gallery、Adaptation Lab 的模拟手机外壳 | `contents` | `phone` | 与手机外壳相同 |

- **通用层** `.lv-shell[data-s19-scope]`：只认标记存在。令牌重映射、卡片与分组、按钮、弹层、顶栏与工具、明细摘要与收起、记账工作区、编辑面、附件区、壁纸与页面环境、组件动效、转场舞台都在这一层；`componentMotion` 读这一层。
- **手机专属层** `.lv-shell[data-s19-scope="phone"]`：只收依赖手机底栏结构的规则——底栏本体与材质、“+”、Tab 选中圆片与 B1 / B2 玻璃胶囊、A 的 DepthGlide 胶囊、底栏里的记一笔菜单及其占位、B2 正文延伸到底栏后方的尾部空间、底栏上的账本胶囊（`current-book-caption.css` 整份，几何按底栏 12px 留白对齐）、底栏让位（`NAV_YIELD`）与软键盘打开时的原位隐藏。脚本里的底栏指示器（`tabIndicator.ts`、`aTabs.ts`）、账本胶囊收回（`useBookCapsuleMotion`）和协调器 `pilot.tsx` 的启用判断也读这一层：手机呈现器按视口计算，Pad 工作区使用下述局部呈现器。
- 浅色与风格条件（`data-theme-mode="light"`、`data-visual-style`）不并入标记，规则照旧各自写；Original 没有 `data-visual-style`，一条也不命中。
- **Pad 左侧导航（1.19.88 起，浅色在 1.19.90 修正）**。大屏触控侧栏复用四种材质的表面、选中和阴影。A 导航选中轻轻浮起，B1 用实体反射，B2 用玻璃选中层，C 用平面和清楚边缘。浅色模式的 Logo 用正文墨色和当前风格的操作面，导航图标继承按钮前景色。深色模式使用白色图形，小加号底座保留品牌色。适用于展开、紧凑和竖屏上下两段。
- **Pad 局部动效（1.19.85–1.19.86）**。正式页面在所属工作区按其宽度轻移和淡入，另一边、侧栏与分隔条保持原位。临时列沿宿主内缘展开，缩窄时回到原面板。B2 使用现有填充与细边界，避免为整块工作区实时取样模糊。减少动态效果时直接切换。Pad 的尺寸、模板映射与草稿策略见 [S18-B §10.5](S18-B-跨设备自适应布局与交互-设计讨论记录-20261027.md#105-已批准实施)。
- 下文有版本日期的示例保留当时范围。自 1.19.85 起，标记为通用层的浅色四风格材质同时覆盖 Pad。
- **守卫** `s19/scope.test.ts`：正式 CSS 不再用 `data-shell="contents"` 作 S19 作用域（只剩 `workspace/workspace.css` 的三条外壳布局规则）；标记只有上述两种写法；依赖底栏结构的规则只写在手机专属层，手机专属层也只收这些；脚本判断与转场舞台读写同一个标记。

## 2. 正式可调用材质与候选边界

| 风格 | 稳定默认 | 显式变体与边界 |
|---|---|---|
| A / Soft Surface | 柔和实体薄片，圆润边缘，宽浅阴影 | 继续复用现有卡片、工具、品牌色角色 |
| B1 / Porcelain | 原有不透明 Satin 瓷底 | `finish: "satin" / "glazed"` 共用实体底座、圆角、厚度；反射默认 60%。Satin 宽柔，Glazed 窄亮并有虚拟光源，不采样后方背景 |
| B2 / Glass | 原有稳定玻璃，保留清透／均衡／柔和 | `frosted` 用原生背景模糊；`clear` / `lens` 在普通 DOM 场景降级稳定玻璃。`optics: "enhanced"` 显式启用轻量边缘候选，不等于真实折射 |
| C / Classic Surface | 原有清楚的实体纸面 | 忽略不属于 C 的瓷/玻璃候选，不替换经典视觉语言 |

已确认参数只在 `MATERIAL_DEFAULTS` 定义：Frosted 放大目标 1.03×，Clear/Lens 1.05×；边缘 45%，左上亮、右下暗；瓷反射 60%。Material Lab 从这里读取。倍率是**有适当纹理时的目标**，不是任意 DOM 背景的承诺；`materialCapability()` 明确返回当前 DOM 实际倍率 1。不得为此持续截图、复制 DOM 或引入曲面 WebGL 生产管线。已有纹理采样代码仍只由 Lab 引入。

普通组件默认 `finish: "auto", optics: "stable"`。新候选没有通过本轮 iPhone 验收前不得批量开启；调用处去掉 `appearance` 即回到稳定路径。瓷面实验的共用配方迁出不改变 Lab 的已选参数。

显式瓷面/增强玻璃用局部叠层承载反射，弹窗应放在页面层与卡片同级；已有把弹窗嵌在卡片内部的业务保持稳定默认，不直接开启候选，以免改变弹窗相对其他页面层的叠放顺序。材质伪元素不接收点击，滤镜不放在内容祖先上。

B2 原始三档值与账号偏好不变。展示卡片用 content；操作面使用 chrome，并令填充至少为 `contentFill + 0.12`，避免柔和档的操作面反而比展示卡片更透。原有模糊继续只作用于面板的装饰伪元素，不模糊文字、不在含 fixed 子节点的父容器加滤镜。输入、品牌主按钮、危险操作不接受透明材质覆盖。

## 3. 控件用途 → 默认表现

| 用途 / 调用 | A | B1 | B2 | C | 形状、状态与层级 |
|---|---|---|---|---|---|

| `danger` / `danger-quiet` | 四风格均用主题危险色语义 | 同左 | 同左，不玻璃化 | 同左 | 实底用于主要破坏操作，描边用于次要；不替代确认逻辑。非 `Button` 元素声明 `danger-quiet` 用途时（附件区「删除」）在手机材质下得到同一危险色文字 + 细描边（1.19.57） |
| `IconButton` | 轻薄工具片 | 瓷片 | 亮面操作玻璃 | 纸面 | 正圆 44px 点击区；必须传 `label` |

| `Card`：数据展示 | 薄片 | Satin 基底 | 内容玻璃 | 纸面 | card 圆角、普通层级；不假装可点击 |

| `BottomSheet` / `ChoiceSheet` | 实体操作薄片 | 现有瓷操作面 | 可读性优先的操作玻璃 | 实体纸面 | 既有 sheet 圆角；结构、档位、遮罩、关闭入口与下拉见下方「弹出面板模板」（1.19.58） |

### 弹出面板模板（1.19.58 起）

所有者 2026-11-14 的决定与逐个弹窗的“关闭前询问”分类登记在 [S19 审查后续待办与弹出面板模板](S19-审查后续待办与弹出面板模板-20261114.md) §2；本节是实施后的现行规则。外壳是 `components/BottomSheet.tsx`（底部面板）与 `components/CenterDialog.tsx`（中央对话框），可调令牌集中在 `components/panel-template.css`。

**六类模板**

| 模板 | 用途 | 外壳与档位 |
|---|---|---|
| T1 选项、操作列表 | 选一项或执行一个操作 | `BottomSheet`，按内容 `content`（最高到大档，1.19.63）；例外：账本选择用固定半屏 `half-fixed` |
| T2 表单编辑 | 填写少量字段 | `BottomSheet`，按内容 `content`（最高到大档，1.19.63）；例外：明细与分析筛选用高半屏 `tall`（固定高度，切换维度时高度不变，1.19.61） |
| T3 确认、警示 | 确认或在几个选项中选择 | `CenterDialog`（`ConfirmDialog` 为 `alertdialog`、`ChoiceDialog` 为 `dialog`），按内容 |
| T4 信息说明 | 展示信息，可附一个动作 | `BottomSheet`，按内容 `content`（最高到大档，1.19.63） |
| T5 大面积编辑 | 内容多、接近全屏 | `BottomSheet`，大档 `large`；门禁变体 `dismissible={false}` + `layer="gate"` |
| T6 轻量浮层菜单 | 锚定在按钮旁、无遮罩 | Pad 仍锚定在触发按钮旁；`DesktopPopover` 沿用独立桌面逻辑 |

**结构**：拖动条（只在可下拉时出现）→ 标题行（标题 + 可选说明，左侧可放返回、右侧可放工具，右上角统一的 44px ×）→ 内容滚动区 → 可选的固定底部操作区（`footer`）；安全区留白与软键盘抬升由外壳负责，内容不再自己加 `env(safe-area-inset-bottom)`。标题随内部状态变化的面板（筛选、预设库）在内容里用 `SheetHeader`。列表底部不再放重复的“关闭”行。

**高度：内容优先**（1.19.63，所有者 2026-11-14 看过各弹窗截图后决定：“我希望大部分弹窗都能够展示出它完整的内容，不用为了凑半屏之类的刻意去调低高度。”）。T1 列表、T2 表单、T4 信息说明一律**按内容，最高到大档**——与 T5 大档同一个上限，内容超过大档才在面板内滚动；不再以约 52%（T1、T2）或约 50%（T4）为上限。只有两处需要稳定高度的面板保留固定档：**账本选择**（固定半屏：所有者早先要求“约 45–55% 的稳定高度”，账本少时不缩成一条窄带、点击目标不贴着下缘）与**明细与分析筛选**（高半屏：切换左栏维度时面板不忽高忽低；下限 32rem 与 Pad 分屏窄工作区也用高半屏两点，所有者 2026-11-14 确认保留）。T5 仍是大档；中央对话框（T3）仍按内容。1.19.58–1.19.62 的半屏档 `half` 已删除（不再有调用方）。

档位只在手机宽度取值；比例乘 `--lv-vh`，在工作区里按工作区高度计算：

| 档位 | 令牌 | 现值 | 用于 |

**按内容档的高度过渡**（1.19.63，`lib/sheetHeight.ts`）：按内容的面板在加载中 → 有数据、空状态 → 有数据、校验提示出现、图片载入等内容变化时，从旧高度过渡到新高度，不在原地跳一下；时长与曲线与面板升起相同（令牌 `--lv-sheet-resize-ms` 260ms、`--lv-sheet-resize-ease` `cubic-bezier(0.32, 0.72, 0, 1)`）。只过渡内容引起的变化：可视区、工作区宽度或软键盘高度变了（面板的最大高度跟着变）就直接取新高度，不和键盘动画抢；第一次测量只记基准，面板升起时不额外播放；正在收起时、减少动态效果时都不过渡。过渡期间面板带 `data-sheet-resizing`，内容区暂时不出滚动条（滚动位置不变），结束后照常滚动。固定高度的档位（固定半屏、高半屏、大档）不需要。明细筛选标题行齿轮打开的“筛选设置”小卡（不属于模板）在底部面板里与面板内容同宽（左右各 16px，挂在标题行下方，1.19.61）；电脑版下拉里仍是锚定齿轮的 320px 小卡。第一版只支持下拉关闭，不做档位之间的拖动切换。数值按所有者看过的实际效果再调，只改令牌。

**遮罩**：弹窗出现后背景一律变暗，画在根节点伪元素上（根节点不做透明度动画，B2 的背景模糊才能采样后方页面）。浅色 Original：底部面板 `--color-overlay-soft`（.25）、中央对话框与大档面板 `--color-overlay`（.35）；深色：底部面板、对话框、大档同一档，取深色主题的 `--color-overlay-soft`（黑色 .52）；浅色 S19 外壳：底部面板、大档面板与同意书门禁用各风格的 `--s19-scrim`（A .24、B1 .26、B2 .22、C .24）；中央对话框（T3）用 `--s19-scrim-dialog`，同一色相、比面板深一档（A .34、B1 .36、B2 .32、C .34，1.19.61，与 Original 面板 .25 / 对话框 .35 两档对应），只认 `CenterDialog` 的根节点 `data-overlay-root="dialog"`，所以同样标着对话框档的大档面板与门禁不受影响。数值是令牌（`s19/s19-lab-tokens.css`，B2 在 `index.css`），颜色字面量不写进其他文件。对话框背后不再有背景模糊。模板遮罩只认 `data-overlay-scrim="sheet" | "dialog"`，不给自带底色的旧弹层再叠一层（同意书 1.19.59 起也用模板遮罩）。

### 选中指示与已选条件标签（1.19.62）

所有者 2026-11-14 定稿（来源与对比样板见 [S19 审查后续待办](S19-审查后续待办与弹出面板模板-20261114.md) §2.1；开发用样板页 `component-gallery.html#selection` 直接引用正式组件）。组件在 `components/ui/SelectionControls.tsx`，外观在 `components/ui/selection-controls.css`，纯逻辑（风格判断、关键帧、标签状态、删除后的焦点）在 `components/ui/selectionModel.ts`。

**四种风格同一个模型**：每种风格都有会移动的选中、网格选中、条件标签出现与消失三类行为，都有动画；区别只在外观与动效性格（B1 / B2 弹性玻璃、A 浮起、C 干脆滑动），逐项表现见 §3 表。规则只写在 S19 通用层（浅色、带 `data-s19-scope` 的外壳）；Original、深色、Pad 与电脑版回落基础外观。

| 组件 | 用法 | 保留什么 |
|---|---|---|
| `MovingSelection` | `<MovingSelection axis="y" role="tablist" aria-label=… aria-orientation="vertical">`，子元素是调用方自己的 `<button>`，用 `aria-selected` / `aria-pressed` / `aria-checked` 标出选中项；横向分段传 `axis="x"` | 按钮、角色、aria、点击与键盘处理全部由调用方保留；组件只加一块 `aria-hidden` 的选中块（B1 / B2 / C）。`base` 只决定基础外观（Original、深色、Pad、电脑版）：默认 `static` 不显示选中块（选中项保持调用方自己的样式）；`slide` 给共享分段控件，保留那块胶囊与原 200ms 滑动，胶囊外观由调用方给；`copy`（1.19.67）给 `SlidingSelection`，同样保留原 200ms 滑动，胶囊外观逐项复制选中按钮的计算样式。S19 里三者相同 |
| `SlidingSelection`（1.19.67 起是 `MovingSelection axis="x" base="copy"` 的薄包装） | 原调用写法不变：`<SlidingSelection className=… role=…>` 包住调用方的 `<button>` | 每个按钮的内容包一层 `data-select-label`：基础外观里选中块在未选按钮的底色之上、文字之下滑过（分析工作台的分类胶囊各自有底色）；S19 里未选项不带自己的底（选中块或浮起层是这一组唯一的面），B1 / B2 / C 取消按钮隔离让文字盖住选中块。原 `sliding-selection.css` 并入 `selection-controls.css` |
| `SelectionGrid` | 包住 `aria-pressed` 的格子按钮（月份格），可以多选 | 只加 `data-select-grid` 钩子，外观与动画全部由 CSS 给出 |
| `ToggleButton`（1.19.67） | 直接替换调用方的开关按钮：`<ToggleButton className=… pressed={开否} onClick={…}>`，渲染 `type="button"` + `aria-pressed` | 只多 `data-select-toggle` 钩子；类名、点击、内容原样；它不是选中指示（不和别的按钮互斥），只是开启状态借用独立选中项的外观 |

| `ConditionTags` / `ConditionTag` | `items: { key, label, removeLabel, title? }[]`、`onRemove(key)`、`empty`；每次渲染可以传新数组 | 整个标签是删除按钮（与原来一样点哪里都删除），可访问名称是 `removeLabel`；标签组 `role="group"`。条件消失后标签在原位置缩小淡出再移除，退场中 `inert`；初次挂载不播放出现动画；用键盘删除后焦点交给后一个（没有就前一个）标签，都没有交给标签组 |

动效参数：会移动的选中块与底栏选中胶囊共用 Motion Token 的 `SELECTION_GLIDE`，C 用 `SELECTION_SLIDE`，A 浮起、网格淡化与标签进出用 `SELECTION_CSS` 登记的 CSS 变量（下方 Motion Token 表）。动画只用 transform、opacity（选中块另有 width / height），多层阴影不逐帧变化。

**怎么选（1.19.65，迁移其余同类控件时照此判断）**：先看数据上是不是“同一时间只有一项被选中”，再看排布。

| 控件 | 判断依据 | 用哪个 | 表现 |
|---|---|---|---|
| 单选列表 | 同一时间只有一行被选中，竖着排 | `MovingSelection axis="y"` | B1 / B2 透明模拟玻璃滑到新行、A 旧行沉回平面、新行浮起（列表不是轨道，完整 A2）、C 浅绿实底干脆滑动；行尾 ✓ 与品牌绿文字保留为第二信号。例外：列表很长、旧的选中行经常滚出视野（几十项的列表）时，选中块会从视野外长距离滑入，改用独立选中项（淡入淡出） |
| 多选列表 | 每行各自选中、可以同时选中几行（“不限”之类是清空） | 每行 `SelectionItem`（网格选中的规则） | B1 / B2 玻璃在这一行淡入淡出、A 这一行浮起、C 交叉淡化；✓ 保留。会移动的选中只能表示一项，不能用 |

| 开关（设置项） | 只有开 / 关两种状态，是一项设置，旁边有说明文字（“同步筛选”“只有管理员能邀请”） | `Switch`（`role="switch"`） | 不属于选中指示，轨道 + 滑块，按原 Token |
| 平铺变体（`data-select-flat`，1.19.68 引入、1.19.69 改定；1.19.70 起 `SelectionGrid` 与带胶囊 / 交互卡材质的选项默认同一规则） | 未选项自己带实底或材质、排布成大块（导出的范围与格式、拍照单张 / 批量、冲突页本地 / 远端、批量添加支出 / 收入、月份格、月份离线下载自动 / 从不），写在 `MovingSelection` / `SelectionGrid` 容器或独立选项上 | 与所在组件相同 | **未选项没有填充，只有一条细边**（强分隔线令牌调淡）表示可点，文字用正文色；**选中项才有面**：B1 / B2 同一块模拟玻璃再加一圈品牌绿细边（白色面板上玻璃的亮边与柔影不够清楚）、A 按 A2 浮起（平铺组不是轨道）、C 浅绿实底加品牌绿细边；选中文字品牌绿，危险语义仍用危险色。原则：未选项不得比选中项更“重”（1.19.68 把未选项画成灰色凹底，B1 / B2 / C 里选中项反而更淡，已废除）。Original、深色、Pad、电脑版不变 |
| 开关按钮（1.19.67） | 只有开 / 关两种状态，表示一种模式是否打开，以按钮的样子放在标题行或工具行里（筛选“多选”、分析卡片“替换”），再点一次就关 | `ToggleButton`（仍是 `aria-pressed` 按钮，不改成 `Switch`） | 关闭时是普通按钮；开启时与独立选中项同一外观：B1 / B2 透明模拟玻璃、A 按 A2 浮起、C 浅绿实底，文字变品牌绿。状态由文字或图标本身表达的切换（密码“显示 / 隐藏”的眼睛、批量选择条的“全选 / 取消全选”）不算，保持原样 |

- 1.19.70：最后一批（外观与设置、分析工作台、展示卡片编辑器指标、账本切换面板账本行）与统一辨识度规则。值、可选 / 禁用判断、角色与 aria 都不变。

  **跳过**：日历热力图日期格（格子底色是数据）、展示卡片编辑器卡槽（真实的明细摘要预览，带自己的材质，选中靠整张卡的外框）、标签多选（保留标签自己的颜色）、开发用风格实验区。

### A 浮起档位（1.19.62）

所有者 2026-11-14 认可（来源：[S19 审查后续待办](S19-审查后续待办与弹出面板模板-20261114.md) §2.2）。A 原来有十几种各写各的阴影配方，有的用墨色、有的带品牌色，普通卡片的影子被负扩散收得几乎看不见，同一用途用了不同配方。现在用同一个物理模型分五档：**离开下面的平面越高，接触影越淡、环境影越大越往下越虚、位移越大**；阴影一律用墨色（浅色 `--color-ink` 的通道 `--s19-a-ink: 36 49 43`，写成字面量，深色下不会跟着变浅），不用纯黑。令牌在 `s19/s19-lab-tokens.css` 的 A 段，A 的其他阴影令牌只引用档位，不再各写配方。

| 档位 | 令牌 | 含义 | 配方要点 | 归入的令牌 |
|---|---|---|---|---|
| A0 嵌入 | `--s19-a-elev-0` | 凹进平面 | 只有内阴影 | `--s19-track-sh`（分段轨道、外观选项组） |
| A1 静置 | `--s19-a-elev-1`、贴身版 `-1-tight` | 贴在平面上 | 细边 + 近影 + 很小的环境影，不位移 | `--s19-card-sh`、`--s19-mini-sh`、`--s19-entry-sh`、`--s19-ticket-sh`（账目“电影票”；原来整组底部另叠的底影由最后一张自己的环境影承担）；明细摘要卡 `--s19-key-sh-tight` / `--s19-mini-sh-tight` 用贴身版——它们在收起动画要用的 `overflow:hidden` 容器里，大范围外投影会被裁成硬边 |

**A2 的轨道内表现**（1.19.72，所有者要求）：分段轨道里的选中块按通用 A2 浮起（上移 2px、放大 1.5%、环境影下移放大）时太重，像一张悬在槽上的小卡片，还偏离了轨道的上下中轴。档位编号不变，仍是 A2，只把这类场景的表现收敛：**真正放在分段轨道里**的会移动的选中（容器写 `data-select-track`：共享分段控件、支出 / 收入、明细全部 / 支出 / 收入、批量修改添加 / 移除、外观明暗三选一、分析抽屉分段、留言引用、账本导入审核二选一、附件 PDF 缩放） 用 `--s19-a-elev-2-track`（A2 表面层 + `0 4px 10px -6px` 墨色 .16 的近影，大部分落在轨道 4px 留白之内），选中项不上移、不放大，面从 96% 以中心原地放大淡入、落下时原地缩回。底槽仍是 A0；1.19.72 起留言引用、账本导入审核二选一与附件 PDF 缩放这三处用画布色写成的轨道在 A 下也改用轨道令牌（A0）。**不在轨道里的一律保留完整 A2 浮起**（1.19.73–1.19.74，所有者纠正：1.19.72 把筛选面板的竖向导航与“月份 / 日期范围”也压平了，“没必要减弱它的浮空感”；1.19.73 一度把会折行的互斥小组改为原地、开关按钮开启也一直原地，所有者看图后决定都恢复浮起）：例如从“时间”切到“支付方式”，“时间”那块薄片逐渐沉下去、与背景融为一体回到同一平面，同时“支付方式”下面出现一张薄片慢慢浮起——这就是通用 A2 的浮起 / 落下动画，A 本来就没有滑动的选中块。网格选中（月份格、会折行的互斥小组、头像）、开关按钮开启、独立选中项与条件标签同样保留完整 A2；原地表现只在带 `data-select-track` 的分段轨道里。新增分段轨道时在容器上写 `data-select-track`（守卫 `SelectionMigration.test.tsx`）。

**不属于高度的“强调”**：主按钮的品牌色光晕 `--s19-accent-sh` 不动。金额框与加号原来的品牌色光晕作为额外的强调层叠在 A3 之上（金额框 16%、加号 50% 品牌色，比原来淡，避免与 A3 的墨色环境影叠得太重；加号保留外圈 4px 白环、用不带亮线的 `-3-drop`）；账本卡直接用 A3，不再带品牌色。B1、B2、C、Original 与深色的阴影令牌不变。

**将来的“浮起程度”**（所有者 2026-11-14 提出，很后期）：五档是同一个模型，可以用一个强度系数同时缩放阴影深浅与位移（例如给 `--s19-a-ink` 阴影的透明度和 `--s19-a-lift-*` 乘同一个系数），做成“轻 / 标准 / 明显”之类的预设，与 B1 的“背景模糊：轻柔 / 标准 / 朦胧”同一种做法。现在只完成了档位统一，系数未实施。

### 语义材质原则（所有者 2026-11-14 同意）

**材质由它背后是什么决定**：直接浮在壁纸或页面内容上的元素（底栏、浮动按钮、顶部工具）用玻璃才有玻璃感；放在面板里面、背后是实心面板的元素（选中块、标签、输入框）用瓷片或实体，靠颜色与光影区分层级。B2 的已选条件标签用瓷片而不用磨砂、面板里的选中玻璃不染色，都是这条原则的应用。将来扩展为完整的语义材质章程（层级 → 用途 → 状态，四种风格各自的材质语言）时以此为起点。

### 提示条（Toast，1.19.66）

所有者 2026-11-14 的要求与决定见 [S19 审查后续待办](S19-审查后续待办与弹出面板模板-20261114.md) §4“提示条（Toast）语义材质”与 §6 第 15–21 条（全部按推荐）。原来有五套各写各的短暂提示（撤销条、Pad 外壳提示、分析工作台提示、拍照导入完成提示、头像奖励横幅），时长 2.6–5 秒不等、只有两套带操作、五种外观完全相同（撤销条渲染在外壳外，其余没有 S19 规则）。现在只有一套。

**结构**：一个应用级队列（`components/toast/ToastProvider.tsx`，挂在 `App.tsx` 原 `UndoProvider` 的位置——登录状态之内、路由与外壳之外，删除一笔后返回列表时撤销仍在）＋每个外壳一个显示宿主（`ToastViewport`：手机 / Pad 在 `WorkspaceShell` 的 `.lv-shell` 里，S19 材质才能命中；电脑版在 `DesktopShell` 的 `.lv-desktop` 里）＋一个调用接口。纯逻辑在 `lib/toast/`（队列 `queue.ts`、时长 `timing.ts`、控制器 `controller.ts`、位置 `placement.ts`），外观在 `components/toast/`，S19 材质在 `s19/toast.css`。

```tsx
const toast = useToast();
toast.show({ tone: "success", text: t("…saved") });
toast.show({ tone: "info", text, action: { label: t("common.action.undo"), run: undo, alternative: "编辑条的撤销按钮" }, scope: "page" });
toast.show({ tone: "error", text: t("…saveFailed"), key: "stats-save", scope: "page" }); // 常驻，有 ×
```

- 选项：`tone`（信息 / 成功 / 警告 / 错误）、`text`（必填）、`detail`（第二行）、`leading`（前置图，例如头像）、`action`（任何类型都可带**一个**操作；`alternative` 必填——提示消失后在哪里还能做同一件事，把 WCAG 2.2.1 写成类型约束）、`key`（合并键）、`scope`（`app` 跨页面保留；`page` 随发出它的组件卸载撤下、不触发操作）、`echo`（页面已常驻显示同一结果）、`announce`（页面别处已播报同一句时传 false）、`onEnd(reason)`、`onSeen`（真正在屏幕上累计满多久回调一次）。`useUndo()` 保留为薄适配，调用方不改。
- **类型不只靠颜色**：实心圆 + 字形（i / ✓ / ! / ×）、读屏前缀（“警告：”“错误：”）、错误另有危险色细描边。圆底：信息 `--color-muted`、成功 `--color-brand`、警告 `--color-warn`、错误 `--color-danger`，字形用对应的 `on-*` 令牌。

**时长**（不是动效，不受减少动态效果影响）：信息 / 成功 `clamp(4s, 1.5s + 0.12s × 可读长度, 8s)`（可读长度 = 中文字数 + 其他文字词数 × 2）；警告同式，6–10s；带操作固定 10s；错误不自动消失（有 ×，被同 key 的消息替换或用户关闭才消失）；错误回声 8s。悬停（只在能悬停的设备）、焦点在提示里、页面切到后台、弹层或“+”菜单打开时暂停；恢复时至少还剩 2s（普通）/ 3s（警告、错误回声）/ 4s（带操作）。

**队列**（同时只显示一条）：同 key 原位更新（槽位不变、计时重置、正文播放一次 Feedback，不重播入场；可跨类型——“保存失败”与“已保存”共用 key，重试成功原位替换错误）；错误与带操作的提示立即替换当前一条——被替换的未关闭错误回到等待位（错误不会悄悄消失），被替换的带操作提示操作结束、不再恢复（每个带操作的调用点都有常设替代路径）；普通提示遇到错误或带操作的当前一条进等待位；等待位只留一条（错误优先，同级留最新），普通消息最多等 3s、警告 6s，过期丢弃，错误不过期；每条有唯一 id，计时按 id 管理（连续删除两笔时第二条的计时从头开始）。

**位置**（所有者决定第 16、18 条）：手机水平居中、`min(视口宽 − 32px, 28rem)`；垂直在底部障碍物最高上缘之上 8px——常驻底栏、抬高 32px 的“+”（标 `data-toast-avoid`）与所有 `[data-lv-bottom-bar]`（保存栏、核对确认条、批量操作栏、留言输入区、分析编辑抽屉、导入完成页按钮栏……），没有障碍物时在底部安全区之上 16px；软键盘打开时底栏与操作栏原位隐藏（`visibility: hidden`，不计入），提示在键盘上方 8px；障碍物变化时按 `--lv-reveal-ms` 平移跟随。**唯一的顶部例外**：页面声明顶部锚点 `[data-toast-anchor="top"]` 时放在它下方 8px（分析工作台编辑态的编辑条；锚点随编辑态消失，离开编辑后的提示回到底部）。电脑版同一算法：底部操作栏之上 16px，没有则离窗口底 24px，窗口居中。Pad 页内及附属任务的提示在发起工作区底部居中，跟随分隔条调整位置；缺少页面归属的全局提示使用外壳底部。拍照导入完成提示因此从顶部移到底部按钮栏之上。

**账本胶囊让位**（1.19.72，所有者要求“提示条与‘我的本地账本’不同时争夺视觉重心”）：手机提示放在底部时，底栏上方的当前账本胶囊先用它原有的“向下缩到底栏上缘之后”让开（200ms），走到约八成时提示再从下方升起（宿主写入场延迟 `--lv-toast-enter-delay` 160ms，只在胶囊此刻还在原位时等）；提示退场到约八成（当前风格 `--lv-dismiss-ms` × 0.8）时，胶囊用原有的“从下方弹起、略过冲”回到原位。胶囊让位期间不卸载（账本切换面板等状态不丢），让开后隐藏（不可点、不可聚焦）；它不再是提示的障碍物，提示放在“+”之上 8px，大致占胶囊原来的高度。状态在 `components/toast/bottomSlot.ts`：宿主写“底部提示位被占用”（手机、放在底部、没有模态弹层），胶囊读。弹层打开时提示藏在遮罩后，不算占用，胶囊回原位（弹层的打开按钮关闭后焦点才能回到它身上），弹层关闭后再让开；“+”菜单展开时菜单本来就盖住胶囊的位置，仍算占用，菜单收起时不会先弹出胶囊再缩回。减少动态效果：胶囊直接隐藏 / 出现，提示不等，胶囊仍等提示淡出后再出现。只是短暂让位，不是隐藏账本入口；顶部锚点（分析编辑态）、Pad 与电脑版不涉及。

**让开**（所有者决定第 17 条）：任何模态弹层打开（`lib/openOverlay.ts` 的判断，正在收起的不算）或“+”记一笔菜单展开（`BottomNav` 写 `data-toast-yield`）时，当前提示退场并暂停计时，新消息照常排队；关闭后再出现（重播入场）。新提示进来时宿主先判断一次，弹层打开时不会先播报再让开。面板自己的反馈（预设库状态行、批量添加的 `Alert`）留在面板里。

**无障碍**：宿主挂载时就有两个空的播报区（`role="status"` polite、`role="alert"` assertive，之后只改文字；同 key 1 秒内只播一次）；alert 只给页面别处看不到、需要立即知道的错误（例如分析保存失败、撤销失败），回声错误与其余类型用 status；可见本体在 `aria-label="通知"` 的区域里，不兼任播报区；出现时不抢焦点；焦点在提示里时 Esc 关闭；提示因操作、×、替换消失而焦点在里面时，焦点回到进入前的元素（已不在时键盘用户回到当前页标题）；键盘焦点落到被提示盖住的元素时把它滚到提示外面（WCAG 2.4.11）。

**材质**（所有者决定第 15、21 条，B2 填充 1.19.67、1.19.72 调整；配方见 §3 表“提示条”一行）：规则只写在 S19 通用层 `.lv-shell[data-s19-scope]`，标记 `data-toast-surface`（不新增 `MaterialRole`，不复用弹层的 `data-overlay-surface`）。与弹层面板同一结构：材质画在 `::before`（B2 背景模糊只在伪元素上，先写 `-webkit-` 前缀），错误描边在 `::after`；面板本身只做位移动画，透明度动画落在 `::before` / `::after` 与内容上。B2 不支持背景模糊时退到 `--color-surface`。Original 从原来的墨色反色条改为浅色实心面，深色、Pad、电脑版沿用同一基础外观，深色时语义令牌自动变深。

## 5. 动作与触发必须分开

| 动作 | 允许触发 | 默认参数 A / B1 / B2 / C | 不该触发 |
|---|---|---|---|
| Press | `Button motion` 的真实按下/释放；工具默认启用 | 120 / 100 / 100 / 80ms，轻微 scale | 挂载、禁用、普通渲染；旧特殊动效按钮不再叠加 |
| Select | Switch 的 checked 改变；网格选中的淡入淡出与选中文字变色（1.19.62） | 200 / 180 / 180 / 120ms | 挂载；会移动的选中块用自己的弹性 / 滑动参数（`SELECTION_GLIDE` / `SELECTION_SLIDE`），不套第二层 |
| Reveal | 持续挂载的 `MotionPresence` false→true | 220 / 200 / 200 / 140ms | 初次挂载，true→true，两个都显示胶囊的页面互切 |
| Dismiss | true→false；先 inert，结束后 hidden | 180 / 180 / 180 / 120ms | 不依靠延迟改变导航或业务状态 |
| Feedback | 完成事件令 `useComponentFeedback(ref, signal)` 的 signal 改变 | 240 / 200 / 220 / 160ms | 挂载、失败、仅点击但尚未完成 |
| Loading | 明确 busy 状态 | 1000 / 1100 / 950 / 900ms 周期 | 无条件循环；退出状态即卸载指示器 |
| 展开块 `Reveal`（1.19.76） | 文档流里一块内容的 `open` 改变（记一笔的分类 / 快捷金额 / 更多选项、行内下拉、行内编辑、批量选择条） | 高度与透明度同步，读 Reveal / Dismiss 时长 | 初次挂载；收起后 `hidden`；`keep={false}` 收起后卸载 |
| 内容切换 `useSwapReveal(ref, key)`（1.19.76） | 同一位置换成另一份内容（列表换组、筛选面板换维度、页内换步、查看 ↔ 编辑） | 新内容淡入并轻移，读 Reveal | 不重新挂载；`key` 第一次不播放 |
| 挂载即出现 `useMountReveal(ref)`（1.19.76） | 之后才挂载的小块（`Alert`、`InlineMessage`、状态行） | 高度从 0 展开 + 淡入 | 页面转场进行中挂载的不做；消失仍直接卸载 |
| 列表增删 `useListMotion(ref, signal)`（1.19.76） | 列表项增删（管理页、附件、留言、子分类展开） | 新项展开到位，留下的项 FLIP 平滑移位 | 第一次渲染与容器换节点时不播放；被删项直接卸载 |

时长权威值在 `component-motion.css`；A 宽柔、B1 克制、B2 轻盈、C 简短。WAAPI 从当前呈现位置取消/反向，结束清理；隐藏或卸载清理。减少动态效果时不做位移动画，保留状态文字。不要给 `MotionPresence` 使用路由 pathname 作为 key；它不决定导航目标、历史或滚动恢复。

原 BottomSheet/ConfirmDialog/ChoiceSheet、底栏指示器、账本胶囊、明细收缩、搜索和专属业务转场继续使用原协调器。**不得为展示通用动效而重包这些组件。**

## 6. 新增组件的最短流程

### 共享壁纸与材质的组合

背景只从 `s19/wallpaper.css` 取 `--lv-wallpaper-bg`，旧材质和转场读取的 `--s19-bg` 是同一来源的别名。三种配方为 aurora（默认柔和极光）、luminous（清透光域）、quiet（静谧渐层）；几何由壁纸决定，光色由既有 `brand / canvas / surface` 和原 B2 暖冷辅光派生，风格仅调整扩散/强度。A 是宽柔打光，B1 的低频渐变扩散随背景模糊强度变化，不模糊前景，B2 保留清晰光色与既有展示/操作玻璃及三档参数，C 与 Original 使用纯画布，不显示壁纸。深色压低环境亮度，保留现有深色组件规则。

`visualStyle.ts` 继续承担本机外观状态与订阅；`libevra.wallpaper` 只保存经过白名单校验的壁纸 ID，没有新后端或账户配置。旧用户、未知值使用极光，不改写其他偏好；读写失败保留会话值，storage 事件跟随其他标签页。主题、风格、玻璃预设和壁纸互不重置。

文档固定背景与大屏固定工作区共用配方，页面不复制渐变、不截取 DOM，也不新增持续滤镜或循环。账本空间欢迎态壁纸透明，展开时只读取既有 `--p / --q4`，不改变海浪几何、材质、品牌交接与导航协调器。外观页三张缩略图使用同一配方及适用布局下的既有材质 Token。

### 账目容器变形的接入边界

`prototype/` 保存电脑端已验收的独立演示。`geometry.mjs` 的坐标、关键帧、返回目标可靠性和周围内容姿态计算不依赖业务；正式 `s19/motion/objectExpand.ts` 直接导入它，由既有 MotionPilot / PaneRouter 在提交前捕获实际来源，提交后对空容器和真实 React 详情分别动画。原型 `motion.mjs` 的 `ContainerPresentation` 仍服务演示 DOM，模拟数据不进入业务；独立 URL 不改变 Object Expand 语义。业务入口通过 `data-object-source` 标记匹配的目标路径，只有实际导航成功才播放，不改变选择、冲突、权限或拖放判断。

共享机制在点击时测量来源，几何与内容在帧锚定时钟上按同一条曲线密集采样，交给 WAAPI 播放；时长与交接比例来自 Motion Token（展开 320ms、收回 300ms）。详情文字不变形：内容按容器宽度等比缩放。A 约 1.1 倍前移并压暗周围，B1 按容器节奏把上下内容完整挤出舞台，B2 后方不动、玻璃（模糊 + 透明填充）直接画在容器本身，C 轻微避让。来源呈现副本 inert、不带事件；返回使用原坐标和滚动状态，目标删除、改序、超出安全区或视口大幅改变（Motion Token 的转场打断规则；工具栏伸缩这类小变化交给逐像素的位置核对）时淡出降级。减少动态效果直接提交；新导航、中断与卸载释放动画并复原被借用的真实节点。真机 Safari 的最终观感仍需单独验收。

1.19.44 起的接入约束（卡片逐渐成为详情）：点击当帧容器从来源卡片的实际位置与尺寸开始长大（第一帧透明叠在真实卡片上，12% 内补满）；详情页面用 React transition 在后台提交，到达后放进容器——按容器宽度等比缩放、顶端对齐、按容器圆角裁剪——随容器一起长大并在 6%–40% 渐显，所以任何时刻容器里都有内容，不再有“铺满却还是空的”一段。详情还没提交时容器最多长到进度 0.12 并慢速蠕动到 0.16，到达即放开。React 提交时把原页面移出工作区，同一个节点随即接到背景舞台（层级 35，在页面之上、常驻底栏 40 之下）继续它的风格响应，不克隆整页；B1 下半页是唯一一张副本，底栏用一份副本留在原处直到被容器盖住。容器在 70% 铺满，原页面与底栏副本在 68%–75% 于其下退场，容器底色 73%–97% 淡回统一壁纸，详情（层级 46）停在最终位置。几何是一条连续曲线（`cubic-bezier(.32,.2,.18,1)`）：原型的两段节奏在 60Hz 手机上表现为“停一帧、再一帧跳出 275px”，现在 12 个 ≥6px 的生长帧、单帧最多约 145px；A 的前移作为叠加的一次起伏保留。详情未到达前返回：路由交回原页，容器从当前姿态缩回卡片、后半段淡去。已到达后返回或正常收回：同步提交列表（恢复滚动），被移出的详情节点放进前景，在收缩的容器里按同一几何缩小、50%–82% 淡出，容器回到实际来源后 78%–100% 淡出露出真实卡片；列表与底栏在容器补满后（8%–10%）出现，出现后移除透明度动画并清掉首帧静态值。带 `backdrop-filter` 的元素不能放在做透明度动画的祖先里（祖先会成为背景根，玻璃读不到后方），这是 B2 容器不用 frosted `::before`、B2 原页面推迟透明度动画、详情渐显结束即移除透明度动画的原因。

帧锚定时钟（`lib/frameClock.ts`）：Object Expand、主 Tab 交换与明细搜索开合的 WAAPI 动画创建后立即暂停，由 rAF 写 `currentTime`；第一帧固定是起始姿态。正常帧间隔取最近 5 帧的中位数（60 / 120Hz 与低电量 30Hz 各按自己的节奏），明显更长的间隔（提交、首次绘制、长任务）只推进一个正常帧，停顿之后不会一下跳出一大段（记账工作区同样用这个时钟；账本空间海浪用同一步长推进主进度，层的弹簧也按这个步长积分）（1.19.43 推进 34ms，Tab 曲线下等于一帧跳 30%）；单帧仍以 34ms 为上限。`limit` 让转场在内容尚未提交时只走到约定位置（主 Tab 与 Object Expand 等新页面）。连续 600ms 没有 rAF（后台、停帧）时看门狗直接收尾。原因是 iPhone Safari 合成器动画以创建时刻为起点，紧接着的重帧会吃掉前一两百毫秒，第一帧就落在中后段；Chromium 在首帧显示时才定起点，桌面逐帧测试测不出来。代价是这几类转场按 Safari 的 rAF 频率（通常 60Hz）更新。`?motion=1` 徽章显示每次转场的帧数、墙钟时长、首帧间隔与最长间隔，供真机核对。浏览器自带返回动画时（`PopStateEvent.hasUAVisualTransition`；旧 Safari 以边缘横向拖动或 touchcancel 判断）协调器只提交页面，不叠收回；视口变化按 Motion Token 的转场打断规则（`TRANSITION_INTERRUPT`：宽度变化或高度变化超过 150px）由协调器统一收束，四种风格一致（只改变可视区的软键盘不打断记账工作区）。明细搜索点击当下只改 DOM 状态并在同一手势里聚焦（键盘照常弹出），胶囊从按钮实际位置左右展开，标题、右侧按钮、月份行、范围说明、S19 底衬与顶部收起读同一个 `--search-k`（与胶囊同一条控件形变曲线），React 状态在形变结束后同步；快速重复开合从当前姿态接续。

技术选择：Shared Element 是交互语义，FLIP 提供首尾几何，WAAPI 承担可取消的呈现；现有 View Transition API 继续服务普通页面转场，对象展开不再叠加浏览器快照动画。选择 WAAPI 是为了独立控制空容器、文字淡入和四种背景响应，并保留无 API 的即时降级；WebKit 在 [Safari 13.1 / iOS 13.4](https://webkit.org/blog/10266/web-animations-in-safari-13-1/) 提供 WAAPI，[Safari 18](https://webkit.org/blog/15865/webkit-features-in-safari-18-0/) 才提供 View Transitions，二者不作为相同的支持门槛。

主 Tab 交换（switchTab，`tabExchange.ts`）：四个主 Tab 之间整页横向交换，两页共用 280ms 与 `cubic-bezier(.3,.15,.15,1)`（起步约 4% / 帧、10%→90% 约 133ms、末段平稳减速；Tab Switch Lab 的 200ms 前冲曲线前两帧就走完 67%）。点击与新页面初始化解耦：点击当帧移动**真实的旧页面**，新页面用 React transition 在后台渲染；旧页先走到约 8%，未到达就慢速蠕动（最多约 13%）。React 提交新页面时把旧页从工作区移除，同一个节点随即接到交换舞台（统一壁纸之上、真实页面之下）继续离开，新页面按时钟当前时间对齐进入，两步在同一帧绘制之前完成；不克隆旧页。分析页的网格宽度首帧按工作区宽度估计（不再先按 0 宽渲染再整页重排），卡片正文按测量尺寸以 transition 渲染并短暂淡入，不占住交换的帧。常驻底栏、加号与壁纸不移动。最左到最右只交换一次；正在交换时只排最后一次点击，完成后从实际所在页出发；浏览器返回同样按 Tab 顺序决定方向。各 Tab 的最后筛选（查询参数，按账本隔离）由 PaneShell 记住，滚动由协调器按 Tab 恢复；再点当前 Tab 仍回到根。输入中、弹窗打开、深色或减少动态效果时即时切换。新页面 1.5 秒仍未提交则放弃呈现、只交付页面。转场进行时（帧锚定时钟或账本空间海浪在跑），新页面里可以晚一点出现的重活先不渲染，转场结束后再以 transition 补上（`lib/motionIdle.ts`；安全阀 2.5 秒）：分析卡片的图表正文就是这样，滑动途中只显示卡片框与标题，结束后零点几秒内出现并短暂淡入。1.19.45 之前卡片正文在滑动途中逐张提交，较慢的手机上会掉几帧。

当前账本胶囊（1.19.50，`components/bookCapsule.ts`、`PersistentBookCapsule.tsx`）：手机有常驻底栏时，明细、分析等页面左下角的账本胶囊挂在常驻底栏上（底栏上缘左侧，留 4px），不再占页面一行——页面内容一直延伸到底栏上缘，胶囊两侧照常可见，阴影只有胶囊自己的一圈。页面只登记“需要显示哪本账”（layout effect，与页面提交同一帧）；主 Tab 交换时胶囊不随页面滑动：两页都需要时不动，目标页不需要时向下缩到底栏上缘之后（越过上缘的部分逐渐裁掉，200ms `(.4,0,1,1)`）再卸载，原来没有、目标页需要时按原有入场从下方弹起（220ms，略过冲）。记账菜单展开时直接隐藏、收起后直接显示；进入次级页面时随常驻底栏一起隐藏。没有常驻底栏（大屏、未登录）时仍按原来的一行显示；减少动态效果时直接出现 / 消失。

默认次级导航由 `isDefaultMotionEdge` 统一覆盖：从任一主层级或次级页面 PUSH 进入另一个次级页面都使用各风格既有的“新页从右侧覆盖”转场，返回只回放刚发生过的那条边的反向；账本空间（进入与离开是它专属的海浪转场，见下）、登录/恢复等外壳外入口不参与。查询参数属于页面状态，不再阻止转场；同一页面换筛选保持滚动。B1 轨道只移动透明正文组（`[data-motion-body]`）：页面既没有 `<main>` 也没有可拆分的标签页顶栏时（明细首页 `.detail-root`、卡片编辑等），整页作为一个轨道移动——1.19.45 之前这些页面的正文不进轨道，新页叠在原地不动的旧页上（明细 →「更多」的重合）。

记账工作区材质、键盘与专注型核对（1.19.51，依据 2026-11-09 记账工作区专项审查与所有者决定）：

- **材质**：页面背景透明、显露统一壁纸（手动记账金额区、保存成功屏不再铺画布 / 纯白）；保存栏（`EntrySaveBar`）、核对确认栏（`StickyActionBar entry`）、OCR / 账单导入确认条与导入完成栏标 `data-bar-surface="chrome"`，按上表使用底部操作区材质，不再在壁纸上形成色块；金额框（手动记账与核对表单）声明 `data-entry-amount`，兼容选择器不再把它映射成展示玻璃，保留白底绿框并按风格换材质；分类、时间、备注等输入保持实体；拖放区保留虚线；原文 / 听到的内容 / 说明 / 识别标签用中性内凹底（`.lv-entry-soft` → `--s19-track-bg`）；沿用上一笔、快捷金额、未选中的支付方式与标签用胶囊材质（`data-entry-chip`）；更多选项外框为展示分组；附件上传区保留品牌虚线、底色改为次要操作面。规则集中在 `s19/entry-workspace.css`，只作用于浅色四风格手机外壳。
- **支出 / 收入**：手机外壳的 A / B1 / B2 不再使用手动记账的绿色顶区，手动记账、文字 / 语音 / 拍照核对与 OCR 单笔核对统一用 `components/entry/KindToggle`——与明细「全部 / 支出 / 收入」同一套类名与滑动胶囊；切换后的业务处理（清空分类、记录已确认方向）仍由各页负责。C 保留绿色顶区与按钮，只把上下留白压缩为 16px（浅色、深色一致）；Original、Pad 与桌面不变。需要按风格换**结构**时用 `lib/useRootVisualStyle`，纯材质差异仍写在 CSS。
- **软键盘**：`lib/softKeyboard.ts` 判定“焦点在文字控件上且可视区被挡住 ≥ 120px、未缩放”（iOS 看布局视口与 visualViewport 之差，Android `resizes-content` 看同宽度下布局高度的缩小），写 `<html data-soft-keyboard>` 与 `--lv-keyboard-inset`。打开时 `data-entry-bar` 的底部操作区与常驻底栏原位隐藏（不抬升、不重排、不可聚焦），收起后按 `--lv-reveal-ms` 淡入；输入框之间切换去抖 150ms，失焦即关闭。手机外壳的四风格、Original 与深色一致；Pad 大屏的保存栏仍按原来的 `useKeyboardInset` 抬升，BottomSheet 的抬升不变。手动记账表单在键盘期间尾部留出被挡住的高度；在备注里按回车提交时先收起键盘，保存栏中的提示才看得见。
- **专注型核对**：拍照单张核对与账单导入核对（`PersistentNavContext.useFocusTask`）与 `/paste/review`、`/voice/review`、`/ocr/overview` 同一语义——常驻五入口底栏让位（隐藏；万一仍在画面上则灰色、`inert`、不可点击），确认栏占用底栏原来的位置，确认 / 保存 / 取消始终完整可见；InnerPage 同时不再为底栏留尾部空间。取消、保存成功、改为手动记账、返回与浏览器返回都会结束让位。选图、选文件、识别中、保存成功与导入完成仍是普通记账工作区，底栏照常显示。
- **底栏让位的过程（1.19.52）**：明细批量操作（`useFocusTask(selecting)`）同样让位，批量编辑 / 删除栏替换底栏。让位分先后：底栏先 `inert`、向下退出（`NAV_YIELD.exit`），结束后才隐藏；替换它的固定栏标 `data-replaces-nav`（`StickyActionBar entry`、账单确认条、批量操作栏在让位时自动标），延迟一个退出时长后从下缘升起；结束让位时底栏先显示再从下方升回（`NAV_YIELD.enter`）。进入次级页面的隐藏不走这段动画；减少动态效果时直接切换。
- **记账时的选中指示（1.19.52）**：五种记账页（`level === "enterMode"`）不标任何主 Tab 为选中，底栏在“+”所在格标 `data-entry-current`；B1 / B2 的玻璃胶囊与 A 的 DepthGlide 胶囊用主 Tab 之间同一套移动动画滑到“+”正后方并在到达前淡出（被“+”挡住），回到主 Tab 时滑回并淡入。C 与 Original 的静止选中圈只是不再显示。
- **按下与悬停不盖掉材质（1.19.53）**：主按钮、浅底按钮、底栏“+”与记一笔入口卡按下时，在原材质上叠一层同色调暗化（`--s19-press-accent` / `--s19-press-soft`：`linear-gradient(暗化, 暗化), 原材质`），渐变、高光、亮边与投影都保留，不再整块换成 `brand-dark` / `brand-soft` 纯色。悬停只给 `(hover: hover) and (pointer: fine)`：触屏点一下会粘住 `:hover`，按钮一直停在悬停色（原来点“+”后 B2 的玻璃“+”变成一整颗纯深绿，就是这个原因）；`components/*.css`、`statsWorkbench.css` 与深色 / 黄色主题的手写 `:hover` 同样只在能悬停的设备上生效。“+”展开时只有里面的图标旋转，按钮表面的渐变与反光不随之旋转。

**转场打断规则**（1.19.57 起统一登记）：视口或舞台尺寸变化时，正在播放的转场是否收束到终点，所有风格（A / B1 / B2 / C）与所有呈现器只认 `lib/motionTokens.ts` 的 `interruptsTransition`——宽度变化（转屏、分屏、窗口缩放）一律打断，高度只在变化超过 `TRANSITION_INTERRUPT.heightPx`（150px）时打断（软键盘、窗口大幅改变）。iPhone Safari 的工具栏伸缩、前进按钮出现 / 消失只改变几十像素，不打断（1.19.42 的“闪一下到终点”就是任何高度变化都收束）。协调器统一监听布局视口与可视区并收束全部呈现器；呈现器不再各自监听视口或写自己的阈值，需要观察内容尺寸的（ABC 控制器）由调用方传入同一规则，并与本次转场开始时的尺寸比较；主 Tab 交换、记账工作区与 B2 默认导航没有自己的尺寸判断。账本空间海浪整页重新载入后的接续（`tide.ts` 的 `takeTideResume`：宽度差 ≤ 2px、高度差 ≤ max(200px, 25%) 时按比例接着画）不是打断，而是“两页能否接着画”的容差，保持原值。调整打断条件只改这一处，并补对应单元测试（`motionTokens.test.ts`、`abcController.test.ts`）。

设计原则：点击后一两帧内必须出现可见变化；转场进行时优先保证帧，能晚一点出现的内容让路（`whenMotionIdle`）；大部分时长留给真实可见的移动，而不是等待或几乎察觉不到的减速。高频反馈最短；普通页面切换与控件形变轻快（约 200–320ms）；需要表达空间关系的对象展开可稍长（约 300–350ms）；普通转场不超过 400ms（记账工作区是整屏的工作区交接，取 300ms 级：1.19.44 的 140ms 揭示走完 844px 时第一帧就是 329px，看不出“从下面上来”），品牌动效另行判断（账本空间海浪约 1 秒）。曲线优先选起步有响应、中段持续、末段平稳的形状，用 60Hz 逐帧位移分布（每帧位移、可见帧数、10%→90% 时长）验证，不只看配置的 duration。开始页海浪本身（`LAYER_MOTION`）等专属动效的参数留在各自文件，不作为可复用语义；账本空间的进入 / 离开转场登记在 `LEDGER_TIDE`。底栏选中胶囊的弹性参数 1.19.62 起与面板里会移动的选中块共用 `SELECTION_GLIDE`，跨“＋”的两段动画与再点一次的收缩仍留在 `tabIndicator.ts`。

### 新接口与兼容性

统一从 `components/ui/StatusControls.tsx` 导入：

```tsx
<Badge tone="warning" size="small">待处理</Badge>
<FilterChip selected={selected} onSelectedChange={setSelected}>仅看已选</FilterChip>
<StatusMessage loading>正在加载</StatusMessage>
<StatusMessage tone="error">加载失败，请重试</StatusMessage>
<StatusMessage tone="success" completion={completedCount}>保存完成</StatusMessage>
<TextField label="名称" hint="填写显示名称" error={validationError ?? ""} />
```

- Badge 的 `tone` 为 neutral/success/warning/error，`size` 为 small/regular；使用既有语义色和胶囊角色，只有文字状态，无点击和 live region。不添加独立模糊。
- FilterChip 复用 CapsuleButton 的尺寸、材质、按压、disabled/appearance；`selected` 与回调受控。选中标记预留固定宽度，不因文字图标替换而抖动。互斥选择不要用多个 FilterChip 重造分段控制。
- StatusMessage 用已有语义软底与 field 圆角，保持文字清晰，不强制玻璃化。错误用 alert，其他状态用 status；loading 不遮蔽说明文字。图标槽固定，默认不入场；仅业务完成后递增 `completion` 播放已有 Feedback，同值或父组件渲染不重播。实际重试按钮可通过 children 组合。
- TextField 新增可选 `error`，同时关联错误、hint 和外部 aria-describedby。没有 error 的旧调用不变；已有手动 aria-invalid 仍可用。错误由真实校验结果提供，不在挂载时擅自校验。`error` 为 undefined 时省略该 prop（项目启用 exactOptionalPropertyTypes）。
- 普通控件允许 className 做容器宽度/间距调整，输入保留原生 size/disabled 属性；颜色使用语义 tone/variant，不散写任意色值。需要改变点击区时优先保留 44px 最小目标，不用缩放文字压缩控件。

### Coverage Agent 的使用顺序

先查本节与 Gallery 的「标签与状态」。该分类提供直接从正在渲染的 TSX 源码提取的完整示例，props 受同一份类型检查；复制到 `src/pages/` 可直接使用，其余目录调整 import 相对路径。其它分类的短示例是调用片段，业务回调由页面提供。

新控件先选语义组件，再传业务数据/回调；保留原权限条件、查询、导航和业务动画。只有至少两个真实场景缺少同一能力、且组合现有组件无法表达时才新增共享接口。旧页面按 Coverage 的任务逐项迁移，不把这份清单当成批量改动授权。

显示/隐藏沿用 MotionPresence 的布尔边沿；用于展开说明时配 aria-expanded/aria-controls，关闭立即 inert。需要保持附近控件位置时由容器预留内容槽，如 Gallery 示例；不同时叠加高度、位移和回弹动画。重渲染、同类页面切换、持久显示均不构成入场事件。减少动态效果和异常中断继续使用既有清理逻辑。
