# Libevra · 颜色主题系统实现规范

本文是主题运行时与 Token 的现行契约。语义原则见[颜色语义规范](颜色语义与配色规范.md)，具体值在 `apps/web/src/index.css`，原始候选与当时验证见文末历史依据。

手机浅色 B2 为正式可选材质，Original 默认；A/B1/C 候选按开发入口开放。B2 预设和参数由 `s19/b2Glass.ts` 定义，偏好按账号保存在本机，不进入账本同步。实验页复用定义但不读写正式偏好，见 [S19 规范](S19-材质组件与动效设计系统.md)。

## 1. 架构

侧栏记账菜单与圆润连接凸起共用 `surface/line` 表面和边框，阴影从 `ink` 派生；功能图标复用 `brand-dark`，悬停复用 `brand-soft`，辅助区选择面板用 `canvas`。均消费现有主题令牌，不新增色值或改变主题配对。

分析编辑器的添加卡片胶囊：浅色绿色主题复用 `brand-dark` 填充与 `on-brand` 白色前景；其它色盘及深色模式复用 `brand/on-brand` 配对，hover 使用填充自身亮度变化，不回退为浅色选中底。规则共用于主辅区和各尺寸，不新增全局 token。

**系统头像（2026-10-25 整合）**：`UserAvatar.tsx` 统一展示初绽及六款基础 SVG，图形用 `currentColor / brand`、衬底用 `brand-soft`；特典倒悬为白图、`brand-dark` 衬底。我的页外环消费 `on-brand`。13 款已存旧稿仅由 `LegacyUserAvatar.tsx` 保留固定色兼容；不在基础系列重新上架。头像身份与主题/语言独立，名称在双语资源中渲染；每个实例独立命名透明蒙版，不新增颜色 token。

主题由两层组成：

1. **CSS 语义 token**：全部定义在 `apps/web/src/index.css` 的 `@theme` 中，组件只消费 token 生成的工具类（`bg-surface`、`text-ink` 等），不写主题分支。
2. **文档级偏好属性**：`apps/web/src/lib/theme.ts` 定义两个独立维度，并把用户选择写到 `<html>`：
   - `data-theme-mode="light|dark"`（`system` 已解析成实际模式）
   - `data-theme-palette="green|red|orange|yellow|cyan|blue|purple"`
   - `data-theme-preference="light|dark|system"`（保留用户的字面选择）

`theme.ts` 只提供基础函数：解析/持久化偏好、解析 system、应用到 `document.documentElement.dataset`、监听系统外观变化。它是可测试的纯逻辑加最小 DOM 接口，不在 React 树里传播主题值。

**本地入口**：`/settings/appearance/theme` 与 prepaint 共用 `theme.ts`。七套色盘均由 `AVAILABLE_THEME_PALETTES` 开放；颜色由 CSS 对 mode × palette 映射，不在页面复制主题状态。

**本地开发入口**：主工作区 `记账程序v1` 的 `http://localhost:5173`，API 为 `http://127.0.0.1:3000`；当前版本与分支只见 [STATUS](../../STATUS.md)。S16 主题预览 Worktree 是历史现场，不作为日常入口；手机 HTTPS 测试另见 [本地开发环境与 5173](../../ops/本地开发环境与5173.md)。

### 1.1 默认与持久化

默认浅色绿色，模式与色盘独立；`system` 解析为系统实际模式。偏好 key 为 `libevra.theme`，未知值按控制器回退。`useSyncExternalStore` 订阅控制器，不另建主题 Context；system 监听和跨标签 storage 事件保持同一来源。

## 2. Token 分工

角色定义于 `@theme`，主题组合覆盖实际值；不在本文再抄完整 HEX 表。

| 组 | 角色 |
|---|---|
| 明暗基准 | `canvas/surface/ink/muted/line/line-strong` |
| 品牌强调 | `brand/brand-dark/brand-soft/accent-ink/chart-rule/category-ink` |
| 状态 | `danger*`、`warn*` |
| 前景 | `on-brand/on-danger/on-warn/on-ink/on-heat/on-tag/control-knob/focus-ring` |
| 财务 | `data-expense/data-income/data-transfer` |
| 图表 | `chart-1…8`、`chart-heat-0…4`，热力 0 档为无记录 |

### 2.7 海浪、玻璃与遮罩

`ocean-1…4` 和 `on-ocean` 表达海浪填充与前景，`glass-highlight` 表达光效，`overlay-soft/overlay` 表达遮罩。材质派生不改主题配对；几何与分层进度按[海浪要求](海浪效果要求.md)，不从早期单 SVG 方案推断 S19 的实现。

## 3. 主题组合契约

两个维度相乘，而不是相加：

```text
resolved theme = f(base mode, accent palette)
```

- **只看明暗**：`canvas/surface/ink/muted/line/line-strong`、图表网格、玻璃、深色阴影。
- **只看色盘**：`brand*`、`accent-ink`、`category-ink`、`focus-ring` 的色相（但对比度由明暗共同决定）。
- **两者都看**：`on-brand`、`focus-ring` 的实际值需要同时满足当前色盘 × 当前模式的对比度；这些是每个色盘/模式组合的必填变量，不是组件分支。
- **只跟明暗、不跟色盘色相**：`danger*`、`warn*`、`data-*`、`chart-*`、`chart-heat-*`、`control-knob`；`on-ocean` 在海浪对应表面上保持可读。
- **用户数据独立**：标签保存色不跟主题，`on-tag` 的自动前景仍待接入；二维码保持固定黑白。

组件层禁止：

```tsx
// 禁止
<div className="dark:bg-...">
<div className={theme === "purple" ? "..." : "..."}>
```

允许的唯一入口是 CSS 在 `[data-theme-mode="dark"]` / `[data-theme-palette="blue"]` 下覆盖 token。

## 4. 固定色与例外

以下颜色**不参与主题化**，并有代码例外/理由：

1. **二维码黑白**：`QrCodeView.tsx` 必须接近纯黑/纯白；相机阈值读取不能跟随主题。保留 `bg-white` 例外；不改成 token。
2. **用户标签颜色**：数据库存 `#RRGGBB` 用户数据，原色显示；选中态文字用 `on-tag`。任意用户色与固定白字的对比度问题不在本轮自动解决，自动前景/浅底描边策略仍待专项设计和验收。
3. **开关旋钮**：`control-knob` 固定在默认白；深色下可通过主题值调整，但不能简单跟随 `surface` 变暗而失去实体感。
4. **明细玻璃**：`glass-highlight` 是透明度/光效，不是实色；保留在 `detail-motion.css` 的说明范围内。
5. **运行中的动画几何**：海浪路径、明细头部插值、过渡曲线不属于颜色 token；任何主题重构不得改动。

## 5. 组件消费与守卫

标题、按钮、选中态按实际填充使用对应前景，图表通过 CSS 变量读财务和图表角色。标签颜色由标签工具读取，不与主题分类图表混用。侧栏记账菜单、分析编辑器按钮和头像的例外按 §1 和[颜色清单](颜色清单.md)维护。

`colors.test.ts` 检查硬编码和允许例外，主题与对比度测试检查映射；新旧映射不能靠删除守卫通过。布局、几何、权限与财务含义不因主题变更而调整。

## 6. 图表分类稳定映射：设计与测试方案（尚未改变现有表现）

### 6.1 已知实现与研究边界

`CategoryDonut.buildSlices()` 先按金额排序，再用**排名** `index` 调用 `categoricalColor(index)`。结果：某分类金额排名变化、月份切换、分类新增/删除时，颜色身份会变。用户会误以为“颜色代表某个分类”。

### 6.2 目标

- 同一分类在跨月份/刷新/设备上颜色稳定；
- 金额排序变化不影响颜色；
- 新增/删除分类只影响最小范围；
- 不要求数据库迁移（本轮不做分类色字段）；
- 保留 8 色之外的降级路径与标记形状。

### 6.3 候选方案

| 方案 | 稳定性 | 改动范围 | 结论 |
|---|---|---|---|
| A. 排名映射（现状） | 低 | 无 | 现有接线；稳定映射须另行确认 |
| B. 持久化分类色槽位（DB） | 高 | 迁移/API/导入导出 | 本轮禁止；持久化色槽留 S16-C-08 / S16-D-08 评估 |
| C. 分类 id 稳定哈希 → 调色板 | 高（同 id 永远同槽） | 纯前端 | **推荐先做无迁移方案** |
| D. 图表使用用户指定分类色 | 取决于缺省与冲突策略 | 分类已有可选色字段；图表消费需评估 | 不把已存在的分类颜色功能当作待开发；图表映射策略另行确认 |

### 6.4 推荐设计（仅方案，未接线）

1. 使用**稳定字符串哈希**（例如 FNV-1a）对分类 `id` 取模 8；不要用数组位置、对象 key 顺序或随机数。
2. 同一时刻若两个分类落到同一槽，按固定哈希顺序做线性探测到下一个空槽；只要分类集合不变，结果确定。
3. 新增分类可能拿走空槽；已有分类在未冲突时保持原槽；删除分类后不重排其他分类。
4. 超过 8 个分类：仍使用 8 色 + `markerShape` 区分，并在图例直接标注名称；不新增颜色。
5. “其它 N 项”使用中性灰，不占用分类色。
6. 分类改名不改色（哈希只看 id）；不同账本同一分类 id 各自独立，但同一账本稳定。
7. 该函数先作为纯函数 + 测试加入，**不接入图表**，直到所有者确认视觉；届时替换 `buildSlices` 的 `color: categoricalColor(index)`。

### 6.5 测试矩阵

- 同集合、不同金额/排序 → 每个分类颜色相同。
- 增加一个分类 → 原有分类颜色不变；新分类获得不同槽（若冲突按探测规则确定）。
- 删除一个分类 → 剩余分类颜色不变。
- 分类改名、账本刷新、序列化重载 → 颜色不变。
- 两个分类哈希碰撞 → 二者颜色不同，且结果确定。
- 分类数 > 8 → 色+形状/直接标注组合可区分；“其它”不占色。
- 颜色不能作为唯一识别：图例必须有名称/标记形状。
- 不改变现有图表金额、tooltip、数据顺序或业务结果。

## 8. 未解决边界

图表分类稳定映射仍为候选；`CategoryDonut` 现按排序位置分配槽位。用户标签任意保存色与固定前景的可读性需专项处理；浅色品牌文字和焦点的已知对比度债务不能写成通过。真机、Safari、长期阅读及新 S19 材质验收以 STATUS 与实际测试证据为准，不由历史浏览器测试替代。

## 14. 深色表面规则

绿色深色采用已确认的 R3-A 品牌组，普通卡片为中性表面；`canvas #17181A`、`surface #2C2C2C` 的配对不随品牌染色。页头和大面积背景保持中性，品牌用于小面积强调。边界用 `line-strong`，装饰用 `line`；hover 沿用填充自身明度及既有表面，不把所有层级做成不同色相。

## 15. 七主题与正式映射

七套色盘 green/yellow/orange/blue/purple/red/cyan 均已开放，键名保持稳定。模式和色盘独立，逐组定义 `on-brand` 与 `focus-ring`，不能全局强制白色前景。金色品牌填充与可读深色前景分工，深色海浪顶层前景按最终映射读取；候选阶段的预览值不得覆盖 CSS 中的正式映射。
