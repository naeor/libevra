## 1. 当前架构

**系统头像（2026-10-25，所有者完成 R2 视觉审核后接入）**：第一批六款单色 SVG 与默认小花由 `components/UserAvatar.tsx` 统一渲染，图形使用 `currentColor` / `brand`，圆形衬底使用 `brand-soft`；选中环、文字及页面消费现有语义 token，主题切换只改变颜色，不改变保存的头像 ID。正式 SVG 位于 `src/assets/avatars/`，与已审核的 `design/avatar-prototypes/round-01/svg/` 逐字一致，测试约束两者不漂移。弦月保持透明蒙版，每个组件实例使用独立 ID。特典「倒悬」采用截图确认的同心分轨稿（`07-daoxuan-special.svg`），例外使用白色图形、`brand-dark` 衬底与白色透明度层次；保持一环一个标记，所有蒙版按实例隔离。

**旧稿固定色例外**：只有 `components/LegacyUserAvatar.tsx` 保留 13 款已存旧稿的固定插画色，防止已有选择变成另一幅图；旧稿不在正式选择列表上架，仅原账户的当前头像作为兼容选项出现。20 个兼容 ID 与“六款审核稿 + 默认小花”的选择集合均定义在 `packages/shared/src/profile.ts`，数据库约束与其一致性由测试验证。七套正式色盘未接入前，临时深色背景与七强调色测试只证明身份稳定、主题变量与蒙版接线，不代表完整主题视觉验收。

主题由两层组成：

1. **CSS 语义 token**：全部定义在 `apps/web/src/index.css` 的 `@theme` 中，组件只消费 token 生成的工具类（`bg-surface`、`text-ink` 等），不写主题分支。
2. **文档级偏好属性**：`apps/web/src/lib/theme.ts` 定义两个独立维度，并把用户选择写到 `<html>`：
   - `data-theme-mode="light|dark"`（`system` 已解析成实际模式）
   - `data-theme-palette="green|red|orange|yellow|cyan|blue|purple"`
   - `data-theme-preference="light|dark|system"`（保留用户的字面选择）

`theme.ts` 只提供基础函数：解析/持久化偏好、解析 system、应用到 `document.documentElement.dataset`、监听系统外观变化。它是可测试的纯逻辑加最小 DOM 接口，不在 React 树里传播主题值。

**尚未接入**：没有 prepaint 脚本、没有调用 `applyThemePreference()` 的设置页、没有 `dark`/色盘值块。深色与各色盘的值由 Codex 设计后，在 CSS 中按 `data-theme-mode` / `data-theme-palette` 覆盖 token；组件无需修改。

### 1.1 默认值

```text
mode = light
palette = green
brand = #55997a
```

默认浅色绿的值与原 1.16.03 相同；新增 token 的默认值经过选择，使已迁移组件在默认主题下解析出与旧字面量相同的颜色（见 §7）。

## 2. 当前 token（50 个）

`@theme` 内共 50 个 `--color-*`。旧 19 个名称全部保留，新增 31 个角色/数据/图表/海浪/玻璃 token。

### 2.1 基准（明暗轴）

| token | 默认值 | 用途 | 应随明暗变化 |
|---|---|---|---|
| `canvas` | `#fafcfb` | 页面底色 | 是 |
| `surface` | `#ffffff` | 卡片/浮层/输入框表面 | 是 |
| `ink` | `#24312b` | 主文字 | 是 |
| `muted` | `#60726a` | 次级文字 | 是 |
| `line` | `#e3ede7` | 发丝线、装饰边界 | 是 |
| `line-strong` | `#7f8f87` | 输入框/可交互边界（**尚未应用到组件**，默认值已按 3:1 预留） | 是 |

### 2.2 强调（色相轴）

| token | 默认值 | 用途 | 应随色盘变化 |
|---|---|---|---|
| `brand` | `#55997a` | 唯一强调色：主按钮底、页头底、选中态 | 是 |
| `brand-dark` | `#447d63` | 强调色的可读深色文字/按压态 | 是 |
| `brand-soft` | `#edf5f0` | 强调浅底、hover、焦点环 | 是 |
| `accent-ink` | `#5f7268` | 图表坐标轴/图例文字 | 是（需保持可读） |
| `chart-rule` | `#8fa39a` | 图表网格/基线 | 是（保持低存在感） |
| `category-ink` | `#3f7059` | 分类图标的深色前景 | 是 |

### 2.3 状态（含义轴，不跟色盘）

`danger` / `danger-dark` / `danger-soft`、`warn` / `warn-dark` / `warn-soft`。失败永远是红色，待处理永远是琥珀色；不能因为用户选择紫色主题就把错误改成紫色。

### 2.4 前景角色（固定覆盖点）

| token | 默认值 | 用于 |
|---|---|---|
| `on-brand` | `#ffffff` | 品牌填充上的文字/图标 |
| `on-danger` | `#ffffff` | 危险填充上的文字 |
| `on-warn` | `#1a1206` | 警告填充上的文字（目前未使用；为未来可读性预留） |
| `on-ink` | `#ffffff` | 深色遮罩/墨色底上的文字 |
| `on-heat` | `#ffffff` | 热力深格文字（存在已知对比度债务，见 §8） |
| `on-tag` | `#ffffff` | 用户标签选中态文字（标签颜色是用户数据，见 §6） |
| `control-knob` | `#ffffff` | 开关旋钮；深色下仍需要可见的实体白，不随表面变暗 |
| `focus-ring` | `#edf5f0` | 键盘焦点环（当前仍是旧浅环；已知 1.08:1，待 Codex 设计，见 §8） |

### 2.5 财务数据（语义，不跟色盘）

`data-expense`（支出）、`data-income`（收入）、`data-transfer`（转账）。图表和统计的事实色从这组读取，不再借分类槽位。

### 2.6 图表与热力

- `chart-1…chart-8`：8 个分类色，SVG/图表通过 `var(--color-chart-N)` 读取。
- `chart-heat-0…chart-heat-4`：日历热力的 5 档斜坡，0 档是“无记录”的中性色。
- 图表标记形状仍由 `markerShape()` 提供，颜色从不是唯一信号。

### 2.7 海浪、玻璃与遮罩

- `ocean-1…ocean-4`：四层海浪填充；路径、层数、速度、波动、交互代码不变。
- `on-ocean`：海浪上文字/图形前景。
- `glass-highlight`：明细动态头部的白色玻璃高光；它描述的是光效，不是可主题化的实色。
- `overlay-soft` / `overlay`：旧 token，保留用于浮层遮罩。

## 3. 主题组合契约

两个维度相乘，而不是相加：

```text
resolved theme = f(base mode, accent palette)
```

- **只看明暗**：`canvas/surface/ink/muted/line/line-strong`、图表网格、玻璃、深色阴影。
- **只看色盘**：`brand*`、`accent-ink`、`category-ink`、`focus-ring` 的色相（但对比度由明暗共同决定）。
- **两者都看**：`on-brand`、`focus-ring` 的实际值需要同时满足当前色盘 × 当前模式的对比度；这些是每个色盘/模式组合的必填变量，不是组件分支。
- **两者都不看**：`danger*`、`warn*`、`data-*`、`chart-heat-*`、`on-tag`（用户数据）、`control-knob`、`on-ocean`（海浪固定视觉身份）。

组件层禁止：

```tsx
// 禁止
<div className="dark:bg-...">
<div className={theme === "purple" ? "..." : "..."}>
```

允许的唯一入口是 CSS 在 `[data-theme-mode="dark"]` / `[data-theme-palette="blue"]` 下覆盖 token。

## 4. 固定色与例外

以下颜色**不参与主题化**，并有代码例外/理由：

1. **二维码黑白**：`QrCodeView.tsx` 必须接近纯黑/纯白；相机阈值读取不能跟随主题。保留 `bg-white` 例外；不改成 token。
2. **用户标签颜色**：数据库存 `#RRGGBB` 用户数据，原色显示；选中态文字用 `on-tag`。任意用户色与固定白字的对比度问题不在本轮自动解决，后续由 Codex 设计自动前景/浅底描边策略。
3. **开关旋钮**：`control-knob` 固定在默认白；深色下可通过主题值调整，但不能简单跟随 `surface` 变暗而失去实体感。
4. **明细玻璃**：`glass-highlight` 是透明度/光效，不是实色；保留在 `detail-motion.css` 的说明范围内。
5. **运行中的动画几何**：海浪路径、明细头部插值、过渡曲线不属于颜色 token；任何主题重构不得改动。

## 5. 迁移记录

已从字面白色/Tailwind 内置色迁移到语义 token 的主要位置：

- 页头/主按钮/选中态：`text-white` → `text-on-brand`；品牌填充按钮同。
- 危险确认：`text-white` → `text-on-danger`。
- 墨色提示条/同步条/撤销条：`text-white` → `text-on-ink`。
- 点击热力深格：`text-white` → `text-on-heat`。
- 用户标签选中：`text-white` → `text-on-tag`。
- 半透明白叠加（页头/录音浮层/骨架）：`bg-white/15…40` → `bg-on-brand/15…40`。
- 白色控件表面：`bg-white` → `bg-surface`（GuestModeBadge 等）；开关旋钮专token。
- 图表：JS 字面量 → `var(--color-chart-*)` / `var(--color-data-*)` / `var(--color-chart-heat-*)`。
- 海浪：4 个 JS 字面量 → `var(--color-ocean-*)`。
- 标签分类色：`ManagePages` 不再直接 import `CATEGORICAL_COLORS`，改从 `tagColors.ts` 取，避免主题图表调色板与用户标签数据耦合。

守卫从仅 hex/rgb 扩展到 Tailwind 内置色类名（`text-white`、`bg-red-500` 等）；QR `bg-white` 是唯一允许的固定色，标签选中 / 开关旋钮已改为语义 token。

## 6. 图表分类稳定映射：设计与测试方案（尚未改变现有表现）

### 6.1 当前问题

`CategoryDonut.buildSlices()` 先按金额排序，再用**排名** `index` 调用 `categoricalColor(index)`。结果：某分类金额排名变化、月份切换、分类新增/删除时，颜色身份会变。用户会误以为“颜色代表某个分类”。

### 6.2 目标

- 同一分类在跨月份/刷新/设备上颜色稳定；
- 金额排序变化不影响颜色；
- 新增/删除分类只影响最小范围；
- 不要求数据库迁移（本轮不做分类色字段）；
- 保留 8 色之外的降级路径与标记形状。

### 6.3 候选方案

| 方案 | 稳定性 | 改动范围 | 结论 |
|---|---|---|---|
| A. 排名映射（现状） | 低 | 无 | 仅作为历史行为 |
| B. 持久化分类色槽位（DB） | 高 | 迁移/API/导入导出 | 本轮禁止，留 S16-C/D |
| C. 分类 id 稳定哈希 → 调色板 | 高（同 id 永远同槽） | 纯前端 | **推荐先做无迁移方案** |
| D. 用户手动指定分类色 | 最高 | DB + UI | 后续可选，不能阻塞 S16-B |

### 6.4 推荐设计（仅方案，未接线）

1. 使用**稳定字符串哈希**（例如 FNV-1a）对分类 `id` 取模 8；不要用数组位置、对象 key 顺序或随机数。
2. 同一时刻若两个分类落到同一槽，按固定哈希顺序做线性探测到下一个空槽；只要分类集合不变，结果确定。
3. 新增分类可能拿走空槽；已有分类在未冲突时保持原槽；删除分类后不重排其他分类。
4. 超过 8 个分类：仍使用 8 色 + `markerShape` 区分，并在图例直接标注名称；不新增颜色。
5. “其它 N 项”使用中性灰，不占用分类色。
6. 分类改名不改色（哈希只看 id）；不同账本同一分类 id 各自独立，但同一账本稳定。
7. 该函数先作为纯函数 + 测试加入，**不接入图表**，直到所有者确认视觉；届时替换 `buildSlices` 的 `color: categoricalColor(index)`。

### 6.5 测试矩阵

- 同集合、不同金额/排序 → 每个分类颜色相同。
- 增加一个分类 → 原有分类颜色不变；新分类获得不同槽（若冲突按探测规则确定）。
- 删除一个分类 → 剩余分类颜色不变。
- 分类改名、账本刷新、序列化重载 → 颜色不变。
- 两个分类哈希碰撞 → 二者颜色不同，且结果确定。
- 分类数 > 8 → 色+形状/直接标注组合可区分；“其它”不占色。
- 颜色不能作为唯一识别：图例必须有名称/标记形状。
- 不改变现有图表金额、tooltip、数据顺序或业务结果。

## 8. 已知限制（明确留给 Codex/所有者）

1. **`focus-ring` 仍是旧浅绿 `#edf5f0`**：相对 canvas 约 1.08:1，不满足焦点指示器 3:1。改成深色环会改变所有控件的焦点视觉，属于设计决策；本轮只定义 token 与基线测试。
2. **热力前景**：`on-heat` 白色在 `chart-heat-3` 上约 2.37:1、在 heat-4 上约 4.07:1；热力格 10px 文字不满足 AA。是否改成深浅分档前景/调整斜坡由 Codex 定。
3. **`on-brand` 默认白对 `brand` 为 3.37:1**（大字号/按钮可用；小正文不达 4.5）。品牌绿保留原值，是否改用深字或加深绿色是产品/视觉决策。
4. **`line-strong` 已按 3:1 预留但尚未用于输入框**；应用到现有输入框会改变默认视觉，需要所有者确认。
5. **深色/色盘值尚未定义**；`theme.ts` 还没有 UI 调用者与 prepaint 脚本，切换闪烁问题尚未进入实现验证。
6. **用户标签任意 hex 与固定前景**的自动对比度方案未实现；本轮只把选中文字改为 `on-tag`。
