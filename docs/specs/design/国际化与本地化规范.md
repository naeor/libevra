# Libevra · 国际化与本地化规范（S16）

> 最后核对: `claude/s16-i18n` 本地分支 / 2026-10-25。本文是界面语言（简体中文 / English）的**唯一规格**：架构、写法、术语表、布局规则与验收方法。

## 0. 一句话结论

- 界面文字全部经过 `t("模块.区域.名称")` 取用；`zh-CN` 是源语言，`en-US` 必须逐键对齐（类型检查 + `i18n.test.ts` 双重拦截）。
- **只翻译界面，不翻译数据**：账本名、分类名（预置分类除外，见 §5）、备注、昵称、用户名、商户、OCR / 语音原文、导出文件内容一律原样。
- **语言 ≠ 货币 ≠ 时区 ≠ 识别语言**：切到英文不会把人民币变成美元，也不会改变日期归属、金额精度或识别规则。
- 偏好存在本机 `localStorage` 的 `libevra.language`（`system` / `zh-CN` / `en-US`），与主题偏好同一机制；不改数据库。

## 1. 架构

| 位置 | 作用 |
|---|---|
| `apps/web/src/i18n/locales.ts` | 支持的语言清单、语言自称、浏览器语言匹配（只看语言，不看 IP） |
| `apps/web/src/i18n/index.ts` | i18next 初始化；导出 `t`、`useI18n()`、`currentLocale()`、`applyLocale()`、缺键记录 |
| `apps/web/src/i18n/resources/zh-CN/*.ts` | 源语言文案，按模块分文件；**对象结构即全部键的定义** |
| `apps/web/src/i18n/resources/en-US/*.ts` | 英文；类型为 `Messages<typeof zh>`，缺键 / 多键都是类型错误 |
| `apps/web/src/i18n/sharedMessages.ts` | `@libellum/shared` 里写死的中文提示（zod 校验信息等）按原文查表翻译 |
| `apps/web/src/lib/language.ts` | 语言偏好：解析、首次运行默认值、持久化、控制器（纯函数，可测） |
| `apps/web/src/lib/languageRuntime.ts` | 浏览器运行时：接 i18next、`<html lang>`、跨标签页同步、系统语言变化 |
| `apps/web/src/pages/LanguagePage.tsx` | 设置 → 显示与数据 → 语言（`/settings/appearance/language`，游客可进） |
| `apps/web/src/components/LanguageSwitch.tsx` | 登录 / 注册 / 找回页右上角的语言切换 |
| `tools/i18n-scan.mjs` | 扫描还没走翻译的中文（注释不算） |

**为什么是 i18next + react-i18next**：成熟、社区最大、复数走 `Intl.PluralRules`、插值 / 嵌套 / 回退都内建；文案用 TS 对象而不是 JSON，键由类型检查核对。两种语言都打进主包（几十 KB），因为离线优先的 PWA 不能让“第一次离线切英文”取决于某个 chunk 是否被缓存。

**语言切换不刷新页面**：`App` 用 `useLanguageRerender()` 订阅 i18next，切换时整棵树重新渲染（项目里没有 `React.memo`）。组件里的 `useI18n()` **刻意不是 hook**——不少测试把展示组件当普通函数调用，组件里有 hook 会在测试里崩。

**回退规则**：英文缺某条 → 显示中文原文；两种语言都没有 → 显示键名，并记入 `missingTranslationKeys()`、开发环境告警。

**默认语言**：本机第一次运行带语言功能的版本时决定一次并记下：以前用过 Libevra（本域名已有本地记录）→ 简体中文（老用户更新后不突变）；全新设备 → 跟随系统（浏览器语言列表里第一个中文或英文；都不是则中文）。

## 2. 写法

```tsx
import { useI18n } from "../i18n/index.js";

export function Example({ count }: { readonly count: number }): React.JSX.Element {
  const { t } = useI18n();
  return (
    <section>
      <h2>{t("ledger.list.title")}</h2>
      <p>{t("ledger.list.count", { count })}</p>
    </section>
  );
}
```

- **键名**：`模块.区域.名称`，小驼峰；模块 = `resources/zh-CN/` 下的文件名。
- **中文原文一字不改**地搬进 `zh-CN`（现有测试按中文断言，默认语言是中文）。
- **插值**写 `{{name}}`；**复数**写 `xxx_one` / `xxx_other`，调用时传 `count`。中文也写两条（内容相同），保持两种语言键结构一致。
- **不在模块顶层取文案**：`const LABELS = { a: t("x") }` 会把导入时的语言固定下来。顶层常量只存**键**或稳定 ID，渲染时再 `t()`。
- `useMemo` 里拼文案时，把 `locale`（`useI18n()` 返回）放进依赖数组。
- 句子中间夹 `<strong>` / 链接时，用 react-i18next 的 `<Trans i18nKey="…" components={{ b: <strong /> }} />`，文案里写 `<b>…</b>`；不要把一句话切成三段拼（英文语序会错）。
- **逻辑不能依赖文案**：`if (action.label === "手动记账")` 一类比较必须改成比较稳定 ID。
- `aria-label`、`title`、`placeholder`、`alt` 也是界面文字，同样要翻译。`data-*`、测试 ID、日志不翻译。
- 改源码文件请用编辑器 / Edit 工具，**不要用 shell 做 UTF-8 字符串替换**（AGENTS.md §6）。

## 3. 格式化（日期、数字、货币）

| 需要 | 用 | 不要 |
|---|---|---|
| 金额 | `formatMoney(minor, currency)`（`lib/format.ts`） | 自己拼 `¥` 与千分位 |
| 币种名 | `currencyName(code)` | 写死“人民币” |
| 月份标题 | `formatMonthLabel("2026-10")` → `2026 年 10 月` / `October 2026` | 拼“年”“月” |
| 日期分组 | `formatDayLabel(localDate)` → `今天` / `Today` / `Wed, Oct 8` | 写死“周三” |
| 一个时刻 | `formatInstant(iso, options)`（`lib/datetime.ts`） | `toLocaleString("zh-CN")` |
| 日历日 | `formatLocalDate("2026-10-25")` | `new Date("2026-10-25")`（会被当成 UTC） |
| 相对时间 | `formatRelativeTime(iso)` → `3 分钟前` / `3 minutes ago` | 自己算“天前” |
| 账目时间 | `formatTimeWithZone(iso, tz)` → `19:34` / `7:34 PM`（+`UTC+8`） | — |
| 图表坐标轴 | `formatAxisAmount`、`bucketLabel`、`bucketFullLabel`（`lib/chart/format.ts`） | — |

- 中文路径保留原来的输出（`1.2万`、`10月`、`2026 年 10 月`），其它语言走 `Intl`（`12K`、`Oct`、`October 2026`）。
- **币种符号按币种固定**（¥ = 人民币、JP¥ = 日元、HK$ = 港币），不随语言变化；分组符 / 小数点取自 `Intl`。
- **存储与计算不变**：`toLocalDate`、`toLocalIso`、`currentMonth`、金额最小单位、统计口径都与语言无关。
- **导出文件不随语言变化**：CSV / XLSX 由服务器生成，请求不带语言；表头、日期格式（`YYYY-MM-DD`）、金额格式固定。2026-10-25 实测中英文界面各导出一次，除每次导出自带的“导出编号”外逐字节一致，再导入按同一规则解析。

## 4. 不翻译的东西

用户数据（账本名、自建分类名、标签、备注、昵称、用户名、商户、OCR / 语音 / 粘贴原文）；服务器保存的历史文字；识别关键词与正则（`transactionText`、`categoryMatch` 等）；提交给服务器的值；导入导出格式；品牌名 `Libevra`；代码注释。

法律文本（隐私政策、使用条款）：页面框架翻译，正文保留中文原文并注明英文译本待专业审核——**不能自行宣称英文版具有法律效力**（路线图 S16-C-10）。

## 5. 预置分类与支付方式

数据库没有“预置分类 ID”，本轮不改结构、不批量改数据。`lib/presetNames.ts`：

- 名字与预置中文名**完全相同** → 英文界面显示对应英文（`餐饮` → `Food & drink`）；
- 用户改过名或自建 → 原样显示；
- **编辑框、请求、导入导出、匹配一律用原名**；`displayCategoryName` / `displayPaymentMethodName` / `displayCategoryDescription` 只用于显示。

## 6. 服务器错误

`errorMessage(error)`（`lib/api.ts`）：中文界面显示服务器原文（与以前一致）；其它语言按错误码查 `errors.api.<code>`，再查 shared 原文对照表，都没有就显示通用说明——不把中文塞进英文界面。错误码本身不变，按错误码的判断不受语言影响。

## 8. 英文布局规则

英文通常比中文长 30%–100%。适配时：

1. 文字容器加 `min-w-0`，允许换行（`break-words` / `[overflow-wrap:anywhere]`）；不要给文字加 `whitespace-nowrap` / 固定宽度。
2. 一行多个按钮：外层 `flex-wrap`，或窄屏改为纵向；按钮文字允许两行。
3. 标签 + 值的行：值 `shrink-0` 时标签必须 `min-w-0`；值较长时允许换到下一行。
4. 底栏 / Tab：用短文案（`shortLabel`），并保证 320px 下不重叠。
5. **不许为了英文整体缩小字号**；不许改已确认的布局、品牌颜色、海浪动画。
6. 长昵称、长账本名与英文文案同时出现时也要验证（`truncate` 只用于用户数据，不用于说明文字）。

## 9. 验收

- `node tools/i18n-scan.mjs`：未走翻译的中文行数（有 `i18n-ignore` 注释说明原因的除外）。
- `pnpm --filter @libellum/web test`：含 `i18n.test.ts`（键集合、占位符、空值、英文残留中文、复数成对、回退、伪语言）、`language.test.ts`（偏好、首次默认、持久化、跨标签页、系统语言）、`apiErrors.test.ts`（服务器错误码全覆盖）、`sharedMessages.test.ts`（shared 原文对照）、`content/announcements.test.ts`（公告英文结构一致）与各页面的英文渲染测试。
- 浏览器：320×568 / 375×667 / 390×844 / 430×932 / 768 / 1200 下中英文截图对照；伪语言长文本压力测试（开发服务器下 `localStorage.setItem("libevra.pseudo", "1")` 并选 English，见 `i18n/pseudo.ts`）。
