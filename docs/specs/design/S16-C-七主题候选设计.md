## 2. 共同规则

- 深色保留 R2-A / R3-A 中性轴：画布、表面、文字、边界一致。品牌用于操作、选中、链接、分类图标与海浪，不把页面染成对应主题的暗色。
- 浅色主按钮用深沉主色与白字，hover 使用更深的 `brand-dark`；深色主按钮用低饱和亮色与深字，hover 使用更亮的 `brand-dark`。Pressed 不另造角色，沿用现有控件反馈。Disabled 保留既有透明度；禁用态不冒充可交互状态。
- 每套的软底与可读前景单独成组，焦点环分别配浅深背景。六套新浅色输入框使用已有 `line-strong`。
- 新六套浅色明细的统计卡使用 `brand-dark` 承载白字；页头小字不再降低前景透明度，避免“白色玻璃 + 半透明白字”叠加造成对比度下降。既有卡片、间距、圆角、动画不变。森林绿保留原玻璃表现，这一差异需要人工比较。
- 六套新浅色的未选中收支文字使用 `muted` 与少量 `ink` 混合，保持次级权重并跨过 4.5:1；错误提示在 `danger-soft` 上使用既有 `danger-dark`。这些是开发预览的颜色分配，不改正式组件。
- 六套新浅色的用户标签消费既有 `--tag-foreground` 自动黑白前景，保持保存色和标签含义不变；森林绿正式浅色仍原样显示，旧白字债务另记。
- 另外 39 个颜色角色在同一模式的七主题间逐项一致：包括财务、错误 / 警告颜色值、图表八色、热力阶梯、遮罩等。标签保存色不变化。没有调整分类颜色算法、排序、金额或财务计算。
- 海浪分别设计四层色阶，品牌文字位于最深层；浅深不是反相或 hue-rotate。几何、速度与交互源文件不动。

## 4. 人工比较重点

1. 森林绿 / 青瓷灰：看海浪与操作色，判断青瓷灰的灰青感是否足够，不能只看名称。
2. 青瓷灰 / 雾霭蓝：两者深色按钮都是柔和冷色；重点看中间海浪、选中态和多页组合，决定是否需要进一步拉开冷色倾向。
3. 暖木棕 / 丹霞红：棕偏木材、红偏陶土；判断大面积浅色页头是否仍能明确区分，木棕是否显旧或沉重。
4. 蜜金黄 / 暖木棕：琥珀是金麦色，木棕更中性；是否符合“黄”的期待由所有者决定。
5. 丹霞红 / 支出与错误、蜜金黄 / 警告：保持现有业务色，观察实际文字、图标和操作语境是否足以区分，不仅比较色值。未为拉开距离而擅自修改业务状态。
6. 森林绿浅色的既有对比度债务原样保留；其余候选的对比度修正是否应在另一次授权中统一回正式森林绿，需单独决定。

没有选出六套的最终优胜色，也没有把“数学上达标”当成整体协调或视觉验收。预览、画板、客观结果及限制见 [本地验证记录](../../archive/releases/S16-C-七主题候选-本地验证-20261024.md)。

### 5.1 金色展示、文字与按钮分工

浅金 `brand` 配深色 `on-brand`，页头、FAB、主按钮均不再用白字；`brand-dark` 专用于小字链接和深金边界，`category-ink` 用于分类图标，`brand-soft` 是浅金统计卡和软底。海浪改用四档金色 / 奶油金与深字，几何和时间参数不变。金色填充无需为了达到白字 4.5:1 而压成棕色。

同一个 `brand-dark` 在既有 Button 中兼任 Hover 填充与文字，直接沿用会使深字落到深底，因此只在隔离预览分配金色 Hover（brand 与白色混合）与 Pressed（brand 与深前景少量混合）。复用既有 Token，不新增永久角色。主按钮与 FAB 使用内侧深金 outline 保证边界；不能用 box-shadow 覆盖既有键盘焦点环。焦点仍由 `focus-ring` 单独承担。

三套新浅色表单的未选中收支项去掉白色透明填充，避免填充稀释前景对比度；文本与既有布局、选择行为不变。六套候选原有预览修正继续保留，森林绿正式浅色不跟随修改。

### 5.2 共用背景基线

开始 R2 时，工作区 `index.css` 和 `r2-colors.test.ts` 已由其他工作整合了石墨灰方案 A。R2 读取已有 canvas `#222429` / surface `#30343a`，没有写这两个文件。与 R1 相比，共享明度轴的 8 项变化见 基线差异（仅本机材料：`preview-artifacts/s16c-r2/shared-baseline-diff.json`），财务、危险、分类八色和热力映射均不变。

预览保留三种私有轮次：R1 原背景、R1 品牌配色搭配新石墨灰、R2 搭配新石墨灰。只有原始背景视图恢复旧明度轴，不能把新背景带来的变化全部归功于 R2 品牌组。四套固定品牌在新旧截图中的表面明度差，也不是本轮重新设计它们。

### 5.3 人工决策点

- 蜜金黄：是否接受浅金卡与深字；与其他主题的深色统计卡有表面极性差别。金色是否足够明朗、深色香槟色是否过淡，需在多页判断。
- 丹霞红：品牌操作与错误 / 支出仍属于红色家族；保留业务色，使用现有文字、图标和危险确认语境区分，没有声称完全消除相近色感。
- 现有 Alert 的 success / info 共用 `brand-soft` / `brand-dark`，所以丹霞红的成功提示也带岩红色。真实组件样例保留并暴露这一 R1 遗留问题，未用仅美化样例的特殊样式掩盖；后续应单独处理成功与信息提示的语义分配。
- 烟霞紫：是否在克制与辨识度之间取得适当平衡；与雾霭蓝并列判断灰紫是否足够明确。
- 既有森林绿浅色与热力图低档文字债务仍按 R1 记录，未借本轮更改四套固定品牌、业务色或图表算法。

所有页面使用 R1 相同的金额、日期、标签、表单输入、展开状态与滚动坐标；70 份根节点内容哈希逐项相同。普通深色表面中性，品牌色只在交互和海浪等品牌区域承担身份。

## 7. 七主题海浪适配（2026-10-24，待最终人工验收）

森林绿深色四层由所有者选定，直接从最新未提交 CSS 读取，顺序为 `#6AA78A` / `#4F8A6D` / `#3F7059` / `#2F5C47`；浅色森林绿不改。不能从 HEAD `24eec44` 恢复旧 CSS 覆盖这组值。其余六套仅调整 `ocean-1…4` 和 `on-ocean`，非海浪 45 个角色与 R3 逐项相同；普通深色仍为 canvas `#17181A` / surface `#2C2C2C`。

新六套深色顶层变亮，`on-ocean` 因此采用与各自品牌相协调的深前景。浅色蜜金黄使用深字，其他新浅色使用白字；均在真实展示态、常规态的文字实际承载层检查。头像沿用正式组件和 16% 前景色圆盘，不改几何或交互。

森林绿深色默认 `on-ocean #E5EFE8` 按要求保留，但对顶层只有 2.38:1，Logo、正文和头像未达相应目标。独立建议仅将海浪前景设为既有 `on-brand #142119`，文字约 5.95:1，头像圆盘叠色后约 4.63:1；不改四层填充，也不默认应用。交互预览中的“深字建议”是只读候选开关，不写正式偏好，最终选择由所有者确认。

[海浪画板](http://127.0.0.1:5200/s16c-waves.html)包含 28 基础图与独立的 2 张森林绿前景建议；[可交互预览](http://127.0.0.1:5200/s16c.html)默认进入本轮海浪，原 R1 / R2 / R3 页面配色与画板保留。截图使用原有点击、滚轮和减少动态效果路径达到进度端点，正常预览保留环境波动和连续弹簧退潮。路径、计时、动画、布局和所有产品源文件不改。

### 7.1 森林绿追加调整（2026-10-24）

所有者认可黑字方向并授权进一步调整森林绿海浪。当前候选采用浅色四层的**完整逆序**：深色从上到下为 `#96C4AC / #6AA78A / #4F8A6D / #3F7059`，使真正最浅的绿成为大面积顶层；独立海浪前景为中性黑 `#17181A`，Logo、标语、头像一致。浅色四层和白字保留，其他六套不改。这样浅深属于同一个绿色阶梯，不再向更深一档平移。

该决定覆盖 §7 前述“固定旧深色阶梯 / 保留浅字”的候选约束，仅作用于本地候选。森林绿在预览文件只覆盖 5 个海浪角色，其他值继续读取正式 CSS，没有复制整套正式主题或覆盖 DeepSeek 的源文件。原先可选前景开关移除，黑字现为候选默认行为。

文字 / 顶层约 9.127:1，头像圆盘叠色后约 6.755:1。新 28 图矩阵仅替换森林绿深色两态，其他 26 图原样保留；当前 42 项 Token 配对无失败。旧 28 图 / Token / 报告留档，新的 Token 表（仅本机材料：`preview-artifacts/s16c-waves-v2/wave-tokens.md`）与 调整前后画板（仅本机材料：`preview-artifacts/s16c-waves-v2/boards/forest-foreground-proposal.png`）供审查。文件名中的 proposal 仅为旧索引兼容，画板内容明确标注前后版本。
