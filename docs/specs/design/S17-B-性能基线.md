# S17 Agent B · 性能基线（B-5，2026-10-27）

> 规格 §36.12 / §44：不能为了性能牺牲精确性；需要可追溯的真实测量值，而不是“很快”之类的结论。
> 测试：`packages/shared/src/performance.test.ts`（2 个用例，可重复执行；数据为种子化 LCG 生成，非真实账本）。

## 1. 测量环境

| 项 | 值 |
|---|---|
| 日期 | 2026-10-27 |
| 机器/系统 | 本机开发环境（Windows，Node.js 24.x，Vitest 5） |
| 命令 | `pnpm --filter @libellum/shared exec vitest run src/performance.test.ts` |
| 数据集 | 2019-01-01 ～ 2027-01-01（2,922 个日桶）；金额为 1–1,000,000 分的随机整数；支出:收入 ≈ 3:1 |
| 约束 | 所有计算为纯函数、单次遍历；金额全程 `bigint`，不经过浮点；无缓存假设 |

## 2. 实测结果（记录于测试输出）

| 数据集 | 计算内容 | 桶数 | 实测耗时 |
|---|---|---|---|
| 50,000 条 | 日序列 `computeTimeSeries` + 累计 `accumulateSeries` + 7 日移动平均 `computeTrailingMovingAverage` | 2,922 日桶 / 2,922 累计点 / 2,922 平均点 | **303.3 ms** |
| 10,000 条 | 日序列 `computeTimeSeries` | 2,922 日桶 | **46.9 ms** |

测试内断言只设 5,000 ms 的宽松上限（防 CI 抖动），真实数字以上表为准；数字来自测试输出的 `[B-5 perf]` 日志行。

## 3. 复杂度与设计约束

- 分桶：一次遍历累加 + O(桶数) 生成，整体 O(n + b)；累计 O(b)；尾随平均滑动窗口 O(b)。
- 不做采样入权威值：图表显示的降采样只允许发生在渲染层（S-01 `computation.sampling` 元信息），计算层永远全量精确。
- 内存：结果对象按桶数线性增长；50k 输入未出现内存压力（单测默认堆内完成）。
- 精度：`bigint` 累加，无 `Number` 转换路径；测试同时断言大整数与精确合计（见 `properties.test.ts`）。

## 5. 已知限制

1. 数字与机器/负载相关，只用于回归对比，不作为产品 SLA；不同机器允许 ±2x 波动。
2. API 端点级性能（SQL 聚合）不在 B 范围；B-5 不碰端点 limit（Lead 明确）。
3. 内存占用未做自动化断言（仅人工观察），如需回归可后续加 `--expose-gc` 的堆采样测试。

## 6. FX 逐日/逐笔扩展基线（2026-10-27，S-01 v2 draft）

对应提案 **B-S01v2-01/B-S01v2-02**（`fx.ts` 扩展）；测试 `packages/shared/src/fxPerformance.test.ts` 默认 skip，需 `FX_PERF=1`。

| 输入 | 调用 | 结果规模 | 实测 |
|---|---|---|---|
| 1,000,000 笔 | `aggregateFxDetailed`（daily-only） | 730 日桶 | **13.6 s** |
| 200,000 笔 | `aggregateFxDetailed`（includeEntries） | 200,000 逐笔 / 730 日桶 | **2.7 s** |
| 10,000 次 | `fxRangeMonths`（36 个月） | 36 月键 | **0.54 s** |

- 单笔约 13–14 µs；逐笔投影与 daily 共用一次扫描，无二次折算；金额全程 BigInt。
- 断言阈值：1M < 25 s、200k < 8 s、10k×36 月 < 2 s（仅防数量级回归）。
- 结论：**daily-only 适合 ≤36 个月图表**（典型 36 月 × 数千笔为毫秒级）；**逐笔明细需显式 `maxEntries`**（默认 50,000）与详情/导出视图，200k 以上走异步批次 + `yieldControl`，避免渲染帧同步。
