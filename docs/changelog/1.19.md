## 1.19.68 · 其余页面的选择类控件迁到正式选中组件（第三批，2026-11-14，仅本机）

- 按 [S19 审查后续待办](../specs/design/S19-审查后续待办与弹出面板模板-20261114.md) §6 第 28 条第三批，把 1.19.67 末尾“剩余未迁”表里记账相关、登录与留言、导入与筛选、导出与离线下载、冲突与附件各页的手写互斥选择，逐处按规格“怎么选”判断后套用 `MovingSelection` / `SelectionGrid` / `SelectionItem`。值、可选 / 禁用判断、角色与 aria、点击与键盘处理都没有改；Original、深色、Pad、电脑版保持原外观（这些组都用 `base` 默认的 `static`：选中项仍是调用方自己的样式，不显示选中块）。
- **覆盖位置与所用组件**

  | 位置 | 控件 | 判断 | 组件 |
  |---|---|---|---|
  | 批量添加（每张卡） | 支出 / 收入 | 两项互斥、一行 | `MovingSelection axis="x"` |
  | 记账“更多选项” | 支付方式（互斥，可再点取消） | 互斥、会折行 | `SelectionGrid` |
  | 留言引用面板 | 账目 / 事件 | 两项互斥、一行 | `MovingSelection axis="x"` |
  | 账本导入审核 | 每条记录“导入 / 跳过”“保留 / 删除” | 两项互斥 | `MovingSelection axis="x"`（“删除”带 `data-select-tone="danger"`） |
  | 明细排序弹层 | 排序字段；升序 / 降序 | 竖排单选列表 | `MovingSelection axis="y"`（行尾 ✓ 保留） |
  | 附件筛选弹层 | 附件“全部 / 含附件 / 无附件”；文件类型五项 | 一行三项；会折行 | `MovingSelection axis="x"`；`SelectionGrid` |
  | 月份选择 `MonthPicker` | 12 个月格与“全部” | 各格独立（`ul > li` 里，保留列表结构） | `SelectionItem`（不可选的月份不显示选中） |
  | 账单导入 | 状态筛选胶囊 | 互斥、会折行 | `SelectionGrid` |
  | OCR 概览 | 状态（旁边还有不参与选中的“筛选”按钮）、来源、方向 | 状态 / 来源会折行；方向三项一行 | `SelectionGrid`；`SelectionGrid`；`MovingSelection axis="x"` |
  | 导出 | 时间范围（5 项 + 自定义，两列网格）；格式（CSV / Excel） | 折成多行；两项一行 | `SelectionGrid`；`MovingSelection axis="x"` |
  | 月份离线下载 | 自动 / 从不 | 两项互斥 | `MovingSelection axis="x"` |
  | 非重复关系 | 有效 / 含已撤销 | 两项互斥 | `MovingSelection axis="x"` |
  | 冲突页 | 每个字段的本地 / 远端（起初都不选） | 竖排互斥 | `MovingSelection axis="y"` |
  | 附件 PDF 预览 | 缩放三档 | 三项一行 | `MovingSelection axis="x"` |
  | 拍照 | 单张 / 批量（`ActionCard`） | 两张卡竖排互斥 | `MovingSelection axis="y"` |

- **跳过项与理由**
  - **登录 / 注册切换（`AuthSwitcher`）**：是 `Link` 导航（`aria-current="page"`），点击是换路由，登录页与注册页各自渲染一份，切换时整块卸载重建，没有“从一项滑到另一项”；`MovingSelection` 也只认 `button` 子元素。保持原样。
  - **记账“更多选项”的标签多选**：选中态是标签自己的颜色填充（`tagFillStyle`，颜色是用户数据，文字色按底色算），套用 `SelectionItem` 会把底色让给透明玻璃、文字换成品牌绿，丢掉标签身份色。与已排在 1.19.69 的“批量修改、OCR 审核详情的多选标签”同一类问题，建议一起决定（见“需要所有者决定”）。批量添加卡片里的标签同理，没动。
  - **C 与 Original 记账页绿色顶区的“支出 / 收入”、扫描 / 语音确认表单与 OCR 审核详情的非 `KindToggle` 分支**：按任务要求与 1.19.51 的决定不动。
  - 数据相关的账本导入审核与冲突页只换外观容器，没有改状态结构，所以不需要跳过。
- **新增的共用规则（`selection-controls.css`，都在 S19 作用域里）**
  - **选中项让位要压过按钮已有的材质映射**：`:is(button, a).bg-brand.text-on-brand`（主按钮渐变）与 `.rounded-field.bg-brand-soft`（柔底）按类名命中，这些页面的选中按钮沿用了这些类名，原规则优先级打平导致选中项盖着品牌渐变（样板页第一次截图里“支出”“CSV”是深绿底配灰字）。新增一个用 `:root:root:root` 抬高优先级的专用块，只重复写“底色透明、无阴影、无描边”。
  - **`data-select-flat`**：未选项自己带实底 / 材质（导出的范围与格式、拍照的单张 / 批量、冲突页两侧、批量添加支出 / 收入、月份格）时，透明玻璃或 A 的白色浮起落在它们旁边看不出差别（截图里“本月”和“上月”没区别）；S19 下未选项改成与分段轨道同一个凹进的底（`--s19-track-*`），选中块是这一组里唯一凸起的面。与 1.19.67 对 `SlidingSelection` 未选项的处理同一思路，但用在容器属性上，不影响其他使用方。
  - **危险语义**：选中项带 `data-select-tone="danger"`（账本导入的“删除”）时文字仍用危险色，选中块只负责“选中”。
  - **材质自带的选中描边让位**：胶囊与交互卡材质（`.lv-material`）对 `aria-pressed` 自带统一选中描边（outline），迁移后与玻璃 / 浮起重复，所以选中项的描边取消，键盘焦点改用 outline 画（选中项的 box-shadow 已让位，焦点环要有）。
  - **被禁用的格子 / 行不显示选中**：`SelectionGrid` / `SelectionItem` 的选中规则加 `:not(:disabled)`，与 `MovingSelection` 脚本里“选中项被禁用就不显示选中块”一致（月份选择里不可选的月份原来就不是选中外观）。
  - 导出格式按钮里的说明文字从 `text-on-brand/80` / `text-brand-dark/70` 改为 `text-current/80` / `text-current/70`：Original 里取值相同（按钮文字色就是 on-brand / brand-dark），S19 里选中项底让给玻璃后按钮文字变品牌绿，说明文字也跟着变，不会剩下白字。
- **组件样板页**新增 `s19/component-gallery/ChoiceLab.tsx`：`component-gallery.html?shot=choices&part=1|2&s19=original|a|b1|b2|c`（可加 `theme=dark`），用与页面相同的写法（同样的组件、类名、容器）展示游客到不了的页面：导出、月份离线下载、拍照单张 / 批量、账本导入、冲突页、OCR、账单导入、非重复关系、PDF 缩放、留言引用、批量添加、支付方式、月份选择；组件样板页第 09 节同步列出。

## 1.19.67 · 切换类控件与开关按钮迁到“四种风格同一个模型”、B2 提示条更易读（2026-11-14，仅本机）

- 按 [S19 审查后续待办](../specs/design/S19-审查后续待办与弹出面板模板-20261114.md) §6 第 28 条（第二批：支出 / 收入切换与外观页明暗三选一）、第 36 条（开关按钮开启状态的 S19 外观）与 §7 第 2、6 条（B2 提示条改填充；直接迁共享组件 `SlidingSelection`，一次覆盖六处）。现行规则见 [S19 设计系统](../specs/design/S19-材质组件与动效设计系统.md) §3 用途表（新增“开关按钮”一行、提示条 B2 一格）、「选中指示与已选条件标签」（组件表、“怎么选”拆出“开关按钮”、1.19.67 接入范围）与「提示条」的对比度一段。值、可选 / 禁用判断、角色与 aria、点击与键盘处理都没有改。
- **共享切换 `SlidingSelection` 改为 `MovingSelection`**（`components/ui/SlidingSelection.tsx` 只剩薄包装：`axis="x" base="copy"` + 文字层）。六个调用方代码不改：
  - 支出 / 收入 `KindToggle`（记账页、扫描与语音确认表单、OCR 审核详情；只在 A / B1 / B2 手机外壳出现，C 与 Original 是绿色顶区的另一套按钮，见下）；
  - 明细页“全部 / 支出 / 收入”；批量修改的标签“添加 / 移除”；展示卡片编辑器的“数值 / 趋势 / 排行”；
  - 分析卡片编辑器的两条横向滑轨（表现形式、目录分区）；分析“添加卡片”抽屉的“分析卡片 / 布局容器”与“系统推荐 / 全部分析 / 我的自定义”。
  - S19 浅色手机外壳：B1 / B2 一块不染色的透明模拟玻璃按底栏胶囊的弹性规则滑动，A 没有色块、选中项按 A2 档浮起，C 浅绿实底干脆滑动，选中文字变品牌绿（原来 S19 下是一块从选中按钮复制来的白胶囊在滑）。
  - Original、深色、Pad、电脑版：与原来完全相同——`MovingSelection` 新增基础外观 `base="copy"`，选中块逐项复制选中按钮的计算样式、按原 200ms 节奏滑动；原 `sliding-selection.css` 的层次（选中块在未选按钮底色之上、文字之下）、“按钮只过渡颜色”与 `!important` 让底规则原样并入 `selection-controls.css`，`sliding-selection.css` 删除。深色与浅色来回切换时，脚本在复制外观与交给 CSS 之间切换（内联外观清掉）。
  - 分析抽屉的分类胶囊各自带瓷片底：留着时选中项的透明玻璃、A 的白色浮起和未选胶囊几乎一样（截图里看不出选了哪个），所以 S19 下 `SlidingSelection` 组里未选项不再带自己的底，选中块（或 A 的浮起层）是这一组唯一的面；C 原来没有给分析抽屉这些控件 S19 规则（选中是品牌实底），现在与其他风格同一模型（浅绿实底）。
- **外观页明暗三选一**（跟随系统 / 浅色 / 深色）与**外观预览“空间 / 明细”**改用横向 `MovingSelection`（少量互斥，`base` 默认不显示选中块）：S19 下与上面相同；Original、深色保持原来的品牌浅底 + 细框。`s19/page-surfaces.css` 去掉选中项的白胶囊（它的优先级高于选中指示），轨道保留。
- **开关按钮 `ToggleButton`**（`SelectionControls.tsx`，第 36 条）：就是调用方的 `type="button"` + `aria-pressed` 按钮，只多 `data-select-toggle` 钩子——不改成 `Switch`（`role="switch"` 要轨道、标题行放不下），不改 Original 的尺寸与描边。开启时在 S19 下与独立选中项同一外观：B1 / B2 透明模拟玻璃淡入、A 按 A2 档浮起（白色薄片 + 完整 A2 阴影）、C 浅绿实底，文字变品牌绿；关闭时回到普通按钮。材质只画在 `::before`（“多选”的 `::after` 是上下各扩 6px 的命中区，所以 A 不拆环境影层），不清调用方的 `box-shadow`（焦点环）。接入：筛选标题行“多选”（底部面板与电脑版两处；电脑版不在 S19 作用域，外观不变）、分析卡片编辑器的“替换”。规格“怎么选”把原来的“开关”拆成“开关（设置项）→ `Switch`”与“开关按钮 → `ToggleButton`”两行。

## 1.19.66 · 提示条（Toast）统一：一个队列、一个组件、随风格的语义材质（2026-11-14，仅本机）

- 按所有者 2026-11-14 的要求与决定：[S19 审查后续待办](../specs/design/S19-审查后续待办与弹出面板模板-20261114.md) §4“提示条（Toast）语义材质”（十条要求）与 §6 第 15–21 条（全部按推荐）。现行规则见 [S19 设计系统](../specs/design/S19-材质组件与动效设计系统.md) §3 用途表“提示条”一行与「提示条（Toast，1.19.66）」一节。业务行为不变：恢复 / 撤销逻辑、导入文案规则、头像“已读”回报时点都没有改。
- **原来**：五套各写各的短暂提示——撤销条（墨色条，渲染在外壳外，`bottom-28` 写死，没有读屏播报，5 秒）、Pad 外壳提示（墨色胶囊，2.6 秒）、分析工作台提示（所有类型一种墨色外观，3.2 / 5 秒）、拍照导入完成提示（顶部滑入，3 秒）、头像奖励横幅（品牌深色，可见 4 秒）；五种外观完全相同。
- **现在一套**：应用级队列 `ToastProvider`（挂在 `App.tsx` 原 `UndoProvider` 的位置，删除后返回列表时撤销仍在）＋调用接口 `useToast()`＋每个外壳一个显示宿主 `ToastViewport`（手机 / Pad 在 `.lv-shell` 里，电脑版在 `.lv-desktop` 里）；纯逻辑在 `lib/toast/`（队列、时长、控制器、位置），外观在 `components/toast/`，S19 材质在 `s19/toast.css`。`useUndo()` 保留为薄适配，`EntryDetailPage` 不改。
  - 类型：信息 / 成功 / 警告 / 错误，任何类型可带一个操作（必须写出提示消失后的常设替代路径，类型约束）；实心圆 + 字形（i / ✓ / ! / ×）+ 读屏前缀，错误另有危险色细描边，不只靠颜色。
  - 时长：信息 / 成功 4–8 秒（按文字长短）、警告 6–10 秒、带操作 10 秒、错误不自动消失（有 ×）、错误回声 8 秒；悬停（能悬停的设备）、焦点在提示里、页面切到后台、弹层或“+”菜单打开时暂停，恢复后至少还剩 2 / 3 / 4 秒。
  - 队列：同时只显示一条；同 key 原位更新（可跨类型：“保存失败”与“已保存”）；错误与带操作的提示抢占，被替换的未关闭错误回到等待位、被替换的带操作提示操作结束；普通提示遇到它们进等待位（最多等 3 秒、警告 6 秒）；连续删除两笔时第二条计时从头开始。
  - 位置（决定第 16、18 条）：手机在底栏、抬高的“+”、账本胶囊、所有底部操作栏与软键盘之上 8px（量出来，不再写死 112px）；只有分析工作台编辑态在编辑条下方；拍照导入完成提示从顶部移到底部按钮栏之上；Pad 宽屏统一在外壳底部居中（原 Pad 外壳提示的位置）；电脑版在底部操作栏之上 16px，没有则离窗口底 24px。
  - 让开（决定第 17 条）：模态弹层打开或“+”记一笔菜单展开时，当前提示退场并暂停，关闭后再出现。
  - 无障碍：两个播报区挂载即存在、之后只改文字（status / alert 分工：alert 只给页面别处看不到的错误，例如分析保存失败、撤销失败）；可见本体在“通知”区域里；出现时不抢焦点；Esc 关闭；操作与 × 都是 44px；提示消失时焦点归还；键盘焦点被提示盖住时滚到提示外面。
- **材质**（决定第 15、21 条，只引用现有令牌）：Original 从墨色反色条改为浅色实心面（`--color-surface` + 1px `--color-line` + `shadow-lg`，深色、Pad、电脑版沿用）；A 用 A3 悬浮档（`--s19-key-bg` + `--s19-a-elev-3`，墨色分层阴影、不带品牌色）；B1 稳定默认的 Satin 瓷底 + `--s19-key-sh`；B2 操作玻璃下限 `--s19-action-bar-bg` + 表面模糊（先写 `-webkit-` 前缀），第二行也用墨色；C 白纸 + 细线轻投影；圆角 `--s19-r-mini`。材质在伪元素上、面板只做位移动画（B2 的模糊才读得到后方）；减少动态效果只淡入淡出。层级 85（高于 A / B1 / C 转场舞台，低于账本海浪）；B2 页面转场期间提示单独成一组，不被页面快照盖住，也不跟着页面滑动（`motion.css` / `hybrid.css` 的 `(*)` 规则对它取消）。

## 1.19.64 · 修复生产构建丢掉无前缀 `backdrop-filter`：Chromium 内核浏览器上 B2 恢复背景模糊（2026-11-14，仅本机）

- 修 [BUG-006](../BUG记录.md#bug-006--生产构建丢掉无前缀的-backdrop-filterchromium-内核浏览器上-b2-没有背景模糊)（所有者 2026-11-14 同意修）。**这个问题早就存在于生产**：触发写法 2026-11-08 随 S19 设计系统进入源码，生产 1.19.49、1.19.53 与现行的 1.19.56 的源码里都有；构建工具一直是 Vite 8 + Lightning CSS，推断这些生产构建同样丢失（没有逐版重新构建验证）。与 1.19.57–1.19.63 的改动无关。
- **现象**：安卓 Chrome、电脑版 Chrome / Edge 等 Chromium 内核浏览器上，B2 弹出面板（明细与分析筛选、选择面板、确认框等所有走弹出面板模板的面板）的玻璃没有背景模糊，后方页面的字直接透过来；B2 点开账目的转场容器、外观设置里的 B2 壁纸样张与 B2 风格图标同样没有模糊。iPhone Safari 不受影响。开发服务器上一切正常。
- **复现**：修复前在 `f52c0607` 真实构建。源码里同一规则同时写 `backdrop-filter` 与 `-webkit-backdrop-filter` 的共 41 条，其中 9 条是先无前缀、后带前缀；进生产构建的 6 条（`s19/overlays.css` 两条、`s19/material-components.css`、`s19/motion/objectExpand.css`、`s19/wallpaper.css`、`pages/theme-appearance.css` 各一条）在产物里全部只剩 `-webkit-backdrop-filter`；另 3 条在只在开发服务器上打开的实验页 `s19/adaptation-lab/lab.css`，不进生产构建。先带前缀的 32 条两种写法都在。本机 Chrome 里 `CSS.supports('-webkit-backdrop-filter', …)` 为 `false`——Chromium 只认无前缀写法。
- **根因**：构建里有两步用 Lightning CSS——Tailwind 4 的优化步骤（`@tailwindcss/vite`，只处理以 `index.css` 为入口 `@import` 进来的样式）与 Vite 8 默认的 CSS 压缩（`build.cssMinify` 默认 `lightningcss`，处理全部 CSS）。Lightning CSS 把两种写法当作同一属性的不同前缀，**后写的是带前缀那条时，只输出带前缀那条**；后写的是无前缀那条时，合并后按目标浏览器补出两种写法。用最小样例对照确认：与浏览器目标无关（Vite 解析后的 `build.cssTarget` 本来就是 `chrome111, edge111, firefox114, safari16.4, ios16.4`，已含 Chromium；不给目标、只给 Safari 18 也一样丢），与是否压缩无关（`minify: false` 也丢），`exclude: VendorPrefixes` 也丢；同样反着写的 `user-select`、`mask-image`、`background-clip` 不受影响，是 `backdrop-filter` 特有的处理。Tailwind 与 Vite 用的 Lightning CSS 1.32 / 1.33 表现一致。
- **修法**：9 条规则一律改成“先 `-webkit-backdrop-filter`、后 `backdrop-filter`”（CSS 的通行顺序，其余 32 条本来如此），取值不变；实验页那 3 条一并改，保持写法一致（开发服务器上本来就正常，改了没有可见变化）。**没有改构建配置**：目标浏览器已经包含 Chromium，Lightning CSS 也没有只关这一项合并的开关；能绕开的只有整体停用 Tailwind 优化与 Vite 的 CSS 压缩（CSS 变大、失去嵌套展开等降级处理）或关掉全部自动前缀（iPhone Safari 18 以前会丢掉其他属性的前缀），代价都远大于问题本身。逐条改顺序容易遗漏、以后新写的规则会再犯的问题由下面的守卫兜住。
- **构建产物的其它差异**：修复前后各构建一次逐条对比，CSS 只有这 6 条规则各多出一条与带前缀取值相同的 `backdrop-filter`，其余规则逐字相同（`product`、`tide` 两个 CSS 文件哈希都没变）；JS 去掉构建时间戳（`__BUILD_STAMP__`）与文件名哈希后逐字相同；`index.html` 只有引用的文件名哈希变了。带前缀写法全部保留，iPhone Safari 的效果不变。浮层根节点那条是“不模糊”的重置，没有别的规则给根节点设模糊，修复前后计算值都是 `none`，看不出差别。
- **守卫**：新增 `tools/check-built-css.mjs`，接入 `pnpm check:build`（`check:delivery` 也会跑到）：构建成功后扫描 `apps/web/dist` 的全部 CSS，同一规则里只有带前缀（Chromium 无效）、只有无前缀（iPhone Safari 18 以前无效）或两种取值不同都算失败，列出文件与规则并提示改成先带前缀的写法。用手写的小分词器（处理注释、字符串、转义、括号与嵌套块），不依赖未声明的解析库；每次运行先用内置样例自检，一条 `backdrop-filter` 都找不到或解析没有回到顶层时直接报错，避免扫描失效后“永远通过”。也可单独检查已有构建目录：`node tools/check-built-css.mjs [目录]`。**已验证**：修复前的产物单独检查失败（列出 6 条），把修复临时撤回后跑 `pnpm check:build` 失败（退出码 1，同样 6 条），修复后通过（4 个 CSS 文件、38 条成对）。[开发与验收规范](../ops/开发与验收规范.md)的开发规则补上“先写带前缀、后写无前缀”与 `check:build` 现在包含的产物检查。
- 验证：web 全量 286 文件 / 2722 项通过（与 1.19.63 相同；本版没有新增 vitest 测试，守卫是构建检查）；shared 89 文件 / 1440 项通过（另 1 文件 3 项跳过，原来就跳过；版本号变更）；交付检查 `pnpm check:delivery` 通过（shared + API 类型检查、web 类型检查与真实构建、新增的产物 CSS 检查 38 条成对、文档链接 / 审计 / 目录 / 章节引用、`check:status`、i18n 扫描 11 文件 107 行持平）；BUG 记录、STATUS 与开发与验收规范的阅读版 PDF 已重新生成并通过 `docs:check-pdf`。API 测试未跑（未改 API 与数据库）。截图对比（不交付）：修复前、后的构建分别由无头 Chrome 的 DevTools 请求拦截直接应答 `localhost:5173`（不启动任何服务进程，沙箱开启，游客模式配置的副本），B2、390×844 打开明细筛选面板：修复前面板后方的“全部 / 支出 / 收入”、“这个月还没有账目”、“记一笔”与底栏文字清楚地透过面板，面板 `::before` 的 `backdrop-filter` 计算值为 `none`；修复后后方页面被模糊，计算值为 `blur(9.1px) saturate(1.5)`。

## 1.19.48 · 账本空间海浪收尾只留 1 号、切换账本等待更短并加提示、修复偶发白屏（2026-11-09，仅本机）

## 1.19.06 · S19 测试风格：明细摘要卡改为随列表上移、在月份下方渐隐（2026-11-07，待所有者真机复测，仅本地）

- 所有者反馈：小卡上滑时出现边缘清楚、遮住下方和左侧的矩形，希望整段动画没有元素碰撞、流畅完成。原因是原版退场里主卡向左滑出并淡出、容器同时从下往上硬裁切，小卡稍后同样左滑并被硬裁切，顶部高度又按另一条直线收起；A / B 的实色卡片放在透明顶区上，半截白色矩形、切边和小卡与分段控件之间忽大忽小的空档都看得见（C 在主题色上同样存在，只是较淡）。
- 改为（四套测试风格，只改样式；Original 未改）：摘要区高度 = 顶部此刻高度 − 其余部分高度，下沿始终紧贴分段控件；主卡与小卡作为一个整体跟着下沿上移，不再横向滑出、不再各自收高；越过摘要区上沿的部分在最多 32px 的渐隐里消失（静止时无渐隐），不会碰到月份、标题和四个按钮。顶部高度曲线、`--p`、测量、吸顶与放开都不变。
- 惯性抖动：这一改动让卡片与列表同向同速移动，主线程事件稀疏时的“台阶感”比横向滑出时轻；Safari 惯性滚动在合成线程上进行，顶部内部的位置只能随主线程更新，无法完全消除（顶部钉住本身仍为 0 偏移）。
- 验证：隔离环境逐帧（收起距离 0–256px 共 12 帧）核对 A / B2 / C：卡片下沿与摘要区下沿始终重合、分段控件间距稳定（A/B 22→9px），月份行与摘要区上沿至少相距 12px，无硬边矩形；行程区滞后 50px 的模拟中 A / B2 / C 顶部偏移仍为 0；Original 逐帧与改动前一致（除定时消失的下载提示）。iPhone Safari 未复测。

## 1.19.05 · S19 测试风格：修正惯性滑动时明细顶部抖动（2026-11-07，待所有者真机复测，仅本地）

- 所有者 iPhone 录屏：A / B 明细页松手惯性滑动时，顶部标题、四个按钮与摘要卡上下抖动，手指按住时正常。原因是 1.19.04 把 A / B 顶部改成普通定位后，它在收起过程中“停在原处”完全依赖主线程及时加高上方的行程区；Safari 惯性滚动在合成线程上进行，慢速时 scroll 事件一两百毫秒才来一次，两次事件之间顶部先随内容上移、再被推回。
