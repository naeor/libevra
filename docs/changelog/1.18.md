## 1.18.1（界面显示 1.18.01）· 分析工作台响应式布局引擎：自动列数、按阅读顺序重排、列数专属布局（2026-10-30，本地）

- **依据**：所有者 2026-10-30 iPad 截图与「分析工作台响应式布局引擎重构」要求；当次确认：列数滑条只放在编辑器里，手动列数主 / 辅工作区各记一份、只在本机，版本 1.18.01。权威规格：[S18 响应式布局引擎](../specs/features/S18-分析工作台响应式布局引擎-20261030.md)。
- **旧引擎的实际缺陷**：
  - 跨列数显示用的是 S17 的 `projectLayout`，它保留行优先**编号**：三列里的第 7 格（第 3 行第 1 列）到五列成了第 2 行第 2 列。卡片因此错位，整片空白，截图里「支出分类」就是这样从第 2 列开始的。
  - 宽工作区的列数只按宽度取上限（最多 6 列）。
  - 编辑器只有 2 / 3 列按钮，而且切换列数会把投影结果直接**改写基础布局**。
  - 行高固定 116px，手动少列时卡片会被拉成很扁的长条。
- **新模型**（不改数据库与配置 schema，沿用 S17 已有的 `profiles` / `mode` 字段）：
  - 基础权威布局 = `main`（`baseCols` + 逻辑格）。
  - 列数专属布局 = `profiles` 里的 `cols-<N>`，同时 `mode = independent`。
  - 显示布局按「该列数的有效专属布局 → 基础列数原样 → 从基础布局响应式排出」解析，永远从基础布局推导，不链式折算。
- **响应式排布**：
  - 按阅读顺序放置，允许补进前一两张卡片旁的空位（名次偏移不超过 2）。
  - 被包围的空洞用卡片自己声明的尺寸横向加宽补上，页尾留白不补。
  - 原尺寸放不下时按尺寸档降级。
  - Spacer 只在它所在的列数里有效。
- **自动列数**：
  - 按网格容器的实际宽度（ResizeObserver，两个工作区各算各的）评分选择，不是能放几列就放几列。
  - 评分考虑格宽与目标 172px 的距离、空洞与整列空白、被迫缩小的卡片；用户亲手排过的列数在格宽舒适时优先，空位视为有意留的。
  - 分数接近时保持上一次的列数，避免抖动。
  - 实测：手机保持 2 列；iPad 竖屏单区 2 列；iPad 横屏 4–6 列；桌面 1440 宽 6 列。系统预设不选会空出整列的奇数列数。
- **行高**：`116 + 0.35 ×（格宽 − 190）`，限制在 116–168px。手机与 iPad 六列不变，浏览与编辑共用同一条轨道。
- **编辑器**：
  - 发布前浮动工具栏精修：默认收起为添加卡片 / 容器 / 预设胶囊；展开按所属工作区宽高限宽 440px、限高 448px（常规约 56%），窄区单列、内容独立滚动、分类固定；支持按钮 / Escape / 同区外部点击 / 标题下拉收起，不退出编辑。保留分类、搜索与列表滚动位置；尺寸换档有迟滞。拖动开始不自动收起、不卸载来源或切换滚动容器；不改网格、保存与拖拽核心。
  - 「调整行列」改为「自动调整列数」开关 + 1…上限的整数滑条 + 当前列数（上限按每格不窄于 104px，最多 8 列），并显示当前排列的来源。
  - 有卡片过扁、每格过宽或大片空白时显示「当前布局较宽松，部分卡片可能显得空旷。」，不阻止保存。
  - 编辑的是**当前看到的那一份**排列，编辑列数在会话中固定。有未保存的修改时滑条禁用并说明原因。
  - 有专属布局时提供「恢复此列数的自动排列」。
- **保存规则**（`commitLayoutEdit`）：
  - 在其它列数只调整位置 → 写入该列数的专属布局。
  - 在基础列数调整 → 更新基础布局，其它专属布局保留。
  - 新增 / 删除卡片（含复制、移入移出容器）→ 编辑结果成为新的基础布局，基础列数改为编辑列数，旧专属布局全部清除。
  - 只改卡片内容 → 布局不动。
  - 结果等于自动排列 → 删除该列数的专属布局。
  - 套用模板 / 恢复默认的起点随撤销历史登记（`EditOrigins`），撤销、重做、超过 50 步都不会认错起点。
  - 已与卡片集合不符的旧专属布局在显示时忽略，下一次保存时清理。
- **旧数据**：
  - 已有布局就是基础布局，专属布局为空；首次升级、首次进入 iPad 都不写任何东西，没有迁移。
  - 生产 1.17.15 客户端读到带专属布局的配置时 schema 允许，只显示基础布局；它在别处增删卡片后，专属布局会被新版本识别为失效。
