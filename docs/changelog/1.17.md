## 1.17.9 · 修复日常启动：start-dev-lan 窗口不再秒关、日常入口固定 HTTP、端口冲突显式失败（2026-10-28，仅本地）

- **改了什么**：`start-dev-lan.cmd` 重写为「启动 + 保持窗口」——固定打开 **`http://localhost:5173`**（不再跳 HTTPS），只有 API 健康检查就绪后才自动开浏览器，启动失败或退出时窗口保留错误与 `EXITCODE`；5173 已被占用时**不启动第二个服务**，改为读取并显示正在运行服务的 `/api/v1/health` 版本，打开该地址后暂停（窗口不再 6 秒自动关闭）。新增独立 `start-dev-lan-https.cmd` 仅供手机同 Wi-Fi 的 HTTPS 安全上下文（录音/离线）使用，缺证书时给出 `pnpm dev:cert` 指引并退出。`start-dev.cmd` 同步重写为本机版。用户可见版本 `1.17.09`（内部 `1.17.9`）。
- **为什么**：所有者日常双击 `start-dev-lan.cmd` 时命令窗口自动消失、Edge 打开 `https://localhost:5173` 报 `ERR_SSL_PROTOCOL_ERROR`。根因有三层：① 旧脚本的「已在运行」分支硬编码了 `https://localhost:5173`，而当时 5173 是遗留的 **HTTP** dev server，浏览器用 HTTPS 打 HTTP 端口必然报错；② 该分支随后执行 `timeout /t 6` 并 `exit`，用户看不到错误；③ Vite 默认端口不 strict，5173 被旧进程占用时会悄悄漂到 5174，造成「页面看到旧版本」的长期混乱。另外 HTTPS 本来只在手机安全上下文需要，日常桌面应保持 HTTP。
- **数据与安全边界**：只改启动脚本、`vite.config.ts` 的 HTTPS 开关与 `strictPort`、开发文档与 AGENTS 规则；不改应用业务逻辑、API、数据库（无迁移，仍 60）、冻结协议 S-01 v2；不删除任何 worktree 或历史分支；旧进程清理仅限本任务确认归属的遗留开发/预览服务，其他 Agent 的 5176 进程保持不动。
- **怎么验证**：`check:docs` / `check:status` / `typecheck` / `check:build` 见 STATUS；真实浏览器（本机 Edge）打开 `http://localhost:5173` 可进入明细、分析页并创建自定义卡片（新指标与图表）；`start-dev-lan.cmd` 第二次运行走「已运行」分支并正确显示运行版本；正在运行的服务重启后 `/api/v1/health` 与页面版本一致。
- **已知限制**：GUI Edge 长期会话此前出现过整页空白，本次已确认由「本地服务未运行」直接造成；若页面空白，先看命令窗口里的启动错误。HTTPS 手机访问仍需自签证书一次性信任；局域网地址随网络变化。

## 1.17.6 · 离线历史读取单月上限改为约 50,000 笔并显式处理「没取完」（2026-10-28，仅本地）

- **改了什么**：离线历史镜像原本每月最多取 40 页 × 100 条（4,000 笔/月），现在最多 500 页（约 50,000 笔/月）。更重要的是「取完」与「被截断」不再混为一谈：达到上限时不再把部分月份写入本地账本，而是记录「未完整」状态、保留已取回条数供断点与重试，并在下载管理、单月下载页与离线提示里显式说明。用户可见版本 `1.17.06`（内部 `1.17.6`）。
- **为什么**：所有者实际账本出现整月超过 4,000 笔的月份，旧实现只把前 4,000 笔当作整月写入本地账本，且界面仍显示「已下载 / 全部月份都已下载」——离线明细与统计会少算且不可发现。只抬高常量不够：截断必须是一等结果，否则新上限只是把静默点移动到 50,000。
- **数据与安全边界**：不改 API（服务端无单月总量上限，单页上限仍 100）；不改逐笔综合折算的 50,000 上限，也不改分析范围的 100,000 条容量守卫；未取完的月份**不写权威本地账本**，因此 S17 分析工作台的来源完整性回执仍为「不完整」，不会把部分数据当整月；无数据库迁移（仍 60）、无冻结协议 S-01 v2 改动。
- **怎么验证**：新增 `fillCoverage` 纯函数边界测试（3,999 / 4,000 / 4,001 / 49,999 / 50,000 / 50,001，其中 50,001 必须 `complete=false` 且只取 50,000）、分页与中断回调测试；下载管理的 `partial` 状态测试；离线 4 个测试文件 53 项通过；全仓 typecheck / test / check:build / check:docs / check:status 见本轮集成验收报告。**未实测真实 50,000 笔端到端**（本机缺 e2e 探针所需状态与库），边界由纯函数与定向测试证明。
- **已知限制**：W5 全部筛选、W6 多设备同步、多指标卡片仍未做；旧 `useStats` 的本机兜底与明细页离线「覆盖到哪个月」提示仍未接线；`sync.ts` 的 `syncMonth` 没有页数上限（与 fill 无关的既有可靠性遗留）。以上均记入[离线历史读取容量上限与长期优化](../specs/features/离线历史读取容量上限与长期优化-20261028.md)的待办与长期方向，不把 50,000 当作永久规格。
