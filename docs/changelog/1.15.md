### 1.15.03 —— **E6 P2 修复：关系并发与导入核对一致性（2026-10-22 发布）**

- **改了什么**：
  1. **“不重复关系”并发确认**：`writeRelations()` 不再用 `findUnique → create`。改为 `createMany({ skipDuplicates: true })`（PostgreSQL `INSERT … ON CONFLICT DO NOTHING`）后重读；同一对并发确认时只有一个请求真正插入，其余按幂等或重激活处理，不再因唯一约束 P2002 返回 HTTP 500。
  2. **账单导入 commit 强制使用最后一次核对结果**：预览新增 `revision`；每次 `recheck` 成功后 +1；`commit` 必须携带同一 `previewRevision`，并逐行比对提交内容与最后一次候选快照（金额/币种/方向/日期/时间/时区/分类/支付方式/备注/标签/勾选）。绕过前端 recheck 修改字段或沿用旧 revision 会返回 409（`preview_stale` / `preview_revision_mismatch`），不会按过期检测结果入账。
  3. **recheck/commit 串行化**：同一 API 进程内用内存队列串行化这两个动作，避免异步窗口里 revision/候选被并发改写；跨进程仍由数据库事务与来源身份/幂等机制兜底。
  4. 版本号 `1.15.02` → **`1.15.03`**。
- **为什么**：S15-E6 专项验收确认了 1 个 P2 并发 500（关系确认）和 1 个 P2 语义缺口（导入可直接绕过前端 recheck 提交过期检测结果）；本轮只修这两个明确问题，不做功能扩张。

### 1.15.00 —— **S15-A/B/C 阶段性发布（2026-10-21）**

**背景**：S15 把"核心记账体验与识别系统优化"拆成 A（语音与字段解析）、B（OCR 多笔交易与概览）、
C（页面结构与日常操作）、E（全账本重复交易检测，仅规划）、D（真机与整体体验验收）。
本轮 A/B/C 首轮开发已由 Lead 逐项复核并在本地合并，基线为 `1aaca0a`；本版是这条基线的第一个生产发布。
**S15-D 没有开始，S15-E 没有批准启动。**

#### 改了什么

**S15-A · 语音识别与字段解析**

1. **默认语音模型改为 multilingual `base`**（`deploy/Dockerfile.api`、`deploy/.env.production.example`），
   `small` 保留为运行时回退（`LIBELLUM_WHISPER_MODEL=small`，无需重建镜像）；
2. 语音识别**并发/排队有界**，忙时快速失败（429），避免拖垮同一容器里的记账 API；子进程恢复、VAD/静音短路、
   错误反馈与分段计时沿用并整理；
3. **解析修复**：日期里的数字不再被当成金额（"10 月 8 日…42 元五角" → 42.5）；补齐角/分与币种解析；
   中文数字省略单位按最后单位补位（`一万二 = 12000`、`三百五 = 350`、`一亿二 = 120000000`、`一万零二 = 10002`）；
4. **分类联想**：餐饮补具体菜名并区分强弱权重；**动作词优先于场所词**（"打车去食堂" → 交通），目的地降权、
   平局取先出现的动作。

**S15-B · OCR 多笔交易与批量整理**

5. **页面/版式分类器 + 可扩展版式注册表**：单笔详情、交易列表、银行流水、转账确认、未知类型；
   已注册 `wechat-bill-list`、`wechat-bill-cards`、`alipay-transaction-list`、`boa-activity-list`、
   `bank-single-detail`、`bank-transfer-confirmation`；
6. **多笔切分与候选模型**：金额/币种/方向/日期/时间/商户/来源/账户/备注/状态/退款/转账/单号/原文/问题，
   区分"缺失"与"待确认"，**不伪造默认值**；单图响应新增 `page_type / requires_user_choice / candidates / warnings`，
   **保留旧 `draft` 字段**（向后兼容）；
7. **跨图/同图重复检测**（60 秒时间窗 + 金额/币种/方向/分类/标签口径）：**只标记，不删除、不合并**；
8. **批量核对 → 统一确认导入**：单笔仍走原核对表单，列表进批量概览，未知页三选（按单笔/按多笔/重新上传）；
   批次只存 `sessionStorage`、**确认前零写入**；确认时逐条复用既有 `createEntry`（离线队列 + 幂等），
   **没有新增批量 API/schema/迁移**；共享账本离线只读、viewer/guest 禁用并说明原因；
9. **概览页优化**：顶部压缩为一行四数（识别/待核对/疑似重复/可导入，全部真实计数）；筛选折叠；
   卡片分层；**分类联想复用语音的 `matchCategory`**，只从批次所属账本已有分类匹配，写入
   `categoryId + categorySource="inferred"` 并标"系统建议"；底部固定确认条展示 blockedReason/逐笔 blocker；
10. **导入完成页**：独立完成态外壳（无左上返回、无右上"重新识别"）、本次会话累计导入 N 笔/共 M 批、
    批次卡片、返回明细/再识别一批、失败最小重试；**Toast** 按成功/部分失败/全失败/pending 区分，
    **pending 不写成服务器已保存**；多批会话只存计数、不存明细/截图。

**S15-C · 页面结构与日常操作**

11. **`/add` 手动记账页四轮重做**：高频字段前置；粘性底部保存条 + 键盘抬高；备注/标签收进"更多选项"；
    修复**时间字段不生效**（改过用所选时间，否则用提交时刻）；快捷金额默认收起；"沿用上一笔"只沿用
    分类/支付方式/币种/标签（金额/备注/时间/方向不变，跳过已归档/删除字段）；币种改为金额卡右侧按钮 +
    底部选择面板；"更多选项"摘要改为实际值混排；统一 `ChevronIcon`；保存栏与中央 `+` 按层叠顺序咬合
    （实测缝隙 0）；

    排版规范 §13.5 记录"金额专用尺寸、不得归并"；时间输入保持 16px（iOS 原生输入控件技术例外）；
13. **明细主页**：修复月份行动画盖住按钮点击区；批量选择/批量编辑/批量删除（逐条复用离线队列，失败有汇总）；
    "更多"重组为导出/筛选与查找/数据维护/重新加载；刷新反馈不再谎称"没有待投递的改动"；
14. **账本设置与返回导航**：设置页去掉重复名称/编号、改名入口收进账本切换；返回新增 `parent` 模式；
    修复"详情⇄设置"与"导入页返回 push + 设置页只 replace"叠加成环（实测 `history.state.idx/len` 不再增长）；

    `mergeLedgerEntries` 按墓碑过滤，已删除条目从列表消失；

    权限/可选范围/`target=source` 禁用/预览校验逻辑全部未动。

**横切 · 视觉与输入修复**

17. **全局表单控件 16px 保底移入 `@layer base`**：此前未分层规则压过所有 `text-*` 工具类（`/add` 金额只有
    16px 的根因）；保留 iOS 16px 保护，新增两条守卫（规则必须在 base 内 + 控件不得出现 <16px 字号类）；
    复制框与留言输入框显式 16px；
18. `APP_VERSION` = **`1.15.00`**；未新增 migration（仍 **51**），未改权限判断、离线队列协议、账本锁/撤销机制。

#### 为什么

- 语音的 `small` 模型在 2 vCPU 上约 25.5 s、`base` 约 6.7 s（S14-V 实测，4.7 s 样本）；本版把 `base` 定为
  代码默认，**生产 `.env` 仍显式 `small` 时不静默改动**，是否切换交所有者决定（见发布验收记录）；
- OCR 之前只能识别单笔，列表截图要用户逐条抄；批量核对把"识别"和"记账"分开：**确认前零写入**，失败可整体重来；
- `/add` 是使用频率最高的页面，时间字段不生效、保存条被 `+` 遮挡、金额字号/焦点态都属于"每天都会碰到"的问题；
- 返回循环与离线删除"卡红"会让用户以为数据丢了或删除失败，属于信任问题，优先修；
- 表单控件 16px 保底未分层是"写了但被静默压回"的典型（`lessons.md` §8.1），移到 base 并加守卫防止复发。
