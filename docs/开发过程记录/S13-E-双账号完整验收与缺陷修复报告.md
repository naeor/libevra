## 四、发现的缺陷、根因与修复

| # | 级别 | 缺陷 | 根因 | 修复文件 |
|---|---|---|---|---|
| D-01 | high | **viewer 无法读账目**：`GET /transactions`、`/transactions/:id`、`/summary` 全部 403 `book_read_only` | `app.ts` 把整个 transaction 模块用写强度 guard 注册；读接口与写接口共用同一守卫 | `apps/api/src/app.ts`、`routes/transactions.ts`（拆 `requireRead`/`requireAuth`） |
| D-02 | medium | 角色变更历史 `from` 写成操作者自己的角色（viewer→editor 却记 from=editor） | `share.ts` 用 `book.role` 当 from | `collab/members.ts` 返回 `previousRole`；`routes/share.ts` 使用它 |
| D-03 | medium | `/books` 的 `memberCount` 含已退出成员（1 人显示 2） | 两处 `_count.members` 未过滤 `leftAt:null` | `routes/books.ts` |
| D-04 | high | 重新邀请忽略本次 role（viewer 重邀后仍是旧 editor） | `respond.ts` 重新加入分支只清 `leftAt`，不写 payload role | `collab/respond.ts` |
| D-05 | medium | 删除对象期间新增引用可能 500（并发竞态） | Prisma `P2003` 落到全局 500 | `lib/errors.ts`：`P2003` → **409 `reference_missing`** |
| D-06 | medium | viewer 在分类/标签/支付方式页面仍看到写入口（只靠服务端 403） | ManagePages 未按 role 隐藏 | `apps/web/src/pages/ManagePages.tsx`（`canWrite` + 只读说明） |
| D-07 | medium | 分享链接加入账本不写 `/ledger/history`（邀请路径会写） | `joinViaShareLink` 只更新成员，未 `recordEvent` | `collab/share.ts`（同一事务写 `member_changed`），`routes/share.ts` 传 actorName |

**回归验证**：D-01～D-04 由 API Agent 修复后回归 79/80（唯一失败即 D-07）；主 Agent 补 D-05/D-06/D-07，并用真实浏览器/API 聚焦验证通过。D-07 的验证：分享链接加入后 `/ledger/history` 出现 `member_changed`（`changes.joined`），加入者角色为链接指定的 viewer。

## 五、未验证 / 受限项（如实标注）

1. **真机 Safari / iPhone / iPad 未验证**：本轮使用桌面 Edge + CDP 模拟手机宽度，**不声称真机 Safari 通过**。
2. **屏幕阅读器 / 辅助技术**未验证；键盘焦点、Esc、弹层焦点已有实现与部分检查，但没有 AT 实测。
3. **管理员访问私人账本**：隔离环境没有管理员，只验证普通账号 `/admin/*` 403；管理员 UI 卡片已用 E2E 测试管理员验证。
4. **XLSX 二进制内容**未逐格检查（只验证 CSV/导出记录）；分享链接过期/满员、邀请过期/撤回、重复邀请刷新因通知配额耗尽未复测。
5. **数据库表级直查**：API 验收以接口为观测面；墓碑/摘要通过 API 行为验证，未额外写 SQL 断言。
6. **冲突链真机**：本轮未改写 sync/conflict；存量标记保护与离线只读已验证，但恢复网络后的 409/ConflictScreen 真机路径仍需所有者验收。
7. 并发删除期间新增引用的 409 分支由手工探针覆盖，未做成稳定自动断言（调度敏感）。
