# S13-F 软件更新页面与版本公告 · 设计决定

> 2026-10-18。**已作为 1.13.09 正式发布（commit `814d797`）。** S14（游客/注册/邀请）不在本轮实施。
> 相关页面：`/update`、`/update/announcements`、`/update/announcements/:version`、`/update/runtime`。

## 1. 目标与信息架构

把原来的 `/update` 从"开发者诊断页"改成三层：

```text
我的 → 软件更新 /update
  ├─ 当前运行版本 + 最近一次正式更新公告
  ├─ 更新公告 /update/announcements
  │    └─ 版本详情 /update/announcements/:version
  └─ 右上角「更多」
       ├─ 复制版本信息（直接复制完整诊断文本）
       └─ 运行信息 /update/runtime
```

`/downloads` 的三个点入口和 Bottom Sheet 语法是视觉参考；下载页的数据下载、缓存、删除逻辑未改。

## 2. 版本事实与本轮版本号

用户的要求里写的是"1.13.08 目前为本地开发版本"。核对真实仓库和生产后发现：

- **1.13.07** 已于 2026-10-18 正式发布；
- **1.13.08** 已于 2026-10-18 作为「当前账本卡片」补丁正式发布（commit `29d0b7d`，
  生产 `/health` 为 1.13.08），**不是未发布版本**；
- 因此 S13-F 使用 **1.13.09** 版本；正式发布后已加入「软件更新与版本公告」公告；
- 公告数据包含三条**实际发布**：1.13.09、1.13.08、1.13.07。没有为了凑数编造更早版本。

### 公告状态规则

```ts
interface UpdateAnnouncement {
  version: string;
  releasedAt: string | null;     // 未发布必须为 null
  status: "released" | "development";
  title: string;
  summary: string;
  sections: { heading: string; items: string[] }[];
  major: boolean;                // 未来重大更新提醒的预留位
}
```

- 正式首页/历史/详情只读取 `status === "released" && releasedAt !== null`；
- 开发版即使以后加入数据，也不能出现在正式发布视图中；
- 历史最多十条**实际发布**，不是连续版本号；
- 没有公告后台、数据库表、自动弹窗、已读状态或跨设备同步。

## 3. `/update` 首页

- `InnerPage` 标题「软件更新」，返回 `/me`，右上角三个点；
- **当前版本卡片**：`APP_VERSION` 来自实际构建；显示 `开发预览` / `正式发布` / `运行版本`
  状态和简短说明；
- 不显示构建时间、缓存、Service Worker 等原始诊断；
- **最近更新公告**：只放一张最近适用公告卡片（版本、日期、标题、摘要、查看入口），
  整卡直接进入**该版本详情**（`/update/announcements/:version`）；「全部公告」才进入历史；
  不展开十条；
- **不伪造更新检查**：没有服务器实时版本查询，因此不显示「已是最新」；页面明确写
  「版本来自当前运行的构建；本页不做服务器实时版本检查」。
- PWA 可能仍在运行缓存旧构建，所以"当前运行版本"只代表本 bundle，不代表服务器最新部署。

## 4. 公告历史与详情

- `/update/announcements`：`InnerPage` 标题「更新公告」，返回 `/update`；只列正式发布；
- 每行：版本、发布日期、标题、摘要、箭头；点击进入详情；
- `/update/announcements/:version`：`InnerPage` 返回 `/update/announcements`；显示完整
  summary + 分组要点；未知/未发布版本显示"没有可查看的正式公告"，不猜测；
- 路由是真实 URL，刷新、直接访问、浏览器返回均正常（已用真实浏览器验证）。

## 5. 右上角「更多」

- 使用与 `BookManageSheet`/`BookSwitcherSheet` 相同的 Bottom Sheet 样式：overlay、
  `rounded-t-sheet`、拖动条、44px+ 行、关闭按钮；
- 两个操作：
  1. **复制版本信息**：异步读取与运行信息同源的诊断快照，调用现有 `copyText`
     直接写剪贴板；成功显示「已复制到剪贴板」并自动收起；失败提示到运行信息页手动复制；
  2. **查看运行信息**：进入 `/update/runtime`；
- Escape、背景点击、关闭按钮都可关闭；打开时锁定页面滚动并聚焦关闭按钮。

## 6. 运行信息页 `/update/runtime`

保留旧 `/update` 的全部诊断能力，并按要求把详情放在最上面、复制区放在下面：

1. **应用与构建**：应用版本、构建时间（本机时间 UTC+8）、构建标记（UTC）、Service Worker、
   网络状态；
2. **本机缓存**：缓存条目、当前版本会读条目、缓存占用、运行记录条数；
3. **当前页面**：页面 URL、记录时间、重新读取；
4. **诊断信息**：原有 `CopyButton`（复制按钮 + 始终可见的只读文本框，剪贴板失败时的兜底）。

更多菜单的复制文本与这里使用同一个 `formatRuntimeReport`，不会出现两套诊断文案。

## 7. PWA / 缓存边界

- 没有修改 Service Worker、IndexedDB、查询缓存、离线同步或下载页；
- 诊断页读取缓存只在用户按"复制/查看运行信息"时发生，不再随更新首页自动读取；
- 不因为公告功能清除/迁移离线数据，不阻塞正常使用；
- 未来重大更新弹窗若实现，必须：同一设备同版本只提示一次、可关闭、不阻止使用、
  不导致离线数据丢失、小更新默认不弹。**本轮不实现弹窗、已读状态、跨设备同步或管理后台。**
