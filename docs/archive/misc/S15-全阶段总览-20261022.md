**目标**：语音记账达到日常可用的速度与可靠性，关键字段（金额/日期/币种/方向）正确，失败/静音/超时有明确反馈。

### 3.1 已交付

| 项 | 内容 |
|---|---|
| 模型策略 | multilingual **`base`** 作为下一版本目标默认；`small` 保留运行时回退（`LIBELLUM_WHISPER_MODEL=small`，无需重建镜像） |
| 并发与稳定 | 语音推理并发/排队有界，忙时 **429** 快速失败，避免拖垮同一容器的记账 API；子进程恢复、VAD/静音短路、错误反馈、分段计时整合 |

## 4. S15-B · OCR 多笔交易与批量整理

**目标**：一张图可以识别多笔、多张图可以合并/分开，跨图重复要提示；最终由用户在概览页统一核对后一次性确认，确认前零写入。

### 4.1 识别层（Python `apps/ocr`）

- **页面/版式分类器 + 可扩展版式注册表**：单笔详情、交易列表、银行流水、转账确认、未知类型；
  已注册 `wechat-bill-list`、`wechat-bill-cards`、`alipay-transaction-list`、`boa-activity-list`、
  `bank-single-detail`、`bank-transfer-confirmation`；
- **多笔切分与候选模型**：金额/币种/方向/日期/时间/商户/来源/账户/备注/状态/退款/转账/单号/原文/问题，
  区分“缺失”与“待确认”，**不伪造默认值**；
- **跨图/同图重复检测**（60 秒时间窗 + 金额/币种/方向/分类/标签口径）：只标记，不删除、不合并；
- **日期归一化**：相对日期、今天/昨天、星期、英文月份；描述中的日期不覆盖交易日期；
- **协议扩展**：单图响应新增 `page_type / requires_user_choice / candidates / warnings`，**保留旧 `draft` 字段**（向后兼容）；
- Python 测试从 125 增至 **182 项**全部通过；真实样本 17 张仅本机自测，不入库。

### 4.2 批量核对 → 统一确认导入

- 上传后按页面类型分流：单笔 → 原核对表单；列表 → 批量核对；未知 → 三选（按单笔/按多笔/重新上传）；
- 批次只存 `sessionStorage`，**确认前零写入**；
- 概览页：真实计数（识别/待核对/疑似重复/可导入）、筛选、卡片分层、逐笔详情、取消、结果汇总；
- 确认导入：一次性固定 UUID v7（`id=idempotencyKey`）→ 逐条复用既有 `createEntry`（离线队列 + 幂等）；
  成功清批次、失败留存重试；**没有新增批量 API/schema/迁移**；
- 导入完成页独立外壳、Toast 按成功/部分失败/全失败/pending 区分，**pending 不写成服务器已保存**；多批会话只存计数；
- 权限：共享账本离线只读、viewer/guest 禁用并说明原因。

### 4.3 已知限制（未做）

1. **真正的 `transfer` kind 未实现**：模型只有 expense/income，转账是分类预设 + `isTransfer` 标记；
2. **“保存为草稿”未做**；
3. **OCR 批次不与账本已有账目查重**（v1 只做同图/跨图；后续 E4 在确认导入时补历史检测）；
4. unknown 与列表混合上传时 unknown 不生成候选，概览只提示数量；
5. 完成页 pending 计数是导入当时的历史值，不追踪后续投递；
6. 未做真实浏览器 E2E/真机截图验收（后续 10-21 做了桌面浏览器冒烟，仍不等于真机）。

## 6. S15-E · 全账本重复交易检测与管理

### 6.1 E1 审查：为什么必须先统一

E1 只读审查（未写业务代码、未建迁移）的结论：

1. 现有重复检测是**三套独立实现 + 一个专用接口，共四种判定口径**，没有共享规则模块：
   Python `apps/ocr/dedupe.py`（图内/跨图/对历史）、前端 `lib/ocr/duplicates.ts`（只有图内/跨图）、
   账本导入 `lib/ledgerImport/duplicates.ts`（跨来源六条规则）、接口 `POST /transactions/duplicates`（精确到分钟全等）；
2. “60 秒”不是唯一口径：三处 60 秒硬编码 + 一处 `HH:mm` 全等 + 一处完全不看时间（游客本地判重）；
   同一笔交易在不同入口可能得到不同结论；
3. “是否查历史”按入口分裂：只有账本导入查目标账本全量历史；OCR 批量完全不查；CSV 只按身份去重；手动/语音完全没有检测；
4. **完全没有**：不重复关系记录、全账本主动审查入口/接口、按金额/来源 ID 的跨历史候选检索、服务端重复候选计算接口；
5. 账本导入的“逐条移除 + 二次确认 + 软删除 + 撤销”语义完整，**不需要重写**；缺口只在候选范围与浏览器内计算；
6. 结论：**未发现阻断 S15 发布的重复检测缺陷**；E2/E3 是规则与数据质量增强，不是修生产事故。

### 6.2 E2 统一规则：一套核心、一套设置

**权威实现**：`packages/shared/src/duplicateDetection.ts`；**唯一设置**：`apps/web/src/lib/duplicateSettings.ts`（localStorage）。

判定顺序（E4/E5 后最终）：

`reminders` → `book` → `kind` → `amount` → `currency` → `time` → `category` → `paymentMethod` → `merchant` → `note` → `tags`

- **同账本、同方向、金额与币种完全相等、真实时间差在用户窗口内**（默认 60 秒）；
- 分类、支付方式默认开启，**只在双方都有值时才要求一致**；商户/备注/标签默认关闭；
- **缺失 ≠ 不同**：一方没有值 → `missing`，不排除；字段不一致 → `mismatch`，排除；
- 时间只比较**带偏移的真实时间戳**；跨分钟/跨午夜/跨时区按绝对时刻；只有日期（`day`）的记录按“同本地日期”弱依据，**不补 12:00**；
- `evidence` 只有 strong/weak/none，**不是概率**；
- 总开关关闭后所有入口不提示，但 `idempotencyKey`、来源单号唯一约束、导入锁**照旧生效**；
- 设置页：**设置 → 记账偏好 → 重复交易检测**；11 个键、严格保存校验、宽松坏数据恢复、恢复默认；**localStorage 按用户隔离、不跨设备**。

### 6.3 E3 不重复关系记忆：用户说“不是同一笔”要记住

**表**：`transaction_not_duplicate_relations`（本地迁移 `20261021031459_s15e3_not_duplicate_relations`，第 **52** 号）。

- 规范化 `a < b`（字符串字典序）后存一行；`UNIQUE (book_id, transaction_a_id, transaction_b_id)`；`CHECK (a < b)`；
- 字段：`book_id`、两交易 ID、`relationship='not_duplicate'`、`decision_source`（manual/review_group/import_review）、
  `decided_by/name/at`、`basis`（判定当时关键字段快照，金额用字符串）、`revoked_at/by/name/reason`；
- 账本级共享、服务器权威；交易侧**不加外键**（软删除不级联，关系保留；永久清理后读取端容忍缺失），账本删除随 `book_id` 级联；
- 接口 `/api/v1/books/:bookId/not-duplicate-relations`：
  - `GET`（viewer 可读，支持 `includeRevoked`、`transactionId`、分页、`stale/effective`）；
  - `POST`（editor+，逐对或一组展开 C(n,2) 个显式对；幂等：新建 201 / 重激活 200 / 原样 200）；
  - `DELETE /:relationId`（editor+，软撤销，行保留，撤销后重新进入候选）；
- **失效规则**：金额、币种、方向、时间任一变化 → 同事务撤销（`key_fields_changed`）；
  读取时用 `basis` 兜底判 `stale`；分类/支付方式/标签/商户/备注变化**不失效**；
- 权限只复用 `access.ts`（viewer 403 `book_read_only`）；导入锁生效时 409 `book_locked`；
- UI：账本设置 → 数据管理 → **“已忽略的重复交易”**，可看生效中/含已撤销、确认人/时间、撤销；
- 离线/游客：关系创建/撤销禁用并解释；个人设置与账本关系分开存储，换设备不会丢关系。

### 6.4 E4/E5 全部入口提醒与全账本检查

**全部入口共用** `duplicateDetection.ts`、同一设置、同一文案 `describeDuplicateMatch`：

| 入口 | 检测时机 | 提醒形式 |
|---|---|---|
| 手动 `/add` | 写入前（先定 id 再检测） | 轻提醒对话框：仍然保存 / 确认不是同一笔 / 取消 |
| 语音 `/voice/review` | 写入前 | 同上（没有“删掉旧的”：草稿不一定对应已有记录） |
| 单图 `/scan` | 写入前 | 四选一：仍然保存 / 确认不是同一笔 / 删掉旧的保存这笔 / 取消 |
| OCR 批量 `/ocr/overview` | 批次内分组；确认导入前对账本历史检测 | 历史命中列出前 3 对依据，可选“仍然全部导入 / 先不导入” |
| OCR 单笔详情 | 沿用批次内分组 | 一句“可能重复：…” |
| CSV `/import` | 导入成功后按 `importRef` 查这一批 | 报告页“检查这批导入”，按组展示依据 |
| 账本导入 `/import-ledger` | 预览阶段（浏览器内） | 分组核对 + 四种快捷决定；预览接入关系抑制 |
| 明细页“更多” | 点“重复账目检测”即时只查当前一笔 | 折叠结果 + “这两笔不是同一笔” |
| 全账本主动检查 | 账本设置 → 数据管理 → 重复账目检测 | 分块扫描、真实进度、按组依据、取消/重试 |
| 游客 | 各页本地数据逐对比较 | 明确写“本次只比对了本机已知数据” |

**新增时两部分检查**：

- 本批之间：`evaluateDuplicateCandidates` 按 `(bookId, kind, amountCents, currency)` 分桶，避免 O(n²)；
- 本批对历史：`POST /transactions/duplicates/candidates`，每候选一次 `findMany` 粗筛（≤501 行），命中后核心复判；
  **不重扫全账本**；单次请求 ≤100 候选、≤500 对、≤500 历史；超出 `truncated` 明说结果不完整。

**全账本检查（E5）**：

- 入口只在账本设置 → 数据管理，不占明细页高频按钮；
- `POST /transactions/duplicates/review` 每次最多 50 个左侧记录、500 个候选配对；`nextCursor` 含左侧/右侧/范围上界，
  密集结果可从同一记录中途续扫；已确认不重复的配对占工作预算但不占可见结果额度；
- 进度只累计完整检查过的左侧记录；可取消、断点重试/重新扫描；新扫描清空旧结果；迟到响应不能恢复旧结果；
- 在线可指定其他账本；离线仅检查本机当前账本；本地用按交易 ID 稳定排序的快照与位置游标，无服务器序号的记录也参与；
- 没有自动删除/合并；跳过只是关提示，要删历史仍走明细页软删除/回收站/权限；
- 规模：≤2000 笔量级可用（E1 实测百条量级）；没有新增索引，大账本会慢，但分块保持可响应。

**旧口径清理**：

- `POST /transactions/duplicates` 内部改用统一核心 + 关系抑制，响应结构 `{duplicates}` 保留；旧客户端只发 `occurredLocalDate + HH:mm` 时，
  按该条自己的 `occurredTz` 还原绝对时刻（不猜服务器时区）；
- 游客本地判重改为 `checkNewCandidates` 的 local 分支；
- Python `apps/ocr/dedupe.py`（含测试）**删除**；`overview.py` 只做字段完整性；
- OCR 前端 0.85 商户相似度前置删除，改为核心的 `matchMerchant` 开关（trim 后严格比较）；
- 各入口手写提示统一由 `describeDuplicateMatch` 生成，缺失字段不再被说成“相同”。

## 7. 账单导入 V2（与 S15-E 并行）

### 7.1 目标与链路

`/import` 从“只接受 Libevra UTF-8 CSV、直接写入”升级为：

**选择文件 → 服务端按内容识别来源并解析 → 统一概览核对（可改字段、可重新判重）→ 一次确认批量入账**。

支持微信 XLSX、支付宝 CSV、BOA PDF、Libevra CSV；旧 `POST /api/v1/import`（Libevra CSV 直写）保留兼容，新前端走 preview/recheck/commit。

### 7.2 架构

| 层 | 位置 |
|---|---|
| 共享契约 | `packages/shared/src/billImport.ts`（preview/candidate/commit schema 与限制常量，前后端共用） |
| 路由 | `apps/api/src/routes/billImport.ts`：`POST /api/v1/import/preview`、`/recheck`、`/commit`；鉴权、账本头 `x-libellum-book` |
| 服务 | `apps/api/src/import/service.ts`：预览缓存、格式识别、适配器、写入事务、`ImportLog` 幂等、提交前复核 |
| 解析器 | `apps/api/src/import/{wechat,alipay,boa,libevra}.ts` |
| 文档抽取 | `apps/api/src/import/extractor.ts` + `extract_document.py`：本机内存解析 XLSX/PDF，只用 Python 标准库，不落盘、不联网 |
| 前端 | `apps/web/src/pages/ImportPage.tsx`、`components/import/BillImportViews.tsx`、`lib/billImportUi.ts` |
| 判重 | 与手动/语音/OCR/账本导入同一核心；文件内 + 历史两层 |

**按内容识别**（不看扩展名）：微信 XLSX 用 ZIP/workbook/表头关键词，支持 Excel serial 日期、共享字符串、28–39 位长单号；
支付宝 CSV 自动 UTF-8/GB18030 解码，识别“不计收支/交易关闭”；BOA PDF 用文本层特征 + 分区/合计对账；Libevra CSV 保留旧表头。
未识别来源明确报错，**不按文件名猜**。

### 7.3 核对与提交语义

- 顶部汇总：读到 / 选中 / 可导入 / 待核对 / 疑似重复 / 已排除；逐笔卡片显示来源、行号/页码、日期精度、警告；
- 字段可改：金额、日期、时间、收支方向、币种、时区、分类、支付方式、备注、标签；改后 `POST /import/recheck` 重新计算警告与重复，不把旧结论写回；
- 2026-10-22 复核修复：币种/时区可修正；服务端校验日期、金额精度、正金额、合法时区与真实时刻，拒绝夏令时缺失/歧义时刻；
  更改记录或勾选范围后确认按钮暂时禁用，重核成功后才允许提交；新的提醒需要重新确认；
- 当前入口与指定账本入口都显式绑定目标账本；V2 三接口鉴权后拒绝缺少明确账本编号的请求；
  Libevra 来源流水编号只用于回查身份，新候选使用独立 UUID，允许同一份导出导入不同账本；
- `identityDuplicate` 是“来源身份已存在”的唯一真相：勾选框禁用且不选中；`duplicateIds` 只是“疑似重复，待判断”；
- 身份去重（`sourceRef` + `ImportLog` 文件指纹）阻止重复写入；内容判重只提示，不自动取消勾选/删除；
- 已确认“不是同一笔”的关系由服务端按对抑制；`reconciliation.ok === null` 不阻断，`false` 要求用户确认后才可提交；
- 提交一次事务批量写入，沿用 `ImportLog`、来源单号、软删除/撤销/权限；失败保留预览可重试；
- 结果页给出来源文件、读到/导入/跳过数量与原因；错误定位到文件行或 PDF 页码。

### 7.5 限制与边界

1. **扫描版 PDF 不支持**：只支持带文本层 PDF；抽不出文本明确报“扫描件不支持”，不做 OCR 猜测。
2. **BOA 只有过账日期**：候选按 `day` 精度、不补 12:00；描述里若出现第二个 `MM/DD`，只加“可能是消费日期、与过账日期不同，请核对”的警告，
   **不编造消费日期，也没有把消费日/入账日作为两个字段落库**；彻底解决需扩交易模型（新迁移，另行批准）。
3. **预览缓存 30 分钟**：服务端内存 Map，重启/过期后失效；前端没有 `GET preview`，刷新核对页回到选文件态。
4. **CSV 内容判重发生在写入后**：旧 CSV 直写链路只能按 `importRef` 写入后检查；新 preview 链路在提交前检查。
5. **大文件边界**：10 MB、20,000 行、PDF 30 页；超出明确拒绝。
6. **设置只在本设备**：沿用 E2 的 localStorage，按用户隔离、版本化，不跨设备同步（本轮明确不做）。
7. **生产未部署**：`apps/ocr/.venv` 与生产 sidecar 的 Python 可用性、真实部署后的性能/内存仍需发布阶段验证。
