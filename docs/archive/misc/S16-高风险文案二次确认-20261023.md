## 4. 已核实正确、应保留的原文

以下内容没有为了“简洁”而删除，继续保留：

- 删除不可逆/不可自助恢复的后果、账本归档 60 天恢复、365 天清理；
- 重复检测“疑似重复只是提示，删不删、留几笔由你决定”；
- 导入提交失败整体回滚、确认后不能撤销、撤销范围与未迁移记录保留；
- 分享链接/恢复码只显示一次、旧链接失效；
- 账号注销后旧设备退出、历史备份不能即时抹除；
- 离线共享账本只读、待同步修改不会被其他设备清掉；
- 账本导入只清理已确认迁入的游客记录，不清空 IndexedDB。

## 6. 历史金额专项判断（未决，非本轮可安全修复）

**事实：**

- `apps/api/src/ledger/history.ts` 的 `renderValue()` 仍把 `amountCents` 原样转字符串；
- 前端 `HistoryList.tsx` 直接显示 `label：from → to`；
- API 测试 `apps/api/test/historyApi.test.ts:198` 仍锁定 `"3500"`/`"3800"`；
- 交易事件记录变更的 from/to，但**不保证保存变更发生时的币种**；当前交易币种可能在之后被修改。

**为什么不能直接改：**

用当前交易币种除以 100 会给历史数据制造新的错误；补历史币种需要新增事件快照或迁移，属于业务契约/数据迁移，超出本轮授权，且所有者已明确“历史金额暂缓”。

**已做的最小安全处理：**

- 成员事件句法、role/kind 英文值、未知字段英文 key 已改为中文展示；
- 未改金额数值和历史契约；
- 在报告与 STATUS 中保留为已知 P0，不得声称已解决。

**建议（需所有者决定）：**

1. 短期：历史金额行只显示“金额已变更”，隐藏具体数值，避免展示错误单位；
2. 中期：事件增加变更时币种快照，再做格式化；
3. 长期：按发生时间/币种回填历史，需迁移与验收。

## 8. 术语与语言复核

- 账本/账目/记录/交易/明细按业务对象区分，不强行统一；
- 删除/移除/清理/永久删除/注销保持后果差异；
- 保存/提交/确认/写入按动作阶段区分；
- 重复交易/疑似重复/重复账目在重复检测路径中保持“疑似、非结论”的含义；
- 支付方式/渠道以 UI 的“支付方式”为主；
- 恢复码与恢复凭证不可合并；
- 内部技术词（回执、幂等、事务、账本锁、墓碑、UTC、A/B）已从高风险用户路径移除或改写。
