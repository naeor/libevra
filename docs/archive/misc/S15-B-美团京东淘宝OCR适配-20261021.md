# S15-B 美团 / 京东 / 淘宝 OCR 适配（2026-10-21）

最后核对: 9064909 / 2026-10-21

## 做了什么

用所有者给的 6 张真实截图（美团 / 京东 / 淘宝 各一张列表 + 一张详情）给 OCR 侧补了
**三平台 × 列表/详情 = 6 个版式**，只动 `apps/ocr`，不改 web/api/shared 协议。

| 版式 id | 页面 | 拆几笔 | 抽取器 |
|---|---|---|---|
| `meituan-order-list` | 美团外卖订单列表 | 4 | `meituan-order-rows` |
| `meituan-order-detail` | 美团外卖订单详情 | 1 | `cn-order-detail` |
| `jd-order-list` | 京东订单列表 | 3 | `jd-order-rows` |
| `jd-order-detail` | 京东订单详情 | 1 | `cn-order-detail` |
| `taobao-order-list` | 淘宝/天猫订单列表 | 2 | `taobao-order-rows` |
| `taobao-order-detail` | 淘宝交易关闭详情 | 1 | `cn-order-detail` |

关键规则：订单卡片以「店铺行（店铺名 + 右侧状态）」定位商户与状态，以**右对齐金额**
（淘宝是 `实付款` 行）定位一笔；金额/日期都不取「共N件 / 使用时长 / 原价 / 共减 / 限时补款 /
预售发货日」；京东卡片不打印日期 → 一律 `missing_date`；淘宝 `09.21` 用截图年份推断并标
`year_inferred`；`交易关闭/超时关闭` → 方向 `unknown` + `order_closed`（不进已支付消费）。

## 验证

- Python 单测 **193 条全过**（原 135 + 新增 58）。
- 6 张真实截图逐张跑 `classify` + `extract_page`：6/6 版式正确、候选数 4/1/3/1/2/1、金额与
  商户全对；汇总行不写进仓库（隐私），只在本轮交接与报告中脱敏呈现。

## 需要所有者决定

1. **`source_platform` 枚举**：Python 已给 `MEITUAN/JD/TAOBAO`，`packages/shared` 只有
   WECHAT/ALIPAY/BANK，API 会过滤成 `null`（不报错，只是 UI 看不到来源）。要不要加枚举？
2. **交易关闭是否生成候选**：现在是"生成 + `order_closed` + 待确认"，不静默删除；若希望
   直接不生成，只改 `_order_direction` 一处。
3. **交易关闭 + 退款成功**：现在按**退款（收入）**生成候选（与微信/支付宝退款行一致）；
   是否改成"完全不生成"，属于产品口径。
4. **`待发货` 映射**：`status="pending"`，即"已付款但未结束"。若账本只关心钱是否已付，
   可把它当 `posted`。
