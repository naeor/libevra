## 0. 一句话结论

二级/三级页面现在共用**同一个顶部导航条**（左上「‹ 返回」吸顶、滚动后标题收进导航条、适配安全区），
内容按**用途**而不是按"一律白卡片"排版：去往别处的是带 `›` 的列表行，只读资料是"标签—值"，
记录（编辑记录、更新公告、导入批次）是连续的细线列表，说明贴着它解释的东西。
业务规则、导入/判重逻辑、数据库、权限判断、文案原文、颜色 token、海浪动画都没有动。

## 3. 导航

- **统一返回**：所有使用 `InnerPage` 的页面左上「‹ 返回」，吸顶，`env(safe-area-inset-top)` 内边距，点按区域 ≥ 44px；返回逻辑仍是原来的 `useGoBack`（有历史就退回，深链/新开标签页回到声明的上级页）。
- **滚动后标题**：页面大标题滚出视野时，导航条中间淡入同名标题并出现细分隔线（`IntersectionObserver`，无滚动监听）。
- **修掉的循环**：
  - 关于 → 隐私政策/使用条款：原来带 `state.from`，`useGoBack` 会**压入**一个新的「关于」，再返回就回到协议页，形成来回。现在不带，普通历史返回即可；深链仍回到设置。
  - 全屏留言板：原来的返回是 `<Link to="/ledger">`（压栈），改为 `useGoBack("/ledger")`，并换成与其它二级页相同的导航条外观。
- **例外（有理由，未套骨架）**：一级页（底部导航）、`/start` 海浪页、导入完成页（会话终点，按设计没有左上返回）、登录/注册。见规范 §16.1。

## 4. 逐页改动

**A 关于**：三张白卡片 → 顶部一行"应用标记 + 一句话 + 版本（点开即软件更新）"，三段说明用小标题分节、不加框，协议两项是列表行。文字未改。

**B 个人资料**：去掉下方「各项的作用」卡片（把昵称/用户名/账号编号又解释一遍）；每项解释直接写在该项下面，账号编号旁加行内复制。**安全提醒保留**，挪到恢复码一组的脚注，并在该组给出「生成新的恢复码」的去处（指向已有的 设置 → 账号安全 → 恢复码 页面）。

**C 账号与数据**：去掉标题下的概述句；内容分成「数据 / 我的账本 / 已归档账本 / 危险操作」几组列表行，危险操作用警示色文字行（确认对话框与流程未改）；错误与成功提示改为 `InlineMessage`（长错误默认两行 + 展开全文 + 可关闭），不再把整页内容推出首屏。

**D 软件更新**：当前版本仍是摘要卡（大号版本号 + 发布日期 + 一行状态）；「近期更新」从孤零零一条变为一小段列表：最新一条展开（含小节标题），其余各占一行；公告多于列出的条数时，末尾给「查看全部 N 条公告 ›」。条数由 `RECENT_UPDATE_COUNT`（当前 5）控制，布局按 5–10 条设计；**公告数据、条数、数据结构都没改**，仍只列不晚于当前运行版本的公告。

**E 全部更新公告**：白卡片堆叠 → 按版本系列（如 1.15）分组的记录列表：版本号 + 日期在上一行小字，标题为主行，摘要预览最多两行；组标题吸顶。按 30–40 条历史设计。公告详情页按文章排：版本/日期在标题上方，摘要作导语，不再单独装框。预览仍用现有 `summary` 字段（独立摘要留待以后）。

**F 我的**：「我的账本」改为打开**当前账本详情** `/books/:当前账本id`（`myBookTarget`）；没有当前账本、或当前账本已不在可访问列表 → 账本空间 `/start`；列表未读到/离线 → 仍打开详情页（详情页自己处理读不到的情况）。不写死任何 id；第二行显示当前账本名。其它入口改为同一套列表行，去向未变。

**G 账本中心**：
- **编辑记录**：从"整块按钮式卡片"改为细线记录列表——操作人（深色）+ 动词（灰）+ 对象，编号是行内可复制的小标签（编号只出现一次）；每条主行单行省略、时间在右；改动最多显示 3 行，其余「另有 N 项改动」；整条可点打开账目详情（与原来一致）。全部历史页按天分组，组标题吸顶，时间只显示时:分。
- **账本信息**：评估后**去掉底部的「账本信息」卡片**——成员数在成员卡上、笔数并入顶部当前账本卡（编号后「· N 笔账目」）、创建日期与估算空间在账本详情页的「这本账的资料」里、「详情」与「查看详情」本就是同一去处。所以没有信息丢失，也没有去掉任何入口。
- **邀请成员**：单人账本里说明移到输入框下方并降为辅助文字（"可以做"而非"必须做"）；多人账本的成员管理页里，邀请是一行带 `›` 的列表项，不再是与成员列表等重的卡片。邀请页的表单直接放在页面上，去掉"卡片里再写一个标题"的重复。

**H 导入流程**：
- 粘贴识别：单笔候选时不再重复显示原文（原文就在上面的输入框里）；多笔时保留，用于核对拆分。
- 拍照识别单笔详情：日期/时间在 360px 以下竖排，修掉 320px 横向溢出；「标记为无效」从红色实底改为 `danger-quiet`（它是次要操作，主操作是「保存并返回概览」）。下载管理的「删除全部已下载数据」与「清除本应用的全部本地数据」同样改为 `danger-quiet`（只换样式，行为与确认流程不变）。
- 导入完成页：每批一张阴影卡 → 一个外框里的批次行；底部两个按钮并排（仍 ≥ 44px，主操作在右）。状态判断、`pending` 的措辞未改。
- 导出 / 导入账本 / 重复检测设置：说明挪到它解释的控件旁（导出编号说明放在导出按钮下；导入规则放在「查看预览」下；七个开关各自重复的同一句说明合并为开关下方的一句，措辞相应合并）。

**其它沿用新骨架的页面**：设置首页（六张等大卡片 → 三组）、账本设置、分类/标签/支付方式管理、成员管理、留言板、下载管理、游客「我的」、账本切换面板、更新菜单面板等，均只换排列，不改去向与条件。

## 6. 未处理问题清单

1. **编辑记录里的金额改动显示的是最小单位**（如「金额：3500 → 3800」）：服务器给的是原始值，格式化需要币种信息，属于数据展示逻辑，本轮未改。
2. **公告预览仍是 `summary`**：独立的列表摘要留待以后（任务说明如此）。
3. **颜色与文案**：按约定后置；本轮只用现有 token。
4. **真机未测**：iOS 安全区、软键盘顶起底部按钮、PWA 独立窗口只在无头 Chrome 与内置浏览器里看过，需要真机过一遍。
5. **账目详情页的「删除」仍是红色实底**：那是主要的不可逆操作，是否改为 `danger-quiet` 留给所有者。
6. **底部「返回更新公告」「‹ 返回账本」这类文字链接是压栈导航**：不会循环，但会多一条历史；是否统一成 `useGoBack` 待定。
7. **320px 下首页嵌入的编辑记录**，对象较长时会被省略得比较早（完整内容点开即见）。
8. **未逐页目检**：管理员页面、账单导入 V2 的深层状态、语音录音中的状态、导入完成页（由单元测试覆盖，未截图）。
9. 个别整页截图里，"滚动后标题"的淡入过渡被截在中间状态，属于截图时机，不影响实际使用。
10. `LedgerInfoPage` 在本轮之前就已没有路由（`/ledger/info` 是重定向），是遗留的无用代码，未删。
