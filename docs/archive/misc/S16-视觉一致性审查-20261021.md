## 0. 一句话结论

**绝大多数页面已经属于同一款软件**：横向基准（24px）、卡片/控件圆角（20/14px）、
字号等级、绿色语义、空状态与错误状态都由共享组件与 token 保证，实测 0 处横向溢出、0 处文本裁切。

漂移集中在两处结构性地方，都不是"某页难看"，而是**同一个模式在不同页面各写了一半**：

1. **同一种控件在不同页面有 2–4 种写法**（横向筛选条、下拉框、分组小标题、次级链接）；
2. **`index.css` 的既有不变量被局部类覆盖**（表单控件 16px）。

本轮修好 2 组（7 个文件，全部为局部、零 token 改动），其余列清单等所有者裁定。

## 2. 已修复（P0/P1）

### 2.1 P1 · 分析页两条横向筛选条画出原生滚动条

| 项 | 内容 |
|---|---|
| 位置 | `apps/web/src/pages/StatsPage.tsx:135`、`:152` |
| 现象 | 桌面 Chrome（Windows 经典滚动条）下，时间段与币种两排筛选片下方各出现**一条带左右箭头的灰色滚动条**；把"一排标签"读成"一个滚动区"。390 宽时两条都出现。 |
| 违反 | 《布局间距与圆角规范》§15.6「同一个模式只有一个来源」的同一原则；且**明细页同款横条已经隐掉**（`DetailPage.tsx:928` 的 `[scrollbar-width:none] [&::-webkit-scrollbar]:hidden`）——**同一个模式，只有一处知道**。 |
| 修法 | 把明细页那**一个既有写法**补到这两处；不动 `index.css`、不加 token、不改滚动能力（触摸/键盘/拖拽照旧）。 |
| 影响面 | 仅分析页两条横条；高度少 1 行滚动条（约 15px），其余布局不变。 |
| 证据 | 前 `shots/desktop-stats-0.png`（币种条下方灰条+箭头）→ 后 `shots-after/desktop-stats-0.png`（干净，`英镑` 靠裁切表示可滚动） |

### 2.2 P1 · 表单控件字号被局部类压回 14px（iOS 聚焦放大整页）

| 项 | 内容 |
|---|---|
| 位置 | `pages/AccountDataPage.tsx:554`（下拉）、`pages/ManagePages.tsx:246`（筛选下拉）、`components/ledger/BatchEditSheet.tsx:129`、`:234`（下拉）、`pages/LedgerPage.tsx:358`（邀请输入框）、`components/MessageBoard.tsx:400`（留言框） |
| 现象 | `index.css` 有一条明确不变量：`input, select, textarea { font-size: 16px }`——**低于 16px 时 iOS Safari 会放大整页且不缩回**。但 `text-body`(14px)/`text-sm`(14px) 这类**类选择器压过元素选择器**，于是这 6 个控件是 14px，而 `TextField`/`PasswordField`/`EntryForm`/OCR 表单是 16px——**同一批输入控件两种字号**。 |
| 违反 | `index.css` §「Never let a form control's text fall below 16px」；《文字语义与排版规范》§13.1（控件字号不属于任何语义等级，应由控件规格统一） |
| 修法 | 6 处改 `text-base`（=16px，与同页文本框一致）。**未引入新 token、未新建组件**。 |
| 影响面 | 控件高 +1~2px；6 个文件各 1–2 行；列表/卡片结构不变。 |
| 证据 | 修后 `shots-after/mobile-books_…-settings_payment-methods-0.png`、`shots-after/mobile-me-1.png`（0 溢出、0 裁切） |

**⚠️ 未在真机 iOS 验证**（无设备）：判定依据是代码里已经写明的不变量，不是猜测。
