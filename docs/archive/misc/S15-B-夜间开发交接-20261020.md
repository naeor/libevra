## 3. 多笔提取 / 标准化 / 重复检测（接口签名）

均为纯函数，无 I/O、无数据库、无网络。完整签名见各文件。

### 3.1 分类与切分

```python
layouts.classify(lines) -> Classification
layouts.registered_layouts() -> tuple[LayoutDescriptor, ...]
layouts.register_layout(descriptor) -> LayoutDescriptor        # 扩展版式
multi_extract.extract_page(lines, classification, *, image_index=0, reference_year=None) -> PageExtraction
multi_extract.extract_pages(pages, *, reference_year=None) -> list[PageExtraction]
multi_extract.register_custom_extractor(name, extractor)       # 扩展行式样
```

- 单笔详情复用既有 `extract.py` 规则（真实截图验证过的部分），不另写一套；
- 交易列表用通用几何规则：金额行 + 紧随的元数据行，不假设行高/列偏移/商户在金额上下方；
- 一行出现**多个数字列**（例如银行列表 Amount+Balance）→ 金额返回 `None` + `amount_uncertain`，
  **不取最右/最左数字**（宁可空着让用户填，也不记一个错金额）；
- 未知页面 → 零候选 + `requires_user_choice=True`。

### 3.2 字段标准化

```python
normalize.read_amount(text, *, currency_hint=None) -> AmountRead
normalize.read_date_time(text, *, reference_year=None) -> DateTimeRead
normalize.normalize_status(text) -> "pending" | "posted" | None
normalize.direction_from_text(text) -> "expense" | "income" | "transfer" | None
```

覆盖：正负号/括号负数/千分位、币种符号与代码（`$` 有歧义时不猜）、
缺失年份（**不补**；显式传 `reference_year` 时补但标 `year_inferred`）、
Pending/Posted、退款优先于支付措辞、收款方不是收支方向（沿用 extract.py 记录的真实事故）。
缺失字段一律 `None` + 类型化 issue（`missing_amount` / `missing_date` / `missing_year` /
`direction_unclear` / `amount_uncertain` / `layout_unverified` / `currency_assumed` 等）。

### 3.3 疑似重复（不接数据库，不删除、不合并）

```python
dedupe.find_within_image(candidates, options=None) -> tuple[DuplicateGroup, ...]
dedupe.find_cross_image(candidates, options=None) -> tuple[DuplicateGroup, ...]
dedupe.find_against_existing(candidates, existing_entries, options=None) -> tuple[DuplicateGroup, ...]
dedupe.find_duplicates(candidates, existing_entries=None, options=None) -> DuplicateReport
dedupe.mark_duplicates(candidates, report) -> None   # 只加 id + 可见 issue
```

- 三个作用域都覆盖：同图内、跨图、与已有账目；
- 交易单号相同 = 强证据；双方单号不同 = 强否定；同单号不同金额 = 标"疑似同一笔但金额冲突"；
- 无单号时：金额+币种+方向+日期相同，且时间在 60 秒内（时间缺失时降级并在 reason 写明）；
- 商户明显不同、方向未知、缺日期 → **不做数值匹配**（避免把两笔真实消费误标）；
- 输出连通分量分组，`duplicate_candidate_ids` 供概览页算"可能重复"数量；
  任何地方都不会删除/合并候选，只让用户核对。

### 3.4 概览批汇总

```python
overview.build_overview(pages, *, existing_entries=(…), options=None, reference_year=None) -> Overview
overview.describe_overview(overview) -> str        # 终端可读
Overview.to_dict()                                 # JSON 可序列化（已测试）
```

汇总：总数 / 可直接确认 / 有疑问 / 可能重复 / 未知页数 / 默认预选 id。
**本层没有保存函数**（刻意不给：保存边界属于所有者决定，设计方向 §3.4/§10.5）。
