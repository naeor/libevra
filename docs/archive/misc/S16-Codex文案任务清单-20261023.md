> **本清单是后续修改任务，不是本轮修改记录。** 本轮只审查，未改产品文案、UI、API、数据库或历史公告。Codex 执行时应按真实当前代码重新定位；行号会随 S16-A 合并变化。

## 0. 执行顺序与边界

1. **P0 先解决事实错误**：历史金额显示、法律页状态。P0 不能只改措辞。
2. **P1 再解决安全/能力/术语**：删除恢复矛盾、导入错误、历史动态句、重复检测术语。P1 里多项需要产品所有者先裁决。
3. **P2 做长度与结构**：解释过多、技术暴露、位置不当；可删可移，但不能删掉安全/财务后果。
4. **P3 最后统一细节**：字词、低频页提示、品牌混排。

**任何任务都不得**：修改用户数据/交易备注/自定义分类/历史正文；改写已发布公告；修改法律条款实质；为了“简洁”删掉删除、恢复、同步、隐私、权限说明；把不同业务含义的术语强行合并；为单句做破坏通用规则的硬编码。

> 任务与 CSV 行**不是一对一**：代码位置相近、同一根因的条目已合并为一个任务。例如 P1-01 同时覆盖批量删除与详情删除两处记录；P2-11 对应账号与数据页的多段长说明。CSV 保留逐位置记录，本清单负责可执行的分组。

## 1. P0 · 事实错误与财务误导

### COPY-P0-01 历史记录金额按原始最小单位显示

| 项 | 内容 |
|---|---|
| 位置 | `apps/api/src/ledger/history.ts:145-149`；`apps/web/src/components/HistoryList.tsx:129-133`；测试 `apps/api/test/historyApi.test.ts:198` |
| 现状 | 金额修改 35.00 → 38.00，历史页显示 `3500 → 3800` |
| 为什么不合适 | 财务结果误导，用户会误读为 3,500/3,800 元 |
| 目标 | 历史中的金额与当前币种按全站共享金额规则显示（符号/小数/币种一致）；原始最小单位继续留在 API，不在客户端另建格式化规则 |
| 删除/移动 | 不允许删掉变更行；允许调整 API 返回契约或客户端格式化实现。优先客户端复用 `formatMoney`，避免改所有金额契约 |
| 业务/安全边界 | 财务；必须补人民币、美元、0/3 位小数币种的展示测试 |
| 验收 | 历史 API 测试 + 前端历史列表测试；真实页面截图确认 `35.00 → 38.00` 而不是 `3500 → 3800` |

## 2. P1 · 安全、能力与关键术语

### COPY-P1-01 删除确认与已删除详情的恢复能力矛盾

| 项 | 内容 |
|---|---|
| 位置 | `apps/web/src/pages/EntryDetailPage.tsx:761`（`S16-COPY-1791`）；同文件 `:196`（`S16-COPY-1741`）；`apps/web/src/components/ledger/batch.ts:402`（`S16-COPY-0385`） |
| 现状 | 删除确认说“无法在应用里自行恢复”，已删除详情却有“恢复这笔记账”；批量删除也有同类不可恢复提示 |
| 为什么不合适 | 用户无法判断删除是否可逆，可能做出错误数据决策 |
| 目标 | 先确认真实能力：单笔/批量/导入删除是否都可恢复、恢复窗口多久；文案与按钮一致，明确“什么情况下可恢复/不可恢复” |
| 删除/移动 | 可移动恢复入口或改写确认；不能只删其中一句制造新的不一致 |
| 业务/安全边界 | 数据安全/不可逆操作；**需产品所有者定夺**，可能涉及后端能力而非文案 |
| 验收 | 删除前、删除后、批量删除三处说法一致；若保留恢复，确认删除文案不再说“无法恢复” |

## 5. Codex 修改前必须向所有者确认的事项

1. 删除/恢复真实能力：单笔、批量、导入删除分别是否可恢复，恢复窗口多久。
2. 法律条款上线状态与可公开措辞。
3. 重复检测的功能名/候选状态名/结果动作名。
4. 账号注销/归档/备份期限是否已有公开承诺，文案是否必须逐字保留。
5. “the free, open ledger”是否品牌标语。
6. 是否允许把技术说明移入折叠/帮助页（涉及 S16-A UI 布局）。
