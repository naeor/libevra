## 0. 一句话

上传截图后按页面类型分流：单笔详情仍走原有核对表单；交易列表（以及与其同批的截图）进入一个
**浏览器临时批次**，在「批量识别结果」概览里逐笔查看、只进详情改有问题的项，最后统一确认，
**逐条复用既有 `createEntry` 本地写入/离线队列/幂等**落账。确认前没有任何账本写入；没有数据库
schema、迁移或新的批量写入 API。

## 1. 实际数据流

```
上传（1–5 张）
  └─ POST /recognize（既有接口，未新增批量 API）
       └─ Python service.py：每张图返回
            page_type / requires_user_choice / candidates / warnings
            + 旧 draft 字段（S5 单笔兼容）
       └─ apps/api/src/ocr/client.ts：snake_case → 共享 OcrCandidate
       └─ routes/recognize.ts：原样返回（响应 schema 只加可选字段）
  └─ ScanPage 分流（lib/ocr/routeDecision.ts）
       ├─ single-detail 且无列表 → 原有 ReviewStep（fold/逐张行为不变）
       ├─ transaction-list（哪怕与单笔图混合）→ 整次上传进批次
       └─ unknown（或声称列表但 0 笔）→ 三选：
            按单笔 → 原有 ReviewStep
            按多笔 → 建批次（单笔结果/空候选也可，标待核对）
            重新上传 → 留在 ScanPage，不自动打开文件选择器
  └─ 批次（lib/ocr/batch.ts + batchStore.ts）
       sessionStorage 键 `libellum:ocr-review-batch`，带 batchId/bookId/items/importIds
       画像：候选字段 + 用户决定（invalid/reviewed/分类/支付方式/标签）
       重复检测（lib/ocr/duplicates.ts）按 60 秒规则在每次编辑后重算
  └─ /ocr/overview（OcrOverviewPage）
       汇总：本次识别 / 待核对 / 可直接导入 / 可能重复 / 已标记无效 / 可导入
       筛选：全部·待核对·已确认·疑似重复；来源；收支
       卡片只读；点「查看详情」→ /ocr/overview/:candidateId
  └─ 详情（OcrReviewDetailPage）
       改金额/收支/币种/日期时间/对象/分类/标签/渠道/账户/备注；
       转账只读标记；可标记无效/恢复；保存只写回批次，不写账
  └─ 统一确认（OcrOverviewPage → lib/ocr/import.ts / importExecution.ts）
       1) 确认弹窗（N 笔、疑似重复提示、无效不计、离线说明）
       2) assignImportIds：**此刻**为每条有效候选生成 uuid v7，id === idempotencyKey，
          先写回 sessionStorage；重试复用同一批 id
       3) buildImportPlan：字段/币种/金额/方向/日期/时间/备注长度校验；
          有 blocker 时一条都不写（按钮平时已禁用并说明原因）
       4) executeImport：逐条 await createEntry(entry.input, localEntry(input, ledger.data))
          - 成功：本机已写；pending=true 表示在离线队列（不冒充云端成功）
          - 失败：继续后面的条目，逐条记录原因
       5) 全部成功 → 清批次；部分失败 → 已成功项移出批次、失败项保留可重试
       6) 结果汇总：成功 N / 失败 M（原因）/ 离线排队数；「查看明细」跳转明细
```

失败/离线路径：

- 识别失败：沿用原有“没读出内容”三选（重试/手动/返回），不产生批次。
- sessionStorage 不可用（隐私模式/配额）：ScanPage 明确报错并留在拍照页，不跳到一个空概览。
- 离线：个人账本仍走 `createEntry` 本地写 + 队列，汇总显示“已在本机排队，联网后自动投递”。
- 共享账本离线 / viewer：概览页确认按钮禁用并写明原因；服务端仍是最终权威。
- 部分写入失败：不静默、不丢弃用户选择；失败项留在批次，重试 id 不变。

## 3. 安全边界（已遵守并验证）

- **未改 Prisma schema、未新增迁移、未新增后端批量写入 API**；`git diff` 不涉及
  `prisma/`、`apps/api/src/routes/transactions.ts`、S14-D 导入锁/撤销机制。
- **确认前零账本写入**：识别只调用读接口；批次只在 `sessionStorage`；详情保存只写批次；
  唯一调用 `createEntry` 的位置在概览页确认之后（`confirmImport`）。
- **幂等**：确认时一次性生成 `id`/`idempotencyKey` 并先落盘；重试复用；`assignImportIds`
  只补缺失项，已存在值不覆盖（单测覆盖）。
- **无权限禁用**：共享账本离线只读（`useSharedLedgerOfflineReadOnly`）、viewer（`useBooks`
  的 role）、批次属于另一账本、无有效笔数、存在 blocker 时按钮禁用并显示原因（纯函数
  `importDisabledReason` 有 7 条单测）。服务端仍会再次拒绝越权写入。
- **失败不静默**：执行器逐条记录成功/失败；有 blocker 时一条都不写；离线 pending 单独
  显示；不伪造云端成功。
- **疑似重复不自动合并/删除**，只提示；用户可全部导入。
- **真实截图/日志未进仓库**：自测输出写在系统临时目录，验证后已删除；`git status` 无
  `real-samples`、无 `.env`、无临时 JSON。
