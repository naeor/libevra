## 1. 改前现状（事实）

- `/add` 结构：`TabPage` + `<form>`；第一轮的粘性行动条 `EntrySaveBar` 是表单最后一个孩子。
- 金额框（白底绿框、`aria-label="金额"`）下方常驻五个快捷金额按钮，占一整行。
- 支付方式（已过滤 `isArchived`）是分类之后、币种之前的**独立一段**横向胶囊。
- 「更多选项」= 备注 + 标签，默认收起，收起行右侧显示「备注、标签」或「已填写」。
- 「复制这一笔」：路由 state 的 `copyFrom`（从明细/详情进入），连金额/备注/标签一起带；**本轮一字未改**。
- 数据来源：`useTransactions({})`（`recent`，当前账本最近交易，用于自动默认值）、
  `useQuickAmounts()`（五个快捷金额）、`useLedger()`（分类/支付方式/标签）。

## 2. 四块改动

### 2.1 快捷金额折叠

- 金额框保留原样；金额框下方新增一行：左「沿用上一笔」，右「快捷金额 ⌄」。
- 点「快捷金额」展开原来的五个金额按钮（`useQuickAmounts()` 的返回值、`minorToInput` 文本、
  写回金额框的逻辑完全复用），再点收起；只有 `open` 一个布尔，无动画、无内部状态。
- 收起、展开两种状态由 `EntryQuickActions` 受控渲染；「再记一笔」把 `quickOpen` 复位为收起。
- 一行两个按钮的宽度按 360px 留好余量（两个胶囊各自 `shrink-0`，标签都不长）。

### 2.2 沿用上一笔

- 入口：金额下方的「沿用上一笔」按钮（与「复制这一笔」是两个独立入口，互不调用）。
- 数据源：**`useTransactions({ kind })`**（当前账本、按当前收支方向过滤）。
  理由（二选一中的后者）：
  - `recent`（`useTransactions({})`）是**全方向**的最新一页；若最近几十条恰好都是收入，
    支出方向会「找不到上一笔」，而更早的支出其实存在。
  - 按 `kind` 过滤后，「跳过不兼容、继续找更早的」由同一套查询层完成（服务器与本地回退
    共用 `filterLocally`），页面不翻页、也不需要新接口。
  - 两者都属于 `useTransactions`，**账本作用域相同**（请求走当前账本，离线回退只读当前账本存储），
    没有跨账本读取路径。
  - 代价：多一个 list 查询（按方向缓存，最多两份）。
- 应用字段（`inheritFromLastEntry`，纯函数）：
  | 字段 | 行为 |
  |---|---|
  | 分类 `categoryId` | 沿用它，前提是该分类存在、`kind` 与当前方向一致、未归档、非系统分类 |
  | 支付方式 `paymentMethodId` | 沿用它，前提是历史有值且未归档 |
  | 币种 `currency` | 无条件沿用（受支持币种的封闭集合） |
  | 标签 `tagIds` | 只保留账本里仍存在的标签，压到 `MAX_TAGS_PER_TRANSACTION` 以内 |
  | 金额 / 备注 / 时间 / 收支方向 | **绝不修改**（返回结构里没有这些字段） |
  | 历史 id / seq / version / 创建与同步状态 | **不复制**（返回结构只有四个字段） |
- 越界与失败：
  - 分类已归档/已删除/系统分类（「暂无分类」）、支付方式已归档、标签已不存在 → 该字段跳过，
    保持当前草稿的值，不退回「其他」「暂无分类」之类的替代值。
  - 空账本 → 提示「这个账本还没有可沿用的记录。」，表单不动。
  - 记录全为另一方向 → 提示「还没有同方向的上一笔记录。」，表单不动。
  - 账本元数据未加载 → 提示「分类与支付方式还没加载完，稍后再试。」，表单不动。
  - 成功 → 提示「已沿用上一笔的分类、支付方式、币种与标签。」，仍由读者手动保存。
- 幂等：同一份输入连续调用两次，第二次结果与第一次同值；不建账、不写库、不碰离线队列。

### 2.3 支付方式移入「更多选项」

- 独立一段删除，控件移入 `EntryMoreOptions` 展开区，顺序：支付方式 → 备注 → 标签。
- 保留原行为：微信/支付宝/银行卡/现金/其他与用户自定义项都来自 `useLedger()`；归档过滤
  （`!isArchived`）仍在页面做；再点已选中项就取消；默认值逻辑（上一笔或「其他」）未改；
  保存读取的仍是同一个 `paymentMethodId`。
- 收起行右侧摘要：`支付方式名 · 备注 · 标签`，有哪项显示哪项；都没有显示「可选」。
  摘要行 `min-w-0 truncate`，「更多选项」与箭头 `shrink-0`，360px 下长名称被截断而不撑破。
- `EntryMoreOptions` 仍是受控组件：`open`、`onToggle`、`paymentMethods`、`paymentMethodId`、
  `onPaymentMethodChange`、`note`、`onNoteChange`、`tags`、`selectedTagIds`、`onToggleTag`
  全部由页面持有，组件无内部状态。
- 数据含义：**支付方式 ≠ 账户**，两者没有合并，也没有互相顶替。

### 2.4 页面顺序

支出/收入切换 → 金额输入 → 一行快捷操作（沿用上一笔｜快捷金额）→ 分类 → 币种与时间（第一轮的
两行紧凑卡片，未改）→ 更多选项（支付方式、备注、标签）→ 粘性保存条（`EntrySaveBar` 未改）。

## 5. 未验证 / 需复核

- **真机与 360px 视觉**：没有起 dev server、没有截图。快捷操作行与「更多选项」摘要的截断/换行
  是按宽度约定的（`min-w-0 truncate` + 两个胶囊），需要所有者在 360px 与真机上目视确认。
- **「沿用上一笔」的实际点击链路**：本仓库测试环境没有 DOM，点击行为只由组件受控渲染 +
  纯函数 + 源码断言覆盖；浏览器里的真实点击未验证。
- **币种沿用的连带效果**：若读者已输入金额再点「沿用上一笔」，币种会按上一笔改变，金额文本保留
  （数字被按新币种重新解释）。这是「沿用币种、不沿用金额」的直接结果，未额外处理。
- **需求选择项（已按其一实现）**：数据源选了 `useTransactions({ kind })`，代价是多一个按方向的
  list 查询；若所有者更在意请求数，可改回复用 `recent` 并接受「最新一页里没有同方向记录」的边界。
