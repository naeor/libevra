## 1. 结论摘要

本次改动完成的是**一个共享的“交易文字 → 记账字段”语义核心**，并把它接到两个入口：

- **语音入口**：录音 → Whisper 转写 → 共享语义核心 → 核对 → 保存。
- **粘贴入口**：粘贴文字 → 预处理/拆分 → **同一个**共享语义核心 → 核对 → 保存。

关键结果：

1. 语音和粘贴不再各自维护金额、日期、分类匹配规则；`packages/shared/src/transactionText.ts` 是两者唯一的业务语义实现。
2. 语音转写文本可编辑，编辑后由浏览器用同一核心重新解析，不需要重新上传音频或重跑 Whisper。
3. 粘贴页提供独立的“粘贴识别”页面、五项底部菜单（手动记账居中）、用户主动触发的剪贴板读取，以及逐笔候选核对。
4. 固定语义测试集上，语音与粘贴对同一句话产生完全相同的字段；金额、日期、时间、币种、支付方式、分类、歧义提示均有自动测试。
5. 本机确实存在可用的 Whisper 模型（先前报告“本机没有模型”的判断有误，已在 §6.5 更正）：`ggml-base.bin` 与 `ggml-small.bin` 由 `pywhispercpp` 的模型目录直接加载；以 21 条合成/授权音频做了真实推理，base 与 small 分别记录转写、字段和端到端结果。真实推理实际使用 **CPU**（日志明确 `no GPU found`），虽然本机装有 RTX 5050。
6. 本轮没有新增数据库表、没有改生产环境变量、没有引入外部 LLM、没有上传任何用户文字或音频。

**不能从本报告得出的结论：**

- 不能把 21 条合成语音的字段准确率直接外推为真实用户、真实麦克风的准确率；样本量小，且全部是 Windows TTS 合成语音，不是自然录音。
- 英语完整句子的日期/英文数词解析仍是明确限制（`$23.62` 这类符号金额可识别）；不能宣称支持英文记账。
- 不能得出“建议把生产默认模型从 base 换成 small”的结论。small 在这批样本上明显更准，但耗时约为 base 的 3.5–4 倍、常驻内存约为 2.5 倍，需要所有者按资源预算决定。
- 不能得出“可以直接发布生产”的结论。本报告只完成本地专项验收，仍需所有者批准与真机验收。

## 3. 共享解析架构

### 3.1 数据流

```text
语音：录音 → POST /api/v1/voice/transcribe → sidecar Whisper 转写文本
      → parseTransactionText(text, { categories, now })
      → transcribeResponseSchema { text, amount, kind, ..., parsed }
      → RecordPage 可编辑转写；编辑后用同一 parseTransactionText 重算
      → handOverSpoken({ text, parsed, source: "voice" })
      → VoiceReviewPage → 核对 → 现有保存/重复检测/幂等链路

粘贴：粘贴文字 → splitTransactionTexts / parseTransactionText(每笔片段)
      → 同一 TransactionTextResult → 候选项核对
      → handOverSpoken({ text: sourceText, parsed, source: "paste" })
      → 同一个 VoiceReviewPage → 核对 → 同一个保存链路
```

### 3.2 关键文件

- `packages/shared/src/transactionText.ts`
  - `parseTransactionText(text, { categories, now })`
  - `parseTransactionTexts(text, options)`
  - `splitTransactionTexts(text)`
  - 导出 `TransactionTextResult`、字段状态、问题类型与 Zod schema。
- `packages/shared/src/speech.ts`
  - 保留旧 `parseSpokenEntry` / `parseSpokenEntryWithCategory` 兼容入口。
  - 导出 `findAmountCandidates` / `AmountCandidate`，供共享核心复用金额候选集，避免两套金额规则漂移。
- `packages/shared/src/voiceParsing.ts`
  - `transcribeResponseSchema` 新增 `parsed: transactionTextResultSchema`；旧扁平字段保留兼容。
- `apps/api/src/routes/voice.ts`
  - 语音接口使用 `parseTransactionText`，返回完整 `parsed`；空转写返回空结果。
- `apps/web/src/lib/scanHandoff.ts`
  - `SpokenDraftHandover` 改为携带 `parsed` 与来源；一次交接、可恢复空态。
- `apps/web/src/pages/RecordPage.tsx`
  - 转写文本可编辑；编辑后用共享核心重解析并展示关键字段。
- `apps/web/src/pages/VoiceReviewPage.tsx`
  - `draftOf(...)` 把候选映射为 `ReviewDraft`：金额、方向、币种、日期、时间、分类、支付方式、备注。
  - 支付方式名称做双向包含匹配（例如账本里的“微信”匹配解析出的“微信零钱”）。
- `apps/web/src/pages/PastePage.tsx`
  - `recognisePastedText(text, categories, now)` 纯函数；页面、剪贴板、候选卡片、隐私说明。
- `apps/web/src/components/BottomNav.tsx`
  - 五入口卡片与居中布局。

### 3.3 共享字段模型

`TransactionTextResult` 包含：

- `amount`：金额字符串，无法确定时为 `null`。
- `currency`：识别到的币种；未写明时默认 `CNY` 并标记为推断。
- `kind`：`expense` / `income`。
- `occurredLocalDate` / `occurredTime`：本地日期/时间，可为空。
- `merchant` / `paymentMethod`：可为空。
- `categoryId` / `categoryMatched`：账本内分类与命中词。
- `note`：供核对页使用的短备注起点。
- `issues`：字段级的问题提示（缺失、歧义、退款、转账、币种推断等）。
- `status`：各字段 `confirmed` / `suggested` / `missing` / `ambiguous`。
- `source`：`natural` / `structured`。
- `multipleTransactions`：文本疑似包含多笔、但无法可靠拆分时为 `true`。

**前端不得因为字段“有值”就当作已确认。** `suggested` 和 `ambiguous` 会在核对页显示提示，关键字段（尤其金额、币种、方向）存在歧义时要求用户确认。

## 4. 粘贴识别入口与页面

### 4.1 五项菜单与居中

`apps/web/src/components/BottomNav.tsx` 的入口顺序固定为：

1. 粘贴识别 → `/paste`
2. 语音记账 → `/record`
3. **手动记账 → `/add`（视觉中央）**
4. 拍照识别 → `/scan`
5. 导入账单 → `/import?from=nav`

布局调整是最小的：卡片从原来的 `w-16` 调整为 `w-14`（sm 起仍 `w-16`），间距收紧；仍为**单行**，没有第二行，没有改中央加号的行为。320px 的计算宽度为 `5×56 + 4×4 + 2×8 = 312px`，可容纳；sm 起为 `5×64 + 4×12 + 48 = 416px`，仍在容器内。

视觉检查方式与限制见 §8.4：用真实组件在 headless Edge 的移动视口渲染 320/375/390px 并截图检查；五张卡片单行、手动记账在中央、没有横向溢出。真实登录后的点击和动画仍留给真机/真实浏览器验收。

### 4.2 页面结构

`/paste` 页面包含：

- 标题“粘贴识别”和说明“粘贴交易文字，自动识别金额、日期和分类。”
- 多行文本框；手动粘贴始终可用。
- “从剪贴板粘贴”按钮；只在用户点击时调用 `navigator.clipboard.readText()`，失败/不支持时提示手动粘贴，不自动读取。
- “识别交易”按钮；“清空”按钮。
- 隐私说明：不会自动读取剪贴板、不上传外部 AI、确认前不写入账本。
- 识别后的候选卡片：金额/方向/币种、日期、时间、商户、支付方式、分类、原文片段、字段问题。
- “核对这笔记账”按钮；疑似多笔无法可靠拆分时禁用并提示先分开粘贴。

### 4.3 多笔处理

- 明确空行分隔且每一段都各自含金额时，拆成多笔候选。
- 横线分隔同样可拆分。
- 编号列表、项目符号列表、或无法确认每行是一笔还是一笔订单的明细时，**不猜**：保留为一条结果并标记 `multipleTransactions`，禁用“核对这笔记账”，提示用户分开粘贴。
- 单笔支付宝/微信详情内部的空行不会被误判为多笔（有专门测试）。

### 4.4 隐私与数据

- 粘贴文字只存在页面 state 和一次性内存交接中；刷新即丢失。
- 不写 `localStorage`、不打印原文日志、不调用外部服务。
- 保存时备注只从解析结果取短文本（粘贴路径优先只填商户），**不会把整段复制来的交易详情/订单号当作备注长期保存**；核对页仍显示原文片段供用户对照。
- 保存仍走现有 `VoiceReviewPage` 的创建交易、幂等键、重复检测与权限链路；没有新增第二套保存接口。

## 5. 共享解析规则摘要

### 5.1 金额

- 支持中文数字、阿拉伯数字、小数、货币符号与常见单位：`28块五` → `28.5`，`28元5角` → `28.5`，`28元5分` → `28.05`，`三百五` → `350`，`一万二` → `12000`。
- 结构化文本优先读取明确标签：实付、付款金额、交易金额等。
- 排除标签不参与金额：原价、优惠、折扣、余额、积分、订单号、流水号、卡号尾号等。
- 无标签多金额无法判断时返回金额歧义（`amount_ambiguous`），由核对页要求确认，不默认取第一个或最大值。

### 5.2 币种

- 识别人民币、美元、欧元、日元、英镑、港币等常见写法与 `CNY/USD/...` 代码。
- 最长词优先，避免“美元”被“元”抢先。
- 未写币种时默认 `CNY`，但状态为 `suggested` 并给出推断提示。

### 5.3 日期与时间

- 相对日期：今天/今日/今早/今晚、昨天/昨日/昨晚、前天/前晚、大前天（最长词优先，避免“大前天”被“前天”截断）。
- 周内日期：上周五、本周五等；省略年份时按用户本地日期判断，未来超过一周回退到去年。
- 完整日期：`2026-10-08`、`2026年10月8日`、`10月8日`。
- 时间：`晚上八点`、`下午3点半`、`10:30`、`八点十分` 等；没有时段且不是数字时钟的裸 `8点` 标为 `suggested`；完全未知时保持空，不伪装成 `12:00`。
- 相对日期使用浏览器本地时钟（`now` 参数），不在 UTC 中计算。

### 5.4 商户、分类、支付方式

- 商户支持介词结构（在/去/到 + 商户）和常见品牌词（麦当劳、星巴克、瑞幸、Uber Eats 等）。
- 分类规则复用/扩展现有 `categoryMatch`：检查动作、地点、品类与冲突优先级；例如“打车去麦当劳”按交通，“在麦当劳买汉堡”按餐饮，“买公交卡”不被“买”误归购物。
- 支付方式识别微信、支付宝、花呗、银行卡、信用卡、现金等；支付宝/微信在“支付方式”语境中是支付方式，不当作商户。
- 退款/转账/还款等语境不会因为出现“收到”就默认归工资；没有合适分类时留空并提示用户选择。
- 分类只从当前账本分类列表匹配；不跨账本、不读别的账本。

### 5.5 不确定性与问题提示

解析结果同时给出 `status` 和 `issues`，区分：

- 明确识别（`confirmed`）；
- 合理建议（`suggested`）；
- 字段缺失（`missing`）；
- 多候选冲突（`ambiguous`）。

关键字段有歧义时，核对页提示并让用户确认，不静默采用。

## 6. 语音链路与专项优化

### 6.1 现状

- `apps/api/src/voice/client.ts` 启动 Python sidecar；`apps/voice/service.py` 用 pywhispercpp 加载模型。
- 默认模型 `base`，可通过 `LIBELLUM_WHISPER_MODEL=small` 回退；线程数受 `LIBELLUM_WHISPER_THREADS` 控制，默认按 CPU 限制为 2。
- 音频到达后内存解码，16 kHz mono float32；短句 VAD 能量门；默认 `language=zh`；`no_context=True`；带记账领域 `initial_prompt`。
- 录音端已有安全上下文检查、权限/设备错误文案、30 秒上限、MediaRecorder 容器选择。

### 6.2 本轮实际改动

- `suppress_nst`：默认开启，过滤 `[BLANK_AUDIO]`、`(音乐)` 等非语音 token，可用 `LIBELLUM_WHISPER_SUPPRESS_NST=0` 退出。
- `temperature=0`：显式 greedy，减少同一句话多次识别的随机漂移；`temperature_inc` 保持库默认，以便解码卡住时恢复。
- sidecar ready 行输出 `suppressNst` / `temperature`，日志能看出实际生效配置。
- `apps/voice/test_service.py` 增加相应断言与默认值测试。

### 6.3 未做什么、为什么

- **未更换默认模型、未下载模型，也未修改生产配置。** 模型是复用本机已有的 `ggml-base.bin` / `ggml-small.bin`；真实推理只在本地临时目录进行，结果没有上传。
- **未安装或新增依赖**：使用 `apps/ocr/.venv` 内已有的 pywhispercpp 1.5.1。
- **没有做 `suppress_nst` / `temperature` 的受控 A-B 对比**：21 条样本只够验证“能正常转写、静音不幻觉、参数确实传入”，不能把转写差异单独归因于这两个参数。因此本报告不宣称这两个参数提高了准确率。
- **未把转写错误当作字段解析错误来“修”**：转写层问题只能在转写层解决，共享解析器不猜测用户没说的话；两类错误在 §6.5 与 §8.3 分开记录。

### 6.4 可编辑转写

RecordPage 的转写文本可编辑；编辑后用同一 `parseTransactionText` 重新计算金额、日期、分类等，再交给核对页。这样用户只需改文字，不必重传音频或重跑 Whisper。核对页仍显示原转写，便于发现“五份/午饭”这类同音错误。

### 6.5 真实 Whisper 推理（2026-10-22）

#### 环境与模型

- 解释器：`apps/ocr/.venv/Scripts/python.exe`，Python 3.12.14，pywhispercpp 1.5.1。
- `ggml-base.bin`：147,951,465 B；`ggml-small.bin`：487,601,967 B；位于 `%LOCALAPPDATA%\pywhispercpp\pywhispercpp\models\`，由 pywhispercpp 自己的模型目录解析，未复制、未提交 Git。
- 推理后端：日志明确 `device 0: CPU (type: 0)`、`no GPU found`；虽然机器有 NVIDIA RTX 5050 Laptop GPU，但当前 wheel 未启用 GPU，本报告不把它写成 GPU 推理。
- 服务配置：默认 base；线程 2；能量 VAD；`language=zh`；`no_context=True`；`suppress_nst=True`；`temperature=0`。模型文件与生产配置均未改动。

#### 音频样本

- 共 21 条 16 kHz 单声道 pcm_s16le WAV：19 条中文、1 条英文、1 条 5 秒静音。
- 来源：Windows Huihui zh-CN / Zira en-US TTS 合成，以及上一轮已记录的 10 条合成样本；不是用户录音，也未上传第三方。
- 覆盖短句、金额、中英混合、日期、商户、人民币/美元、带噪、快语速、慢语速；静音用于验证 VAD。

#### 转写与字段结果

> 分母说明：字段统计排除静音，共 20 条；日期/时间/商户/支付方式只在“参考文本存在该字段”时计入分母。`en_01` 的参考文本是英文数词（twenty-three dollars…），属于已知未支持范围，单独保留，不能拿它宣称中文解析退化。

| 指标 | base | small |
|---|---|---|
| ASR 严格完全一致（21 条，含英文/静音） | 3/21 | 9/21 |
| 中文 19 条归一化 CER（数字/汉字写法差异也计入） | 26.3% | 12.1% |
| 正确参考文本 → 共享核心：金额/币种/收支/日期/商户/支付/分类 | 19/20、19/20、20/20、16/17、10/10、11/11、20/20 | 同左（共享核心相同） |
| 实际转写 → 共享核心：金额/币种/收支/日期/商户/支付/分类 | 19/20、20/20、20/20、16/17、3/10、11/11、13/20 | 20/20、20/20、20/20、16/17、9/10、11/11、18/20 |
| 全部非空期望字段逐条全对 | 11/20 | 17/20 |

- **ASR 层错误**：严格完全一致会把“42元5角/42元五角”这类写法差异也算作不一致，所以 exact 只是保守下界，CER 更能反映字面差异。语义上，base 把“麦当劳”听成“卖当牢/麦刚牢”、把“星巴克”听成“新八课”、把“Uber Eats”听成“估賓”、把“23美元62美分”重复成“23美元62美元”；small 的明显听错集中在噪声样本“麦刚牢”，并把“记一笔”听成“记亿笔”、“餐厅”听成“参影”。
- **共享解析层错误（文字正确时）**：本轮发现并修复了 `23美元62美分` 只取 23、`十月八日` 不识别、“超市买牛奶水果”被“水果”拉成餐饮、“全家便利店”无购物分类、`Uber Eats` 无餐饮分类、退款/转账分类被“朋友”误触发等问题；修复前后同一批样本：参考文本金额 18/20 → 19/20、分类 14/20 → 20/20；small 实际转写金额 19/20 → 20/20、分类 12/20 → 18/20。剩余分类错误是 ASR 把商户听错导致的端到端错误，不是解析器不认正确文字。
- **端到端剩余失败**（small）：`en_01` 英文日期不支持（已知限制）；`instruction` 因“参影”丢失餐饮分类；`zh_10` 因“麦刚牢”丢失商户和分类。base 的失败更多来自转写错字，而不是共享解析。
- **延迟与资源**（单条音频，CPU）：base 1.24–1.48 s/条，small 4.28–5.12 s/条，静音 7–9 ms；模型加载 base 139 ms、small 393 ms；进程 ready 分别约 1.0 s、2.0 s；工作集加载/峰值 base 258/396 MiB、small 641/801 MiB。small 更准，但耗时约 3.5–4 倍、常驻内存约 2.5 倍；本轮不改变默认 base，也不建议在生产环境未经批准切到 small。

## 7. 字段解析错误 → 修复对照

| 问题 | 修复 |
|---|---|
| 中文金额分/角与空格：`28 元 5 角` 解析失败 | `readFraction` 允许空格，角/分分别换算；补测试 |
| “美元”被“元”抢先识别成人民币 | `detectCurrency` 按最长词优先匹配；补测试 |
| `昨晚` 没有解析成昨天 | 相对日期词表增加昨晚/昨早/今早/今晚/前晚；`大前天` 放在 `前天` 前避免截断；补测试 |
| 金额为空时误报 `amount_missing`，实际是歧义 | 改为 `amount_ambiguous`，问题字段和提示一致 |
| 退款/转账/还款被“收到”带到工资类收入分类 | 对泛化收入分类做抑制；无合适分类时提示用户选择 |
| 一段结构化详情中间有空行，被拆成两笔 | 空行只有“至少两段各自含金额”时才作为分隔，否则保留整段 |
| 账本支付方式叫“微信”，解析结果叫“微信零钱”，匹配不到 | 支付方式名称双向包含匹配；保留原文供核对 |
| 粘贴备注可能把整段原文/订单号带入交易 | 粘贴路径 `draftOf(..., keepTranscriptInNote=false)`：原文只显示在核对页，备注只预填商户 |
| 编号列表被当成一笔或强行拆错 | 不猜：标记 `multipleTransactions`，禁用保存按钮，提示分开粘贴 |
| 未知时间被写成中午 12:00 | 未识别时间保持空；`10:30` 等数字时钟 confirmed，裸 `8点` 仅 suggested |
| 分类只靠“买”字，公交卡被归购物 | 分类动作/地点/品类优先级规则调整；补公交卡、麦当劳、打车等样例 |
| 真实转写文本“23美元62美分”只读出 23 | `findForeignCurrencyWithCents` 合并美元/美分，`23美元62美分` 与 `二十三美元六十二美分` 均得 23.62 USD；补测试 |
| 真实参考文本“十月八日”日期为空 | 中文月/日分支识别 `十月八日`，按当前年份推算并标 suggested；补测试 |
| “和朋友”把转账/退款误判成工资类收入 | 泛化收入分类抑制不再只凭“朋友”字样，必须出现退款/转账/还款等语义；补测试 |
| “超市买牛奶水果”因“水果”被归餐饮 | 超市/便利店/商场作为购物强证据，优先于单个食品词；补测试 |
| “全家便利店”没有购物分类、`Uber Eats` 没有餐饮分类 | 词表补充全家、便利店、Uber Eats；补测试 |
| 同一句话语音与粘贴得到不同字段 | 两个入口都调用 `parseTransactionText`；固定样例断言 `parsed` 完全相等 |

### 8.3 错误分类

测试和报告把三类结果分开，不合并成一个“成功率”：

- **转写错误（ASR）**：Whisper 听错字。base 把“麦当劳”听成“卖当牢/麦刚牢”，把“星巴克”听成“新八课”，把“Uber Eats”听成“估賓”；small 只在噪声样本把“麦当劳”听成“麦刚牢”。这些只能靠转写层/上下文改善，本轮通过真实推理记录，未用共享解析器掩盖。
- **字段解析错误**：文字本身正确，但金额/日期/分类解析错。本轮修复了美元/美分合并、十月八日、超市/便利店分类、退款/转账误判等，并有固定测试。
- **端到端错误**：ASR 错字导致后续字段丢失。例如 small 的 `instruction` 把“餐厅”听成“参影”后失去餐饮分类，`zh_10` 把“麦当劳”听成“麦刚牢”后失去商户与分类。这类错误不计入“共享解析器不认正确文字”的失败。

指标口径：ASR 严格一致、中文 CER、正确参考文本的字段准确率、实际转写的字段准确率、端到端逐条全对，五个数字分别报告，不合并。

## 11. 已知限制与后续建议

1. **真实语音样本仍不足**：本轮用的是 21 条 Windows TTS 合成音频，不是自然录音、真实手机麦克风或多人噪声环境。已经证明“能真实加载、能推理、字段链路可联合评估”，但不能把 17/20 这类小样本结果外推为线上准确率。建议所有者提供可授权的小样本集（原始音频 / 人工文本 / Whisper 实际输出 / 预期字段）再做验证；不得上传到第三方。
2. **base 默认未换 small**：small 在这批样本上更准，但 CPU 单条约 4.3–5.1 秒、工作集约 641–801 MiB，明显重于 base。切换生产默认模型需要所有者按服务器资源和并发预算另行批准；本轮未改生产配置。
3. **GPU 未启用**：机器有 RTX 5050，但当前 pywhispercpp wheel 日志为 `no GPU found`，实际 CPU 推理。启用 GPU 需要重新构建/安装后端并做新的资源验收，不在本轮范围。
4. **编号列表/复杂多笔不拆**：这是有意的保守选择，避免把订单明细合成错误一笔；后续可做“用户确认后的拆分”而不是自动拆。
5. **币种只识别不换算**：美元金额保持美元，不做汇率折算。
6. **非标准时间表达**：如“中午”“傍晚”没有具体小时时，保持时间为空并提示用户；不会造出 12:00。数字时钟（`10:30`）和明确小时（`晚上八点`）才会填时间。
7. **英文支持有限**：`$23.62` 等符号金额可解析，但英文数词、`Last Friday` 等英文日期没有支持；不能宣称支持英文记账。
8. **剪贴板兼容性**：iOS/Safari 的权限行为需真机验证；失败已有手动粘贴兜底。
9. **真实手机布局/键盘/动画**：headless 快照只能证明静态布局，需真机检查 320/375/390 的点击、键盘遮挡和动效。
10. **S15-D**：真机综合验收仍单独未完成；本报告不改变该结论。
