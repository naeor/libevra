### 4.1 识别层（Python `apps/ocr`）

- **页面/版式分类器 + 可扩展版式注册表**：单笔详情、交易列表、银行流水、转账确认、未知类型；

- **已注册真实版式**：`wechat-bill-list`、`wechat-bill-cards`、`alipay-transaction-list`、`boa-activity-list`、`bank-single-detail`、`bank-transfer-confirmation`；
- **重复检测**：同图/跨图、60 秒时间窗 + 金额/币种/方向/分类映射/标签口径，只标记、不删除不合并；
- **日期归一化**：相对日期、"今天/昨天"、星期、英文月份；描述中的日期不覆盖交易日期；
- **协议扩展**：单图响应新增 `page_type / requires_user_choice / candidates / warnings`，**保留旧 `draft` 字段**（向后兼容）；
- **验证**：Python 测试从 125 增至 **135 条全过**；真实样本 17 张用于本地自测（不入库）。

### 4.2 批量核对 → 统一确认导入（第一版）

- 上传后按页面类型分流：**单笔 → 原核对表单；列表 → 批量核对；未知 → 三选（按单笔/按多笔/重新上传）**；混合上传进同一批次；
- 批次只存在 **sessionStorage**（`batchId/bookId/items/importIds`），**确认前零写入**；
- 概览页：真实计数、筛选（全部/待核对/已确认/疑似重复 + 来源 + 收支）、卡片、详情入口、取消、结果汇总；
- 单笔详情页（新路由）：可编辑金额/收支/币种/时间/商户/分类/标签/渠道/账户/备注，可标记无效/恢复，**只写批次**；
- 确认导入：一次性固定 UUID v7（`id=idempotencyKey`）→ **逐条复用既有 `createEntry`**（离线队列 + 幂等）→ 成功清批次、失败留存重试、逐条汇总；**无新增批量 API/schema/迁移**；
- 权限：共享账本离线只读、viewer/guest 禁用并说明原因。

### 4.3 概览页优化（第二轮）

- **顶部压缩**：副标题一行；六格统计 → 一行四数（识别/待核对/疑似重复/可导入，全部真实计数）；其余统计进「详情与统计口径」；批次级警告不隐藏；
- **筛选折叠**：主状态常驻，来源/方向收进「筛选」面板，能力不删；
- **卡片分层**：状态+日期+来源 / 金额·币种·方向+商户 / 分类·支付方式·警告+详情；干净记录无警告；
- **分类联想**：新增 `lib/ocr/category.ts`，**复用语音的 `matchCategory`**；只从批次所属账本已有分类匹配商户/备注；已选分类、转账、退款、方向不明、归档/系统分类不猜；商户与备注指向不同分类判歧义返回空；写入 `categoryId + categorySource="inferred"`，卡片/详情标「系统建议」；不伪造置信度；
- **状态一致性**：「可导入」改为真实可写数（不再用 valid 冒充）；缺币种计入「待核对」且排除「可导入」；口径统一；
- **底部固定确认条**：可导入 N 笔、blockedReason、逐笔 blocker 展开；0/阻塞时禁用；列表尾部留白；确认仍走既有导入链路。

### 4.4 导入完成页（第三轮）

- 完成态改用独立外壳 `ImportDoneScreen`：**无左上返回、无右上「重新识别」**；
- 结构：状态图标+标题（全部成功/部分成功/失败）+「本次会话累计导入 N 笔 · 共 M 批」+ 批次卡片（最新在前：第 N 批/时间/成功/失败/pending 说明）+ 主按钮「返回明细」+ 次按钮「再识别一批」+ 失败时最小重试入口；
- **Toast**：顶部滑入、约 3 秒自动消失、`pointer-events-none` 不挡操作；文案按成功/部分失败/全失败/pending 区分，**pending 不写成服务器已保存**；
- **多批会话**：`sessionStorage` 只存 `bookId + 序号 + 时间 + 成功/失败/pending 计数`（不存交易明细/截图）；同 batchId 重试不重复计数；不同账本开新会话；刷新后若完成态丢失但有会话，显示会话累计 + 两个入口。

### 4.5 真实样本与冒烟验证

- 真实图片冒烟：微信「账单全部列表」→ `transaction-list` / `wechat-bill-list` / **8 笔候选**，旧 `draft` 字段保留；
- 已覆盖的版式：微信账单列表/卡片、支付宝交易列表、BOA 列表/单笔/转账、银行单笔详情；服务消息流保持 `unknown` 不猜交易。

### 4.6 已确认的限制（未做，不假装完成）

1. **真正的 `transfer` kind 未实现**：数据模型只有 expense/income，转账目前是分类预设 + `isTransfer` 标记；新增类型涉及 schema/统计/迁移，需所有者单独决定；
2. **「保存为草稿」未做**：仓内没有通用草稿能力；
3. **批次不与账本已有账目查重**：v1 只做同图/跨图；
4. **unknown 与列表混合上传**：列表优先进批次，unknown 页不生成候选（概览提示数量）；
5. **确认成功后不自动跳转**：先展示结果汇总，用户点「查看明细」再走；
6. **未做真实浏览器 E2E / 真机截图验收**：需所有者用真实账号/截图复核；
7. **导入完成页的 pending 计数是导入当时的历史值**（只存计数，无法追踪后续投递）。
