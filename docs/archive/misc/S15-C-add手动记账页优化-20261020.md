## 1. 改前现状（事实，来自代码与渲染）

### 1.1 页面结构

`/add` → `apps/web/src/pages/AddEntryPage.tsx`；外壳是 `TabPage`
（`components/Layouts.tsx:135`）：

- 根节点 `flex h-dvh flex-col overflow-hidden`（`Layouts.tsx:162`）；
- 中间是**唯一滚动区** `flex-1 overflow-y-auto overscroll-contain`（`:166`）；
- 滚动区内容列 `max-w-md pb-24`（`:169`）；`pb-24` 是给底部导航中间抬起的「+」留的；
- `BottomNav` 是滚动区的**兄弟节点**，自带 `pb-[env(safe-area-inset-bottom)]`（`BottomNav.tsx:241`）。

自上而下（改前）：

1. 绿色 header，仅「支出 / 收入」两个按钮（`AddEntryPage.tsx` 旧 316 行起）；
2. 金额：白底 + 2px 绿框 + `<input aria-label="金额" inputMode="decimal" autoFocus>` + 快捷金额；
3. 分类：可折叠（默认收起，显示「暂无分类」）；
4. 支付方式：胶囊；
5. 币种：**6 个胶囊**（`CURRENCIES` 有 6 种，360px 上折两行）+ 两行精度说明；
6. 时间：`datetime-local` 整段；
7. 备注：整段输入框；
8. 标签：整段胶囊（没有标签时整段不渲染）；
9. 保存：表单最末的 `px-6 py-6` 按钮。

### 1.2 字段、状态与提交

- 字段：kind、amountText、categoryId、paymentMethodId、currency、occurredAt、note、tagIds。
- 提交 `save()`：校验金额 → 用 `uuidV7()` 生成 id 与 idempotencyKey → `createLocally(...)`；
  失败再走一次本地写入；成功后 `setSaved(entry)` 显示 `EntrySaved`。
- 共享账本 + 离线时只读：`useSharedLedgerOfflineReadOnly()`，按钮禁用并显示原因。
- 「再记一笔」重置金额/备注/标签/时间，并聚焦回金额。

### 1.3 垂直长度来源与保存位置

改前约 9 段纵向排列。360px 下通常要滚动约一屏到一屏半；保存按钮在**最底部**，填完金额后
要跨过分类、支付方式、币种、时间、备注、标签才能按到。`TabPage` 的滚动区高度已经扣掉
顶部横幅与底部导航，所以真正可用的首屏高度比 `dvh` 还小。

### 1.4 TabPage 的约束（决定了保存条方案）

- 不能把行动条放到 `TabPage` 外面：布局由 `Layouts.tsx` 持有，且本轮该文件属于别的改动；
- 滚动区底边 = 底部导航上沿；底部导航已经消费了 `env(safe-area-inset-bottom)`；
- 中间「+」按钮从导航顶部**向上探出约 9px（外加 4px ring）**，行动条底边若贴住导航上沿，
  必须给它留出这段高度；
- 滚动区内容底部还有 `pb-24`，滚到底时行动条会落在距导航约 96px 的位置（与改前底部的
  留白同源，不是被遮挡）。

## 2. 方案比较

### 方案 A（采用）：滚动区内 `sticky bottom-0` 行动条

- 结构：行动条仍是 `<form>` 的最后一个孩子，`position: sticky; bottom: 0`；
- 保存永远可见，且**在文档流里**：滚到底时最后一块内容（更多选项/备注/标签）能完整滚到
  行动条上方，不存在「最后一行永远被盖住」；
- 不碰 `Layouts.tsx` / `BottomNav.tsx`；滚动区底边就是导航上沿，天然不重叠；
- 底部留 20px，给导航中间抬起的「+」让位；
- 软键盘：用 `visualViewport` 量出「滚动区底边到键盘上沿」的距离，把整条抬起；
  Android 的 `interactive-widget=resizes-content` 会缩小布局视口，此时量出来是 0，不重复抬。

### 方案 B（未采用）：`fixed` 底部条 + 导航高度/安全区偏移

- 需要知道导航实时高度与安全区，`bottom` 只能写死或再读 DOM；
- 会同时出现「固定层 + 导航」两层底栏，软键盘与 `dvh` 变化时最容易互相打架；
- 内容需要额外 padding 才不被遮挡，且必然要改 `TabPage` 或与另一个 Agent 的文件协调。

### 方案 C（未采用）：把保存放到顶部 / header

- 拇指可达性最差；而且保存依赖金额校验，错误提示离操作点太远。

**选 A 的理由**：在不动布局外壳的前提下，同时满足「始终可见」「不永久遮挡」「不碰
BottomNav」「软键盘可处理」四个条件，改动集中在一个页面的渲染层。

## 3. 实施内容

### 3.1 新的首屏顺序（高频在前）

1. 支出 / 收入；
2. 金额（保持输入框与绿框，新增一行「金额 · 点按即可修改」提示）；
3. 快捷金额；
4. 分类；
5. 支付方式；
6. **币种 + 时间合成一张两行卡片**（常用次级）；
7. **更多选项**（备注 + 标签，默认收起，低频）；
8. 保存行动条（sticky）。

### 3.2 金额（要求 1）

- 仍是 `<input aria-label="金额" inputMode="decimal" autoFocus>`，未改成展示卡；
- 上方加 12px 提示「点按即可修改」，卡片保持白底 + 2px 绿框，`cursor-text`；
- 输入、校验、提交逻辑未动。

### 3.3 保存行动条（要求 2，`apps/web/src/components/entry/EntrySaveBar.tsx`）

- `data-entry-actions="sticky"`，class `sticky bottom-0 z-20 mt-5 bg-canvas`；
- 内部 `border-t border-line px-6 pt-3 pb-5`：
  - `pt-3` + 按钮 `py-3.5`（约 50px）+ `pb-5`（20px 给「+」）；
- 校验错误与「共享账本只读」提示也移到这里，点保存就在原地看到原因；
- `pb-24` 的尾部留白保留（滚到底时行动条距导航约 96px，与改前页面底部留白一致）；
- **未重复加 `env(safe-area-inset-bottom)`**：滚动区在导航之上结束，导航已经把系统区
  让出来了；再叠一次会在带 Home Indicator 的 iPhone 上凭空多 34px 空档。理由写在
  `EntrySaveBar.tsx` 顶部注释里。

### 3.4 软键盘（`apps/web/src/components/entry/keyboardInset.ts`）

- `keyboardOffset(scrollportBottom, visualViewportTop, visualViewportHeight)`：
  `键盘顶 = 可视区顶 + 可视区高`，返回「行动条需要抬起多少」；没有键盘时结果为负 → 0；
- `useKeyboardInset(scrollRef)`：监听 `visualViewport` 的 `resize`/`scroll`、窗口 `resize`
  以及滚动区尺寸变化（`ResizeObserver`）；双指缩放时不抬；
- 只在 `inset > 0` 时写 `style={{ bottom: inset }}`，其余时间就是 `bottom-0`；
- ⚠️ **`index.html` 本身已有 `interactive-widget=resizes-content`**，所以 Android 上
  `dvh`/布局视口会随键盘缩小，公式自动得 0；当前 iOS Safari 不认这个 meta，公式给出真实高度。

### 3.5 币种 / 时间（要求：常用次级，保留可编辑）

- 合成一张 `rounded-field border border-line bg-surface` 的两行卡片，行高 `min-h-12`；
- 币种：原生 `<select aria-label="币种">`，6 个 `<option>`（人民币/美元/欧元/日元/港币/英镑），
  仍可修改；文字 16px，避免 iOS 聚焦时自动放大；
- 时间：仍是 `datetime-local step="1"`，仍可修改；
- 精度说明改为**仅在 0 位小数币种（日元）出现**，不再常驻两行。

### 3.6 更多选项（要求 4，`apps/web/src/components/entry/EntryMoreOptions.tsx`）

- 默认收起；`<button aria-expanded aria-controls="entry-more-options">`；展开后：
  - 备注：同一个输入框，`maxLength=200`，`aria-label="备注"`；
  - 标签：同一组按钮、同一套选中颜色、`MAX_TAGS_PER_TRANSACTION = 10` 的上限逻辑
    原样保留在页面里；标签 header 文案不变；
- 收起时若已填写，右侧提示变为「已填写」，避免隐藏内容被忘记；
- `copyFrom`（复制这一笔）带备注/标签时自动展开；「再记一笔」重新收起。

### 3.7 转账（要求 3）

**当前 main 代码里不存在「转账」顶层按钮，未改数据模型。** 证据：

- `packages/shared/src/ledger.ts:27`：`TRANSACTION_KINDS = ["expense", "income"]`；
- `packages/shared/src/presets.ts:30`（支出分类「转账」）与 `:37`（收入分类「转账」）；
- `AddEntryPage` 的顶层切换只映射这两个 kind，转账分类与其他分类一样在分类选择器里。

若所有者看到旧版三按钮，是 PWA 缓存了旧构建，不是当前源码。

### 3.8 连续记账（E，未实现）

只在默认值 effect 上方留了注释：将来继承金额/备注/标签的入口应是那里的默认值逻辑与
