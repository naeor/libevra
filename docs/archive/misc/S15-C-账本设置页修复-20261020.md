## 2. 问题一：账本设置页信息重复

### 2.1 基线事实

- `BookSettingsPage.tsx` 的 `InnerPage` subtitle 渲染 `名称 · 编号`；
- 顶部 `BookIdentityCard`（`BookSwitcherSheet.tsx`，账本详情页复用）渲染名称 / 编号 / 成员数 / 切换；
- 下面「账本资料」section 再渲染 `账本名称`（可改名）与 `账本编号` 两行，viewer 另有一句说明。

→ 名称、编号各出现 2–3 次。

### 2.2 改法（按所有者决定实现）

1. **删除整个「账本资料」section**：两行数据、`ActionRow` / `ReadOnlyRow` 两个行组件、以及外层容器一起删除（组件在本文件内，只被这一块使用）。
2. **改名入口移进顶部卡片**：`BookIdentityCard` 新增**可选** `onRename?: (() => void) | undefined`。
   - 不传：输出与基线**逐字节相同**的单 `<button>` 卡片（账本详情页、viewer 走的都是这条）；
   - 传了：卡片变成容器 + 两行——第一行仍是原来的身份行（整块可点＝切换），第二行是「修改账本名称 ›」。
   - **为什么是第二行而不是按钮里的按钮**：卡片本身是 `<button>`（所有者「右侧「切换」按钮整块可点」），嵌套 `<button>` 是无效 HTML，会让一次点击触发两个动作。测试里断言了按钮嵌套深度为 1。
   - 改名行**不再重复名称**：它是动作，不是值；名称只在身份行出现一次。
3. **`BookSettingsPage` 只在 `canWrite` 时传 `onRename`**（`{...(canWrite ? { onRename: openRename } : {})}`），viewer 不传。
4. **subtitle 不再传**（owner 给的选项：可留一句说明或不传；这里选不传——标题 + 一张身份卡片已经说清，且少一行就给内容多一行空间）。原「正在读取……」的 pending 文案随 subtitle 消失，加载态仍由 `SkeletonRows` 表达。
5. **viewer 说明保留**，位置改到卡片下方：
   「你对这本账只有查看权限，所以账本名称不能在这里修改。」
   （原文是「名称等资料不能在这里修改」，因「账本资料」块已删除而收窄为「账本名称」。）
6. 其余三个区域（记账管理 / 数据管理 / 危险操作）与末尾「成员与邀请…」一句未动。

### 2.3 结果

| 事实 | 基线 | 现在 |
|---|---|---|
| 名称渲染次数（设置页） | 3 | 1（卡片） |
| 编号渲染次数（设置页） | 3 | 1（卡片） |
| 改名入口 | 「账本资料」块首行 | 卡片内第二行（仅 owner/editor） |

## 3. 问题二：导出 ⇄ 账本设置 返回循环

### 3.1 根因（沿用任务书已定位的结论，未重新发明）

- `InnerPage` 用 `useGoBack(backTo)`；`useGoBack` 在没有 `state.from` 时「有历史就 `navigate(-1)`」，`backTo` 只是深链兜底。
- 设置 → 导出 后，导出的返回用 `-1` 回设置；设置的返回又用 `-1`，而它背后那条历史条目正是导出 → 循环。

### 3.2 改法

1. `connectivity.ts`：新增 `export type BackMode = "history" | "parent"`；`useGoBack(fallback, mode = "history")`。
   - `parent` 分支：`void navigate(fallback)`（普通 navigate，**不 replace**），排在「5 连击逃生」之后、「`state.from` / 历史」之前；
   - 该分支**不吃 `state.from`**：它表示「我的父级固定」，不能被别人的来路改写；
   - 保留 5 连击逃生（10 秒 4 次 → 首页），它是判断「用户卡住了」的既有保护。
2. `Layouts.tsx`：`InnerPage` 新增可选 `backMode?: BackMode`，默认 `"history"`，透传给 `useGoBack`。
3. `BookSettingsPage`：`backTo={`/books/${bookId}`}` + `backMode="parent"`（返回账本详情）。
4. `ExportPage`：`ExportView` 新增 `backMode` 透传；
   - `ExportForBook`：`backTo={`/books/${bookId}/settings`}` + `parent`；
   - `ExportForCurrentLedger`：`backTo="/"` + `parent`。
5. 其它页面一个都没改：`AboutPage` / `LegalPage` 的 `state.from` 逻辑与测试保持原样；测试用清单式断言钉住「源码里出现 `backMode` 的文件只有 Layouts / connectivity / 这两个页面」。

### 3.3 结果

- 设置页返回 → `/books/:bookId`（账本详情），与来路无关；
- 导出（目标模式）返回 → `/books/:bookId/settings`；
- 导出（当前账本，`/export`）返回 → `/`；
- 「导出 ⇄ 设置」这一对不再可能循环。

## 5. 未做 / 已知风险

### 5.1 残余循环：账本详情 ⇄ 账本设置（**需要所有者或 Lead 决定**）

- `parent` 模式按任务书用「普通 navigate（push）」后：设置页 push `/books/:bookId`，设置页自己的历史条目仍留在详情之前；而 `BookDetailPage` 的返回仍是历史模式（`navigate(-1)`），于是
  `设置 → 返回（详情）→ 详情返回（历史 -1）→ 设置 → …` 会来回走。
- 严重度：比原来的「导出 ⇄ 设置」轻——它只在连续按返回时出现，而且 10 秒内按 4 次会回首页（逃生逻辑仍然有效）；但严格来说「无论从哪来都不可能循环」这一条**没有完全达成**。
- 两个一行修法（都超出本轮允许改动的文件范围，故未做）：
  1. `BookDetailPage` 改 `backTo="/start"` + `backMode="parent"`（最贴近层级语义）；
  2. 设置页 `parent` 返回改 `navigate(backTo, { replace: true })`（无循环，但违背任务书「保持普通 navigate，不 replace」的原则）。
- 本轮按任务书原样交付，并把这一条留给上层决定。
