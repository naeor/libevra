## 5. E3 “不是同一笔”关系记忆（17/18，发现 P2 并发缺陷）

覆盖：创建返回 201、反向重复提交幂等、默认列表、viewer 只读/写 403 `book_read_only`、非成员 403 `book_forbidden`、路径与请求头账本不一致 400 `book_mismatch`、跨账本交易对拒绝、自配对拒绝、备注变化不失效、金额变化同事务撤销且原因 `key_fields_changed`、撤销幂等、软删除后不可见。

### 5.1 未通过项（B12，P2）

```
8 个并发 POST 创建同一对关系：
HTTP statuses = [200, 201, 500, 500, 500, 200, 200, 200]
事后该对关系数 = 1
```

- **期望**：全部 2xx（创建 201 或幂等 200），无 500；
- **实际**：3/8 请求 500；关系本身没有被重复创建（唯一约束兜住），没有数据丢失或越权；
- **根因（静态审查）**：`apps/api/src/ledger/notDuplicateRelations.ts` 的 `writeRelations()` 先 `findUnique` 再 `create`，并发窗口内两个请求都查不到，后创建者撞唯一约束 `P2002`；路由未捕获该错误，落到 500；
- **重试行为**：客户端重试会得到幂等 200；但用户可能看到一次失败提示；
- **建议修复**：捕获 `P2002` 后回读已有关系并按“未变化/已重激活”返回 200；或在数据库层用 `INSERT ... ON CONFLICT DO UPDATE`；补并发回归测试。修复属于业务代码改动，本轮未做。

### 5.2 其他验证

- 关系表：`(book_id, transaction_a_id, transaction_b_id)` 唯一、`CHECK(a<b)`、账本外键 CASCADE、交易侧无外键；空库迁移 52 成功；`viewer` 不能写、`editor+` 可写；关系按 A/B 规范化，正反提交幂等。
- 时间戳/证据：关系带有 `basis` 快照与确认人/确认时间；金额变化后在同一 PATCH 事务内撤销，历史仍保留软撤销记录；分类/支付方式/标签/备注变化不撤销，符合设计决定。
- 删除一侧交易后关系不再 `effective`；永久清理后因无交易外键不会阻断清理，读取时按缺失侧处理。

### 5.3 关系 UI 往返（8/8 通过）

隔离前端账本中选一笔有 35 个候选的记录 → 明细页“更多 → 重复账目检测” → 点“这两笔不是同一笔” → 候选减少到 34 → 账本设置“已忽略的重复交易”出现该对及确认人 → 点“撤销这条判断” → 状态更新为已撤销。说明关系记忆、展示、撤销闭环可用。

## 7. E5 全账本扫描与性能（15/15 通过）

| 场景 | 数据规模 | 结果 |
|---|---|---|
| 普通大账本 | 2000 笔互不重复 | seed 11.8s；40 页；全扫 6.9s；最慢单页 212ms；`processedSum=total=2000`；0 候选；无跨页重复/遗漏 |
| 密集同额同时段 | 35 笔 | 595 对；2 页；262ms；`processedSum=35`；无重复/遗漏 |
| 中断后续扫 | 595 对 | 中断后重新扫描结果一致 |
| 扫描中新增交易 | 旧 `throughSeq` | 旧扫描保持 35 笔/595 对，不倒退；新扫描 36 笔/630 对 |
| 关闭提醒 | — | 200，空结果 |
| 非法时间窗 | `999999999` | 400 |
| 非成员 | — | 403 |

- 扫描每页最多 50 个左侧记录、500 个候选；游标含 `leftSeq/rightSeq/throughSeq/activeSeq`；进度只累计完整左侧记录；没有自动删除/合并。
- **性能结论**：2000 笔可用但全扫约 7 秒，密集账本最慢页 212ms，属 P3 已知性能边界；没有新增索引，>2000 笔会更慢。

### 8.1 真实样本主流程（30/30）

| 来源 | 解析结果 | 提交结果 | 幂等/重复 |
|---|---|---|---|

| BOA PDF | 108 笔；8 页；对账 `reconciliation.ok=true`；全部 `timePrecision=day` | 提交 108；fileRef `In-20261021-201729-c5f1` | 重传 108 笔全部身份重复 |
| Libvelra CSV | 首次 1 笔 | 写入 1 笔 | 同内容换来源编号：`identityDuplicate=false`、`duplicateIds.length=1`、`selected=true`（业务疑似重复只提示，不自动取消选择） |

- 重检：改金额 1.23 后调用 `/recheck`，再提交成功写入 12 笔；
- **观察项（P3）**：修改候选但不调用 `/recheck`，直接 `/commit` 仍能写入（见 §10 P2-2 的同一根因）；身份重复仍被事务内拦截；
- **观察项（P3）**：同一 fingerprint 已导入后强制提交另一个预览，返回的是历史导入报告（`importedCount=12`），而实际新增 0；正常 UI 不会走到该路径，API 消费者可能误读。

### 8.2 边界 / 安全（13/13）

- 跨账本预览：另一账本的预览 ID 不可见/不可用（410 `preview_expired`，不泄露存在性）；
- 非成员 / 无权限：401 未登录、403 `book_forbidden`、viewer 导入他人账本 403；
- 缺目标账本：400 `missing_target_book`；
- 非法 previewId：410 `preview_expired`；
- 非法提交结构/行：400，不半写入；
- 纯文本文件、空文件、超 10MB、PDF 无文本层：明确拒绝/可理解错误，不产生候选；
- BOA 真实样本：描述中的第二个日期作为“可能是消费日期”警告，不擅自改交易日期；对账一致；
- 身份重复与业务疑似重复分开：`identityDuplicate` 禁选/不选中；`duplicateIds` 仅提示，不自动删除。

### 8.3 导入缓存与提交机制（静态）

- 预览保存在进程内，TTL 30 分钟、容量 25、全局 FIFO 淘汰；按 `userId+bookId` 隔离；服务重启全部失效；提交后复用报告；
- 提交使用 `pg_advisory_xact_lock(import:bookId:fingerprint)`；同文件并发提交顺序化；来源身份由 `importLog`、已有 `sourceRef/sourceTransactionId` 和批内去重共同兜底；`P2002` 转 409 `duplicate_source`；
- 风险观察：全局 FIFO 可能淘汰其他用户未过期预览（P3，单机单用户部署下影响有限）；`ImportLog.format` 固定为 `csv`（P3，不影响数据）。

1. **P2-1 关系并发创建返回 500（已实测确认）**
   - 复现：8 个并发 `POST /books/:bookId/not-duplicate-relations` 提交同一对；
   - 实际：`[200,201,500,500,500,200,200,200]`，关系数仍为 1；
   - 影响：用户可能看到一次失败提示，重试可成功；无重复关系、无数据丢失、无越权；
   - 根因/建议：见 §5.1；建议在进入 S15-D/发布前修复并加并发回归测试。

2. **P2-2 导入 commit 不强制服务端 recheck（已实测确认）**
   - 复现：预览后修改金额（如 1.23→9.99）但不调用 `/recheck`，直接 `/commit`；实际写入 12 笔；
   - 影响：如果直接调用 API，可能带着过期的 `duplicateIds`/提示提交，导致**业务疑似重复提醒漏报**；来源身份重复仍由事务内 `importLog`、`sourceRef`、`sourceTransactionId` 过滤，不会重复写入；
   - 正常 web UI：编辑/勾选后会置 dirty，确认按钮要求重新核对；实际用户主路径有防护；
   - 建议：服务端增加 `previewRevision`/`recheckToken`，commit 校验版本；或 commit 内部重新计算候选/警告。

3. **P2-3 E5 历史扫描丢失日精度（静态审查 + 已在实现说明记录）**
   - `candidateFromTransaction()` 未设置 `occurredAtPrecision`，历史交易默认按 `second`；旧 CSV 只有日期的记录落库为 12:00 后，会被当作真实时刻比较；
   - 影响：可能造成少量误报/漏报；不自动删除、不自动合并，影响可控；
   - 建议：给交易增加/暴露 `occurredAtPrecision` 字段，或在候选适配器按来源恢复 day 精度；至少在 S15-D 说明书中保留。

4. **P2-4 预览缓存全局容量 25、FIFO 淘汰（静态审查，未造成数据问题）**
   - 多用户/多预览并发时可能淘汰他人未过期预览，用户会收到 410 `preview_expired` 并需重新上传；
   - 本机单用户部署影响低；建议改为按用户配额或 LRU，并在 UI 说明预览会过期。

## 11. 已知限制与未覆盖项

**产品既定限制（不是本轮回归）**：

- E5 历史日精度如上；旧 CSV 入口仍是“写入后按 importRef 判重 + 缺时间补 12:00”，与导入 V2 的身份去重不同；

- 重复检测设置仅 localStorage、按本机账号隔离，不跨设备；
- 关系表无交易侧外键；同一对重确认会覆盖上次撤销历史（每对一行）；关系无传递性；
- 无自动删除/合并/覆盖正式交易，所有确认都是用户显式操作。

- 多人同时操作同一账本的真实浏览器会话（API 并发/权限已测）；
- 跨设备同步、多标签 localStorage 竞争；
- 生产数据库迁移、回滚演练、生产 Python sidecar 可用性；
- 移动端视觉与手感（S15-D 所有者验收范围）。
