# S16-D · D4/D5 本地候选验收（2026-10-26）

> 最后核对: `14656e9` / 2026-10-26（本轮基线，交付提交见分支日志）。
> 执行状态唯一出处：[STATUS](../../STATUS.md)。产品与计算合同：[规格 §7](../../specs/features/S16-D-历史汇率与折算基础设施.md#7-d4d5-显示与交互合同)。本报告记录本轮实现与验证，不代表生产启用。

## 1. 实际功能

- D4：设置 → 显示与数据的「汇率折算模式」，默认关闭，设备本地按账号保存。开启后，明细主金额折算、辅行原币；同币种不重复；首页展开/折叠综合小计一致；详情展示历史依据、实际日、ECB 来源、原币及待复核状态。编辑恢复原币金额输入。
- D5：综合收入、支出、差额，分类小计、月份趋势、相对时段与指定历史月份，原币汇总；可切回原有分析。缺项明确标不完整并定位失败账目，不画虚假完整占比。
- 正式 API 接入与公共表增量定义已在独立环境工作，未挂试验页面替代正式流程。没有复制整页、改颜色令牌/海浪动画或添加交互下钻；原有记账流程、分币种分析和权限判断保留。

## 3. 示例与精度

2026-10 的共享样本：100 CNY、20 USD、10 EUR、1500 JPY、80 HKD、50 GBP 支出，另有 2000 CNY 收入。引用已实际获取的 2026-10-23 ECB 参考值；24/25 日按周末规则回退至 23 日。

目标 CNY 的逐笔支出分别为 100.00、133.40、74.66、63.81、68.03、445.85，合计 **885.75 CNY**；收入 **2,000.00 CNY**，差额 **1,114.25 CNY**。以独立 Python Decimal（ROUND_HALF_UP）核查，不能先把 GBP 比值粗略四舍五入再合计。

1999-01 样本：100 USD 与 100 CNY。该日 ECB 没有 CNY 参考值；目标 CNY 时原币 CNY 自身仍是 100 CNY，USD→CNY 无法折算。页面显示不完整、成功支出小计 100 CNY 和一笔失败定位，而不是把失败项补零并声称完整。目标 USD 的共享成员看到个人默认币种视图，所有者的开关与默认货币不受影响。

## 5. 数据库、安全与集成

专用库 `libevra_fx_s16d_dev`、`libevra_fx_s16d_test`；恢复演练库 `libevra_fx_s16d_restore_test`。工具仅允许回环地址和这些确切库名，拒绝主开发或生产目标。最初 58 迁移基线 dump 后恢复到空演练库，49 张表行数逐项一致；证据 `_backups/fx-d4/backup-proof.json` 与 `before-fx.dump`。没有把“文件存在”当成备份通过。

之后才整合 schema 和第 59 个 `20261026120000_fx_public_rates`，仅新增公共 `fx_snapshots` / `fx_resolutions`，没有交易/用户表迁移、金额回填或原件更新。原 pending SQL/模型已移除。专用开发/测试库分别执行增量迁移；主库与生产没有操作。

`server.ts` 装配真实 ECB 适配器与 pg 存储；`buildApp` 沿用 session/consent guard。集成测试发现仅声明限流配置并未生效，修复为插件就绪后子作用域注册；最终额度 600 次/分钟，避免十四个月逐日冷缓存查询被自身中断，测试验证前 600 次成功、第 601 次返回 429。客户端仍串行去重，服务端合并同日并发，不下载全历史。外人读取账本 403，viewer 可读仍不可写；公共汇率查询不能成为账本授权。

原件 DTO 不包含 bookId，计算模块从捕获的已鉴权请求/离线 scope 附加归属。范围结果不持久化为第二套账本；下载凭据只存 ID。新旧请求键、AbortController、每步作用域校验、单笔有界缓存及原有 pending/deleted 合并规则一起防止迟到结果串用。关闭/删除账号时新偏好键也会清理；普通退出保留该账号自己的显示选择，不给其他账号使用。

## 6. 自动化与性能

自动化通过：shared **377 项**、Web **1,367 项 / 150 文件**、API **611 项 / 57 文件**，另跑历史专项 **202 项 / 5 文件**（与上述部分重叠，不能相加）；浏览器 **12/12**。API 包含新增三项正式路由鉴权、跨账本/查看者边界和实际限流。测试库明确是本分支专用库，不清空其他 AI 共用的测试数据。`typecheck`、`check:build`、`check:docs`、`check:status`、`check:db` 与 Prisma schema validate 均通过。日志为本机 `_backups/fx-d4/*-final.log`，截图与口令不提交。

Web 新用例覆盖安全范围之外的整数字符串格式化、JPY 零位、缺失保持原币而非假零、同币种不重复、未知账号默认关闭、范围上限、50,000 笔线性完整性检查及待同步原件合并不复活服务器旧删除；关闭/删除账号的偏好清理也有回归断言。

继承已验证的每 200 笔 MessageChannel 分批计算，基准覆盖 20/5,000/50,000、冷热缓存、切目标与修订。新增源数据完整性核对使用 Map/Set，消除了 `receipt IDs × 原件` 二次方扫描；范围最多 14 个月/100,000 笔，超过时要求缩小时段，不返回假完整小计。真实 UI 大规模分页吞吐与低端手机帧率不能由纯引擎基准代替。

本轮 Node v24.20.0 独立模拟基准：20/5,000/50,000 笔异步汇总分别 **0.43/49.84/375.75 ms**，全部与同步精确结果一致；50,000 笔期间心跳 249 次、最大间隔 **2.75 ms**。5,000 条有界缓存工作集全部命中、24.32 ms；50,000 条遍历大于缓存容量时热遍历仍约 354 ms，不声称全量缓存命中。完整值 `_backups/fx-d4/benchmark-final.json`。这些是本机计算基准，不包含真实联网、DOM 渲染或低端设备。
