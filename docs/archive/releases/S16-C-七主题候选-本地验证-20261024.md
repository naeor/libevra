## 4. 配色与客观结果

设计规则、正式名称与旧键名关系见 [候选规范](../../specs/design/S16-C-七主题候选设计.md)。11 品牌角色分别设计，其余 39 角色按模式在七主题间完全一致。没有 hue-rotate、反相、其他六色自动接入或财务色重映射。

- 252 组配对检查（仅本机材料：`preview-artifacts/s16c/contrast.json`）：六套新品牌组的正文 / 按钮 / 软底 / 焦点 / 海浪达到对应 4.5:1 / 3:1 目标；原始公共 Token 的既有欠缺列为 inherited，不冒充全数通过。
- 实际渲染检查（仅本机材料：`preview-artifacts/s16c/rendered-contrast.json`）：28 个实际明细 / 状态页面、812 个可见节点，计算真实颜色、透明度与背景层叠加，支持浏览器 RGB / OKLab。六套新候选在这一范围内未发现剩余不达标节点；正式森林绿浅色仍有 12 个不达标节点，未改。
- 六套新浅色统计卡与前景分配修正了玻璃叠加欠缺；未选中收支文字由轻微混色提高可读性，错误提示用 `danger-dark` 承载。Token 原始状态值与财务含义仍相同。
- 森林绿浅色：主按钮约 3.37:1；玻璃统计卡小字约 2.21–2.54:1，大字约 2.77:1；次级按钮 / 成功提示约 4.34:1；未选中收入约 4.46:1；浅色旧焦点环及错误软底也有既有欠缺。按本轮“不重新设计正式森林绿”要求保留，不能声称全部七主题达到 AA。
- 热力及任意标签的业务颜色不重新设计。完整图表截图保留既有浅色热力前景欠缺；分类按排名赋色的历史行为也未改，不把“同一固定数据下颜色稳定”冒充跨月份算法已解决。
- 28 个真实标签实例（仅本机材料：`preview-artifacts/s16c/tag-contrast.json`）检查确认同名标签背景色在 14 种组合完全一致。六套新浅色仅消费已有自动前景，未改标签保存色；森林绿浅色亮黄标签的白字欠缺仍保留。
- 交互保持证据（仅本机材料：`preview-artifacts/s16c/interaction-proof.json`）：从森林绿浅色记账表单切到青瓷灰深色，输入金额 47.90 保持不变；页面内暖木棕 / 深色选择也会同步到外部预览工具。系统选项经过选择检查，未改变真实操作系统来模拟硬件验证。

本审计限指定文字与纯色背景叠加；装饰线、禁用态、渐变像素、全站所有弹层与真实硬件不构成全面 WCAG 认证。焦点 / 边界有 Token 检查及可交互状态样例；未声称所有交互时刻都逐帧验证。

## 5. 人工观察，不自动定稿

| 主题 | 需人工判断的具体表现 |
|---|---|
| 森林绿 | 正式基准不再选色；浅色对比度债务要不要另开授权统一处理 |
| 琥珀黄 | 金麦色是否足够“黄”；与警告同属暖金，实际文案 / 图标语境是否足够区分 |
| 暖木棕 | 大页头与深统计卡是否显旧、沉重；与丹霞红的暖棕 / 陶土红区分是否满意 |
| 雾霭蓝 | 与青瓷灰深色操作色是否足够分开，是否偏商务；观察海浪中间层而非只看色点 |
| 烟霞紫 | 浅色是否太偏灰，深色选中与按钮是否仍清楚且不发亮 |
| 丹霞红 | 品牌红与错误 / 支出的相近感；不得为解决品牌相似而偷偷改变业务红 |
| 青瓷灰 | 是否保留灰青 / 釉色身份，同时与森林绿、雾霭蓝都能分辨 |

额外的公共分配决定：六套新浅色深强调统计卡与森林绿原玻璃卡不同，是为可读性作的候选取舍；是否接受、或另行授权对正式基准统一调整，留所有者决定。没有代选最终六色。
