## 回滚

1. **先看有没有人被设为“记账”**。1.19.53 不认识 `recorder`：只要有成员或未用完的分享链接是“记账”，旧应用读到它就会出错。回滚前须先把这些成员改为“编辑全部”或“只读”（在 1.19.56 界面里由管理员修改，或经所有者批准后改数据库），并撤销角色为“记账”的分享链接：
   ```bash
   cd /srv/libevra/deploy
   sudo docker compose -p deploy --env-file .env -f docker-compose.prod.yml exec -T db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Atc "SELECT role, count(*) FROM book_members GROUP BY role; SELECT role, count(*) FROM book_share_links GROUP BY role;"'
   ```
2. 只回滚应用（不动数据库）：
   ```bash
   cd /srv/libevra/deploy
   sudo docker compose -p deploy --env-file .env -f docker-compose.prod.yml -f /srv/libevra-release-1.19.56-20261111/rollback-1.19.53.yml up -d --no-deps api web
   rsync -rltp --exclude='/deploy/*.sh' /srv/libevra-release-1.19.56-20261111/previous-source/ /srv/libevra/
   printf '1.19.53\n' > .last-deployed
   printf '2046c53a7a7b25b80706c0db3cdad6c5297f7383\n' > /srv/libevra/.deployed-commit
   ```
3. 核对 `https://libevra.com/api/v1/health` 返回 `1.19.53`、`database=up`。迁移保留（68 项）：新增的枚举值、约束与列对旧应用无影响，`invite_admin_only` 被旧版本忽略；不要回退迁移。
4. 数据恢复只在所有者明确要求时执行 `restore.sh <备份>`，会丢失发布后的新数据，须另行批准。
