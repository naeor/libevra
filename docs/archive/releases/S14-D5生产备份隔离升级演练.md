## 7. 新版 API 与 S14 隔离功能验证

隔离 API：

- `/health`：`ok=true`、`version=1.14.17`、`database=up`；
- 使用隔离库内新建的测试账号和测试账本，不读取/打印生产用户数据；
- 正式来源 B → 新建空目标 A：
  - 创建 job → `awaiting_confirmation`；
  - 锁定期直接写目标交易 → **409 `ledger_locked`**；
  - 最终确认 → target 2 行，来源清理 disposition `canArchive=true`、`migrated=2/2`；
- 第二个空目标导入后撤销 → target 0 行、锁 0；
- 第三个空目标等待确认后时间到 → 自动撤销完成、target 0 行；
- 所有测试新建的空目标账本在撤销后仍存在（未archive/未丢弃），符合方案 B；
- 隔离 API 启动不改变升级前既有数据摘要。

> 说明：自动撤销的最后一步通过 Prisma 将 deadline 设为过去时间触发 worker 清扫；第一次尝试用 psql 直接改 deadline 时，因隔离库/Prisma 的时区显示差异未被识别为过期（不是生产路径，生产 deadline 由 API 的 JS Date 写入）。改用 Prisma 写入后 worker 正常自动撤销。这不影响生产代码路径，但记录为演练操作注意事项。

### 仍未消除的风险/条件

1. 本次只在**一次性隔离集群**验证，不是生产发布演练；未执行生产部署或生产 migration；
