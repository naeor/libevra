## 2. 默认账本名按请求语言创建

**问题**：服务器在注册事务里创建第一本账，名字写死 `我的账本`；英文界面注册的新用户会在第一屏看到中文账本名。之后改名只能由用户手动做，属于界面替用户多写一次数据。

**决定**：由**服务器按请求语言**创建默认名，而不是显示层映射（映射会让同一个数据在不同语言下显示不同名字，违反"只翻译界面，不翻译数据"，且约 20 个显示位置都要记得映射）。

**实现**：

| 位置 | 内容 |
|---|---|
| `apps/api/src/ledger/defaultName.ts`（新） | `defaultBookNameFor(acceptLanguage)`：`zh*` → `我的账本`；`en*` → `My Ledger`；缺失/畸形/其它语言 → 中文默认名。请求头只用于在两个常量之间选择，不插值、不落库 |
| `apps/api/src/routes/auth.ts` | 注册事务里建第一本账时传入 `defaultBookNameFor(request.headers["accept-language"])` |
| `apps/api/src/routes/books.ts` | `POST /books` 未填名称时同样按本次请求语言建名（不是按第一本账创建时的语言） |
| `apps/web/src/lib/api.ts` | `buildHeaders()` 对 JSON 请求统一发送 `accept-language: currentLocale()`；**文件下载有意不带**（导出内容必须与界面语言无关，由 `ExportPage.locale.test.ts` 钉住）。离线队列发送时用的是编辑时的界面语言 |

**边界**：账本名创建后是用户数据，切换界面语言**不会**改名（符合国际化规范 §0）。游客账本的「我的本地账本」写在本机数据库、可能随导入成为正式账本名，按数据处理保持中文，未纳入本次改动。

**测试**：`apps/api/test/defaultBookName.test.ts`（解析 6 例、注册英文/无头、新建第二本账）；`apps/web/src/lib/apiHeaders.test.ts`（4 例：请求头随界面语言、指定账本时仍携带、文件下载不携带）。

## 3. 英文文案全量审校

**范围**：`apps/web/src/i18n/resources/en-US/` 25 个模块（约 3,154 条键 × 2 语言）、公告英文（15 篇）、法律页中文为准的说明、日期/货币格式、英文布局规则（规范 §7/§8）。**不含**：数据（账本名、分类名、备注、昵称、OCR/语音原文）、品牌名 Libevra、法律正文英文译本（法律正文仍以中文版本为准）。

**方法（AI 起草审校，不等同于母语审校）**：

1. 逐模块通读英文文案，按"准确性 / 自然度 / 一致性 / 术语 / 长度与挤压 / 语气 / 大小写与标点 / 复数与占位符"九个维度检查；
2. 与中文源文、术语表（规范 §7）、页面上下文（组件使用处）交叉核对，避免望文生义；
3. 记录：**必须改**（错译、误导、事实不符）、**建议改**（不自然/过长）、**保留**（刻意选择，写明理由）；
4. 修改后跑 `node tools/i18n-scan.mjs`、web typecheck 与测试。

**审校结论**：本次 AI 起草审校共改动 **19 个文件、74 处**（“必须改 / 建议改 / 细节调整”三级），完整逐条清单见 [英文审校清单](S16-G-英文审校清单-20261025.md)。分布与要点：

- **术语统一**：Duplicate check → **Duplicate detection**（设置项、错误码、公告）；records → entries；tick → check（美式）；cancelled → canceled；recovery key → recovery credential；“Back to entries”大小写统一。
- **必须改（错译 / 误导 / 事实不符 / 不成句）**：如 `inviteNotice` 原句不通、`dataio.ackHint` 双 "checked" 歧义、`ocr.done.batchPending` 缺名词与单复数错、`errors` 三处 cancelled、公告 1.15.00 导航循环句等。
- **errorMessage 整句**：凡 `{{error}}` / `{{reason}}` 接冒号的一律改句号（10 处），避免渲染成 `"…: That didn’t go through."`。
- **保留并说明**：两处被组件测试明确钉住的文案（`nav.needsAccount` 逗号形式、`offline.questionsTitle` "Your choice needed"）未改；建议的 "Needs your choice" 因与测试断言和原意图冲突暂不采纳。
- **未触碰**：`en-US/account.ts`（当时另一 AI 正在改头像名称），审校意见单列在清单第 4 节（如 "The Hanged" → 中性名、"Sign-up invite code" → "Invite code"），待其改动落地后一并处理。
- **待所有者拍板的系统性项**：Archive vs Retire 双状态、引号外标点风格、Sign-up vs Create account、`(No note)` 与 `(no tags)` 大小写统一等，见清单第 3 节。
