### P2-1 关系并发 500

- **问题**：8 路并发确认同一对“不是同一笔”时，`findUnique → create` 竞态触发唯一约束 P2002，HTTP 500。
- **修复**：`writeRelations()` 改 `createMany({ skipDuplicates: true })`（`INSERT … ON CONFLICT DO NOTHING`）后重读；只有真正插入的请求计 `created`，其余返回幂等 200/重激活。
- **回归**：`notDuplicateRelations.test.ts` 新增 8 并发用例；全部 200/201、无 500、created 总和 1、关系行 1。

### P2-2 导入 commit 强制使用最新核对

- **问题**：预览/重检后修改字段或勾选，不调用 `/recheck` 直接 `/commit`，会用新字段写入但沿用旧检测结果。
- **修复**：
  - 预览增加 `revision`（初始 1，每次 recheck 成功 +1）；
  - commit 必填 `previewRevision`，不匹配返回 409 `preview_revision_mismatch`；
  - commit 逐行比较提交内容与最后一次候选快照（金额/币种/方向/日期/时间/时区/分类/支付方式/备注/标签/勾选），不一致返回 409 `preview_stale`；
  - 同一进程内串行化 recheck/commit，避免 revision 与候选快照在异步窗口被并发改写；
  - 前端 `commitBill` 自动带 `preview.revision`。
- **回归**：4 路并发 commit 同一预览只入账一次；旧 revision 409；修改行未 recheck 409、recheck 后 200。

## 7. 健康检查、验收与回滚

### 7.1 发布后最小验收

1. `/api/v1/health` 版本/数据库正确；`/healthz` 200；
2. 登录、打开账本、列表加载；
3. 手动/导入各一笔（可用测试账本）确认写链路；

6. 生产日志无 500/P2002/迁移错误。

### 7.2 回滚

- **应用回滚**：回退到上一发布 commit `9064909` / 镜像 `1.15.01`，重新 `up -d`；**不自动回滚数据库**。
- **数据库兼容**：第 52 号迁移只新增表/索引/触发器，旧 1.15.01 代码不访问该表，应用回滚后数据库可保持 52。
- **数据库回滚**：仅当迁移导致 schema 异常时，使用发布前 dump 整库恢复；必须所有者批准，且会丢失发布后的新写入。
- **导入契约回滚**：旧前端（未刷新）调用新 commit 会因缺少 `previewRevision` 被拒绝（400），不会静默写入；发布后通知用户刷新，紧急回滚需同时回退前后端。
