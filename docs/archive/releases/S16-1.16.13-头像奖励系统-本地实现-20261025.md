## 2. 时区（规格修订的核心）

- 判定只看**服务端 UTC 时间 + 账户 IANA 时区**，客户端时钟不参与。
- 时区来源：Web 每个请求带 `x-libellum-time-zone`（设备 `Intl` 时区）；服务端校验合法 IANA 值后写 `users.time_zone`，并记录 `user_time_zone_changes`；非法/缺失时回退 UTC（`time_zone_confirmed = false`）。
- 冷却 6 小时：防止频繁切换时区影响纪念日判定；冷却内只记录变化，不改判定时区。
- 已测：北京/洛杉矶/伦敦的当地哲学日；UTC 日期与当地日期跨日；DST 边界；连续多日登录不重复；时区切换不回收已得奖励；两台设备并发只发一次。

## 3. 数据与幂等

新增（第 **57** 号迁移 `20261025130000_avatar_rewards`）：

- `avatar_unlocks`（`UNIQUE(user_id, avatar_id)`，含 source/activity/时间）——「已拥有」的唯一依据，服务端 `createMany(skipDuplicates)` 保证幂等。
- `avatar_reward_events`（`status` pending/confirmed、`confirmed_at`）——「待通知 / 已确认」；发放与创建事件同事务。
- `avatar_make_up_grants`（一次补领的使用记录，`UNIQUE(user_id)`）——把补领机会放成一行，成功才消费。
- `user_time_zone_changes`（时区变化历史）；`users.time_zone`、`users.time_zone_updated_at`、`users.time_zone_confirmed`。

状态映射：**已发放** = `avatar_unlocks` 有行（且事件已建）；**待通知** = 事件 `pending`；**已确认** = 事件 `confirmed`。事件只有 `pending`/`confirmed` 两态，展示与确认分离，客户端不能直接提交「我解锁了」。

## 4. 服务端接口

- `GET /api/v1/avatar-rewards`：返回活动配置、已解锁列表、补领可用性、待通知事件、账户时区；请求时先执行一次机会检查（登录/同步/页面刷新都会跑到）。
- `POST /api/v1/avatar-rewards/:avatarId/make-up`：服务端校验活动可补领、未结束、有历史可补、未拥有、未使用，事务内创建 grant + 解锁 + 事件；并发冲突返回 `make_up_used`（409），失败不消耗机会。
- `POST /api/v1/avatar-rewards/:eventId/confirm`：`pending → confirmed`，幂等（重复确认返回 204，不当作错误）。
- `GET /auth/me`：有未确认事件时附带 `avatarRewardEvents`；`PATCH /auth/profile` 保存 `avatarId` 前校验特典头像已解锁，否则 `avatar_locked`（409）。
- 错误码（已入中英文 i18n）：`avatar_locked` / `avatar_already_owned` / `make_up_used` / `make_up_unavailable`。

## 5. 前端

- `apps/web/src/lib/avatarRewards.ts`：奖励状态查询（30s staleTime、窗口聚焦刷新）、补领请求、事件确认；请求头统一带设备时区。
- `AvatarRewardBanner`：底部导航上方的非模态提示条（头像缩略图 + 「获得新头像 · 降临」+「查看头像收藏」+ 关闭）。一次一条，多款显示数量；约 4 秒自动收起，关闭/点击即确认。**「+」入口卡片展开时立即让位**（`useEntryMenu()` 为真时不显示，菜单关掉后若未确认会重新出现），不拦滚动、不抢焦点、不挡「+」。
- 头像页 `AvatarPickerPage`：经典头像始终可选；特典未解锁显示锁标记、「特典系列 · 未解锁」、解锁条件与禁用保存；已解锁显示解锁日期。全部头像可预览题注。
- `AvatarCreationNoteSheet`：创作注记入口只在有注记的头像（倒悬/降临）出现，手机为底部抽屉、桌面为居中面板；文案在 i18n `account.avatars.notes`（《原神》非官方致敬声明，中英各一份）。
- 中英双语：新增 `rewards` 命名空间（`zh-CN/rewards.ts`、`en-US/rewards.ts`），其余文案并入两边 `account.ts`；`i18n:scan` 0 行。
