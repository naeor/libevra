## 3. 性能测量与调整

Windows 本机 Node v24.20.0，独立合成流水，六币种、多个历史月份/日期；以下为一次运行耗时（毫秒），不是目标硬件承诺。提供方是内存模拟，不含真实网络/SQL 延迟。

| 笔数 | 日期数/提供方调用数 | 冷汇总 | 重复汇总 | 切换目标 | 修订重算 | 末尾工作集热命中 | 缓存上限 |
|---|---|---|---|---|---|---|---|
| 20 | 20 / 20 | 1.42 | 0.27 | 0.89 | 0.67 | 20/20，0.23 ms | 实存 60 |
| 5,000 | 84 / 84 | 132.55 | 58.73 | 104.07 | 126.17 | 5,000/5,000，38.32 ms | 5,000 |
| 50,000 | 84 / 84 | 627.58 | 577.19 | 577.07 | 517.30 | 5,000/5,000，43.61 ms | 5,000 |

首次方案对 50,000 笔也逐笔使用 LRU，冷/热约 1,315/1,361 ms，缓存容量不足导致顺序扫描无收益。最终超容量的汇总直接计算，避免冲掉单笔浏览缓存；未建设物化月份或分类表。性能脚本在测完汇总后才将末尾工作集装入缓存，表中热命中与全表重算是两种场景。汇率只对去重日期抓取；实际数据库查询性能、移动端主线程卡顿和 Worker 分批策略仍需正式接入时测量。

```powershell
pnpm --filter @libellum/shared exec vitest run --config fx.vitest.config.ts

```

启用真实本机 PostgreSQL 专项（连接安全检查拒绝外部地址与非测试库名）：

```powershell
$env:FX_PG_TEST = '1'
# TEST_DATABASE_URL 使用现有本机测试库；也可用 FX_TEST_ENV_FILE 指向本机 .env，绝不打印口令。
pnpm --filter @libellum/shared exec vitest run --config fx.vitest.config.ts
```

未设置开关时三个 PostgreSQL 用例显式跳过；本次交付验证设置了开关并实际执行。工作树依赖复用本机已有包，离线安装缺少 pnpm 元数据后改用本地目录链接，无新增依赖或锁文件改动；Prisma Client 复用同一未改变 schema 的本机生成物。正式接入或新机器环境需按既有流程生成 Client。
