### 5.2 故障注入与恢复（D5）

新增测试覆盖：

1. **目标并发变化**：第一批提交后目标新增账目，下一批检测到 `target_changed`，任务 `paused`；已提交 2 条保留，无回执、不删除 A。
2. **最终 A 删除失败**：第一批导入后修改 A 行 version，最终事务失败；A 仍存活、无 `ledger_imports` 回执；恢复 A version 重试后最终对账通过并软删除 A。
3. **账号停用**：worker 在每批和最终删除前显式检查账号状态；停用后任务 `paused`、0 写入，不因绕过 HTTP 会话检查而继续写。
4. **S13 生命周期**：目标账本归档后 worker 在同一资格检查中 `paused / book_archived`，0 写入，不绕过生命周期。

### 5.3 真实 API kill/restart

在隔离库 `ledger_s14_restart_test` 和独立 API 进程 `3201` 上：

- 通过真实 HTTP 创建正式来源 B（5,000 笔）与目标 A；
- 创建分批任务，`sourceCount=5000 totalBatches=25`；
- 第一个 API 进程在任务 `queued / imported=0 / nextBatch=0` 时被真实 `SIGKILL`；
- 启动第二个 API 进程；
- 恢复扫描继续任务，最终 `completed imported=5000 nextBatch=25`；
- 目标 5000、来源 5000、回执 5000，重复 `sourceRef` 为 0。

### 5.4 生命周期与关键事件边界

- 导入目标/来源的归档、弃置、删除、单人、邀请、分享校验沿用 D4 的 `loadSoloImportBook`，每批和最终删除前复查；合并后没有削弱任何 S13 权限/生命周期判断。
- A 账目的导入软删除写入现有 `TransactionEvent`（与普通 DELETE 相同），**不冒充 P0/Critical Chain 业务事件**；导入不会伪造账本创建/archive/注销等关键事件。
- S13-I 的历史备份恢复可能复活 A 中已被导入流程软删除的交易，这是 S13-I 既有语义边界；本记录不声称该风险已解决。
- D5 来源清理已在阶段三实现，且必须走 S13 生命周期（弃置/恢复/墓碑），不得直接 SQL 删除账本；阶段三 API 测试已验证 archive/restore，不绕过生命周期。
