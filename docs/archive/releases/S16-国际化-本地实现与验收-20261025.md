# S16 国际化（简体中文 / English）· 本地实现与验收

> 最后核对: `claude/s16-i18n` 本地分支 / 2026-10-25。基线 `c74727e`（= 1.16.08 已发布代码 = GitHub `main` = 统一开发基线 `codex/s16-b2-neutral-dark`）。
> **未合并、未 push、未部署、未升版本号、未改数据库结构、未碰生产。** 写法与术语以 [国际化与本地化规范](../../specs/design/国际化与本地化规范.md) 为准，本文只记录这一轮做了什么、怎么验证、还剩什么。

## 0. 结论

- 简体中文与 English 都是正式支持语言：Web 端全部界面文字走 `t()`，`node tools/i18n-scan.mjs` 扫描 **0 处**未翻译中文（有意保留的数据类中文逐行标注 `i18n-ignore` 与原因）。
- 3,154 条文案键 × 2 种语言；268 个服务器错误码、209 条 shared 原文（139 条精确 + 70 条模式）、15 篇公告（12 篇更新公告 + 3 篇重大公告）有英文。
- 语言可在 **设置 → 显示与数据 → 语言 / Language**（游客也能进）与**登录 / 注册 / 找回页右上角**切换；默认参考浏览器语言、不看 IP；切换不刷新页面，保存在本机，刷新 / 重开 PWA 后仍然有效。
- 全部检查通过：`pnpm typecheck`（三个包）、Web 测试 **137 文件 / 1,288 条**、shared 326 条、API 555 条（另 4 条按环境跳过，与本轮无关）、`pnpm check:build`、`check:docs`、`check:status`。
- 真实 React 页面 + 本机开发库虚构数据，6 个视口 × 33 个页面中英文截图：**英文在 320–1200px 全部页面没有横向溢出、没有元素出屏**；伪语言（文字再加长 40%）发现的问题已修。

## 1. 范围

**做了**：国际化基础设施；语言偏好与切换入口；Web 全站界面文字（含弹窗、底部操作板、空状态、加载、错误、Toast、校验、删除确认、`aria-label` / `placeholder` / `title`）；日期 / 时间 / 数字 / 货币名称 / 图表坐标 / 相对时间按语言格式化；服务器错误按错误码翻译；shared 校验与识别提示翻译；更新公告与重大公告英文整篇；英文长度引起的布局适配；测试、扫描工具、伪语言压力测试；文档。

**没做（刻意）**：

| 项 | 原因 |
|---|---|
| 账号级语言同步（`User.language`） | 本轮不改数据库结构；偏好按设备保存，与主题一致（路线图 S16-G-07 / S16-E-03 后续） |
| 法律正文英文版 | 用户同意的是中文原文（内容哈希）；英文译本须专业审核（S16-G-10）。英文界面显示“仅提供中文、中文版本适用、译本审核中” |
| 服务器端文案改造 | API 契约与中文原文一律不动；英文由客户端按错误码 / 原文对照翻译 |
| “识别语言”独立设置 | 识别（OCR / 语音 / 粘贴）仍按中文规则，界面语言不影响识别（S16-G-08 后续） |
| 第三种语言 | 架构已支持：加目录 + 逐键补齐即可（规范 §1） |

## 2. 关键决定（含本轮自行判断的部分）

1. **选型 i18next + react-i18next**（成熟、社区最大、复数走 `Intl.PluralRules`）；文案写成 TS 对象，英文类型为 `Messages<typeof zh>`，缺键 / 多键在 `typecheck` 阶段报错。**新增依赖 2 个**（i18next 26.5.7、react-i18next 17.1.5，及其依赖 html-parse-stringify、use-sync-external-store），通过 pnpm 供应链策略检查。
2. **两种语言都打进主包**（离线优先：不能让“第一次离线切英文”取决于某个 chunk 是否已缓存）。代价：主 JS 从 1,206 KB / gzip 343 KB 增至 1,669 KB / gzip 466 KB（英文文案约 54 KB gzip、公告英文与 shared 对照表、i18next 本体、调用处的键名）。**后续可优化**：英文包按需加载 + 联网空闲时预取（需同时保证离线可用），本轮未做。
3. **`useI18n()` 刻意不是 React hook**：项目不少测试把展示组件当普通函数调用；重新渲染由 `App` 统一订阅（`useLanguageRerender()`），切换时整棵树重渲染，不重新挂载，表单输入、滚动、查询缓存、登录状态、离线队列都保留。
4. **默认语言**：本机第一次运行带语言功能的版本时决定一次并记下——以前用过 Libevra 的设备（本域名已有任何本地记录）记为**简体中文**（老用户更新后不突变）；全新设备记为**跟随系统**（浏览器语言列表中第一个中文或英文；都不是则中文，`locales.ts` 一行可改）。
5. **预置分类 / 支付方式**：数据库没有预置 ID，不改结构也不改数据；名字与预置中文名**完全相同**时英文界面显示英文（`餐饮` → Food & drink、`微信` → WeChat Pay），编辑框、请求、导入导出、匹配一律用原名（`lib/presetNames.ts`）。
6. **账本名一律不翻译**（按任务要求）。因此服务器给新账号自动建的「我的账本」、游客的「我的本地账本」在英文界面仍显示中文——见 §9 待决定。
7. **新建账本时名称留空**：英文界面下默认名写入 “My ledger”（新数据按创建时的语言命名；已有账本绝不改名）。
8. **币种符号按币种固定、不随语言变**（¥ = 人民币、JP¥ = 日元、HK$ = 港币）；分组符 / 小数点取自 `Intl`；中文界面所有格式化输出与以前逐字相同。英文时间用 12 小时制（`7:34 PM`）。
9. **英文校验提示**：服务器 `validation_failed` 时先按 shared 原文对照表给出具体原因（“Passwords must be at least 8 characters”），查不到再给通用说明。
10. **注销 / 删除服务器数据的确认短语**：服务器只认中文短语；英文界面也接受 “Close account” / “Delete server data”（不区分大小写），提交时仍发送中文短语——服务器规则不变。
11. **英文布局适配**（不缩字号、不改颜色 / 品牌 / 动画）：见 §8；全局只加了一条 `body { overflow-wrap: break-word }`（只在“本来就要溢出”时生效）。
12. **开发用伪语言**（`i18n/pseudo.ts`，仅 `import.meta.env.DEV`）：字母加重音、加长 40%、加括号，用于发现漏翻、截断与破版。

## 4. 数据与语言的边界（逐项核对）

| 项 | 结果 |
|---|---|
| 用户分类名、账本名、备注、昵称、用户名、标签、商户、OCR / 语音 / 粘贴原文 | 原样显示（截图中英文界面里的中文备注即用户数据） |

| 离线数据 | 切换只调用 `i18next.changeLanguage`，不触碰 IndexedDB / 队列；持久化的离线诊断日志按写入时的文字显示（见 §9） |
| 导入导出 | 导出由服务器生成、请求不带语言；中英文各导出一次 CSV / XLSX，除每次导出的“导出编号”外逐字节一致 |

## 8. 布局检查报告

**自动检测结果（修复后）**：英文 6 视口 × 33 页：横向溢出 0、出屏元素 0；被裁切文字只剩视觉隐藏的 `sr-only` 图例（设计如此）与用户数据的省略号截断（长账本名，允许）。

| 位置 | 问题 | 处理 |

| 账目编辑分类网格 | 320px 三列里 Entertainment / Uncategorized 词中断开 | 非中文界面按最小 7rem 自动排列（320px 两列，390px 起三列）；中文仍三列 |

## 9. 未解决问题与需要所有者决定

1. **默认账本名**：服务器为新账号建的「我的账本」、游客的「我的本地账本」在英文界面显示中文（按“账本名称保持原样”的要求未翻译）。若希望英文用户看到 “My ledger”，可仿照预置分类做“仅与默认原名完全相同才映射”的显示层处理（约 20 个显示位置），或服务器按语言建默认名（需 API 改动）。
2. **英文措辞审校**：Ledger / Entries / Insights / Shared / Me；弃置 = Retire、归档 = Archive；注销账号 = Close account；收支方向 = type；账本空间 = Your ledgers；协作页“创建者”译为 Owner；ConflictScreen 的“用你的 / 用服务器上的” = Kept yours / Kept the server’s 等（完整清单见规范 §7）。
3. **品牌标语英文**：「记一本账，安静而长久。」→ “One ledger, quietly kept for years.”（应用内仍是旧标语；新官方标语「记账，按你的方式」未在本轮改动，若要替换需另行决定中英文写法）。footer “offline-first bookkeeping app” 用了 bookkeeping 一词。
4. **语音识别只懂普通话**：英文界面说明写了 “Voice entry understands Mandarin Chinese”，请确认是否这样对外说明。
5. **文案事实**：账单导入写着「全部在本机处理，不上传第三方服务」，但文件实际上传到 Libevra 服务器识别；中英文都可能需要改写（本轮按原意翻译，未改中文）。
6. **既有问题（本轮未改，只记录）**：JoinPage 中文里有字面 `**…**`；ConflictScreen 金额一律按人民币显示；账本导入中文里露出内部代号「目标账本 A」。
7. **服务器 / 识别服务原文**：OCR 服务（Python）返回的识别提示、服务器存进数据库的推荐提醒通知正文、离线诊断日志条目，在英文界面仍按写入时的中文显示（推荐提醒在英文下按通知类型给出译文）。
8. **切换语言后的提示句**：保存在组件状态里的一次性提示（筛选提示、批量结果、刷新提示）要到下一次操作才换语言。
