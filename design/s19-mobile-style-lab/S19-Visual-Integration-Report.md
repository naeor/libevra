# S19 视觉风格集成报告（Visual Integration Report）

> 2026-11-07 · 本地开发版本 **1.19.2** · 范围：手机布局（`.lv-shell[data-shell="contents"]`）浅色模式
> 本轮只做视觉层接入；未做 Push / Pop 转场，未上传、未部署、未改数据库。

## 1 接入概览

**原则**：现有 Libevra 决定功能、交互与动画；第五轮 Style Lab 原型（本目录 `lab/`）只作视觉参考。没有用原型里的简化页面替换任何组件。

**做法**：只增加“材质令牌 + 限定作用域的样式 + 一个测试开关”，业务组件一行未改。

| 项 | 内容 |
|---|---|
| 开关 | `apps/web/src/lib/visualStyle.ts`：`original / a / b1 / b2 / c`，写在 `<html data-visual-style>`；Original 不写属性（任何 S19 规则都不会命中）。选择存在本机 `libevra.s19-visual-style`（属于应用前缀，“清除本机全部数据”会一并清掉），跨标签页同步 |
| 入口（仅测试） | ① 设置 → 外观 → 主题 页底部「S19 视觉风格（测试）」；② 页面右侧小把手（独立 React 根，不进应用组件树）；③ 测试链接 `?s19=a` / `b1` / `b2` / `c` / `original` |
| 门控 | 只在开发服务器（`import.meta.env.DEV`）与显式测试构建 `VITE_S19_STYLE_LAB=1 pnpm build`（`vite.config.ts` define `__S19_STYLE_LAB__`）里存在。**正式构建在打包阶段整段删除**：已检查正式产物中没有实验 chunk、样式或相关字符串 |
| 默认 | Original。切换只改 html 属性：不重新登录、不重新初始化、页面 / 滚动 / 筛选保持 |
| 加载 | `main.tsx` 与账本恢复并行加载实验模块，首次渲染前等待（带着已选风格刷新不闪 Original；加载失败不影响启动） |
| 作用域 | 每条规则以 `:root[data-visual-style=…][data-theme-mode="light"] .lv-shell[data-shell="contents"]` 开头；页面背景用 `body:has(.lv-shell[data-shell="contents"])`。Pad（`wide`）、电脑版外壳、深色模式不命中 |

## 3 UI 冲突与处理结果

状态：✅ 已解决 · ⚠️ 未解决 · ◐ 视觉细节未完全还原 · ❓ 需要设计判断

| # | 项目 | 冲突原因 | 处理方式 | 状态 |
|---|---|---|---|---|
| 1 | A/B1/B2 顶部不是主题色色块 | 正式版明细与 Tab 页顶部是 `bg-brand` + 白字，且承担 `--p` / `--header-p` 收起动画 | 只在这些风格里把顶部背景设为透明、`--color-on-brand` 重映射为正文色；顶部内主题色 / 危险色底的元素与头像白圈恢复白色；收起后的承载层用伪元素渐显 | ✅ |
| 2 | 明细摘要卡的大范围柔和投影 | 摘要卡在 `overflow:hidden` 的可收起容器里（收起动画的一部分），大投影会被裁成硬边 | 摘要与次级小卡改用贴身细描边 + 1–2px 近影；不改容器 | ◐ A 的“浮起感”弱于原型 |
| 3 | B1/B2 收起后顶栏的背景模糊 | 本机无 GPU 的 Chromium 中，明细顶部（吸顶、层叠上下文内）的 `backdrop-filter` 透不到下面滚过的列表；伪元素上的模糊同样无效 | 模糊仍加在已吸顶的顶部与吸顶分段上（真机可能生效）；承载层不透明度提高到 0.80–0.90，没有模糊时也压得住文字 | ⚠️ 真机效果未验证；B2“更轻更透”的特征因此减弱 ❓ |
| 4 | Tab 页顶部的玻璃模糊 | 顶部动作区可能直接渲染没有 portal 的弹层，给顶部加 `backdrop-filter` 会把弹层困在顶部里 | Tab 页顶部不加模糊，只用更不透明的奶油 / 透光承载层 | ◐ |
| 5 | 底栏玻璃 | 正式版底栏与内容是并列布局，内容不会滚到底栏下面；改成悬浮覆盖会动布局与滚动留白 | 保留布局；底栏材质画在 `nav::before` 上（不让底栏成为弹层的包含块），只透出页面环境，不做模糊 | ◐ |
| 6 | 中间“＋”的尺寸与位置 | 原型 54px / 上浮 18px；正式版 64px / 上浮 32px，记一笔面板的位置与五卡间距依赖它 | 几何不变，只换材质（A 主题色渐变 + 白圈，B 主题色瓷片，C 纯色 + 白圈） | ❓ 是否统一到原型尺寸 |
| 7 | Bottom Sheet / 对话框的玻璃 | Sheet 与对话框没有 portal，面板上加 `backdrop-filter` 会困住里面再打开的 fixed 弹层 | 面板不做模糊，用更高不透明度的同色材质；B1/B2 遮罩变浅 | ◐ |
| 8 | A 的“电影票”明细行 | 正式版是一个 `ul.rounded-card` 里的行 | 纯 CSS：`ul` 去底去阴影、每个 `li` 成小卡（6px 接缝圆角、首尾外圈 20px、后一张压前一张 0.5px）；待同步 / 冲突 / 已删除行保留原状态底色 | ✅ |
| 9 | 编辑记录（按日分组的 RecordGroup） | 正式版是贴边整宽行，原型是分组卡片 / 票据 | 局部布局变体：列表收进分组卡片，行的左右留白改成卡片内边距；A 为票据。同一组件的其它页面（更新公告等）一致变化 | ✅ |
| 10 | 危险按钮（退出登录、删除这一笔） | 原型把“退出登录”做成浅底红字 | 保留正式版实心危险色（破坏性操作的可辨识度） | ❓ |
| 11 | 输入框 | 原型 A 为浅灰槽、B1 玻璃输入、B2 实心槽 | 四套都保留正式版白底输入框 | ◐ |
| 12 | 深色模式 | 原型深色只有方向稿 | 四套只作用于浅色；深色时自动显示 Original 深色（逐像素一致） | ⚠️ 未做 |
| 13 | Pad / 电脑版 | 用户要求不受影响 | 作用域限定手机外壳；`body:has()` 只在手机外壳存在时绘制背景 | ✅ 逐像素一致 |
| 14 | C「我的」大头像顶部的纸面上沿 | 头像区填满顶部，纸面伪元素会压住头像下沿 | 「我的」顶部不加纸面上沿，其余 Tab 页与明细有 | ◐ |
| 15 | 记一笔表单顶部、空间转场引导页、页面最上方的离线提示条 | 不属于本轮覆盖的结构（各自的主题色区 / 外壳外元素） | 保持 Original，背景环境照常 | ◐ |
| 16 | B2 背景光斑 | 原型用内联 SVG | 用 CSS 渐变按原型坐标近似；高光点降低强度（原值在顶部工具旁像一块污渍） | ◐ |
| 17 | 颜色字面量规则（`colors.test.ts`） | 规则只允许令牌文件写颜色 | 颜色值全部收进 `s19-lab-tokens.css`，在测试 EXEMPT 中登记为与 `index.css` 同类的令牌文件并写明原因；其余实验样式只读变量 | ❓ 请所有者确认这条登记 |
| 18 | 账目详情转场 | 正式版无 push 动画 | 按本轮要求不新增 | — 下一轮 |

## 6 下一阶段建议

1. **先选定方向，再收窄范围**：建议所有者在真机上用右侧把手对比四套（开发环境 `localhost:5173` 或测试构建）。选定后把该套令牌迁进 `index.css` 正式令牌、删除其余三套与 `colors.test.ts` 的临时登记；不建议四套长期并存。
2. **玻璃风格（B1/B2）若入选，需要先做结构准备**：Sheet、对话框、Tab 页顶部弹层统一走 portal（脱离卡片与顶部），之后才能安全地给面板和顶部加真正的背景模糊；同时在真机上确认明细吸顶顶部的模糊（#3）。
3. **待设计判断**：“＋”是否改为原型尺寸（#6）；退出登录是否改浅底红字（#10）；输入框材质（#11）；A 摘要卡是否允许在收起容器外留出投影空间（#2，需动布局）。
4. **深色模式**：选定风格后再按原型方向稿补深色令牌（当前回退 Original 深色）。
