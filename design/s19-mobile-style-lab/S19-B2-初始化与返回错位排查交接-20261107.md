### 已知差异与待证实线索

**转场启用条件是已知差异。** 普通入口没有 `?motion=1` 时，B1 不默认启用该试点控制器；B2 手机主工作区会启用。实际导航动画白名单是“我的 → 设置 → 语言／主题”等设置路径，明细页不在白名单里。必须观察明细页空闲时是否真的有活动 View Transition，不能把控制器存在等同于正在播放转场。

**共享吸顶覆盖存在，但不是完整根因。** `ambient.css` 对 A／B1／B2 都在 `--p=1` 时通过 `top: -100000px` 放开顶部，并将分段控件设为 `position: relative`。这与预期交互有冲突，但不足以解释“A 刷新正常、B2 刷新异常、切回 A 可能残留”。先查为什么同一规则出现不同实际效果，不要开工就删除它来掩盖初始化差异。

**B2 底栏空间与行程计算的组合是待验证假设。** B2 使用负 `margin-bottom` 和额外 `padding-bottom` 扩展到栏后；明细同时将内容 minHeight 设为“scroller.clientHeight + 菜单占位 + 260px”。可能在短列表中改变可滚动总行程，使共用的放开吸顶规则更容易暴露。此前没有在同一组真机状态下量出这个因果关系，更未证明它能解释切回 A／B1 的残留。

`useBottomNavUnderlay` hook 本身未按风格限制挂载，CSS 才限 B2；它会写 `data-b2-scroll-underlay` 与 `--s19-b2-dock-overlap`，清理对 DOM 是否仍连接有条件。需要区分“标记留着但无样式消费者”和“内联高度／进度实际污染另一风格”，不能仅看到标记就判定泄漏。还需检查 `ResizeObserver`、微任务清理、React StrictMode 重订阅及 `detailTransition` 的 minHeight 恢复时序。

**返回涉及不同坐标与滚动模型。** “我的”是 `h-dvh` 框架内滚动，“设置”是随内容增长的文档滚动。`pilot.tsx` 保存／恢复两者，测量捕获前后原点；当前新页 `hybrid-b2-recover` 的 transform 全程为 none，只恢复模糊和透明度。应检查浏览器生成的 group 坐标、捕获边界、真实页面布局及撤层时机，而不是直接继续添加像素补偿。

风格切换时检查控制器的订阅、MutationObserver、`engine.cancel()` 与 `dispose()`，以及 `data-motion-*`、`data-b2-motion-page`、内联 CSS 变量、动画是否回到应有状态。初始化也会设置稳定环境背景；它与临时旧页快照不同。预期转场完成后不保留完整旧页面 DOM 或快照层。

## 5 复现与测量顺序

1. **保护并核对现场。** 跑 agent brief，确认本机目录、版本、服务与未提交文件，不重启或清理现场来获得“正常”。只在本地操作；任何覆盖／清理前按仓库 WIP 规范保护，不能 `reset --hard`、`git clean` 或覆盖整目录。
2. **按第 1 节的切换序列复现。** 使用相同账号、账本、月份、列表长度、屏幕方向和入口。明确区分“风格热切换”“切换后页面刷新”“新标签冷启动”“HMR”。普通刷新仅用于复现矩阵，不作为绕过方案。
3. **优先比较 A 刷新与 B2 刷新后的真实 DOM。** 至少在首次可见、初始化／观察器稳定后、收缩完成、继续向上滚动、切换风格不刷新后取样。增加 C 刷新作为对照。短列表与长列表分别记录，避免滚动上限不同造成误判。
4. **独立采样返回链。** 在“我的”展开与已收缩两种位置各做设置往返；记录导航前、DOM 提交与恢复后、原生 ready、异常帧附近、finished／cancel 后。识别移动的是 DOM、原生伪元素组还是画面内容。降低动画速度只能辅助定位，也应保留正常速度的复现证据。
5. **每次只改变一个诊断变量。** 必要时在隔离测试中比较无转场、仅原生转场、完整 Hybrid，或有／无底栏重叠区；记录对照结果并恢复诊断改动。这不是授权把关闭功能或全局重置当作正式修复。

### 每次采样的必要内容

- 风格／主题／外壳属性、路由与查询参数、版本、入口协议、是否刷新、是否减少动态；B2 预设及账号参数恢复时机。只记录诊断所需值，不输出令牌、账目文字或整份存储。
- 从 `html → body → #root → workspace/pane → 页面根 → 滚动容器 → content → header/分段` 的真实祖先链。祖先可能是 `display: contents`，不要凭 class 名猜测几何盒子。
- 各层 computed styles：`display`、`position`、`top/bottom`、`transform` 与 `transform-origin`、`overflow-x/y`、`filter`、`backdrop-filter`、`contain`、`isolation`、`will-change`、`opacity`、`z-index`、`view-transition-name`，以及 height/min-height、padding/margin。检查 fixed/sticky 的实际定位及滚动祖先。
- 几何与滚动：`getBoundingClientRect()`、`scrollTop`、`scrollHeight`、`clientHeight`、`window.scrollY`，并计算最大滚动量。记录 `--p`、`--detail-scroll-travel`、`--header-p`、`--header-range`、`--s19-b2-dock-overlap` 及 content 内联 minHeight。
- View Transition：`data-motion-direction/hybrid/backdrop`、捕获页面标记、old/new/group 的 transform／尺寸／filter，以及活动动画与取消／回退原因。记录 ready／finished，不用真实 DOM 坐标正常替代最终画面正常。
- 视口：`innerWidth/innerHeight`、`visualViewport` 的尺寸、offset、scale，安全区与动态高度；观察 Safari 工具栏展开／收起、首屏视口变化及 resize 是否触发转场取消。

### Safari 和已有网络线索

先验证应用自己的 DOM 与时序，再考虑 Safari 合成差异。以下是此前查到的原始资料，仅供缩小排查范围，不证明 iOS 27.0.1 命中同一缺陷：

- [W3C View Transition 生命周期](https://drafts.csswg.org/css-view-transitions-1/#intro)：旧页静态捕获与新页实时捕获在独立层播放，结束后移除该层。
- [W3C 快照定位基准](https://drafts.csswg.org/css-view-transitions-1/#snapshot-containing-block-concept)：快照基准与移动浏览器可变视口的关系。
- [WebKit 285400](https://bugs.webkit.org/show_bug.cgi?id=285400)：滚动／内容边距下的快照定位问题，上轮查询工单未关闭；后续需核对适用条件。
- [WebKit 272556](https://bugs.webkit.org/show_bug.cgi?id=272556)：转场结束位置跳动，与阴影造成的绘制溢出有关；这是已修复历史案例，不能当作当前设备根因。
- [WebKit 302256](https://bugs.webkit.org/show_bug.cgi?id=302256)：转场期间背景模糊异常的报告，与稳态布局问题要分开。
