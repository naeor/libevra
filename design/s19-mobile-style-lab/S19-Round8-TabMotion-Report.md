# S19 第八轮 · 顶栏清理、底栏弹性玻璃胶囊两套动效与摘要恢复（简短报告）

> 2026-11-07 · 本地 1.19.4 · 只作用于测试风格（开发环境 / `VITE_S19_STYLE_LAB=1`）；Original、Pad、电脑版、深色模式不变。未做 Push / Pop 转场，未改账目详情、日期月份动画与返回逻辑。

## 怎么在 iPhone 上比较

设置 → 外观 → 主题 页底部「Tab Indicator Motion」，或页面右侧小把手，选择 **V1 — Behind the Plus** / **V2 — Disappear & Reappear**（记在本机，刷新后保持）；也可以直接打开 `…/?s19=b2&s19tab=v2`。两套共用同一个胶囊、同一材质、同一导航，只换动画。

## 1. 取消明细页的收缩顶栏（A / B1 / B2）

- 删掉了第六、七轮的两块承载层：明细顶部收起后渐显的实色 / 玻璃顶栏，以及吸顶时把“全部 / 支出 / 收入”包进去的那条带；相关背景模糊也一并去掉。
- 顶部收起（`--p`：标题淡出、摘要卡滑走）照常。收起后顶部**不再吸顶**，和分段控件一起随列表自然滚出视口；往回滚时自然回来、再展开。原理：顶部上方的滚动行程区在收起距离内随滚动增高，所以收起过程中顶部仍停在原处，超过收起距离后就正常滚走，不需要吸顶。
- 实测（390×844）：滚动 230px 时顶部收成 60px、仍在原处；滚动 420px 时顶部已滚出（top −105）、分段控件也已滚出，期间没有任何背景出现或闪烁。
- 例外：**展开搜索时**顶部（含搜索框）仍吸顶，背后垫一层与环境同色的底，跟随搜索开合 0.16s 淡入淡出，不随滚动出现；取消搜索后恢复上面的行为。
- C 与 Original 保持原规则（主题色顶部吸顶）。分析 / 账本 / 我的这些 Tab 页顶部的承载层本轮未动（不在本次范围）。

## 2. 底栏选中玻璃胶囊（B1 / B2）

- 形状：中间短直边 + 两端半圆；高度与原选中圆片相同（390 宽时 52px），宽度 60px（1.15:1）；中心对准 Tab 按钮中心，图标与文字布局、点按区域不变。原来的选中圆片在 B1 / B2 里透明但保留占位。A、C 不变。
- 材质（由第七轮的玻璃参数推出）：B1 是少量奶油白填充 + 细边高光 + 轻阴影；B2 白色覆盖更弱（顶部 .30 → 中段 .04）、边缘光更清楚。两者底部都有一点主题色余光，选中图标与文字为主题色，与未选中项保持可分辨。
- **没有加背景模糊**：胶囊下面只有底栏自己的玻璃和平滑的页面背景，模糊看不出来；在测试用 Chromium 里，加了模糊反而把胶囊刷成一块偏白的实心片（底栏是层叠上下文，模糊只取到底栏内部）。
- 层级：底栏是层叠上下文，胶囊 z-index 1，Tab 图标与文字原本就是 z-10，“＋”提升到 z-index 2 —— 所以胶囊永远在“＋”与图标之下，不挡“＋”的点按区域（胶囊本身不接收点按）。“＋”的尺寸与位置未变。

## 3. 动画实现

- **Web Animations API**，只动 `transform`、`width`、`opacity`（胶囊是底栏里一个绝对定位的小元素，宽度变化不影响别处布局）；不逐帧改模糊。没有新依赖。
- 不改 `BottomNav`：每个 Tab 页各自渲染底栏，切换页面时底栏整体替换。实验脚本（`apps/web/src/s19/tabIndicator.ts`）用 MutationObserver 在**同一帧、绘制之前**发现新底栏和新的 `aria-current`，把胶囊挪进新底栏并从上一位置动到新位置。导航不经过它：点击后页面立即切换，动画只是跟上。
- 目标位置用真实 Tab 按钮的 DOM 位置测量，不写死屏宽或间距；窗口 / Safari 地址栏变化时重新测量。
- 形变：运动方向的前缘先走、后缘滞后（拉伸量的 70% 分给前缘），最多拉长到 1.28 倍；到点后越过 2–3.5px，回弹一次。从右往左时镜像。
- 打断：新的切换会取消旧动画，从胶囊**当前所在位置**接着走，不排队；快速连按“分析 → 账本”最终停在账本。
- 减少动态效果：不移动，只在目标位置 120ms 淡入。

| 切换 | 是否跨“＋” | V1 Behind the Plus | V2 Disappear & Reappear |
|---|---|---|---|
| 明细 ↔ 分析、账本 ↔ 我的 | 否 | 方向性拉伸平移 190ms | 同左 |
| 分析 ↔ 账本 | 是 | 连续移动，从“＋”后方穿过，210ms | 原位朝目标方向拉伸后收窄消失（120ms）；目标处从来时一侧 12px、0.6 倍宽出现，伸展、越过一点再回弹（170ms，延迟 60ms，两段只重叠约 60ms），共 230ms |
| 明细 ↔ 我的、明细 ↔ 账本、分析 ↔ 我的 | 是 | 同上，距离更长，约 270ms | 同上，230ms |
| 再次点按当前 Tab | — | 原地轻收再回（0.92 → 1.04 → 1，180ms） | 同左 |
| 点“＋” | — | 胶囊不动，当前 Tab 不变 | 同左 |

逐帧抽查（暂停在 25% / 50% / 75%，390 宽）：明细 → 分析 25% 时前缘已走 35px、后缘 23px，宽 72px；75% 时中心越过目标 3px；分析 → 账本（V1）25% 时胶囊在“＋”后方，被“＋”遮住一部分；V2 同一切换 25% 时只剩原位的拉伸胶囊（不透明度 .84），50% 时目标处胶囊已出现（.98）、原位残影 .18，75% 时只剩目标处。六种切换在两套里最终都与选中 Tab 中心重合。

## 4. 摘要卡顺序与编辑器

- 恢复原结构：上方收支概览大卡（月份、支出、收入、币种），下方结余与日均支出两张小卡；保留第七轮的紧凑高度（顶部 306px，原 388px）。
- 第七轮的“结余优先”只是 CSS 视觉换位，**从未写入卡片配置**：默认布局（主卡收支概览 / 第一张结余 / 第二张日均支出）、用户已保存的自定义布局、拖拽与保存、旧数据兼容都没有被改动过，也无需迁移。现在明细展示顺序与“编辑展示卡片”的预览（大卡 → 左小卡 → 右小卡）再次一致，已截图核对。

## 5. Safari 与兼容性风险

- 胶囊是插入到 React 管理的底栏里的外部节点；React 不会删除它，底栏卸载时一起移除。已在页面切换、热切换风格、搜索、记一笔面板开合中验证，但仍属于测试用的接法，正式采用时应改为 `BottomNav` 内部渲染。
- 胶囊不加模糊，因此不受 Safari / Chromium 背景模糊差异影响；层级只依赖底栏这一层叠上下文，不涉及裁切。
- 收起顶栏取消后，明细页已无滚动触发的模糊层；只剩搜索时的静态底和 Tab 页顶部原有的承载层。

## 补充（1.19.05）：惯性滑动时顶部抖动

- 现象（所有者录屏）：A / B 明细页松手惯性滑动时，顶部标题、四个按钮与摘要卡上下抖 2–3pt，手指按住时正常。
- 原因：本轮第 1 节把 A / B 顶部改成普通定位后，它在收起过程中“停在原处”完全依赖主线程及时加高上方的行程区。Safari 惯性滚动在合成线程上进行，慢速时 scroll 事件一两百毫秒才来一次；两次事件之间顶部先随内容上移，下一次事件再被推回。
- 修复：收起过程中顶部仍用 `sticky` 交给合成线程钉住，只在完全收起后放开（顶部随列表滚走的效果不变）；另加 `bottom` 限制，往回滑时也不会被滞后的行程区往下带。C 也加了这条（它的收起方向原本就钉住）。Original 未改，它在展开方向的惯性下仍有同样的下坠。
- 验证：人为让行程区滞后 50px：修复前 A / B 偏移 −50 / +50px，修复后 A / B / C 均为 0。
- 录屏里还能看到：标题 “Libevra” 半透明淡出时，后面偶尔出现一块边缘清楚的浅色矩形（从屏幕左缘到标题右侧）。本机浏览器无法复现，像是 Safari 为淡出中的标题单独建层时的绘制问题；请复测时留意它是否还在。
- 所有者倾向 V1 Behind the Plus（已是默认）；V2 暂保留在测试入口，确认后移除。

## 补充（1.19.06）：摘要卡退场与“矩形”

- 所有者反馈：小卡上滑时出现边缘清楚、遮住下方和左侧的矩形；抖动减轻，变成“快速抖几下就到了”。要求整段动画无元素碰撞、流畅完成，可以改小卡的退场方式。
- 原因：原版退场有三个各自独立的时钟——主卡左滑 + 淡出、主卡容器硬裁切收高（0–40%）；小卡左滑 + 淡出、小卡容器硬裁切收高（30–80%）；顶部高度线性收起（0–100%）。实色卡片在透明顶区上，于是能看到被切成半截的白色矩形、左滑露出的切边，以及小卡与分段控件之间时大时小的空档（A 在 40% 处约 37px）。C 在主题色上同样有，只是较淡。
- 新的退场（`shared.css` 末尾，四套测试风格共用；各风格的版式数字在 `compact.css`（A/B：114 / 38）与 `classic.css`（C：144 / 64））：
  1. 摘要区高度 = 顶部此刻的高度 − 其余部分此刻的高度 → 下沿始终紧贴分段控件；
  2. 主卡与小卡作为整体随下沿上移（`translateY`），不再横向滑出、不再各自收高，小卡与主卡间距不变；
  3. 摘要区上沿裁切，配最多 32px 的渐隐遮罩；静止时渐隐宽度为 0。卡片是“滑进月份行下方、逐渐消失”，与月份、标题、四个按钮之间始终隔着至少 12px。
  顶部高度曲线、`--p`、DetailPage 的测量、吸顶与放开都没有改。
- 惯性抖动：Safari 惯性滚动在合成线程上进行，钉住的顶部内部（卡片、月份）只能随主线程事件更新，所以仍会有轻微的台阶感；新退场里卡片与列表同向、接近同速，比横向滑出时轻。顶部本身的位置在 50px 滞后模拟下仍为 0 偏移。若真机上仍明显，下一步只能考虑把摘要卡从顶部里移到可滚动内容中（需要改页面结构，不再是纯视觉层）。
- 抖动的原理、残余来源与以后可选的改法整理在 [惯性抖动原理备忘](S19-Inertia-Jitter-Notes.md)（暂停，待与所有者讨论）。
- 上一轮提到的“标题淡出时背后的浅色矩形”与本条可能不是同一个现象；新退场去掉了主卡的半透明 + 左滑 + 裁切组合，如果标题后面仍出现矩形，请录屏告诉我。
