# S19 第七轮 · 明细顶部紧凑化与玻璃材质局部修正（简短报告）

> 2026-11-07 · 本地 1.19.3 · 只作用于测试风格（开发环境 / `VITE_S19_STYLE_LAB=1`）；Original 默认外观、Pad、电脑版、深色模式不变。未做 Push / Pop 转场。

## 已解决

**明细顶部高度（390 宽）**

| | Original / C | A / B1 / B2（改前） | A / B1 / B2（改后） |
|---|---|---|---|
| 顶部整体（静止） | 388px | 388px | **306px（−82px，约 −21%）** |
| 标题、月份、间距合计 | 160 | 160 | 124 |
| 主摘要卡（月份 · 币种 / 支出 · 收入） | 136 | 136 | 100 |
| 次级小卡 | 92 | 92 | 82 |
| 最后一张卡 → 分段控件 | 44 | 44 | 22 |

- 去掉的是留白：顶部上下留白、月份行与摘要的间距、卡片内边距、币种行多出的一截、分段控件上方的空档。金额字号未缩小（主摘要仍 24px）；币种按钮仍是 32px 高的点按区域，只是与卡片内边距重叠。
- **结余优先**（所有者补充意见）：两张小卡移到上面，第一张（默认“结余”）是整块摘要里最大的数字（26px 粗体），“按 N 天计算”缩为 11px 紧贴数字下方。只改视觉顺序，DOM、读屏顺序、“编辑展示卡片”配置都不变。
- 收起动画：`--p` 的取值、顶部收起后的 60px、分段吸顶位置（距顶 109px）四套与原版一致；中间帧（滚动 60 / 150 / 230px）截图连贯。实现方式是让 DetailPage 的高度测量可以读取三个 CSS 变量（`--hero-chrome`、`--card-floor`、`--secondary-floor`），没设置时取原值 160 / 128 / 74，所以 Original 截图与改动前**逐字节一致**。在页面上直接切换风格（Original → A → C → B2）每次都重新测量为 388 / 306 / 388 / 306。
- C 按要求没有跟随压缩；摘要与分段之间在 C 里原本就有纸面过渡，未改。

## 材质修改（B1 / B2）

玻璃操作层改由五个参数统一推出（`s19-lab-tokens.css`，写在 `<html>` 上即可整体覆盖，为以后“柔和 / 标准 / 清透”预设预留）：

| 参数 | B1 | B2 |
|---|---|---|
| 覆盖色 `--s19-glass-rgb` | 253 251 246（奶油白） | 250 251 249 |
| 乳白强度 `--s19-glass-milk` | 1 | 1 |
| 背景模糊 `--s19-glass-blur` | 16px（原 24） | 14px（原 20） |
| 边缘高光 `--s19-glass-rim` / 阴影 `--s19-glass-shadow` | 1 / 1 | 1 / 1 |

| 部件 | B1：改前 → 改后 | B2：改前 → 改后 |
|---|---|---|
| 顶部工具钮 | 奶油 .57→.50 实感 → 顶部白 .48、中段奶油 .20、底部 .30，加 0.6 倍模糊 | .50→.40 → .38 / .10 / .20，加模糊 |
| 收起的搜索按钮底 | .55 → .30 | .46 → .20 |
| 展开的搜索框 | 白色实底 → 奶油 .74 + 模糊 | 白色实底 → .64 + 模糊 |
| 收起后的顶栏 / 吸顶分段 | .90 / .84 → **.78 / .68** | .88 / .80 → **.66 / .54** |
| Tab 页顶栏（不能加模糊） | .93 / .87 → .86 / .80 | .90 / .82 → .80 / .72 |
| 底栏 | .69 / .62 / .78 → .66 / .58 / .74 | 不变 |

默认展开状态仍然没有顶栏，承载层只在收起时随 `--p` 渐显，没有新增横向分界线。文字与图标颜色不随这些参数变化。

## 未解决

1. **背景模糊是否真的生效（最重要）**：在本机无头 Chromium（无 GPU）里，小尺寸测试元素在 10px 模糊时正常，16–24px 不出效果；明细顶部吸顶后即使降到 12px 也没有模糊，而计算样式与能正常模糊的测试元素完全相同，根因没有找到。**iPhone Safari 上未验证**。如果真机同样不模糊，收起后顶栏下面滚过的文字会以 B1 约 22–32%、B2 约 34–46% 的浓度透出来，此时需要把顶栏乳白强度调回去一些（只改 `--s19-glass-milk`）。
2. **背景本身平坦处透不出东西**：B1 中下部、B2 光斑之间背景几乎是单色，降低白色覆盖后只是“变淡”，看不出玻璃；没有为此加大模糊。
3. **Safari 状态栏 / 安全区**：A / B 的顶部是透明的，Safari 状态栏区域会取到页面背景色，展开和收起两种状态下的观感需要真机看。
4. **Original 的空状态**同样被推到列表区外（390×664 时按钮在 635–675），本轮按“只改测试风格”没有动；C 在出现一次性提示条时仍差约 20px。
5. **极窄屏（< 360px）**：为避免金额折行，结余与收支金额各降一档（22px / 20px）；320×568 下静止时列表几乎看不到，需要滚动。
6. 结余优先依赖“第一张小卡”这个位置：用户若把第一张改成别的指标，被放大的就是那个指标；视觉顺序与读屏顺序不同。
7. 分析、账本、我的等 Tab 页顶部本轮没有紧凑化。

## 回归验证（隔离环境：本地数据库 + 真实 API + 测试构建，无头 Chromium；**不是 iPhone Safari 真机**）

- Original 明细截图与改动前逐字节一致；C 与第六轮逐字节一致；Pad 1024×1366、电脑版 1440×900、深色模式下 Original 与 B2 逐像素一致。
- 收起动画中间帧与吸顶几何正确；搜索展开、排序面板、账目详情进入与返回、底栏记一笔面板、四风格热切换（页面与滚动保持，重新测量正确）均正常。
- 截图尺寸：390×844、390×664、375×548、320×568、430×932；正常数据与空账号两种状态。
- web typecheck、`check:build`、i18n 扫描通过；Web 全量 2415 项中 2 项失败来自工作区未提交的 `SourceEntries.tsx`，与本轮无关；正式构建产物中仍无实验代码。
- 未验证：iPhone Safari 真机（模糊、状态栏、地址栏收放、触控手感）、较大系统字体、减少动态。

## 后续建议（未执行）

1. 先在 iPhone 上确认 B1 / B2 顶栏是否真的模糊，再决定 `--s19-glass-milk` 的默认值；之后可以基于它做“柔和 / 标准 / 清透”三档。
2. 若采用结余优先，正式做法是在“编辑展示卡片”里提供“结余为主卡”的选项（需要改配置与组件），并决定 C 是否跟进。
3. 经确认后把空状态横向卡片移植到 Original（同一处，不涉及业务）。
4. 分析、账本、我的的顶部做同样的留白收紧。
5. 若决定长期使用玻璃顶栏，可以考虑把承载层做成独立元素（需要改组件），绕开这次在 Chromium 里看到的模糊问题。
