研究结论与所有者决定已记录于 [增量缓存研究与真机结论](reports/incremental-cache-20261107.md)：包含 0.4.1 三档不透明度的重复测试数据、局限与最终选型依据。该报告是本轮收尾结论的唯一出处；Lab 保留供查阅。

本轮使用 [Quick Benchmark](quick.html)：同一局域网手机打开 `http://电脑局域网地址:5191/quick.html`。固定最多 18 个案例：四算法 80 笔初筛；Native / Viewport Tiled 在 45%、72%、90% 乳白覆盖不透明度下各重复两次；最后两案例比较 240 笔。透明度仅改变覆盖层，模糊半径与代理精度不变。顺序轮换，汇总按透明度、数据量、阶段独立分组。自动滚动改为连续移动及反向；仍非真实触摸。

0.3.1 修复自动测试缺少子步骤进度的问题：每轮展示 9 个阶段及当前阶段实际耗时；模糊迭代按时间预算批量消费，减少细粒度 Promise 开销。单次画面构建超过 60 秒会取消并中断测试，失败记录随 JSON 导出，未完成轮次不计入性能比较。此超时是实验保护上限，不是性能合格标准；整套测试耗时取决于设备，不保证几分钟内完成。

独立的 LMPP / SSPR 算法实验。仅使用固定种子生成的账目，不加载正式产品组件、账号、API 或财务数据库。依赖浏览器 Canvas 2D、CSS 和 Performance API；监控库为本地固定版本 web-vitals 5.1.0，许可证在 vendor/LICENSE。

## 打开与使用

在仓库根目录运行：

```powershell
node experiments/material-lab/serve.mjs
```

电脑诊断页：http://localhost:5191 。**手机测试入口：http://localhost:5191/mobile.html**；手机将 localhost 替换为电脑的局域网 IP（启动终端会列出候选地址）。两台设备需在同一局域网；若防火墙未放行，需在本机允许该服务的局域网访问。服务器提供静态实验页及模拟测试报告接收，不提供正式产品业务接口。它与正式开发地址 5173 独立。

手机页面点击「开始手机性能测试」即可运行，不依赖 DevTools。默认 80 / 240 笔 × 四算法 × 冷 / 热 × 三次，共 48 轮，约数分钟；可停止并保留完整轮次。之后点击「开始手动体验测试」，上下甩动账目、拖动面板、切换算法、输入或连续点击，点击停止保存这次会话。使用「保存 JSON 报告」下载；支持 Web Share 文件分享时也可选择「存储到文件」。HTTP 局域网不保证 Web Share 可用，下载不依赖它。浏览器报告来自运行设备，桌面模拟不能冒充 iPhone。

桌面原诊断页保留同步算法调用，用于画质对照和复现 v0.2 方法；**分批调度、自适应保护和新增负载位于 mobile.html**，手机应使用此入口。正式 Libevra 页面未接入。

左栏切换四种算法、字形精度、模糊、材质、主题和模拟数据。中间场景可滚动；浮层及底部导航共享相同的材质参数。下方三个诊断画布分别显示真实背景、代理及模糊结果。移动面板时按场景坐标重新采样；边缘位移场以尺寸与强度缓存。原生 CSS 方案不支持自定义位移，公平测试时统一关闭。

页面底部运行 Benchmark，选择正常、窄屏或长列表场景及重复次数。测试时请保持页面前台、不调整视口或操作页面；可点击停止保留已完成的轮次。导出 JSON 含原始帧采样、环境、事件、各操作与分阶段耗时；CSV 是每轮摘要。数据仅下载到本机。

## 四条实现路径

| 路径 | 输入与缓存 | 成本与画质边界 |
|---|---|---|
| A 原生 | 高精度场景画布作为真实背景，CSS backdrop-filter | 浏览器决定模糊和合成，无法独立获得 GPU 耗时；不以脚本耗时零代表无成本。 |
| B 预计算 | 同一高精度背景降采样，完整三重盒式模糊；结果缓存 | 静态内容滚动可直接采样；修改内容需生成新结果。不是精确高斯模糊。 |
| C SSPR 统一 | 字形灰度网格、彩色形状代理，拼接连续低分辨率场景后统一模糊 | 全量代理拼接有成本；1×1 丢失字形空间信息，需人工比较。 |
| D SSPR 分块 | 逐笔代理 LRU 缓存，128 像素高条带，Halo 模糊结果缓存 | 依数据、布局、主题、精度、算法版本失效；改排序复用代理，区块内容会重新核对。 |

中文字形由实际 system-ui 字体栅格的 alpha 覆盖率生成 1×1、2×2、3×3 网格。英文也按字符生成，以真实累计文本测量校正宽度。图标保留颜色和形状；文字按固定行布局截断，不假装支持正式产品全部排版。

统一与分块共用三次可分离盒式核，单次半径 r，有限支持范围为 3r，所以 Halo 使用 3r。边缘裁剪遵守同一钳位规则。页面提供像素差检查；这只证明两种自定义模糊路径的一致性，不证明与原生模糊等价。

## 测量口径

- **算法**：performance.now 实测代理生成、CPU 像素模糊、Canvas 材质采样／提交时间。完整高精度参照背景的重建时间单独保存在 referenceMs。所有算法都重建同一参照背景；D 目前只增量优化代理与模糊，没有增量优化参照画布。
- **帧调度**：rAF 间隔及 P50/P95/P99、FPS 估计。长帧阈值为 50ms；目标刷新率由用户填写，不能当作显示器硬件检测。后台样本排除，历史采样有容量上限。
- **真实输入响应**：Event Timing 拆分 Input Delay、Processing Duration、Presentation Delay；最小观察阈值 16ms，duration 有 8ms 量化。无样本不等于零延迟。web-vitals 的 INP 是整个页面生命周期的暂定值，不能按算法归因，也不由脚本合成交互产生。
- **Lab 操作**：分别记录首次双 rAF 绘制机会、完整异步操作／动画完成、完成后的绘制机会。双 rAF 是近似观察点，不保证真实屏幕已经呈现，不命名为 INP。滚动、动画的完整时长与输入反馈时长分开。
- **内存**：缓存统计来自真实条目及载荷尺寸。RGBA 画布按宽×高×4 估计，不含对象、纹理副本与驱动开销；不是实际显存。JS Heap 仅在 performance.memory 可用时展示，不等于整个页面内存。
- **硬件**：GPU 利用率、真实显存、功耗、温度均不支持直接读取。Chrome Performance / Memory、Safari Timelines 可辅助调查，不能由 FPS 推算这些指标。

## v0.3 方法审查与修正

1. v0.2 Uniform 在查完整模糊缓存之前先拼接了全部代理，热缓存仍有 560 / 1680 次代理更新。v0.3 将结果缓存查询前置；完全相同内容命中时不再生成代理、不重新模糊。新内容依然需要重建 Uniform，未将它变成另一套 Tiled 算法。
2. v0.2 的「超预算」曾实际按预算的 1.5 倍计数；已改为严格超过指定预算。手机报告同时包含预算值和来源，可选择实测空闲 rAF 中位间隔或手动对照值。约 239 次/秒只是 Headless 环境的回调节奏，不是屏幕呈现 FPS。
3. 帧样本同时保存开始与结束时间；测试窗口不再纳入跨越窗口起点的帧，页面隐藏时重置采样起点，避免恢复后的巨大间隔污染统计。
4. 手机热缓存测试先构建初始场景，然后修改**新内容**，不重放已经缓存过的完整修改序列。因此不可将 v0.3 热缓存结果直接横比 v0.2 的最佳复用成绩。冷缓存只清应用缓存，执行路径仍经过预热。
5. 自动程序操作的 Event Timing / INP 结果固定为 null，并说明原因。手动会话按事件发生时间截取 Event Timing（interactionId > 0）；可能包含一次交互的多个事件，数量不是交互次数。web-vitals INP 仍是**页面生命周期暂定值**，单独标注，不能归因于某个算法或某段自动负载。不支持的浏览器显示不支持，而不是零。
6. 异步更新的首次双 rAF 可能发生在数据处理完成之前；因此另存完整操作完成时间及完成后的绘制机会。二者都不是精确屏幕呈现时间。rAF P95 可能遗漏少量极慢帧，需结合 P99、长帧数和逐阶段样本判断。
7. 总缓存命中率会被大量重复字形查询拉高，不等于整张纹理或整页免计算的比例。v0.3 另导出 glyphs / rows / tiles / surfaces / maps 分层计数。严格超预算比例也可能被约 0.1ms 的调度和计时波动拉高，不能直接等同于肉眼掉帧率。

## 手机模式与保护机制

- 保留浏览器实际 DPR、布局视口、visualViewport、触摸点和 UA。高精度背景最多约 400 万像素、边长 16384；代理最多约 100 万像素。分别导出实际 DPR、有效背景 DPR、请求和有效代理比例。预算可能降低画布精度，不能声称所有大场景都按设备原生 DPR 渲染。
- 后台背景与代理按行构建，模糊沿用相同三重盒式核，通过生成器按线段让出执行；不需要 Worker、OffscreenCanvas、HTTPS 或后端。默认每批 3ms，可调 1–8ms。记录实际 CPU 时间、让出次数、最大批次时间与不可抢占单元超额次数。Canvas、内存分配和浏览器内部绘制不是可抢占指令，预算是调度目标，不是绝对硬实时保证。
- 滚动、输入或拖动期间延后后台工作；新任务取消旧任务；后台页面取消当前构建与自动轮次并关闭滤镜。尚未完成的自动轮次不混入统计。
- 一秒窗口持续高帧时间或输入延迟时，先降低代理比例，压力持续则改用不透明材质。静态级别真正设置 `backdrop-filter: none`、停止纹理采样与模糊、释放应用缓存和材质画布；账目文字、金额、按钮和导航仍保留。深色主题使用深色静态面层。
- 默认实验阈值为帧 P95 >40ms 或输入 >120ms，连续两个窗口升级；稳定 12 秒后逐级尝试恢复。所有阈值可查看和调整，**未验证为生产默认值**。原生路径没有代理精度可降，第一级不会伪称已减少原生滤镜成本；持续压力进入静态级别才关闭滤镜。
- 手机自动负载增加快速反向滚动、面板拖动、连续运行稳定性。交替算法和缓存顺序、轮换长短场景；仍无法完全排除设备升温，环境与执行顺序留在报告中。降级轮次明确计数，不能与未降级轮次当成同画质比较。
- 提供显式静态降级演示；演示事件标记为人工演示，不算真实压力证据。接缝按钮对 20 笔同源代理比较 Uniform / Tiled，可搭配 2、3、4、6、8、12 半径及三种字形精度检查；它不证明与原生高斯模糊或真实字体细节等价。

Benchmark 在同样种子、数据量、布局与参数下执行预热、加载、600ms 滚动、单笔更新、五笔连续更新和两次 180ms 浮层动画。轮换算法顺序；cold 清除应用缓存，warm 先执行同一工作负载再测。此处不是浏览器、字体或驱动的真正冷启动。图表与诊断画布刷新暂停，但仍有 rAF、Observer、计时及运行器开销；没有宣称无监控负担。

参考画布 DPR 上限 2，并按 1200 万像素与 30000 像素边长预算降低；实际比例随环境导出。小屏可用工作区窄于请求尺寸时按实际宽度渲染，并同时导出 requestedWidth 与 width。长列表成本和画质须结合这些值判断。

## 本机检查与初步结论

2026-11-07：固定数据、分位数、LRU、多个半径的 Halo 等价性、脏区范围共 5 项单元测试通过；浏览器单笔修改只重建 1 个代理，三种字形精度的统一／分块 RGBA 差均为 0；390px 页面未出现横向溢出。正常、窄屏、长列表三个场景，各完成四算法×冷／热×2 次，合计 48 轮；JSON / CSV 内容检查通过。

通过浏览器真实输入事件管线验证 Event Timing 与 web-vitals：一次切换算法捕获了 144ms 的事件响应及 INP 更新，包含 Input / Processing / Presentation 分解。此单次观测只用于确认采集功能有效，不是稳定性能结论。

v0.2 首轮自动化浏览器观测中，D 冷缓存代理重建为 86 次（80 笔初始＋6 笔修改），C 为 560 次；D 热缓存可复用本轮全部代理与模糊区块。这证明增量缓存路径生效，不能单凭次数认定整体性能更优。完整操作时间仍含参照画布重建和浏览器调度；v0.3 已修复上述 Uniform 重复工作，旧数字不代表新实现。

此环境的 rAF 间隔约 4ms，属于自动化浏览器观测，不可外推手机刷新率、GPU 或功耗。未在 iOS Safari / 真机上获得可靠对照证据，暂不足以支持接入正式 UI。当前没有哪条路径被认定全面优于原生。

尚未完成的研究包括：真实 DOM 场景映射、正式产品级布局与字体变化、真实设备画质盲测、Safari 跨版本验证、浏览器渲染轨迹与功耗测量。未引入持久缓存、Worker、服务端图像存储；这些不是当前实验的先决条件。

## v0.3 验证范围

v0.3 本机功能检查：10 项纯函数 / 调度测试通过；DPR 3 的 390px 浏览器模拟完成四算法 × 两场景 × 冷热 × 两次，共 32 轮，自动结果未混入 INP；精确内容命中时 Uniform 代理更新与模糊时间均为零。浏览器输入管线验证了触摸点击和拖动记录、过期构建取消、CPU 节流下实测压力触发保护、深色不透明回退后材质计算停止、旋转中止、JSON 保存。320px HTTP 局域网访问、API 缺失回退、模拟隐藏事件中止检查通过；半径 2 / 3 / 4 / 6 / 8 / 12 的 Halo 对照最大差为零。这些是桌面浏览器功能验证，**尚未替代真实 iPhone Safari / Android Chrome 验收**；真实甩动、系统键盘、安全区域、Safari 文件保存和后台切换仍需手机实测。
