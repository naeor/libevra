# 输入能力、悬停与指针

> 上位：[SKILL.md](../SKILL.md) 规则 1、2。依据见 [sources.md](sources.md)。

## 1. 判断输入能力（P-06；统一方案属 T-02【待技术验证】）

**输入能力与窗口大小分开判断。** 宽窗口可能只有触摸（平板横屏），窄窗口可能接着鼠标（缩小的桌面浏览器窗口）。

| 手段 | 含义 | 用在哪里 |
|---|---|---|
| `@media (hover: hover) and (pointer: fine)` | **主要**指针能精确悬停 | 只在有悬停时才出现的视觉增强（项目先例：`statsWorkbench.css` 的轮播箭头） |
| `@media (any-pointer: coarse)` | **任一**指针是粗指针（有触屏） | 保留 44px 触控命中区（`.touch-target`），不因为「宽屏」就缩小 |
| `@media (any-hover: hover)` | 至少一个输入能悬停 | 判断「悬停增强能否被用到」，不能当作「所有用户都能悬停」 |
| `PointerEvent.pointerType` | 本次事件来自 `mouse` / `pen` / `touch` | 区分**这一次**手势（如鼠标拖动阈值与触摸长按） |

易错点：

- 接触控板的 iPad 常报告 `pointer: coarse` + `hover: none`；触屏笔记本常报告 `pointer: fine` + `hover: hover` 但同时有触摸。**两条路径都必须能用。**
- 能力会在运行中变化（接 / 拔键盘鼠标、平板切换模式）。用 `matchMedia(...).addEventListener("change", ...)` 跟随，不要只在启动时读一次。
- **禁止**：`window.innerWidth > N` 推断「有鼠标」；用 User-Agent 判断设备型号（S18-B §3.7）；建全局 `isDesktop` 开关来切换交互逻辑。
- Tailwind v4 的 `hover:` 变体只在 `@media (hover: hover)` 下生效（做实现前用本仓库版本核实一次）；**手写在 `.css` 文件里的 `:hover` 不受保护**，需要自己包进媒体查询，否则触屏上会「粘住」悬停态。
- 在 T-02 结论出来前，优先用 CSS 媒体查询；需要 JS 时只读事件上的 `pointerType`，不建新的全局检测模块（建模块属于工程准备项，应单独提出）。

## 2. 交互状态体系【规范默认】

每个可交互元素都要把下表状态想清楚；缺状态是电脑端最常见的「手机味」。

| 状态 | 何时出现 | 规则 | 项目现有写法 |
|---|---|---|---|
| 常态 rest | — | 一眼能看出可交互（不能只靠悬停才知道能点） | — |
| 悬停 hover | 鼠标进入 | 100ms 内出现；**比常态对比度更高**；不改变尺寸与位置（不推挤邻居） | 次级按钮 `hover:bg-brand/20`；绿色文字操作 `text-brand` → 悬停加深到 `text-brand-dark`；品牌填充按钮用自身亮度变化 |
| 按下 active | 鼠标按住 | 比悬停再进一步，给「已接收」的确认 | — |
| 键盘焦点 focus-visible | Tab / 方向键到达 | 只在键盘导航时出现，鼠标点击不出焦点环；不被固定栏遮挡 | `focus-visible:ring-4 focus-visible:ring-focus-ring`（输入框为 `focus:`） |
| 选中 selected | 被选中 | **与焦点外观不同**（焦点 = 正在操作哪个，选中 = 哪些会被操作） | 批量模式 `aria-pressed` |
| 禁用 disabled | 不可用 | 保持可见；需要让人发现的禁用项（菜单项、工具栏）用 `aria-disabled` 保持可聚焦并说明原因 | `disabled:opacity-45 disabled:cursor-not-allowed`（有意不设 token） |
| 加载 / 拖放目标 | 进行中 / 拖动经过 | 加载保持原标签加指示；拖放目标高亮并显示落点 | 见 [selection-and-dnd.md](selection-and-dnd.md) |

细则：

- **不新增颜色 token**。如果现有 token 在某个主题下悬停不可感知（如 `brand-soft` 对 `surface` 对比过低的旧问题），先报告，按颜色规范流程处理。
- 浅色 `focus-ring` 相对画布约 1.08:1、未达 3:1，是颜色规范里**已登记的待决策债务**；不要私自改值，但电脑端交付时在汇报里提一句「键盘焦点在浅色主题下不明显」。
- 静态文字、纯展示的卡片**不给**悬停反馈；同一个点击目标的各部分要同时高亮。
- **没有死区**：看起来能点的整块都要能点（项目先例：`OcrOverview` 整卡点击用唯一按钮 `after:absolute after:inset-0`）。
- 列表行悬停用整行浅底高亮，帮助横向对行；**不要缩放、位移或加阴影抬起列表行**（会让相邻行抖动）。
- 悬停过渡只动 `color` / `background-color` / `border-color` / `opacity` / `box-shadow`，≤150ms，禁止 `transition: all`；`prefers-reduced-motion` 下直接切换。

## 3. 悬停揭示的控件【规范默认】

适用：行尾快捷操作、卡片角落操作、轮播箭头、分隔条把手等「平时淡化、悬停才显」的控件。必须**同时**满足：

1. **键盘也能露出**：`:hover` 与 `:focus-within`（或控件自身 `:focus-visible`）同样触发；
2. **触控有路径**：在 `any-pointer: coarse` 时常驻，或有长按菜单 / 详情页等等价入口；
3. **不跳布局**：用 `opacity` / `visibility` 显隐并预留位置，不用 `display` 切换造成重排；
4. **不是唯一入口**：删除、编辑等关键操作在详情页或菜单里也能做（表格行操作藏在悬停里很难被发现）。

禁止：悬停打开导航菜单作为唯一入口；悬停自动播放；悬停触发写入或任何有副作用的请求。

可选：悬停停留 ≥100ms 后预取详情数据（只读、无副作用，用现有 React Query 预取机制），属于性能优化，需单独评估。

## 4. 光标【规范默认】

| 光标 | 用在 |
|---|---|
| `default`（箭头） | 普通区域 |
| `pointer`（手形） | **以本仓库现状为准**：浏览器默认给链接手形；按钮是否给手形要全站一致（Tailwind v4 预设已把按钮改回 `default`，仓库内目前只有零星 `cursor-pointer`）。**新增组件跟随同类组件，不各自决定**；统一与否列为 S19 视觉一致性议题 |
| `text`（I 形） | 可选中的文字、输入框（浏览器默认，不要覆盖） |
| `grab` / `grabbing` | 只给拖动把手或「主要操作就是拖动」的区域；可点击打开的卡片不要整块显示 `grab` |
| `col-resize` / `row-resize` | 工作区分隔条等可调尺寸的边 |
| `not-allowed` | 禁用控件（现有约定）；拖动到不可放置处 |
| `wait` / `progress` | 不用；用局部加载指示 |

## 5. 点击、中键、滚轮语义【规范默认】

- **单击 = 主操作**。网页里「打开」用单击，**不要求双击**；双击只能做加速（且不能劫持文字上的双击选词）。
- **中键 / Ctrl(⌘)+点击 / Shift+点击 导航入口**是浏览器的「新标签 / 新窗口打开」：导航优先用真实 `<a href>`（或 router `Link`），点击处理对带修饰键或非左键的点击放行（项目先例：`HierarchyView.tsx`）。暂时不能改成链接的导航按钮，用 `lib/desktopInput.ts` 的 `wantsNewTab` + `openInNewTab` 补上（先例：账目行、侧栏主导航，1.18.10），并排除依赖本页上下文的情况（多选、冲突、未同步、外部账本）。在已安装的 PWA 独立窗口里，新标签行为由浏览器决定，不要假设。
- 鼠标侧键（后退 / 前进）走浏览器历史，不拦截；页面状态要经得起后退 / 刷新。
- **滚轮不劫持**：不把纵向滚轮改成横向翻页、不做滚动吸附式整屏跳转；`Ctrl+滚轮` 是浏览器缩放，不拦截（项目先例：`lib/spaceTransition.ts` 对 `ctrlKey` 放行）；横向滚动容器要支持 Shift+滚轮与触控板横扫。
- 文字可选中：金额、备注、商户、编号要能被鼠标选中复制；`user-select: none` 只用于拖动把手和拖动进行中。
