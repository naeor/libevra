# 右键菜单（Context Menu）

> 上位：[SKILL.md](../SKILL.md) 规则 3。依据：Apple HIG Context menus / Pointing devices、Microsoft Menus and context menus / Mouse interactions、WAI-ARIA APG Menu 模式（见 [sources.md](sources.md)）。

## 1. 原则【规范默认】

- 右键菜单是「**这个对象**的高频次要命令」的快捷集合。**菜单里的每一项都必须在界面别处可达**（详情页、「更多 ⋯」按钮、工具栏、批量栏）——不允许出现只有右键才能做的事，因为右键没有任何视觉提示，触控用户也用不到。
- **一致性**：同一类对象在全应用要么都有右键菜单、要么都没有；用户在一个列表里学会右键，会在其它列表里继续尝试。
- 菜单与上下文菜单的分工：挂在按钮上、按钮本身就是为了展开命令的 → 普通菜单（点击打开）；挂在内容对象（账目行、卡片、账本）上的 → 上下文菜单。
- 菜单只放命令，不放说明性内容；要展示信息用弹出面板或对话框。

## 2. 触发方式（全部支持）

| 方式 | 说明 |
|---|---|
| 鼠标右键、触控板双指点按、macOS Control+点击 | 浏览器都会派发 `contextmenu` 事件 |
| 键盘 Shift+F10、菜单键（`event.key === "ContextMenu"`） | 菜单锚定在元素上而不是指针处；项目先例：`workspace/openDrag.tsx` 的 `onKeyDown` |
| 触控长按 | 与现有「长按浮起拖动」共存，沿用 `openDrag.tsx` 的模型（拖动已开始则不弹菜单），**不要再给长按加第二种含义** |
| 可见的「更多 ⋯」按钮 | 打开**同一份**命令列表；这是给不知道右键的人和触控用户的入口 |

## 3. 什么时候拦截浏览器原生菜单

- **只在定义了自定义菜单的对象上** `preventDefault()`。其它地方保留浏览器菜单（检查、翻译、打印等是用户的权利）。
- **不拦截**：输入框 / 文本域 / 可编辑区域（需要粘贴、拼写建议、输入法）；对象内**已有非空文字选区**时（用户要复制）。
- 自定义菜单覆盖了链接型对象时，中键 / Ctrl(⌘)+点击「新标签打开」仍须可用（见 [input-and-hover.md](input-and-hover.md) §5）。
- 不要试图阻止 Firefox 的 Shift+右键强制原生菜单。

## 4. 内容与排序【规范默认】

- **短**：常见 5–9 项，最多约 3 组（分隔线分组），子菜单最多一层且标题能预示内容。
- **顺序**：打开 / 查看 → 编辑类 → 复制 / 移动 / 在工作区打开 → 分隔 → **危险操作放最后**（删除、移除），用现有 `danger` 色（`--color-danger` / `text-danger`），不新增颜色。
- **文案**：动词开头、与界面其它入口同名同义（同一个命令全应用只有一个叫法）；需要进一步输入或确认的项以「…」结尾（如「移动到账本…」）。
- **禁用项保留显示**（`aria-disabled="true"`，可聚焦），能说明原因时说明（如「离线时不可用」）。原因判断**引用现有判断函数**，不得改写、移动或合并（AGENTS §6 敏感权限规则）。
- **多选时**：右键已选中的对象 → 作用于整个选择集，首行写「已选 N 笔」；右键**未选中**的对象 → 先把选择改为该对象再弹菜单（Windows / macOS 文件管理器惯例）。
- **快捷键提示**：Libevra 没有桌面应用的菜单栏，快捷键需要别的地方可发现。菜单项右侧可用弱化文字显示快捷键（按平台显示 ⌘ / Ctrl），**前提是对应快捷键已经过所有者确认**（见 [keyboard-and-focus.md](keyboard-and-focus.md) §6）。

## 5. 定位、行为与无障碍【规范默认】

- **位置**：鼠标打开时左上角对齐指针、向右下展开，碰到视口边缘翻转或贴边；键盘打开时锚定在元素上。
- **不被裁切**：渲染到页面顶层（portal / `position: fixed`），以**整个视口**为边界，而不是所在的工作区、卡片或侧栏（与 S18-B §5.3「菜单不得被裁切」同一要求）。
- **焦点**：打开后焦点进入第一个可用项；↑↓ 移动并循环，Home / End 到首尾（项目先例：`RailEntryMenu.tsx` 的 `onMenuKey`）；→ 打开子菜单、← 返回；Enter / Space 执行；**Esc 关闭并把焦点还给触发元素**；Tab 关闭菜单并按正常顺序移走焦点。可选：按首字母跳到对应项。
- **关闭**：点击菜单外、窗口失焦、页面滚动、窗口尺寸变化、路由变化都关闭；执行命令后关闭。
- **语义**：`role="menu"` / `role="menuitem"`（勾选项 `menuitemcheckbox` / `menuitemradio`）；「更多」按钮加 `aria-haspopup="menu"` 与 `aria-expanded`。
- **动效**：≤100ms 淡入或直接出现；`prefers-reduced-motion` 下直接出现；出现时不得移动页面内容。

## 6. 实现要点

- **命令只定义一次**：为每类对象建一份命令描述（id、文案 key、图标、是否危险、快捷键、`enabled(ctx)`、`run(ctx)`），「更多」按钮、右键菜单、快捷键、批量栏都读这一份——四处各写一遍迟早不一致（AGENTS「一件事只留一份记录」）。
- `enabled(ctx)` 只**调用**现有的权限 / 游客 / 离线 / 外部账本判断，不复制其逻辑。外部账本工作区里离线写入被拒绝（`lib/ledgerWriter.ts`），菜单里的写操作同样禁用。
- 复用 `openDrag.tsx` 已有的右键与 Shift+F10 处理、`RailEntryMenu.tsx` 的方向键逻辑。若需要抽出通用菜单组件，那是**单独一件事**，且不得顺带改动其中的显示 / 可点判断。
- 删除类命令走现有确认与撤销（`ConfirmDialog`、`UndoProvider` / `UndoBar`），不另做一套。
- 测试：Vitest 用 `fireEvent.contextMenu`、`fireEvent.keyDown(el, { key: "F10", shiftKey: true })`；Playwright 用 `locator.click({ button: "right" })` 与 `keyboard.press("Shift+F10")`。
